# 00 - Go 技术文档编写规范总览

> 🟢 本规则库只适用于 Go 项目的技术文档。<br>
> 🔴 不适用：产品、设计、美术、运营和管理文档；也不以通用 Go 经验替代项目事实。

---

## 1. 目标与边界

技术文档只记录工程、模块、契约、测试、运行和技术决策。目标是让读者快速找到可信结论，而不是把代码、配置或其他领域内容再抄一遍。

本规则库只管理 `项目文档/技术文档/`，不定义完整项目文档的分类。产品需求、策划设计、美术规范、运营和管理流程由各自既有规范与责任人维护；它们不得混入技术文档目录。

| 合格特征 | 最低要求 |
|---|---|
| 可发现 | 从 `README.md` 找到文档 |
| 可验证 | 关键结论有代码、配置、契约或测试来源 |
| 易理解 | 结论在前，短段落、列表和必要表格优先 |
| 可维护 | 有 负责人、状态、更新时间和废弃路径 |

## 2. 核心原则

1. 项目中的 `go.mod`、`go.sum`、`go.work`、源码、配置、构建和 CI 事实优先。
2. 一篇文档只回答一个主要问题；不预建空目录或空模板。
3. 数值、接口、配置和 schema 只保留一个权威来源。
4. 已验证、提议、待确认和废弃内容必须显式区分。
5. 代码规范仍由 Go AI 编码规则库维护，不在技术文档中重复。
6. `00` 至 `07` 是技术主题基线，不是文档数量上限；主题下按真实维护需求扩展子文档，必要时才新增 `08` 及后续主题。
