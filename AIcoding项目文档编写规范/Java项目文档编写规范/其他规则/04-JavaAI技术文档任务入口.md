# 04 - Java AI 技术文档任务入口

> 🟢 本文件适用于 AI 创建、修改、审查和同步 Java 技术文档。<br>
> 🔴 不适用：臆造项目事实、伪造验证，或擅自升级 JDK、依赖、框架和构建系统。

---

## 1. 开始前

1. 确认任务属于技术文档，或由实现任务的文档影响判断触发；产品需求、策划设计、美术规范、运营和管理流程不在本规则范围，不得写入 `项目文档/技术文档/`。
2. 阅读当前 AI 编辑器的项目级规则入口、贡献指南、技术文档根目录 `README.md`、`00-新人上手.md`、`01-技术总览.md` 和已有主题目录；Codex 的入口通常是 `AGENTS.md`，其他编辑器使用各自已验证的入口形式。
3. 搜索同主题文档、主题 `README.md` 和 ADR，避免重复。
4. 检查相关构建文件、源码、配置、迁移、契约、测试、部署和 CI 事实。
5. 确认来源、读者、状态和负责人；负责人缺失时先询问，仍无法确认只能在 `草稿` 中临时标记 `待确认`。

## 2. 创建、更新与同步

- 🔴 已有文档足够覆盖同一个主要问题时优先更新；否则先归入既有 `02` 至 `07` 技术主题并按模板新建子文档。
- 🔴 仅当现有 `00` 至 `07` 都无法合理容纳，且满足 `01-技术文档组织与维护规范.md` 的新增主题条件时，才新增 `08` 及后续一级技术主题。
- 🔴 新建主题目录必须同时创建 `README.md` 和至少一篇真实正文；不得预建空目录或空模板。
- 🔴 AI 不得臆造负责人；`待确认` 只允许用于 `草稿`，文档转为 `有效` 前必须明确人员、团队或项目认可的责任角色。
- 🔴 更新技术文档根目录或最近一级主题目录的 `README.md`、关联链接和术语区。
- 🔴 代码、配置、迁移、契约、依赖或运行流程变更使 `有效` 文档失真时，同步更新受影响内容；无法确认时报告差异。
- 🔴 新增、拆分、合并或删除独立业务模块时，检查并更新项目已有的模块覆盖矩阵；没有独立映射文件时至少检查技术文档 `README.md` 的模块入口。
- 🔴 当前事实必须以源码、路由、配置、迁移、契约和测试为依据；同步后扫描受影响文档中的旧术语和旧能力描述。
- 🔴 文档被替代时改为 `已废弃`，保留原因与替代路径。

## 3. 交付

交付时说明触发本规则的原因、修改内容及依据、负责人和状态、已同步文档、已执行校验、未验证范围与风险；确认无文档影响时说明判断依据，不得静默跳过。
