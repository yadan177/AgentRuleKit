# 01 - 技术文档组织与维护规范

> 🟢 本文件适用于 JS+TS 技术文档的目录、索引、命名、元数据和生命周期。<br>
> 🔴 不适用：非技术文档的组织与维护。

---

## 1. 推荐目录

```text
技术文档/
├── README.md
├── 00-新人上手.md
├── 01-技术总览.md
├── 02-架构与工程/
├── 03-模块设计/
├── 04-接口与数据/
├── 05-测试与质量/              # 有独立维护需求时创建
├── 06-运行维护/
└── 07-架构决策记录/
```

| 位置 | 内容 |
|---|---|
| `00-新人上手.md` | 环境、权限、首次运行、验证和求助入口 |
| `01-技术总览.md` | 运行时、包管理器、工作区、关键入口和术语 |
| `02-架构与工程/` | 应用/包边界、构建、环境变量和依赖约定 |
| `03-模块设计/` | 模块职责、状态、异步边界和验证 |
| `04-接口与数据/` | HTTP、事件、浏览器存储、schema 和兼容性 |
| `05-测试与质量/` | 测试策略、质量门禁、性能基线和可观测性 |
| `06-运行维护/` | 构建、部署、排障、恢复和运行手册 |
| `07-架构决策记录/` | ADR 与技术取舍 |

- 🔴 `00-新人上手.md` 放在技术文档根目录。
- 🔴 `05-测试与质量/` 仅在有独立 owner、独立更新节奏或至少 3 篇资料时创建；否则写入模块或运行维护文档。
- 🔴 不新增产品、设计、管理或代码规范目录。

## 2. 索引与命名

每个含正文的目录必须有 `README.md`，只做导航：

```markdown
# <目录名称>

| 文档 | 说明 | 状态 | Owner |
|---|---|---|---|
| [<标题>](./<文件名>.md) | <一句话说明> | active | <负责人> |
```

- 🔴 创建、移动、重命名或废弃文档后更新最近一级 `README.md`。
- 🔴 文件名使用简短中文主题；禁止日期、版本号、“最终版”和“新版”。
- 🔴 引用必须给出具体路径、标题或 JS/TS 符号，禁止只写“见代码”。
- 🟡 跨文档术语登记在 `01-技术总览.md` 的术语区。

## 3. 元数据与生命周期

除 `README.md` 外，技术文档使用：

```yaml
---
title: <标题>
owner: <负责人或待确认>
status: draft | active | deprecated
last_updated: <YYYY-MM-DD>
related: [<项目内相对路径>]
sources: [<代码符号、配置、契约或测试记录>]
---
```

- 🔴 `draft` 写清待确认项；`active` 只记录当前有效事实；`deprecated` 写明替代路径。
- 🔴 实质修改更新 `last_updated`。
- 🔴 废弃时保留原文、原因和替代路径，不直接删除。
