# 02 - JS+TS 技术文档编写规范

> 🟢 本文件适用于 JS+TS 工程、模块、接口、数据、测试、运行和 ADR 正文。<br>
> 🔴 不适用：将框架、依赖、命令或性能结论写成没有证据的项目事实。

---

## 1. 写作要求

- 🔴 先写用途、范围和结论，再写必要细节。
- 🔴 每段只表达一个意思；使用列表、表格和短句，删除重复背景与空话。
- 🔴 数值、接口签名、环境变量、配置和 schema 指向权威来源，不复制第二份真相。
- 🔴 无证据时使用 `> ⚠️ 待确认：<问题>`，不得猜测。
- 🟡 组件、调用或数据关系复杂时才使用 Mermaid。

## 2. JS+TS 事实检查

| 主题 | 优先来源 |
|---|---|
| 运行时与依赖 | `package.json`、锁文件、Node/浏览器配置和工作区定义 |
| 类型与构建 | `tsconfig*.json`、构建配置、脚本和现有应用/包结构 |
| 配置与数据 | 环境变量 schema、配置文件、迁移、浏览器存储和数据定义 |
| 契约 | OpenAPI、事件定义、共享类型、客户端/服务端契约 |
| 质量与运行 | 测试配置、日志、错误上报、性能记录、CI 和部署配置 |

- 🔴 涉及 Promise、任务取消、订阅、定时器、事件监听或资源时，说明创建方、所有者、取消/清理时机和错误路径。
- 🔴 涉及 HTTP、事件、浏览器存储或服务端数据时，说明提供方、消费方、兼容性和权威定义。
- 🔴 构建与排障步骤写清前置条件、操作、预期结果、失败处理和验证点。
- ❌ 不默认使用 React、Vue、Next.js、Vite、Webpack、Node 框架或测试工具；以项目证据为准。

## 3. 状态与自检

| 状态 | 要求 |
|---|---|
| `draft` | 说明提议内容、待确认项和验收条件 |
| `active` | 说明适用范围、来源、限制和验证方式 |
| `deprecated` | 说明废弃原因、替代路径和生效时间 |

- [ ] 开头有用途、范围和不覆盖内容。
- [ ] 关键结论可定位到来源，未知项已标记。
- [ ] 异步、事件、资源清理和兼容性边界在适用时已说明。
- [ ] 索引、链接和文档变更记录已同步。
