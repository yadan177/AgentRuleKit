# 14 - Unity 安全模块规则

> 🟢 本文件适用于 Unity 项目的安全防护（客户端数据 / 反作弊 / 资源保护 / 网络安全 / 用户隐私 / 支付安全）。

> 🔴 不适用：纯单机游戏（无网络）、纯服务端业务逻辑（用对应语言规则）、UI 样式设计

---

## 1. 客户端数据安全

🔴 **AI 开始前**必须识别数据分类、目标平台、已安装安全插件、服务端信任边界、隐私地区要求和现有密钥管理方案。客户端不能成为关键权限、支付、随机结果或反作弊判定的最终信任方。

### 1.1 存储选型

| 平台 | 推荐方案 | 加密 |
|---|---|---|
| **iOS** | Keychain | 系统级加密 |
| **Android** | EncryptedSharedPreferences / Keystore | AES-256 |
| **Windows** | DPAPI / Credential Manager | 系统级 |
| **Editor（仅调试）** | EditorPrefs | **不加密**（仅本地开发） |

🟡 项目已提供或明确选择跨平台安全存储抽象时，可使用 `ISecureStorage` 一类接口；平台 API 与第三方插件的可用性、密钥来源和降级行为必须逐平台验证。

```csharp
public interface ISecureStorage {
    void Save(string key, string value);
    string Load(string key);
    void Delete(string key);
}

// iOS 实现：Security.framework / Keychain
// Android 实现：EncryptedSharedPreferences
// Windows 实现：DPAPI
```

🔴 必加约束：

- ✅ **Token / API Key 用安全存储**（不用 PlayerPrefs）
- ✅ **不要存明文密码**
- ✅ **不存游戏存档以外的敏感数据**

### 1.2 存档加密

🟡 本地存档可在威胁模型需要时使用经审查的加密方案；若密钥随客户端分发，加密只能提高篡改成本，不能替代服务端权威与关键数据校验。

🔴 不要复制“只调用 `Aes.Create()`”的半成品代码。存档保护至少要明确：经认证的加密（或独立完整性校验）、每份数据唯一的 nonce/IV、认证标签、密钥来源、格式版本、轮换/失效策略和解密失败处理。具体算法与 API 必须以目标 Unity/.NET 运行时和平台安全能力验证为准。

```csharp
public interface ISaveProtector
{
    byte[] Protect(byte[] plain);
    bool TryUnprotect(byte[] protectedData, out byte[] plain);
}

// ISaveProtector 由项目已验证的安全实现提供。
// 密文格式应包含格式版本、nonce/IV、认证标签和密文；密钥不写入存档或 PlayerPrefs。
public sealed class SaveSerializer
{
    private readonly ISaveProtector m_protector;

    public SaveSerializer(ISaveProtector protector)
    {
        m_protector = protector;
    }

    public void Save<T>(T data) where T : class {
        var json = JsonSerializer.Serialize(data);
        var plain = Encoding.UTF8.GetBytes(json);
        var protectedData = m_protector.Protect(plain);
        File.WriteAllBytes(GetSavePath(), protectedData);
    }

    public T Load<T>() where T : class {
        var protectedData = File.ReadAllBytes(GetSavePath());
        if (!m_protector.TryUnprotect(protectedData, out var plain))
            throw new InvalidDataException("存档已损坏、被篡改或无法由当前密钥读取。");

        var json = Encoding.UTF8.GetString(plain);
        return JsonSerializer.Deserialize<T>(json)
            ?? throw new InvalidDataException("存档内容格式无效。");
    }
}
```

🟡 若项目只需要检测基础篡改，也可以采用带签名/校验的存档格式；无论选择哪种方案，都必须明确攻击模型和服务端校验边界，不能把客户端密钥当成保密根。


## 2. 反作弊（服务端权威）

### 2.1 设计原则

🔴 联网产品的关键判定必须由服务端或可信执行边界完成——不信任客户端数据。纯离线功能无法获得同等级防护，应明确其篡改风险和可接受范围。

| 操作 | 客户端角色 | 服务端角色 |
|---|---|---|
| **伤害计算** | 提交攻击请求 | 计算伤害、扣 HP |
| **奖励发放** | 提交成就 | 验证成就、发放奖励 |
| **排行榜** | 提交分数 | 服务端计分（不信任客户端分数）|
| **抽卡 / 开箱** | 请求开箱 | 服务端随机 + 发放 |
| **支付** | 请求支付 | 服务端验证 + 发放 |

```csharp
// ❌ 危险：客户端算伤害
float damage = attack * 1.5f - defense * 0.3f;
enemyHealth -= damage;  // 作弊：damage 可被修改为 99999

// ✅ 正确：客户端提交，服务端算
public async Task AttackAsync(int targetId, int skillId) {
    await _api.PostAsync("/v1/battle/attack", new {
        targetId, skillId
        // 不带 damage —— 服务端算
    });
}
```

### 2.2 服务端检测

🟡 推荐：服务端检测异常行为。

| 检测项 | 异常 |
|---|---|
| 攻击频率 | 1 秒内攻击 > 10 次 |
| 单次伤害 | 1 秒内造成伤害 > 100000 |
| 通关速度 | 30 秒内通关正常需 10 分钟的关卡 |
| 金币变化 | 单次获得金币 > 1000000 |
| 设备异常 | 模拟器 / Root / 调试器 |

```csharp
// 服务端伪代码
public async Task<BattleResult> ProcessAttackAsync(long playerId, AttackRequest req) {
    var lastAttack = await _redis.GetAsync($"last_attack:{playerId}");
    if (DateTime.UtcNow - lastAttack < TimeSpan.FromMilliseconds(100))
        throw new RateLimitException("操作过于频繁");

    var player = await _db.GetPlayerAsync(playerId);
    var skill = await _db.GetSkillAsync(req.SkillId);
    var damage = CalculateDamage(player, skill, req);

    if (damage > player.MaxPossibleDamage * 1.5)
        await _auditLog.LogAsync("SUSPICIOUS_DAMAGE", playerId, damage);

    await ApplyDamage(req.TargetId, damage);
    return new BattleResult { Damage = damage };
}
```


## 3. 客户端防作弊（基础防护）

> ⚠️ **重要**：客户端防作弊是**纵深防御**——不替代服务端验证。

### 3.1 检测 Root / 越狱

🟡 推荐：检测设备是否被 Root / 越狱（合规与防作弊需求）。

```csharp
public class DeviceIntegrity {
    public bool IsCompromised() {
#if UNITY_ANDROID && !UNITY_EDITOR
        return CheckRootBinaries() || CheckSuBinary() || CheckRWAccess();
#elif UNITY_IOS && !UNITY_EDITOR
        return CheckJailbreakFiles() || CheckCydiaURL() || CheckFork();
#else
        return false;  // Editor / 其他平台
#endif
    }
}
```

🔴 注意：**不要直接禁用游戏功能**——检测到 Root 只是上报，让用户选择继续玩或退出。

### 3.2 检测调试器

🟡 推荐：检测调试器（仅 Release 模式启用）。

```csharp
public class DebuggerDetector {
    public bool IsDebuggerAttached() {
#if !UNITY_EDITOR && (DEVELOPMENT_BUILD || UNITY_EDITOR)
        return false;
#elif UNITY_ANDROID
        return AndroidJavaClass
            .FromType("android.os.Debug")
            .CallStatic<bool>("isDebuggerConnected");
#elif UNITY_IOS
        return CheckDebuggerSysctl();
#else
        return false;
#endif
    }
}
```

🔴 必加约束：

- ✅ **仅在 Release 构建启用**（不影响开发体验）
- ✅ **上报不阻断**（调试器可能是合法用户）
- ✅ **避免误判**（LPSCHR / lldb-server / 模拟器都会触发）

### 3.3 内存修改检测

🟡 联网产品可在服务端权威、网络预算和隐私策略允许时定期校验关键状态；客户端校验只能增加篡改成本，不能作为信任根。

仅在 Unity 6+ 且项目已经验证 `Awaitable` 作为异步基础设施时，可使用下面的形式；较早版本应沿用项目既有的协程或网络调度抽象，且同样传递取消信号。

```csharp
// 客户端：定期验证 HP/金币是否与服务端一致
public async Awaitable ValidateStateLoopAsync(CancellationToken token) {
    while (!token.IsCancellationRequested) {
        await Awaitable.WaitForSecondsAsync(60f, token);
        var serverState = await _api.GetPlayerStateAsync(token);
        if (serverState.Hp != LocalPlayer.Hp) {
            ProjectLog.Write(LogLevel.Warn, "Security.State", "HP 异常，按服务端状态刷新");
            LocalPlayer.Hp = serverState.Hp;
        }
    }
}
```


## 4. 资源保护

### 4.1 Asset Bundle 加密

🟡 若项目已有 AssetBundle/Addressables/YooAssets 资源体系，且威胁模型确实要求提高资源提取成本，可评估其兼容的加密或签名方案。客户端可读取的资源与密钥无法实现绝对保密；不要因本节自行新增不可维护的加密层。

```csharp
// 仅展示边界：保护格式、认证、密钥获取与轮换由项目已验证的资源保护服务负责。
public interface IBundleProtector
{
    bool TryUnprotect(byte[] protectedData, out byte[] plainData);
}

public sealed class ProtectedBundleLoader
{
    private readonly IBundleProtector m_protector;

    public ProtectedBundleLoader(IBundleProtector protector)
    {
        m_protector = protector ?? throw new ArgumentNullException(nameof(protector));
    }

    public async Task<AssetBundle> LoadBundleAsync(string path)
    {
        var protectedData = File.ReadAllBytes(path);
        if (!m_protector.TryUnprotect(protectedData, out var plainData))
            throw new InvalidDataException("资源损坏、篡改或当前密钥不可用。");

        var request = AssetBundle.LoadFromMemoryAsync(plainData);
        return await request;
    }
}
```

### 4.2 IL2CPP 与代码混淆

🟡 IL2CPP、符号处理、混淆和完整性保护应按目标平台、Unity 版本、热更新方式、调试/崩溃分析需求与预算评估；它们提高逆向门槛，不能替代服务端授权与密钥管理。

| 平台 | 必加 | 推荐 |
|---|---|---|
| **iOS** | 按 Unity 平台构建要求确认 | 评估与签名、崩溃分析和合规兼容的保护方案 |
| **Android** | 由项目的脚本后端与插件兼容性确认 | 评估 R8/混淆、完整性与应用商店要求 |
| **Windows / Mac** | 由发布渠道、运行时和性能要求确认 | 评估代码与资源保护的收益、兼容性和维护成本 |

🔴 必加约束：

- ✅ iOS、Android 与桌面端的脚本后端以当前 Unity 版本、目标架构、插件兼容性和构建验证为准；不把任一后端写成所有 Release 的默认要求。
- ✅ **不要把业务密钥硬编码**（即使混淆也能反编译）

### 4.3 防资源提取

🟡 若项目已有 Addressables/YooAssets 或其他资源体系，并且威胁模型确实要求提高资源提取成本，可评估该体系兼容的加密/签名方案（详见 09-资源管理规则）。不要为了资源保护擅自迁移资源系统或在客户端硬编码密钥。


## 5. 网络安全

### 5.1 必加约束

- ✅ 生产环境中携带认证、个人信息或交易数据的 API 使用 HTTPS；本地开发、模拟服务或受控测试的明文例外必须由配置明确，不能流入生产。
- 🟡 请求签名、nonce、设备绑定和防重放仅在服务端协议明确要求时实现；客户端不得自行发明字段、算法或过期窗口。
- 🔴 **关键操作必须由服务端校验**（不信任客户端），包括权限、金额、奖励、库存和支付状态。

### 5.2 请求认证与防重放

客户端二进制中无法长期保守共享 HMAC 密钥。因此，**不要把 `_secret`、HMAC 签名密钥或服务端私钥硬编码进 Unity 客户端**；攻击者能够提取它，静态“请求签名”不能证明请求可信。

服务端协议若需要附加防重放，应明确并实现以下边界：

- 认证凭据的签发、刷新、失效与撤销；客户端只使用项目已有认证服务注入的短期凭据。
- 服务端生成或验证的 nonce、一次性请求 ID / 幂等键、时间窗口和已用请求记录；只校验时间戳不足以阻止窗口内重放。
- 如采用设备绑定或设备证明，密钥材料必须由平台安全存储/硬件能力保护，服务端需验证证明并处理换机、撤销和隐私告知。
- 请求体规范化、版本兼容、失败码和重试必须与服务端契约一致，不能由客户端自行拼接签名字符串。

```csharp
// 仅展示调用边界：认证与防重放字段由项目已确认的协议服务提供。
var request = new HttpRequestMessage(HttpMethod.Post, relativePath);
request.Headers.Authorization = new System.Net.Http.Headers.AuthenticationHeaderValue(
    "Bearer", tokenProvider.GetValidAccessToken());
request.Headers.Add("Idempotency-Key", requestIdProvider.Create()); // 仅服务端契约要求时添加

// 不要在此处生成或保存服务端共享 HMAC 密钥。
var response = await client.SendAsync(request, cancellationToken);
```

### 5.3 反调试（网络层）

🟡 推荐：检测异常 IP 模式（同账号多 IP / 高频切换 IP）。

```csharp
// 服务端伪代码
var recentIps = await _redis.LRangeAsync($"user:{userId}:ips", 0, 9);
if (recentIps.Distinct().Count() > 5) {
    await _fraudDetector.FlagAsync(userId, "MULTIPLE_IPS");
    // 可能触发：强制二次验证 / 临时封号
}
```


## 6. 用户隐私

### 6.1 必加约束

- ✅ **遵守《个人信息保护法》（PIPL） / GDPR**
- ✅ **明确告知收集哪些数据**（隐私政策）
- ✅ **用户可导出 / 删除自己的数据**（数据可携权）
- ✅ **未成年人保护**（实名认证、防沉迷、未成年退款）

### 6.2 数据收集最小化

🔴 必加约束：**只收集业务需要的数据**。

| 数据 | 是否必要 | 用途 |
|---|---|---|
| 设备标识 | ⚠️ 视合法目的与平台能力而定 | 反欺诈 / 风险控制；需最小化、告知与保留期限 |
| 手机号 | ⚠️ 看场景 | 实名 / 客服 |
| 身份证 | ⚠️ 看场景 | 实名 / 防沉迷 |
| 地理位置 | ❌ 通常不必要 | — |
| 通讯录 | ❌ 严禁 | — |
| 短信 | ❌ 严禁 | — |

### 6.3 数据加密与脱敏

详见 14.5 网络安全。


## 7. 支付安全

### 7.1 服务端验证（必加）

🔴 必加约束：**支付由服务端验证**——客户端只发起请求。

```csharp
// ❌ 危险：客户端算金额
public void OnPurchaseButtonClick() {
    int amount = 99;  // 客户端写死 → 作弊改 0
    _api.PostAsync("/v1/purchase", new { amount, productId });
}

// ✅ 正确：服务端算金额
public void OnPurchaseButtonClick() {
    _api.PostAsync("/v1/purchase", new { productId });  // 只传 productId
    // 服务端查表得金额
}
```

### 7.2 防刷与防退款

- ✅ **支付凭证服务端验证**（不信任客户端回调）
- ✅ **一人一单**（活动期间防刷）
- ✅ **未发货退款**（未成年退款必须执行）

### 7.3 Apple / Google 内购

🔴 必加约束：**内购必须用官方 SDK**（IAP / BillingClient）——不用第三方支付。

```csharp
// iOS 内购
using UnityEngine.Purchasing;
public class IAPManager : IStoreListener {
    public void BuyProduct(string productId) {
        _controller.InitiatePurchase(productId);
    }

    public void OnPurchaseComplete(Product product) {
        // 1. 验证 receipt（服务端验证）
        var receipt = product.receipt;
        StartCoroutine(_api.VerifyReceiptAsync(productId, receipt, OnVerified));
    }

    private void OnVerified(VerifyResult result) {
        if (result.IsValid) {
            // 2. 发放奖励（服务端发放）
            _api.GrantRewardAsync(result.PlayerId, productId);
        }
    }
}
```

服务端验证 receipt：
```csharp
// 服务端伪代码
public async Task<VerifyResult> VerifyReceiptAsync(string productId, string receipt) {
    // 1. 调用 Apple / Google 验证
    var isValid = productId switch {
        "com.example.coin_100" => await AppleVerifyAsync(receipt),
        _ => await GoogleVerifyAsync(receipt)
    };
    if (!isValid) return VerifyResult.Invalid();

    // 2. 检查是否已使用（防重放）
    if (await _redis.ExistsAsync($"receipt:{receipt.GetHash()}"))
        return VerifyResult.Replay();

    // 3. 标记已使用
    await _redis.SetAsync($"receipt:{receipt.GetHash()}", "1", TimeSpan.FromDays(365));

    return VerifyResult.Ok();
}
```


## 8. AI 安全清单

AI 实现 Unity 安全相关功能时，必须按此清单核查：

### 8.1 数据存储

- [ ] Token / API Key 用安全存储（Keychain / Keystore）
- [ ] **不把 Token 写 PlayerPrefs**
- [ ] 存档加密方案与威胁模型、密钥来源和平台能力匹配（如需要）

### 8.2 反作弊

- [ ] **所有关键判定放服务端**（伤害 / 奖励 / 抽卡 / 支付）
- [ ] 服务端检测异常行为（攻击频率 / 伤害异常）
- [ ] 客户端基础防作弊（仅 Release）：Root 检测 / 调试器检测 / 内存校验

### 8.3 资源保护

- [ ] 资源保护方案与现有资源系统和平台能力匹配（如需要）
- [ ] Release 后端、代码混淆与防篡改方案经过目标平台、热更新与构建流程验证（如需要）

### 8.4 网络

- [ ] **所有 API 用 HTTPS**
- [ ] 请求签名、设备绑定与防重放策略符合服务端协议（如需要）

### 8.5 隐私

- [ ] 遵守《个人信息保护法》/ GDPR
- [ ] **只收集必要数据**（最小化原则）
- [ ] 用户可导出 / 删除数据
- [ ] 隐私政策明确告知

### 8.6 支付

- [ ] **服务端验证支付凭证**（不信任客户端）
- [ ] 一单一单防刷
- [ ] 用官方 IAP SDK（iOS StoreKit / Google Play Billing）
- [ ] Receipt 一次性（防重放）
- [ ] 未成年退款支持


> 💡 完成上述 6 大类 = Unity 安全模块最小可用基线。
