# 06 - Unity 项目配置

> 🟢 本文件适用于检查或修改 Unity 的 Editor Settings、Project Settings、包、渲染管线、Build Settings 与预设。
>
> 🔴 不适用：把示例配置直接覆盖到未知项目，或未经授权升级 Unity、包、渲染管线与构建体系。

---

## 1. 项目初始化与兼容性检查

🔴 **AI 修改配置前**必须先读取 `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json`、现有渲染与输入设置、目标平台、构建脚本和同项目配置。以下值是按条件选择的参考，不是可直接覆盖的默认清单。

### 1.1 Unity 版本锁定

> 🔑 **关键决策**：项目应锁定团队已验证支持的 Unity 版本；新项目可优先评估当前 LTS，但不得擅自升级已有项目。

✅ 推荐
- 使用项目已锁定版本；新项目可在平台、插件和发布周期均兼容时选择受支持的 LTS
- `ProjectSettings/ProjectVersion.txt` 写入具体版本号（如 `2022.3.20f1`）
- 团队所有成员 IDE（VSCode / Rider）版本统一

❌ 不要
- 使用 Unity Beta / Tech Stream 版本（除非项目明确需要）
- 混用 2021 LTS + 2022 LTS

### 1.2 Packages/manifest.json 必备包

✅ 按项目需要选择
- 渲染：已采用 URP 时使用 `com.unity.render-pipelines.universal`
- 输入：沿用项目已经启用的 Input System 或 Legacy Input
- UI：沿用已采用的 UI Toolkit、UGUI 或其他 UI 体系
- 调试：仅在项目已有或用户授权时引入 Memory Profiler、Profiler Core 等工具

❌ 不要
- 引入"看起来很全"的 Asset Store 包（按需引入）
- 同时启用新旧 Input System（除非项目有兼容性需求）

### 1.3 文件夹结构

✅ 推荐
```
Assets/
├── Scenes/
├── Scripts/
├── Prefabs/
├── Materials/
├── Shaders/
├── Textures/
├── Audio/
├── Animations/
├── Resources/        # 仅用于运行时动态加载的资源
├── ScriptableObjects/ # 配置数据
└── Editor/           # 仅 Editor 脚本
```

❌ 不要
- 在 `Assets/` 根目录直接放脚本 / 资源
- 未核实项目资源系统时批量使用 `Resources/` 或迁移到 Addressables（详见 09）
- 混用 `/Scripts/` 和 `/scripts/`（大小写不一致）


## 2. 🟠 Editor Settings（必须配置）

### 2.1 Version Control 模式

> 🔑 **关键决策**：Unity 项目必须用 **Visible Meta Files** 模式，与 Git 兼容。

✅ 推荐
```
Edit > Project Settings > Editor > Version Control Mode: Visible Meta Files
```

❌ 不要
- `Hidden Meta Files`（`.meta` 文件会被忽略，Git 无法追踪）
- 在未确认团队合并与资产序列化策略时擅自切换 Asset Serialization

### 2.2 Asset Serialization

✅ 推荐
```
Asset Serialization: Force Text
```

理由：文本格式利于 Git 合并冲突解决和版本对比。

### 2.3 Script Compilation

✅ 推荐
- 移动端/正式发布的 Scripting Backend 以目标平台、插件、热更新与构建验证结果为准；IL2CPP 是候选，不是默认切换动作
- Api Compatibility Level、C# 语言特性与包兼容性以项目当前配置和目标平台为准
- 在目标平台、插件和构建流程均验证兼容时，发布版本可评估 `IL2CPP`

❌ 不要
- 未确认目标平台、热更新方案和第三方插件兼容性时切换 Scripting Backend 或 API Compatibility Level


## 3. 🟠 Project Settings 关键项

### 3.1 Player Settings

| 项 | 推荐值 | 备注 |
|----|--------|------|
| Company Name | 公司名 | 用于 Build 输出目录 |
| Product Name | 产品名 | 显示在 Build 标题 |
| Default Icon | 项目图标 | 必加 |
| Resolution | `Use Default` | 不锁定 |
| Run In Background | ✅ | 调试时切换窗口不暂停 |
| Resizable Window | ✅ | Editor 调试用 |

### 3.2 Quality Settings

✅ 推荐
- 至少 3 个 Quality Level：Low / Medium / High（移动端）
- VSync Count: Don't Sync（PC）/ Every V Blank（移动端）
- Anti Aliasing: 根据设备档位、渲染管线和画质目标验证后设置

❌ 不要
- 默认使用 Ultra Quality（移动端性能瓶颈）
- 所有平台都用同一个 Quality Profile

### 3.3 Graphics Settings

✅ 推荐
- URP Asset 按平台分（移动端 URP vs PC URP）
- 阴影 Distance: ≤ 50（移动端）/ ≤ 200（PC）
- 阴影 Cascades: 2（移动端）/ 4（PC）


## 4. 🟠 渲染管线选型

### 4.1 URP vs HDRP vs Built-in

| 维度 | URP | HDRP | Built-in |
|------|-----|------|----------|
| 适用平台 | 移动 / PC / Switch | PC / 主机 | 维护旧项目 |
| 性能 | ⭐⭐⭐⭐ | ⭐⭐ | ⭐ |
| 视觉表现 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| 学习成本 | 中 | 高 | 低 |
| 未来趋势 | ✅ 推荐 | ✅ 主机项目 | ❌ 淘汰中 |

✅ 推荐
- 新项目可在目标平台、插件和画质需求都兼容时评估 URP
- 高端平台或影视级渲染可评估 HDRP；已有 Built-in、URP 或 HDRP 项目应优先维持当前管线

### 4.2 URP Asset 配置

✅ 推荐
- 每平台一个 URP Asset（URP-Mobile / URP-PC）
- Renderer Feature 按平台裁剪（移动端禁用 SSAO / Bloom）
- LOD Bias: 1.5（移动端）/ 1.0（PC）


## 5. 🟠 Build Settings

### 5.1 场景列表

✅ 推荐
- 第一个场景是 Splash / 启动场景
- 场景按顺序加入 Build Settings
- 场景路径用相对路径（如 `Assets/Scenes/Main.unity`）

❌ 不要
- 场景顺序混乱（先用 UI 场景后用战斗场景）
- 路径含中文 / 空格

### 5.2 平台切换

✅ 推荐
- 项目已采用且当前 Unity 版本支持 Build Profiles 时，用其按平台分组
- Android / iOS / Windows / macOS 各自的 Player Settings 覆盖
- 切换平台后立刻跑一次 Build 检查


## 6. 🟡 预设管理（推荐）

### 6.1 Default Presets

✅ 推荐
- 创建常用资产的 Default Preset：AudioClip / Texture / Material / Prefab
- 预设放在 `Assets/Editor/Presets/`
- Preset 可通过 `Assets > Create > Preset` 快速应用

### 6.2 预设示例：Texture Import

```csharp
Default Texture:
- Texture Type: Sprite (2D and UI)
- Filter Mode: Bilinear
- Compression: Normal Quality
- Max Size: 2048
```


## 7. 🟡 常见配置错误清单

### 7.1 配置陷阱

| 陷阱 | 表现 | 解决方案 |
|------|------|---------|
| Color Space 选错 | 颜色发灰 | 按渲染管线、目标平台、美术资产与现有项目设置验证；不要用“2D=Gamma、3D=Linear”替代实际测试 |
| URP Asset 没换 | 移动端用 PC URP，掉帧 | 切换平台前换 URP Asset |
| API Compatibility 不匹配 | 包导入失败 | 以 Unity 版本、已安装包、目标平台和项目现有兼容级别验证后调整 |
| Target Architecture 错 | Android ARM64 不支持 | 勾选 ARM64（Google Play 要求）|

### 7.2 调试方法

> 💡 工具：
> - `Edit > Project Settings` 全面板检查
> - `Window > Analysis > Profiler` 看性能
> - `Edit > Preferences > External Tools` 配置 IDE


## 8. 🟢 高级配置（可选）

### 8.1 Custom Defines

✅ 可选
- 日志与诊断由统一日志门面的构建策略控制；不要在业务调用点逐条使用 `#if DEVELOPMENT_BUILD`，详见 [07-日志与调试规则](./07-日志调试规则.md)
- `#if UNITY_ANDROID` / `#if UNITY_IOS` 平台分支

❌ 不要
- 定义过多自定义宏（难维护）
- 宏嵌套超过 2 层

### 8.2 Scripting Define Symbols

✅ 推荐
- 按平台分组：`UNITY_ANDROID;UNITY_EDITOR` 等
- 团队自定义宏加项目前缀（如 `MYGAME_DEBUG`）

### 8.3 Addressables 配置

🟡 仅当项目已采用 Addressables 或资源架构明确选择它时配置本节：
- Group、地址、Build Path 与远程加载策略遵循项目现有资源/热更新设计，而不是按场景名称机械分组。
- `RemoteBuildPath`、`LocalBuildPath`、CDN、缓存和内容更新需要与发布流程、目标平台和回滚策略一并验证。
- 是否迁移 `Resources/` 由资源盘点、包体、内存、热更新需求和迁移风险决定；不要将“用 Addressables 替代 Resources”写成默认操作。

❌ 不要
- 未核对引用、包体和加载链路就混用或批量迁移 Addressables 与 Resources，导致资源重复或引用丢失。


## 9. 项目配置完成检查清单

AI 创建 / 修改 Unity 项目配置时，必须按此清单核查：

- [ ] Unity 版本锁定到 LTS
- [ ] `Packages/manifest.json` 必备包齐全
- [ ] 文件夹结构符合 § 1.3
- [ ] Editor Settings 用 Visible Meta Files + Force Text
- [ ] Scripting Backend、API Compatibility 与热更新/插件在目标平台构建中已验证
- [ ] Player Settings 关键项配置
- [ ] Quality Settings 按平台分级
- [ ] URP Asset 按平台分
- [ ] Build Settings 场景顺序正确
- [ ] 切换平台后 Build 通过

> 💡 完成上述 10 项 = Unity 项目配置最小可用基线。
