# 13 - Unity 服务端模块规则

> 🟢 本文件适用于 Unity 客户端的服务端集成（REST API / WebSocket / 实时同步 / 离线缓存 / 错误处理 / 部署监控）。

> 🔴 不适用：纯单机游戏（无服务端）、纯客户端 UI 设计、服务端内部架构（用对应语言规则）

---

## 1. 服务端集成边界

🔴 **AI 的职责是按既定契约实现 Unity 客户端集成**。服务端语言、BaaS、云函数、专用服务器和部署方式必须由项目架构或用户确认；本文件的比较表用于理解已选方案，不授权客户端任务自行选型或引入 SDK。

### 1.1 Unity 客户端面对的服务端模式

| 模式 | 特点 | 适用 | 客户端 SDK |
|---|---|---|---|
| **BaaS（后端即服务）** | 零运维 | 简单游戏、独立开发者 | Firebase / PlayFab / 腾讯云游戏 |
| **自建 REST API** | 完全可控 | 中型游戏、定制业务 | 自行实现 |
| **云函数 / Serverless** | 弹性扩缩容 | 不规律流量 | 自行实现 |
| **专用游戏服务器** | 高实时 | 多人游戏、MMO | 自行实现 + NetCode |

🟡 可在架构选型阶段参考：

- 独立项目可评估 BaaS（PlayFab / Firebase 等）的运维成本与合规边界。
- 定制业务可评估自建 REST API 的控制力与维护成本。
- 多人游戏可评估专用游戏服务器、同步框架与服务端权威策略。


## 2. 客户端-服务端通信模式

### 2.1 请求-响应（REST）

🟡 项目已采用 HTTPS + REST + JSON 时，可按既有 API Client、认证、重试和 DTO 约定实现；其他协议或序列化格式以已确认契约为准。

```csharp
// ✅ 项目已确认 HTTP + REST + JSON 时，用统一的 API Client
public sealed class GameApiClient {
    private readonly HttpClient _client;
    private readonly TokenService _tokens;

    public GameApiClient(HttpClient client, string baseUrl, TokenService tokens) {
        _client = client;
        _client.BaseAddress = new Uri(baseUrl);
        _client.Timeout = TimeSpan.FromSeconds(10);
        _tokens = tokens;
    }

    public async Task<ApiResult<PlayerDto>> GetPlayerAsync(int playerId, CancellationToken ct = default)
    {
        try {
            using var response = await SendWithFreshTokenAsync($"v1/players/{playerId}", ct);
            response.EnsureSuccessStatusCode();
            var json = await response.Content.ReadAsStringAsync(ct);
            var player = JsonSerializer.Deserialize<PlayerDto>(json);
            return player is null
                ? ApiResult<PlayerDto>.Fail("INVALID_RESPONSE", "响应体为空或格式不合法")
                : ApiResult<PlayerDto>.Ok(player);
        } catch (OperationCanceledException) when (ct.IsCancellationRequested) {
            throw; // 调用方决定取消后的 UI 与重试行为
        } catch (HttpRequestException ex) {
            return ApiResult<PlayerDto>.Fail("NETWORK_ERROR", ex.Message);
        }
    }

    private async Task<HttpResponseMessage> SendWithFreshTokenAsync(string relativePath, CancellationToken ct)
    {
        using var request = CreateAuthorizedGet(relativePath);
        var response = await _client.SendAsync(request, ct);
        if (response.StatusCode != HttpStatusCode.Unauthorized)
            return response;

        response.Dispose();
        await _tokens.RefreshAsync(ct);
        using var retry = CreateAuthorizedGet(relativePath);
        return await _client.SendAsync(retry, ct); // 只重试一次；退避与并发刷新遵循项目策略
    }

    private HttpRequestMessage CreateAuthorizedGet(string relativePath)
    {
        var request = new HttpRequestMessage(HttpMethod.Get, relativePath);
        request.Headers.Authorization = new System.Net.Http.Headers.AuthenticationHeaderValue(
            "Bearer", _tokens.AccessToken);
        return request;
    }
}
```

### 2.2 长连接（WebSocket）

🟡 聊天、实时通知或协作在服务端契约支持时可使用 WebSocket。开始前应确认消息边界、最大包大小、认证刷新、重连策略、主线程分发和离线补偿；本节不把任一客户端库设为默认依赖。

```csharp
public class RealtimeClient : IDisposable {
    private const int k_maxMessageBytes = 256 * 1024;
    private ClientWebSocket _socket = new();
    private readonly Uri _uri;
    private CancellationTokenSource _cts = new();
    private Task? m_receiveTask;

    public event Action<RealtimeEvent>? OnEvent;

    public async Task ConnectAsync(string accessToken) {
        _socket.Options.SetRequestHeader("Authorization", $"Bearer {accessToken}");
        await _socket.ConnectAsync(_uri, _cts.Token);
        m_receiveTask = ReceiveLoopAsync(); // 不在 Task.Run 中直接触碰 Unity 事件或 UI
    }

    private async Task ReceiveLoopAsync() {
        try {
            while (!_cts.Token.IsCancellationRequested) {
                var json = await ReceiveTextMessageAsync(_cts.Token);
                if (json is null) break;

                var evt = JsonSerializer.Deserialize<RealtimeEvent>(json);
                if (evt is not null)
                    OnEvent?.Invoke(evt);
                // 若项目将此循环放到后台线程，必须通过其既有主线程调度器再触发 Unity UI/对象访问。
            }
        } catch (OperationCanceledException) when (_cts.IsCancellationRequested) {
            // 正常关闭
        }
    }

    private async Task<string?> ReceiveTextMessageAsync(CancellationToken ct) {
        var buffer = new byte[8 * 1024];
        using var message = new MemoryStream();
        while (true) {
            var result = await _socket.ReceiveAsync(new ArraySegment<byte>(buffer), ct);
            if (result.MessageType == WebSocketMessageType.Close) {
                await _socket.CloseOutputAsync(WebSocketCloseStatus.NormalClosure, "closed", ct);
                return null;
            }
            if (result.MessageType != WebSocketMessageType.Text)
                throw new InvalidDataException("仅接受已约定的文本消息。");

            message.Write(buffer, 0, result.Count);
            if (message.Length > k_maxMessageBytes)
                throw new InvalidDataException("WebSocket 消息超过项目允许的大小。");
            if (result.EndOfMessage)
                return Encoding.UTF8.GetString(message.GetBuffer(), 0, checked((int)message.Length));
        }
    }

    public async Task SendAsync(RealtimeCommand cmd) {
        var json = JsonSerializer.SerializeToUtf8Bytes(cmd);
        await _socket.SendAsync(json, WebSocketMessageType.Text, true, _cts.Token);
    }

    public async Task DisconnectAsync(CancellationToken ct = default) {
        if (_socket.State is WebSocketState.Open or WebSocketState.CloseReceived)
            await _socket.CloseOutputAsync(WebSocketCloseStatus.NormalClosure, "client closing", ct);

        _cts.Cancel();
        if (m_receiveTask is not null)
            await m_receiveTask;
        _socket.Dispose();
    }

    public void Dispose() {
        // 同步释放是兜底；正常业务退出优先 await DisconnectAsync。
        _cts.Cancel();
        _socket.Dispose();
        _cts.Dispose();
    }
}
```

## 3. 错误处理

### 3.1 统一错误码

🟡 推荐：**客户端 + 服务端约定统一错误码**。

```csharp
public enum ApiErrorCode {
    Success         = 0,
    Unknown         = 1,
    NetworkError    = 1001,  // 网络问题
    Timeout         = 1002,  // 超时
    Unauthorized    = 2001,  // 未登录 / token 失效
    Forbidden       = 2002,  // 权限不足
    NotFound        = 2003,  // 资源不存在
    VersionTooOld   = 3001,  // 客户端版本过旧
    MaintenanceMode = 3002,  // 服务端维护中
    ServerError     = 5000,  // 服务端内部错误
}
```

### 3.2 客户端错误处理

```csharp
// ✅ 统一错误处理
public async Task HandleErrorAsync(ApiResult result) {
    if (result.IsSuccess) return;

    switch (result.Code) {
        case ApiErrorCode.Unauthorized:
            await _tokenService.ClearAsync();
            SceneManager.LoadScene("Login");
            Toast.Show("请重新登录");
            break;
        case ApiErrorCode.VersionTooOld:
            SceneManager.LoadScene("ForceUpdate");
            break;
        case ApiErrorCode.MaintenanceMode:
            SceneManager.LoadScene("Maintenance");
            break;
        case ApiErrorCode.NetworkError:
        case ApiErrorCode.Timeout:
            Toast.Show("网络异常，请稍后重试");
            break;
        case ApiErrorCode.ServerError:
            Toast.Show("服务异常，请稍后重试");
            // 上报错误日志
            await _crashReporter.ReportAsync(result);
            break;
        default:
            Toast.Show(result.Message);
            break;
    }
}
```


## 4. 离线缓存

### 4.1 缓存层级

```
┌─────────────────┐
│ 内存缓存（10-100ms）│  ← 当前 Session
└────────┬────────┘
         ↓ miss
┌─────────────────┐
│ 磁盘缓存（10-100ms）│  ← 跨 Session
└────────┬────────┘
         ↓ miss
┌─────────────────┐
│ 网络请求（200-2000ms）│  ← 真实数据
└─────────────────┘
```

### 4.2 缓存实现

```csharp
public class LocalCache {
    private readonly string _cacheDir;
    private readonly IMemoryCache _memory;

    public LocalCache(string cacheDir, IMemoryCache memory) {
        _cacheDir = cacheDir;
        _memory = memory;
    }

    public async Task<T> GetOrFetchAsync<T>(
        string key, Func<Task<T>> fetcher, TimeSpan ttl
    ) {
        // L1: 内存
        if (_memory.TryGetValue(key, out T cached)) return cached;

        // L2: 磁盘
        var path = Path.Combine(_cacheDir, $"{key}.json");
        if (File.Exists(path)) {
            try {
                var json = await File.ReadAllTextAsync(path);
                var data = JsonSerializer.Deserialize<T>(json);
                _memory.Set(key, data, ttl);
                return data!;
            } catch { /* 损坏的缓存忽略 */ }
        }

        // L3: 网络
        var fresh = await fetcher();
        _memory.Set(key, fresh, ttl);
        await File.WriteAllTextAsync(path, JsonSerializer.Serialize(fresh));
        return fresh;
    }

    public void Invalidate(string key) {
        _memory.Remove(key);
        var path = Path.Combine(_cacheDir, $"{key}.json");
        if (File.Exists(path)) File.Delete(path);
    }
}
```

### 4.3 缓存策略

| 数据类型 | 缓存策略 | TTL |
|---|---|---|
| 用户配置 | 内存 + 磁盘 | 7 天 |
| 静态资源（图片 / 文本）| 磁盘 | 30 天 |
| 实时数据（背包 / 任务）| 内存 + 磁盘 | 1 小时 |
| 配置（活动 / 公告）| 内存 + 磁盘 | 直到过期时间 |
| 用户数据 | 内存 | Session 内 |


## 5. 增量同步

### 5.1 版本号同步

🔴 必加约束：实时数据用**版本号 / 时间戳**做增量同步——避免每次拉全量。

```csharp
public class IncrementalSync<T> where T : IVersioned {
    private readonly LocalCache _cache;
    private readonly GameApiClient _api;

    public async Task<List<T>> SyncAsync(string resourceType) {
        var localKey = $"sync:{resourceType}";
        var local = _cache.Get<List<T>>(localKey) ?? new();
        var lastVersion = local.LastOrDefault()?.Version ?? 0;

        // 拉取增量
        var delta = await _api.GetDeltaAsync<T>(resourceType, lastVersion);

        // 合并
        var merged = MergeDelta(local, delta);
        _cache.Set(localKey, merged, TimeSpan.FromHours(1));
        return merged;
    }

    private List<T> MergeDelta(List<T> local, List<T> delta) {
        // 用版本号去重 + 合并
        var dict = local.ToDictionary(x => x.Id);
        foreach (var item in delta) {
            dict[item.Id] = item;  // 新版本覆盖旧版本
        }
        return dict.Values.OrderBy(x => x.Version).ToList();
    }
}
```

### 5.2 冲突解决

🟡 推荐：**最后写入获胜（Last-Write-Wins）**——简单，适合大多数场景。

```csharp
public record PlayerData(
    int Id,
    int Level,
    int Exp,
    long UpdatedAt  // 时间戳
) : IVersioned {
    public long Version => UpdatedAt;
}
```

服务器收到客户端更新：
```csharp
// 服务端伪代码
if (clientPlayer.UpdatedAt < serverPlayer.UpdatedAt) {
    return Error("本地版本过旧，请重新拉取");
}
UpdatePlayer(clientPlayer);
```

🔴 必加约束：客户端**先 GET 最新数据 → 本地修改 → POST**——避免基于过期数据修改。


## 6. 部署与监控

### 6.1 客户端版本管理

🔴 必加约束：**每次发版要带版本号**——服务端可强制升级。

```csharp
public class AppVersion {
    public string Version { get; set; }      // "1.2.3"
    public int BuildNumber { get; set; }     // 12345
    public string MinSupportedVersion { get; set; }  // 最低支持版本
}
```

### 6.2 强制升级

```csharp
public async Task CheckVersionAsync() {
    var config = await _api.GetAppConfigAsync();
    if (IsVersionLower(AppVersion.Current, config.MinSupportedVersion)) {
        SceneManager.LoadScene("ForceUpdate");
        return;
    }
    if (IsVersionLower(AppVersion.Current, config.RecommendedVersion)) {
        Toast.Show("检测到新版本，建议更新");
    }
}
```

### 6.3 错误上报

🟡 项目已经接入错误上报 SDK 或统一门面时，沿用其采样、去敏、用户标识和离线缓存策略；Sentry、Firebase Crashlytics 只是可评估的候选，不要因本节自动安装 SDK。

```csharp
// 项目已有错误上报门面的调用形态（接口名与字段以项目实际定义为准）
m_errorReporter.CaptureException(exception, sanitizedContext);
m_errorReporter.TrackEvent(eventName, sanitizedProperties);
```

🔴 必加约束：上报必须**去敏感**——不上报密码、Token、原始请求体或可直接识别玩家身份的字段；用户标识、保留时间与删除机制须符合项目隐私策略。


## 7. AI 服务端集成清单

AI 实现 Unity 客户端的服务端集成时，必须按此清单核查：

### 7.1 架构

- [ ] 服务端架构与所有权已由项目确认（BaaS / 自建 / 云函数等）
- [ ] 通信模式与接口契约已确认（REST / WebSocket / 实时同步等）
- [ ] 多人游戏使用项目已验证的同步方案

### 7.2 通信

- [ ] 使用项目已验证的客户端与异步模型
- [ ] 生产敏感接口使用 HTTPS，例外由环境配置明确
- [ ] 超时、认证刷新和错误码与服务端契约一致
- [ ] 用户可见的错误处理与 UI 提示符合产品约定

### 7.3 缓存

- [ ] 缓存层级明确（内存 / 磁盘）
- [ ] 缓存 TTL 合理
- [ ] 数据更新时主动失效缓存

### 7.4 同步

- [ ] 实时数据用增量同步（版本号 / 时间戳）
- [ ] 读写流程、幂等键和并发控制符合服务端契约
- [ ] 冲突解决策略已明确（Last-Write-Wins 或其他项目策略）

### 7.5 错误处理

- [ ] 统一错误码
- [ ] 401 → 跳登录
- [ ] 版本过旧 → 强制更新
- [ ] 维护中 → 维护页

### 7.6 部署

- [ ] 客户端版本号管理
- [ ] 强制升级机制
- [ ] 错误上报（去敏感）
- [ ] 关键事件埋点
