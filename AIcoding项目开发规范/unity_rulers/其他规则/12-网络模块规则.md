# 12 - Unity 网络模块规则

> 🟢 本文件适用于 Unity 项目的网络通信（HTTP / WebSocket / Unity NetCode / 序列化 / 同步 / 安全）。<br>
> 🔴 不适用：纯单机游戏（无网络功能）、业务逻辑实现、UI 样式设计

---

## 1. 网络协议选型

🔴 必加约束：**先确认已有协议、接口契约、已安装网络库、目标平台与安全要求，再写代码**。不要把 `UnityWebRequest`、`HttpClient`、NGO、Mirror 或第三方库当作本规则库的默认依赖。

### 1.1 协议选型决策表

| 协议 | 特点 | 典型场景 | 项目确认后可选实现 |
|---|---|---|---|
| **HTTP / HTTPS** | 请求-响应、无状态 | REST API、登录、资源下载 | `UnityWebRequest` / `HttpClient` |
| **WebSocket** | 全双工、长连接 | 聊天、实时通知、协作 | `NativeWebSocket` / 第三方库 |
| **TCP** | 可靠、有序、低延迟 | 自定义二进制协议、实时游戏 | `System.Net.Sockets` / `NetCode` |
| **UDP** | 不可靠、低延迟 | 实时多人游戏、状态同步 | `NetCode for GameObjects` / `Mirror` |
| **gRPC** | 高效、跨平台 | 微服务通信 | `Grpc.Net.Client` |

🟡 常见映射（先以现有契约、服务端与目标平台为准）：

- **登录 / 资源 / 配置** → HTTP / HTTPS
- **聊天 / 实时通知** → WebSocket
- **多人游戏同步** → 经验证的实时传输与同步方案（可能使用 UDP、NGO、Mirror 或项目自有服务）
- **移动端到生产服务端** → 认证或敏感数据使用 HTTPS；本地开发例外必须由配置明确

❌ 不要：

- 实时同步用 HTTP 轮询（延迟高 + 服务器压力）
- 重要数据用 HTTP 明文（被中间人攻击）
- 未经协议、安全与运维评审就自行实现 TCP/UDP 协议

### 1.2 Unity NetCode vs Mirror

🔴 必加约束：多人游戏必须沿用或经明确选型确认的网络方案；迁移同步框架会影响协议、服务端、序列化、部署与测试，不得仅因本表而执行。

| 维度 | NGO（Unity NetCode） | Mirror |
|---|---|---|
| 维护方 | Unity 官方 | 社区 |
| 性能 | 取决于同步模型、Transport、拓扑与项目实现 | 取决于同步模型、Transport、拓扑与项目实现 |
| API 稳定性 | 以当前 Unity/包版本与升级计划验证 | 以当前包版本、维护状态与社区兼容性验证 |
| 文档与支持 | 以当前官方文档与项目经验验证 | 以当前维护状态、文档与项目经验验证 |
| 学习成本 | 取决于团队经验与目标功能 | 取决于团队经验与目标功能 |

🟡 可在新项目选型阶段根据团队经验、目标平台、服务端兼容性、性能验证与维护成本比较 NGO、Mirror 或其他方案。


## 2. HTTP 客户端

### 2.1 UnityWebRequest vs HttpClient

🟡 优先使用项目已验证的 HTTP 客户端与异步模型；只有在 Unity 版本、目标平台、包与现有网络层均兼容时，才评估 `HttpClient` 或 `UnityWebRequest` 的取舍。

```csharp
// ✅ 仅在项目已验证 HttpClient 与目标平台兼容时使用
using var client = new HttpClient { BaseAddress = new Uri("https://api.example.com") };
client.DefaultRequestHeaders.Add("Authorization", $"Bearer {token}");

var response = await client.GetAsync("/users/123");
if (response.IsSuccessStatusCode) {
    var json = await response.Content.ReadAsStringAsync();
    var user = JsonSerializer.Deserialize<User>(json);
}
```

```csharp
// ⚠️ UnityWebRequest（老项目兼容用）
using var request = UnityWebRequest.Get("https://api.example.com/users/123");
request.SetRequestHeader("Authorization", $"Bearer {token}");
var op = await request.SendWebRequest();
if (request.result == UnityWebRequest.Result.Success) {
    var json = request.downloadHandler.text;
}
```

### 2.2 必加约束

- ✅ 生产环境的敏感或认证 API **必须用 HTTPS**；本地开发与受控测试环境的例外应由项目配置明确。
- ✅ 为请求设置符合产品体验与重试策略的超时；10 秒只是示例，不是固定值。
- ✅ 沿用项目的错误处理、认证刷新、重试和 UI 状态策略；401、5xx 不应被机械地统一处理。
- ✅ 捕获能够处理或补充上下文的异常，避免静默吞错；不要用笼统捕获掩盖取消和程序错误。

```csharp
// ✅ 完整示例
public async Task<User> GetUserAsync(int userId, CancellationToken ct = default) {
    using var client = new HttpClient { Timeout = TimeSpan.FromSeconds(10) };
    client.DefaultRequestHeaders.Authorization = new("Bearer", _tokenService.Get());

    try {
        var response = await client.GetAsync($"/users/{userId}", ct);
        response.EnsureSuccessStatusCode();
        var json = await response.Content.ReadAsStringAsync(ct);
        return JsonSerializer.Deserialize<User>(json)
            ?? throw new InvalidOperationException("Empty response");
    } catch (HttpRequestException ex) {
        ProjectLog.Exception("Network", ex); // 替换为项目真实日志门面
        throw new NetworkException("获取用户失败", ex);
    }
}
```

❌ 不要：

- 同步等待（`Wait()` / `Result`）——阻塞主线程
- 不设超时——挂起 30 秒
- 用 `WWW`（已废弃）
- 捕获异常后不处理（`catch { }`）


## 3. 序列化

### 3.1 选型

| 格式 | 特点 | 适用 |
|---|---|---|
| **JSON** | 可读、通用、解析慢 | REST API、配置 |
| **Protobuf** | 高效、二进制、跨语言 | 实时游戏、移动端 |
| **FlatBuffers** | 高效、零拷贝 | 移动端、性能敏感 |
| **MessagePack** | 二进制、JSON 兼容 | 缓存、跨服务 |

🟡 推荐：

- **REST API** → JSON（用 `System.Text.Json` 或 `Newtonsoft.Json`）
- **实时游戏** → Protobuf（跨平台 + 性能）
- **本地存档** → Protobuf 或 MessagePack

### 3.2 JSON 序列化最佳实践

```csharp
// ✅ 仅在项目当前 Unity/.NET 配置与程序集已验证支持时使用 System.Text.Json
[Serializable]
public record UserDto(
    int Id,
    string Name,
    string Email,
    DateTime CreatedAt
);

// 配置
var options = new JsonSerializerOptions {
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull
};
```

🔴 必加约束：

- ✅ 使用项目已采用的序列化库、特性和 DTO 约定；`[Serializable]`、`record` 与具体库的支持不能互相替代。
- ✅ 字段命名策略与服务端契约一致（camelCase、snake_case 或其他）；不得仅凭客户端偏好改写协议。
- 🟡 仅在契约允许且项目已有设置时忽略 null 字段。
- ✅ **数字类型明确**（不要用 `object`）

❌ 不要：

- 用 `Dictionary<string, object>`（反序列化不安全）
- 用 `dynamic`（运行时类型错误）
- 自己写 JSON 拼接（注入风险）


## 4. 网络同步（多人游戏）

### 4.1 客户端-服务器架构

🔴 必加约束：实时多人游戏应使用已经完成协议、安全与兼容性验证的专用方案；自研 UDP、现成框架和服务端实现都需要明确所有权、测试与运维边界。

🟡 推荐架构：

| 架构 | 适用 | 框架 |
|---|---|---|
| **Client-Authoritative** | 休闲 / 合作 | 项目已采用的同步框架 |
| **Server-Authoritative** | 竞技 / 反作弊 | NetCode for GameObjects |
| **Deterministic Lockstep** | RTS / 格斗 | rollback-netcode |
| **Relay** | P2P / 大世界 | Photon / Mirror |

### 4.2 同步频率

🔴 必加约束：**网络带宽是有限资源**——按需同步。

| 类型 | 频率 | 优化 |
|---|---|---|
| 玩家位置 | 10-30 Hz | 客户端预测 + 服务器校正 |
| 玩家状态（HP/MP）| 1-5 Hz | 事件触发而非轮询 |
| 静态数据（配置）| 启动时 1 次 | 缓存到本地 |
| 聊天 / 事件 | 触发式 | 增量发送 |

❌ 不要：

- 每帧发送全部游戏状态（100 玩家 × 60Hz = 6000 包/秒）
- 用字符串序列化（用 Protobuf / FlatBuffers）
- 在主线程处理网络数据（卡顿）


## 5. 错误处理与重试

### 5.1 重试策略

🟡 推荐：**指数退避（Exponential Backoff）+ 抖动**：

```csharp
public async Task<T> RetryAsync<T>(Func<Task<T>> action, int maxRetries = 3) {
    for (int i = 0; i < maxRetries; i++) {
        try {
            return await action();
        } catch (HttpRequestException) when (i < maxRetries - 1) {
            var delay = TimeSpan.FromSeconds(Math.Pow(2, i))  // 1s, 2s, 4s
                         + TimeSpan.FromMilliseconds(Random.Shared.Next(0, 1000));  // 抖动
            await Task.Delay(delay);
        }
    }
    return await action();  // 最后一次
}
```

### 5.2 重试决策表

| 错误 | 重试？ | 理由 |
|---|---|---|
| 5xx 服务器错误 | ✅ 是 | 临时故障 |
| 429 Too Many Requests | ✅ 是（带退避）| 限流 |
| 网络超时 | ✅ 是 | 临时网络问题 |
| 4xx 客户端错误 | ❌ 否 | 请求本身有问题，重试无用 |
| 401 Unauthorized | ❌ 否 | 触发 token 刷新流程 |
| 400 Bad Request | ❌ 否 | 代码 bug |


## 6. 网络安全

### 6.1 必加约束

- ✅ 生产环境中携带认证、个人信息或交易数据的 API 使用 HTTPS；本地开发例外必须由配置明确。
- 🟡 Token 的存储方式以项目的平台安全存储封装为准；不得把长期敏感凭据明文写入 PlayerPrefs。
- 🟡 请求签名、nonce 与防重放仅在服务端协议明确要求时实现；不得在客户端硬编码服务端共享密钥。

### 6.2 Token 管理

```csharp
// ✅ 用 DeviceKeyStore 抽象（不同平台不同实现）
public interface ISecureStorage {
    void Save(string key, string value);
    string Load(string key);
    void Delete(string key);
}

// iOS: Keychain
// Android: EncryptedSharedPreferences
// Editor: EditorPrefs（仅调试）
```

### 6.3 防作弊网络层

- ✅ **服务端校验**所有关键操作（不信任客户端数据）
- ✅ **关键计算放服务端**（伤害计算、奖励发放）
- ✅ **Token 绑定设备**（同一 token 不能在多设备使用）


## 7. 离线与缓存

### 7.1 缓存策略

| 数据 | 缓存策略 | TTL |
|---|---|---|
| 用户配置 | 内存 + 磁盘 | 启动加载 |
| 静态资源（图片 / 配置）| 磁盘 + 内存 | 7 天 |
| 用户数据 | 内存 | Session 内 |
| 实时数据 | 内存 | 实时刷新 |

```csharp
// ✅ 用 IMemoryCache + IDiskCache
public class DataCache {
    private readonly IMemoryCache _memory = new MemoryCache(new MemoryCacheOptions());
    private readonly IDiskCache _disk = new DiskCache("cache/");

    public async Task<T> GetAsync<T>(string key, Func<Task<T>> loader, TimeSpan ttl) {
        if (_memory.TryGetValue(key, out T cached)) return cached;
        if (_disk.TryGet<T>(key, out cached)) {
            _memory.Set(key, cached, ttl);
            return cached;
        }
        var fresh = await loader();
        _memory.Set(key, fresh, ttl);
        await _disk.SetAsync(key, fresh);
        return fresh;
    }
}
```

### 7.2 离线支持

🟡 推荐：

- 检测网络状态（`Application.internetReachability`）
- 离线时显示缓存数据 + "离线模式"提示
- 在线时增量同步


## 8. AI 网络模块清单

AI 实现 Unity 网络模块时，必须按此清单核查：

### 8.1 协议与选型

- [ ] 协议选型已确定（HTTP / WS / UDP / gRPC）
- [ ] 多人同步方案、Transport、服务端兼容性和升级所有权已确认；不因“新项目”默认选择 NGO
- [ ] 生产环境中的认证或敏感 API 使用 HTTPS；本地开发例外有明确配置

### 8.2 HTTP 客户端

- [ ] 使用项目已验证的 HTTP 客户端、认证刷新与取消模型
- [ ] 超时、重试、401 与 5xx 策略符合接口契约和产品体验（10 秒不是固定值）
- [ ] 记录可处理异常的上下文，不吞掉取消和程序错误

### 8.3 序列化

- [ ] 选型已定（JSON / Protobuf / FlatBuffers）
- [ ] 字段命名一致（camelCase 或 snake_case）
- [ ] 忽略 null 字段
- [ ] 不使用 `Dictionary<string, object>`

### 8.4 同步与实时

- [ ] 多人游戏使用已确认并完成兼容性测试的专用同步方案
- [ ] 同步频率、插值与事件模型由带宽预算、实体数量、目标延迟和压测结果决定；10–30 Hz 仅可作为测试起点
- [ ] 仅在玩法、服务端权威和回滚/校正策略已定义时实现客户端预测

### 8.5 安全

- [ ] Token 用 Keychain / Keystore 存储
- [ ] **不把 token 写 PlayerPrefs**
- [ ] 关键操作服务端校验
- [ ] 请求签名（防重放）

### 8.6 离线

- [ ] 缓存策略明确（内存 / 磁盘 / TTL）
- [ ] 离线模式友好提示


> 💡 完成上述 6 大类 = Unity 网络模块最小可用基线。
