# 15 - Unity AI 通用入口规则

> 🟢 本文件适用于任何 AI 工具在 Unity 项目中进行开发、审查、排障与规则维护。
> 🔴 不适用：替代项目事实、自动批准技术迁移，或伪造验证结果。

---

## 1. 使用方式

本文件是 Unity 规则库的执行入口。AI 先遵守本文件，再按 [00 - Unity AI 编码规则总览](./00-文档总览.md) 和当前任务读取必要专题规则；它不替代 01 至 14 的具体经验与示例。

- 🔴 **必须**将用户当前任务、目标项目的现有约束和工具安全限制置于通用建议之前。
- 🟡 **推荐**只读取与当前任务直接相关的专题规则，避免把整套参考资料当作无差别的硬性指令。
- 🟢 **可选**在一次性对话中手动附加本文件、总览和相关专题规则。

## 2. 项目事实检查

### 2.1 开始前证据

修改 Unity 项目前，AI 应按任务检查可获得的下列证据：

1. `ProjectSettings/ProjectVersion.txt`、已有脚本语法与目标平台。
2. `Packages/manifest.json`、`packages-lock.json` 与本地 Package 引用。
3. `.asmdef`、命名空间、当前模块依赖和同模块既有实现。
4. 已采用的渲染管线、UI、输入、资源加载、网络和日志方案。
5. 构建脚本、CI、测试、设备验证步骤和团队贡献约定。

### 2.2 决策边界

- 🔴 **必须**只调用项目已安装、版本兼容且有代码或配置证据支持的 Unity API 与包。
- 🔴 **必须**优先复用同模块已验证的异步、资源释放、日志、事件和错误处理模式。
- 🔴 **必须**在证据缺失时说明不确定点；无法安全判断时询问用户，不得以本规则库示例替代项目事实。
- ❌ **禁止**把 Unity 编辑器版本、URP/HDRP、UI 框架、资源系统、网络库或第三方架构写成所有项目的默认前提。

## 3. 变更边界

### 3.1 未授权时不得改变的事项

- 🔴 未获明确授权时，不升级 Unity、包、C# 语言级别、渲染管线、资源系统或构建配置。
- 🔴 未获明确授权时，不引入第三方依赖、不进行无关重构、不批量移动资源或改写 Project Settings。
- 🔴 修改资源时必须维护 Asset 与 `.meta` 的对应关系，并核对受影响引用。
- 🔴 资源句柄、事件订阅、协程与异步操作必须有明确的所有权、取消或释放路径。

### 3.2 最小可验证改动

- 🟡 推荐先完成可验证的最小改动，再讨论性能优化、架构抽象或可选重构。
- 🟡 性能问题先使用 Profiler、Frame Debugger、Memory Profiler 或项目已有指标定位，再选择缓存、对象池或渲染策略。
- 🟡 跨模块、跨端或跨语言任务先明确客户端、服务端、资源服务与平台 SDK 的责任边界。

### 3.3 缺陷排查与修复

- 🔴 **必须**：涉及 Bug、报错或非预期行为时，先阅读并遵守 [16 - Unity 问题定位与根因确认规则](./其他规则/16-问题定位与根因确认规则.md)；不得以猜测性的补丁代替根本问题确认。
- 🔴 **必须**：根本问题未确认时，明确已知事实、待验证疑点和确认度；不得把症状消失或单次成功描述为已完成根治。
- 🟢 **可选**：可进行最小、可回滚的诊断性观测，或在用户明确授权时实施临时止血；两者都不得伪装成最终修复。

## 4. 专题规则选择

| 任务 | 优先阅读 |
|---|---|
| C# 脚本、生命周期、协程、序列化 | 01、10 |
| 架构、模块职责、单例、状态机或事件 | 02 |
| GC、帧率、物理、渲染或加载性能 | 03、09 |
| UGUI 或 UI Toolkit | 04 或 05，按项目已采用的 UI 体系选择 |
| Project Settings、包、渲染管线或构建 | 06 |
| 日志、异常、定位与测试 | 07 |
| Git、`.meta`、场景或 Prefab 协作 | 08 |
| 资源、Prefab、ScriptableObject 或加载系统 | 09 |
| Editor 工具 | 11 |
| 网络、服务端集成、安全或隐私 | 12、13、14 |
| Bug、报错、首次流程异常或非预期行为 | 16，以及涉及领域的专题规则 |

## 5. 验证与交付

### 5.1 验证要求

- 🔴 **必须**执行项目中可用且与改动相称的验证；无法执行时必须说明原因、未验证范围和风险。
- 🔴 **必须**核对修改是否超出用户任务范围，新增依赖是否获授权，资源与 `.meta` 是否成对维护。
- 🟡 UI、资源、网络和性能改动应列出需要在 Unity Editor、目标平台或真机上复核的项目。

### 5.2 交付说明

每次任务完成时，AI 应说明：

1. 修改了什么，以及为什么。
2. 执行了哪些验证及其结果。
3. 哪些验证未执行、原因和剩余风险。
4. 需要用户确认的项目事实、迁移或外部协作事项。
