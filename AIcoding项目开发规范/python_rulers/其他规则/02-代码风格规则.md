# 02 - Python 代码风格规则

> 🟢 本文件适用于 Python 代码的格式、命名、导入、注释和静态检查。<br>
> 🔴 不适用：要求项目迁移到某个格式化器、检查器或类型工具。

---

## 1. 项目工具优先

- 🔴 优先遵守仓库中的 `pyproject.toml`、配置文件、CI 和现有代码风格。
- 🔴 修改代码后执行项目已有的格式化、静态检查或类型检查；无法执行时说明原因。
- ❌ 禁止仅为统一风格引入或升级 Black、Ruff、isort、mypy、pyright 等工具。

## 2. 命名与导入

| 对象 | 默认形式 |
|---|---|
| 模块、函数、变量 | `snake_case` |
| 类、异常、类型变量 | `PascalCase` |
| 常量 | `UPPER_SNAKE_CASE` |
| 私有实现 | 前缀 `_`，不作为公共契约 |

- 🔴 名称表达领域含义，禁止 `data`、`temp`、`handle` 等无上下文泛名长期存在。
- 🔴 导入放在文件顶部并按项目工具排序；避免 `import *` 和未使用导入。
- 🟡 注释解释原因、约束或风险，不复述代码表面动作。

## 3. 文档字符串与类型

- 🔴 公共模块、类和函数的文档字符串格式遵循项目既有约定。
- 🟡 公开边界和复杂数据建议标注类型；类型注释不能替代输入校验或业务说明。
- 🟢 小型私有函数若名称和类型已清楚，可不重复写冗长文档字符串。
