# 09 - Python 日志调试规则

> 🟢 本文件适用于 Python 的日志、异常定位、调试、指标和追踪。<br>
> 🔴 不适用：将临时 `print`、敏感数据或吞掉的异常作为正式排障方案。

---

## 1. 日志原则

- 🔴 沿用项目已有日志库、格式、级别、字段和输出方式。
- 🔴 日志记录发生了什么、影响什么、关键上下文和关联标识；不要只写“failed”。
- 🔴 错误边界记录异常信息和原因链一次，避免每层重复打印同一堆栈。
- 🟠 禁止记录密码、令牌、Cookie、认证头、完整个人数据、密钥和未脱敏请求体。

## 2. 调试与可观测性

- 🔴 临时调试输出在提交前删除，或改为项目标准日志并确保级别合适。
- 🟡 需要跨请求、任务或服务排障时，沿用现有 request ID、trace ID、结构化字段或指标。
- 🟡 性能问题优先用 profiler、指标、追踪或可复现测试定位，而不是先猜测缓存或并发方案。

## 3. 异常与告警

- 🔴 告警阈值、错误上报和采样策略必须沿用项目现有平台和约定。
- 🔴 不得以捕获后仅记录日志的方式把失败伪装为成功；调用方仍需得到可处理的错误结果。
