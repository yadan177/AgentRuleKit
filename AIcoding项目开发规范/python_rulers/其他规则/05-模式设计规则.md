# 05 - Python 模式设计规则

> 🟢 本文件适用于 Python 的模块职责、依赖关系、抽象与状态设计。<br>
> 🔴 不适用：为使用设计模式而增加层级、单例、工厂或框架。

---

## 1. 设计边界

- 🔴 模块对外暴露最小、稳定的接口；内部实现细节以 `_` 前缀或目录边界隔离。
- 🔴 一个模块负责一个领域能力；循环导入、跨层访问和隐式全局依赖出现时先澄清边界。
- 🟡 优先组合和纯函数；状态、I/O 和框架调用放在边界层。

## 2. 抽象与依赖

- 🔴 仅在存在多个实现、测试替身或稳定调用边界时引入 `Protocol`、ABC 或适配器。
- 🔴 外部客户端、时钟、存储和配置通过参数、构造函数或项目既有容器传入。
- ❌ 禁止用模块级单例、Service Locator 或动态导入隐藏依赖，除非项目已有并且调用边界明确。

## 3. 状态与配置

- 🔴 配置解析、默认值和校验在应用启动或明确入口完成；业务代码不应到处读取环境变量。
- 🟡 复杂状态流使用显式状态对象、事件或表驱动逻辑；不要用大量布尔标志拼接状态机。
