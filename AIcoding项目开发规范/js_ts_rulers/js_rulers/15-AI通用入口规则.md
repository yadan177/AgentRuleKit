# 15 - JavaScript AI 通用入口规则

> 🟢 适用于任何 AI 工具在 JavaScript 项目中进行开发、审查、排障与规则维护。<br>
> 🔴 不适用：替代仓库事实、自动批准依赖/运行时迁移，或伪造验证结果。

---

## 1. 使用方式

本文件是 JavaScript 规则库的执行入口。AI 先遵守本文件，再按 [00 - JavaScript AI 编码规则总览](./00-文档总览.md) 和当前任务读取必要专题规则；它不替代 01 至 14 的完整经验、边界与示例。

- 🔴 **必须**将用户当前任务、仓库已有约束与工具安全限制置于通用建议之前。
- 🟡 **推荐**只加载当前任务直接相关的专题规则；不要把框架、工具或样式示例误读为必须引入的依赖。
- 🟢 **可选**在一次性对话中手动附加本文件、总览和相关专题规则。

## 2. 项目事实检查

### 2.1 开始前证据

修改 JavaScript 项目前，AI 应按任务检查可获得的下列证据：

1. `package.json`、锁文件、包管理器、运行时版本和现有脚本。
2. bundler、测试、lint、格式化、环境变量、CI 和部署配置。
3. ESM/CJS 边界、目录结构、别名、同模块既有实现和公开 API。
4. 已采用的浏览器/Node.js 运行时、框架、状态、数据访问、样式、日志和错误上报方案。
5. 测试基线、浏览器/服务端兼容范围、性能/安全要求和团队贡献约定。

### 2.2 决策边界

- 🔴 **必须**只调用项目已声明、版本兼容且有代码或配置证据支持的 API 与依赖。
- 🔴 **必须**优先复用同模块已验证的异步取消、错误处理、输入校验、日志和测试模式。
- 🔴 **必须**在证据缺失时说明不确定点；无法安全判断时询问用户，不得以本规则库示例替代项目事实。
- ❌ **禁止**把 Node.js、React、Vue、Vite、Webpack、Vitest、Jest、ESLint、Prettier、Tailwind 或 Sentry 写成所有 JS 项目的默认前提。

## 3. 变更边界

### 3.1 未授权时不得改变的事项

- 🔴 未获明确授权时，不升级 Node.js、包管理器、构建工具、框架、模块系统或浏览器兼容目标。
- 🔴 未获明确授权时，不新增依赖、不替换状态/数据/样式方案、不改动锁文件策略、CI 或发布配置。
- 🔴 异步请求、订阅、定时器、事件监听、对象 URL 与资源句柄必须具有明确取消或清理路径。
- 🔴 对外 API、存储 schema、环境变量、cookie/CORS/CSP 与错误上报字段的兼容性影响必须先确认。

### 3.2 最小可验证改动

- 🟡 推荐先完成可验证的最小改动，再讨论抽象、性能优化或可选迁移。
- 🟡 性能问题先使用项目已有 profiler、浏览器性能工具、指标或 benchmark 定位，再选择缓存、渲染或打包优化。
- 🟡 安全相关改动应先明确运行位置、信任边界、用户输入和线上安全响应头配置，不能只凭前端代码示例下结论。

## 4. 专题规则选择

| 任务 | 优先阅读 |
|---|---|
| 函数、模块、类、命名或语言特性 | 01、10 |
| 模块职责、状态、错误传播或设计模式 | 02 |
| 渲染、内存、网络、Node 热路径或性能指标 | 03 |
| Promise、`async/await`、事件循环、并发或取消 | 04 |
| 存储、HTTP、cookie、缓存或跨标签通信 | 05、11 |
| `package.json`、构建、环境变量、lint 或格式化 | 06、10 |
| 日志、Source Map、错误上报、调试或测试 | 07、08 |
| Git、提交、LFS、PR 或 CI | 09 |
| 用户输入、认证、授权、加密、依赖或浏览器安全 | 11 |
| React 组件、CSS、设计 token 或样式方案 | 13、14（仅在项目已使用对应体系时） |

## 5. 验证与交付

- 🔴 **必须**执行项目中可用且与改动相称的验证；无法执行时必须说明原因、未验证范围和风险。
- 🔴 **必须**核对改动是否超出用户任务范围，新增依赖、锁文件和兼容性变更是否获授权。
- 🟡 优先运行仓库已有脚本；没有统一脚本时再根据项目使用的包管理器与工具链选择 lint、test、build 或类型检查命令。

每次任务完成时，AI 应说明修改内容、执行的验证及结果、未验证范围与需要用户确认的项目事实。
