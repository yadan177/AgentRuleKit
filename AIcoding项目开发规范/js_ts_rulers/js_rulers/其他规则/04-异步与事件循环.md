# 04 - JavaScript 异步与事件循环规则

> 🟢 本文件适用于 JavaScript 异步机制（Promise/async-await/微任务/并发限流）。

> 🔴 不适用：业务逻辑实现、UI 样式设计

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 异步错误吞掉（没有 catch）

**Promise 链必有 `.catch()` / `try/catch`**。

```js
// ❌ 没 catch（unhandledrejection）
fetchUser(1).then(user => render(user));

// ✅
fetchUser(1)
  .then(user => render(user))
  .catch(e => logger.error(e));
```

**async 函数必有 `try/catch` 或显式向上抛**。

```js
// ❌ async 函数吞错
async function getUser(id) {
  const user = await fetchUser(id);    // 报错直接 unhandled
  return user;
}

// ✅
async function getUser(id) {
  try {
    return await fetchUser(id);
  } catch (e) {
    logger.error(e);
    throw e;                           // 向上抛
  }
}
```

**全局 `unhandledrejection` 兜底**（必加）—— 见 [02 §2](./02-模式设计规则.md)。

### 1.2 回调地狱（callback hell）

**全部用 `async/await`**，不要嵌套 `.then()`。

```js
// ❌ 回调地狱
fetchUser(1, (err, user) => {
  if (err) return handleError(err);
  fetchOrder(user.id, (err, order) => {
    if (err) return handleError(err);
    fetchProduct(order.productId, (err, product) => {
      // ...
    });
  });
});

// ✅
try {
  const user = await fetchUser(1);
  const order = await fetchOrder(user.id);
  const product = await fetchProduct(order.productId);
} catch (e) {
  handleError(e);
}
```

### 1.3 同步等待异步（用循环等待 Promise）

```js
// ❌ 死循环阻塞主线程
let user;
fetchUser(1).then(u => { user = u; });
while (!user) {}                       // 永真循环，页面卡死

// ✅ await 是唯一方式
const user = await fetchUser(1);
```

### 1.4 async 函数返回值与栈

**`return await` 的边界**：

```js
// ✅ try/catch 中需要 await 才能捕获
async function getUser(id) {
  try {
    return await fetchUser(id);        // await 让错误进 try/catch
  } catch (e) {
    return null;
  }
}

// ✅ 简单包装时直接 return
async function withLogging(p) {
  const result = await p;
  logger.log(result);
  return result;                       // 不需要 return await
}
```

**不要把回调当 Promise**：

```js
// ❌ util.promisify 包裹过了，但传给 .then 回调
fs.readFile(path, (err, data) => {});
fs.promises.readFile(path).then(...);  // ✅ 用 promises 版
```

### 1.5 事件循环阻塞（长任务）

**单个任务 < 50ms**，超过必拆。

```js
// ✅ 让出主线程
async function processItems(items) {
  for (const item of items) {
    heavyWork(item);
    await new Promise(r => setTimeout(r, 0));   // 让出
  }
}
```

详见 [03 §推荐 3](./03-性能优化规则.md#3-长任务拆分)。

### 1.6 微任务 vs 宏任务顺序

**Promise.then / queueMicrotask = 微任务**（在当前任务结束后立即执行）

**setTimeout / setInterval / I/O = 宏任务**（在下一轮事件循环执行）

```js
// 教学输出：仅用于说明事件循环顺序，不应复制到业务运行时代码。
console.log('1');                       // 同步
setTimeout(() => console.log('2'), 0);  // 宏任务
queueMicrotask(() => console.log('3')); // 微任务
Promise.resolve().then(() => console.log('4'));  // 微任务
console.log('5');                       // 同步

// 输出顺序：1, 5, 3, 4, 2
```

**用 `queueMicrotask` 立刻调度**（不用 `Promise.resolve().then()`）：

```js
queueMicrotask(() => doSomething());
```

### 1.7 异步并发控制（不限流导致雪崩）

**并发必须有上限**。

```js
// ❌ 一次性发 1000 个请求
await Promise.all(urls.map(url => fetch(url)));

// ✅ p-limit 限流
import pLimit from 'p-limit';
const limit = pLimit(5);                      // 最多 5 并发
await Promise.all(urls.map(url => limit(() => fetch(url))));
```

**全部成功才继续用 `Promise.all`，否则用 `Promise.allSettled`**。

```js
// ✅ 全部成功才进下一步
const [users, orders] = await Promise.all([fetchUsers(), fetchOrders()]);

// ✅ 部分失败也要拿到所有结果
const results = await Promise.allSettled(urls.map(u => fetch(u)));
const successful = results
  .filter(r => r.status === 'fulfilled')
  .map(r => r.value);
```

## 2. 🟡 推荐 · 团队约定

### 2.1 取消异步（AbortController）

**fetch / axios 必须支持 `AbortSignal`**。

```js
const controller = new AbortController();

const promise = fetch('/api/data', { signal: controller.signal });

// 用户取消（路由切换 / 组件卸载）
controller.abort();

try {
  const res = await promise;
} catch (e) {
  if (e.name === 'AbortError') return;        // 被取消不算错
  throw e;
}
```

**React 场景**：

```jsx
useEffect(() => {
  const controller = new AbortController();
  fetchUser(id, { signal: controller.signal }).then(setUser);
  return () => controller.abort();             // cleanup
}, [id]);
```

### 2.2 超时设置（必加）

```js
async function fetchWithTimeout(url, ms = 5000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);
  try {
    return await fetch(url, { signal: controller.signal });
  } finally {
    clearTimeout(timer);
  }
}
```

### 2.3 重试策略（指数退避）

**网络错误重试 3 次**（指数退避 + 抖动）：

```js
async function retry(fn, max = 3) {
  for (let i = 0; i < max; i++) {
    try {
      return await fn();
    } catch (e) {
      if (i === max - 1) throw e;
      const delay = 1000 * 2 ** i + Math.random() * 200;
      await new Promise(r => setTimeout(r, delay));
    }
  }
}
```

**不要**对 4xx 重试（客户端错误，重试无用）。仅对网络错误 / 5xx 重试。

### 2.4 异步函数命名

返回 Promise 的函数可以加 `Async` 后缀（项目约定）：

```js
export async function fetchUserAsync(id) { /* ... */ }
```

**不要**用 `getDataAsyncAndCache` 这种复合名——拆开。

## 3. 🟢 可选 · 视情况

### 3.1 Generator / Async Iterator

流式数据 / 分页场景：

```js
async function* paginate(url) {
  let page = 1;
  while (true) {
    const data = await fetch(`${url}?page=${page}`);
    if (data.length === 0) return;
    yield* data;
    page++;
  }
}

for await (const item of paginate('/api/items')) {
  process(item);
}
```

### 3.2 Web Locks API（资源互斥）

多 tab 互斥场景（同一用户多 tab 不能同时操作）：

```js
await navigator.locks.request('my-resource', async (lock) => {
  // 持有锁期间独占
  await doWork();
});
```
