# 07 - JavaScript 日志与调试规则

> 🟢 本文件适用于浏览器端、Node.js 工具和服务端渲染项目的运行时日志、调试与错误上报边界。
>
> 🔴 不适用：将浏览器控制台输出当作审计记录、指标采集、链路追踪或未经批准的第三方错误上报接入。

---

## 1. 统一入口与职责

> **适用条件与验证**：先检查项目已有日志封装、错误上报、构建工具、环境变量注入方式、隐私策略和同模块调用方式。

- 🔴 **必须**：业务代码统一调用项目日志门面；除日志门面、项目已有的错误上报封装和明确隔离的本地调试脚本外，不直接调用 `console.*`。
- 🔴 **必须**：日志门面统一负责等级、分类、格式、脱敏、采样、显示和构建策略；不得在每个业务调用点重复判断 `import.meta.env.DEV`、`process.env.NODE_ENV` 或其他环境变量。
- 🟡 **推荐**：运行时诊断与正式错误上报分开。错误上报只保留经过脱敏、限频且项目批准的异常或事件。

## 2. 五级日志与分类筛选

> **适用条件与验证**：项目需要在本地、测试环境或开发构建中按问题类型筛选日志时适用。

- 🔴 **必须**：五级日志仅通过统一门面输出：`trace`（最细节）、`debug`（开发状态）、`info`（关键流程）、`warn`（可恢复异常）、`error`（失败）。等级语义、分类名称和默认策略由项目维护，调用点不得自行改变全局开关。
- 🔴 **必须**：调用点只提供等级、分类、稳定事件名、已脱敏上下文和可选异常；不要以字符串拼接代替结构化字段。
- 🟡 **推荐**：中文协作项目的事件正文使用中文，便于开发、测试和运营排障；分类、事件键及结构化字段键遵循项目既有稳定命名，不为翻译而破坏查询与跨系统关联。
- 🟡 **推荐**：本地默认只开启 `warn` 与 `error`，排障时临时开启所需等级或分类；高频 `trace` 必须有关闭或采样策略。

```js
// 使用项目真实的门面名称和字段约定；此处不假定任何日志包或构建工具。
appLog.debug('network', '请求已发起', { requestId });
appLog.warn('network', '请求超时，准备重试', { requestId, retryCount });
appLog.error('resource', '资源加载失败', { assetKey }, error);
```

## 3. 构建策略与正式包边界

> **适用条件与验证**：项目需要区分本地开发、测试/灰度和生产构建时适用。

- 🔴 **必须**：发布构建的五级本地日志默认均不显示。是否由构建期移除调用、替换为无操作门面或由运行时配置关闭，必须使用项目现有且已验证的构建能力，并检查产物与实际运行结果。
- 🔴 **必须**：如项目构建支持常量折叠或死代码消除，应只在日志门面或其构建入口集中配置；不要让业务调用点散落环境判断。若无法保证调用被移除，应避免在日志参数中进行昂贵计算或读取敏感数据。
- 🔴 **必须**：正式包需要的崩溃、认证、支付或安全事件走项目已有受控上报接口；关闭本地日志不得导致产品要求的诊断缺失。
- 🟡 **推荐**：QA 或灰度环境通过构建配置或远程诊断配置临时启用特定等级/分类，并在任务结束后恢复默认策略。

## 4. 数据安全与调试

- 🔴 **必须**：日志与错误上报不得包含密码、令牌、Cookie、完整个人数据、支付信息、密钥、未脱敏请求/响应体或内部服务实现细节。
- 🔴 **必须**：捕获到异常时按项目既有策略决定上报、转换或继续抛出；不得只输出日志后静默吞掉异常。
- 🟡 **推荐**：需要定位线上问题时优先使用项目已有的 Source Map 上传、错误平台、浏览器性能面板、网络面板或服务端可观测性工具；不要为单个问题新增未验证依赖。

## 5. 验证与例外

- 🔴 **必须**：验证本地/测试环境中的等级和分类筛选、生产构建中的五级本地日志关闭、异常路径、脱敏和受控错误上报的受影响部分。
- 🟡 **推荐**：交付时说明启用的等级、分类、已验证构建方式、未覆盖环境和隐私/上报风险。

> **例外**：一次性本地脚本和已隔离的开发工具可以按照项目约定直接输出诊断信息；它们不得被打入浏览器生产包或常驻服务运行路径。
