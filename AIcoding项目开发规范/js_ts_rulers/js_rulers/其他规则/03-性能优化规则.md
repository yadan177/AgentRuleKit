# 03 - JavaScript 性能优化规则

> 🟢 本文件适用于 JavaScript / Node.js 项目的运行时性能（V8/DOM/内存/打包）。<br>
> 🔴 不适用：业务逻辑实现、UI 样式细节、第三方业务 SDK

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 热路径（hot path）禁止项

**热路径**：每帧 / 每次 scroll / 每次 render 都会执行的代码（事件回调、render 函数、动画循环）。

- ❌ **循环里声明函数**

```js
// ❌ 每帧都创建新函数
for (let i = 0; i < 1000; i++) {
  arr.forEach(() => doSomething(i));    // 每次 forEach 都创建新函数
}

// ✅ 提到循环外
const handler = (j) => doSomething(j);
for (let i = 0; i < 1000; i++) {
  arr.forEach(handler);
}
```

- ❌ **循环里分配大对象**
- ❌ **循环里读 DOM**（强制 layout 重排）
- ❌ **同步阻塞**（for 循环做百万级运算）

### 1.2 V8 引擎反优化（deopt）

**不要混用 `number` / `string`**：同一变量不要既存数字又存字符串。

```js
// ❌ 触发 hidden class 变化
let count = 1;            // Smi (Small Integer)
count = '1';              // 变成 String，hidden class 切换
count = 2;                // 又是 Smi，切换回来

// ✅ 一旦定型就不变
const count = parseInt(input, 10);
```

**对象 shape 不要中途增删字段**：

```js
// ❌
const user = {};
user.name = 'alice';
user.age = 25;              // 每次新增字段，V8 切换 hidden class

// ✅ 一次性初始化
const user = { name: 'alice', age: 25 };
```

**禁用 `arguments` / `eval`**（deopt）。

### 1.3 DOM 操作批量与重排

**批量插入用 DocumentFragment**：

```js
// ❌ 每次 appendChild 都触发 reflow
for (const item of items) {
  const li = document.createElement('li');
  li.textContent = item.name;
  list.appendChild(li);              // 1000 次 reflow
}

// ✅ DocumentFragment 一次性插入
const frag = document.createDocumentFragment();
for (const item of items) {
  const li = document.createElement('li');
  li.textContent = item.name;
  frag.appendChild(li);
}
list.appendChild(frag);               // 1 次 reflow
```

**读写分离（避免 layout thrashing）**：

```js
// ❌ 读 → 写 → 读 → 写（多次重排）
elements.forEach(el => {
  const h = el.offsetHeight;          // 读
  el.style.height = (h + 10) + 'px';  // 写（使上面缓存失效）
});

// ✅ 全部读完再写
const heights = elements.map(el => el.offsetHeight);  // 一次性读
elements.forEach((el, i) => {
  el.style.height = (heights[i] + 10) + 'px';         // 一次性写
});
```

**用 `requestAnimationFrame`** 做动画 / 滚动回调（与浏览器刷新率同步）。

**虚拟滚动**：列表 > 1000 项必用。

- React: `react-window` / `react-virtual` / `@tanstack/react-virtual`
- Vue: `vue-virtual-scroller`

### 1.4 内存泄漏（事件 / 闭包 / 定时器）

- ❌ `addEventListener` 必加 `removeEventListener`
- ❌ `setInterval` / `setTimeout` 必加 `clear`
- ❌ 闭包不持有大对象（DOM / 大数组）
- ✅ `WeakMap` / `WeakSet` 用于缓存（不阻止 GC）

```js
// ✅ WeakMap 缓存（DOM 节点删了缓存自动清）
const cache = new WeakMap();
function getMetadata(node) {
  if (!cache.has(node)) {
    cache.set(node, computeMetadata(node));
  }
  return cache.get(node);
}
```

**React 中**：
- `useEffect` 必返回 cleanup 函数（订阅 / 事件监听 / 定时器）
- 避免在依赖里放对象 / 数组（每次 render 都是新引用 → 重复执行 effect）

### 1.5 长列表与虚拟滚动

- 1000+ 列表用虚拟滚动
- 分页 / 懒加载（首屏只加载可见区域）
- 不可变数据（`immer`）有性能开销，高频更新场景用 `mutative` 或原生结构

### 1.6 网络请求（fetch / 缓存 / 重复请求）

**去重（dedup）重复请求**：

```js
// ✅ 用 AbortController 取消上一次未完成的请求
let abortController = null;
async function search(keyword) {
  abortController?.abort();
  abortController = new AbortController();
  try {
    return await fetch(`/api/search?q=${keyword}`, {
      signal: abortController.signal,
    });
  } catch (e) {
    if (e.name === 'AbortError') return;   // 被取消不算错
    throw e;
  }
}
```

**缓存**：
- HTTP 缓存：`Cache-Control` / `ETag`
- 客户端缓存：React Query / SWR 自带
- Service Worker：复杂离线场景

**预加载（prefetch）/ 预连接（preconnect）**：

```html
<link rel="preconnect" href="https://api.example.com">
<link rel="preload" href="/font.woff2" as="font" type="font/woff2" crossorigin>
```

### 1.7 打包优化（tree-shaking / code splitting / 资源压缩）

- **按路由懒加载**（见 [01 §7](./01-代码编写规则.md) 动态 import）
- **第三方库按需引入**：

```js
// ❌ 全部引入
import _ from 'lodash';

// ✅ 按需
import debounce from 'lodash/debounce';
```

- **图片压缩 / webp**（构建工具自动转）
- **gzip / brotli**（Nginx / CDN 配置）

### 1.8 Node 后端性能

- **流式处理大文件**（不用 `fs.readFile` 全部读到内存）

```js
// ❌ 大文件全部读进内存
const data = fs.readFileSync('huge.log');

// ✅ 流式
const stream = fs.createReadStream('huge.log', { encoding: 'utf8' });
for await (const chunk of stream) {
  processLine(chunk);
}
```

- **集群 / worker_threads**（CPU 密集）
- **数据库连接池**（mysql2 / pg 的 pool）
- **不要在事件循环跑 CPU 密集**（用 `setImmediate` / `process.nextTick` 让步）

## 2. 🟡 推荐 · 团队约定

### 2.1 性能测量先行（不靠猜）

**工具**：

| 工具 | 用途 |
|------|------|
| Chrome DevTools Performance | 录制运行时 timeline |
| Lighthouse | 综合评分（性能 / SEO / 可访问性） |
| WebPageTest | 多地点实测 |
| React DevTools Profiler | React 组件渲染时长 |
| `performance.mark` / `performance.measure` | 自定义埋点 |

### 2.2 性能预算（Performance Budget）

**Core Web Vitals**：

| 指标 | 目标 | 含义 |
|------|------|------|
| **LCP** (Largest Contentful Paint) | < 2.5s | 最大内容渲染时间 |
| **INP** (Interaction to Next Paint) | < 200ms | 交互到下一次绘制 |
| **CLS** (Cumulative Layout Shift) | < 0.1 | 累计布局偏移 |

其他预算：

- FCP < 1.8s
- TTI < 3.8s
- JS bundle < 200KB（gzip 前）
- 单页面 < 100 个 HTTP 请求

### 2.3 长任务拆分

单个任务 > 50ms 必拆：

```js
// ❌ 单个长任务
function processItems(items) {
  for (const item of items) heavyWork(item);
}

// ✅ 让出主线程
async function processItems(items) {
  for (const item of items) {
    heavyWork(item);
    await scheduler.yield();         // 浏览器新 API
    // 或 setTimeout(0)
  }
}
```

## 3. 🟢 可选 · 视情况

### 3.1 WebAssembly / Worker 卸载

CPU 密集场景（图像处理 / 加密 / 解析大文件）：

- Web Worker：跑独立 JS
- WebAssembly：跑 C / Rust 编译产物

### 3.2 Service Worker 缓存策略

- 离线优先（PWA）
- stale-while-revalidate：先返缓存，后台更新

### 3.3 Edge / CDN 计算

静态资源 CDN 缓存、Serverless 边缘函数。
