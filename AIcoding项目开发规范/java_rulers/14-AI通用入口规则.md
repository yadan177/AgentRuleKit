# 14 - Java AI 通用入口规则

> 🟢 适用于任何 AI 工具在 Java 项目中进行开发、审查、排障与规则维护。<br>
> 🔴 不适用：替代仓库事实、自动批准框架/依赖迁移，或伪造验证结果。

---

## 1. 使用方式

本文件是 Java 规则库的执行入口。AI 先遵守本文件，再按 [00 - Java AI 编码规则总览](./00-文档总览.md) 和当前任务读取必要专题规则；它不替代 01 至 13 的完整经验、边界与示例。

- 🔴 **必须**将用户当前任务、仓库已有约束与工具安全限制置于通用建议之前。
- 🟡 **推荐**只加载当前任务直接相关的专题规则；不要把整套参考资料误读为一次改动必须完成的架构改造。
- 🟢 **可选**在一次性对话中手动附加本文件、总览和相关专题规则。

## 2. 项目事实检查

### 2.1 开始前证据

修改 Java 项目前，AI 应按任务检查可获得的下列证据：

1. `pom.xml`、`build.gradle(.kts)`、wrapper、JDK 版本、编译参数和锁定依赖。
2. 模块边界、包命名、分层、异常/日志/DTO 约定和同模块既有实现。
3. 已采用的 Web 框架、数据访问方案、迁移、缓存、消息、认证和可观测性组件。
4. 测试、静态检查、CI、容器、部署与运行时配置。
5. API/数据库兼容性、目标环境、性能/安全要求和团队贡献约定。

### 2.2 决策边界

- 🔴 **必须**只调用项目已声明、版本兼容且有代码或配置证据支持的 API 与依赖。
- 🔴 **必须**优先复用同模块已验证的事务、异常映射、校验、日志、配置和测试模式。
- 🔴 **必须**在证据缺失时说明不确定点；无法安全判断时询问用户，不得以本规则库示例替代项目事实。
- ❌ **禁止**把 Spring Boot、MyBatis、JPA、JUnit、Mockito、Maven、Gradle 或某个 JDK 版本写成所有 Java 项目的默认前提。

## 3. 变更边界

### 3.1 未授权时不得改变的事项

- 🔴 未获明确授权时，不升级 JDK、Spring/框架版本、构建插件、数据库驱动或容器基础镜像。
- 🔴 未获明确授权时，不引入依赖、不替换 ORM/日志/认证方案、不改动 schema、CI 或发布策略。
- 🔴 事务、线程池、连接、文件、锁和异步任务必须保持明确生命周期、异常处理与关闭路径。
- 🔴 对外 API、事件、数据库 schema、配置项和观测字段的兼容性影响必须先确认。

### 3.2 最小可验证改动

- 🟡 推荐先完成可验证的最小改动，再讨论架构抽象、并发优化或可选迁移。
- 🟡 性能问题先使用项目已有指标、JFR、profiler 或压测证据定位，再选择缓存、线程或 JVM 调优。
- 🟡 安全相关改动应先明确身份、授权、信任边界与线上配置，不能只凭框架示例下结论。

## 4. 专题规则选择

| 任务 | 优先阅读 |
|---|---|
| 类、集合、流、Optional、命名或风格 | 01、02 |
| 异常、事务回滚、全局错误处理 | 03、06 |
| 线程、锁、异步、虚拟线程或资源释放 | 04 |
| 模块职责、分层、模式、DDD 或事件 | 05 |
| Controller、HTTP/API、校验、限流或兼容性 | 06、12 |
| SQL、ORM、事务、迁移、索引或连接池 | 07、12 |
| 单测、集成测试、Mock、覆盖率或排障 | 08、09 |
| 依赖、格式、静态检查、Git 或发布 | 02、10、13 |
| JVM、GC、缓存、线上性能或可观测性 | 09、11、13 |
| 认证、授权、密码学、上传或敏感数据 | 12 |

## 5. 实现任务的文档影响门禁

- 🔴 **必须**在新增、修改或删除功能前判断技术文档影响；该判断适用于实现任务，不以用户是否明确提出“写文档”为前提。
- 🔴 业务模块、页面、路由、API、数据结构、数据库迁移、鉴权、配置、状态机、生命周期、部署、术语或验证结论发生变化时，必须读取 `.ai-rules/java-project-docs/其他规则/04-JavaAI技术文档任务入口.md` 和 `.ai-rules/java-project-docs/其他规则/01-技术文档组织与维护规范.md`，并同步受影响文档。
- 🔴 跨工程契约发生变化时，必须检查所有相关工程的技术文档；受影响文档未同步时，不得将功能报告为完整完成。
- 🔴 确认不影响技术文档时，交付中必须写明“文档影响：无”及判断依据；不得静默跳过。
- 🟡 纯内部重构、变量重命名或格式调整未改变外部契约、业务行为和运维方式时，通常可以判定为无文档影响。
- 🔴 项目尚未导入技术文档规则或无法定位对应入口时，必须报告缺失，不得声称已经执行文档规则。

## 6. 验证与交付

- 🔴 **必须**执行项目中可用且与改动相称的验证；无法执行时必须说明原因、未验证范围和风险。
- 🔴 **必须**核对改动是否超出用户任务范围，新增依赖、版本变动和兼容性变更是否获授权。
- 🟡 优先使用仓库已有 wrapper、测试、静态检查和构建命令；没有统一脚本时再按项目事实选择 Maven 或 Gradle 对应任务。

每次任务完成时，AI 应说明修改内容、实际读取的开发与文档规则、文档影响结论、同步的文档、执行的验证及结果、未验证范围与需要用户确认的项目事实。
