# 07 - Go 日志调试规则

---

> 🟢 本文件适用于 **Go 项目中所有日志输出、错误排查和调试场景**
> 🔴 **不适用**：metrics 指标采集（见 [11-§ 7](11-测试与可观测性.md)）、tracing 链路追踪（见 [11-§ 8](11-测试与可观测性.md)）
> 🟡 本文件假设使用**结构化日志**（structured logging）——不再使用 `log.Printf` 裸字符串；中文协作项目的 `msg` 正文默认使用中文，字段键仍遵循项目稳定命名。

## 1. 日志库选型

### 1.1 决策表

🔴 必加约束：新项目必须在以下四者中选一

| 库 | 性能 | 生态 | 适用场景 |
|---|---|---|---|
| **`log/slog`**（Go 1.21+） | 高 | 标准库 | ✅ **首选**——零依赖，Go 官方结构化日志 |
| **`uber-go/zap`** | 最高 | 丰富 | 对性能有极致要求、需要复杂配置 |
| **`rs/zerolog`** | 最高 | 一般 | 追求零分配、JSON 原生输出 |
| **`log`** | 低 | 标准库 | ❌ 仅玩具项目——无结构化、无级别 |

```go
// log/slog（推荐）
import "log/slog"

slog.Info("用户登录成功",
    slog.String("user_id", userID),
    slog.String("ip", remoteIP),
)

// zap
import "go.uber.org/zap"

logger, _ := zap.NewProduction()
logger.Info("用户登录成功",
    zap.String("user_id", userID),
    zap.String("ip", remoteIP),
)

// zerolog
import "github.com/rs/zerolog/log"

log.Info().
    Str("user_id", userID).
    Str("ip", remoteIP).
    Msg("用户登录成功")
```

### 1.2 推荐：`log/slog`

🟡 推荐：Go 1.21+ 项目直接用 `log/slog`——标准库、零依赖、够用。

```go
import (
    "log/slog"
    "os"
)

func main() {
    // 生产环境：JSON 输出
    logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
        Level: slog.LevelInfo,
    }))
    slog.SetDefault(logger)

    // 开发环境：文本输出（更可读）
    // logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{
    //     Level: slog.LevelDebug,
    // }))
}
```

### 1.3 何时用 zap 而非 slog

| 场景 | 用 |
|---|---|
| Go < 1.21 | zap |
| 已有 zap 生态（如 Uber 内部工具链） | zap |
| 需要 `zapcore` 级别的自定义 encoder / sampler | zap |
| **其余所有场景** | slog |

## 2. 结构化日志字段约定

### 2.1 标准字段

🔴 必加约束：**每条日志必须包含以下字段**

```json
{
    "time": "2024-01-15T10:30:00.000Z",
    "level": "INFO",
    "msg": "user logged in",
    "caller": "handler/user.go:42",
    "user_id": "usr_123",
    "trace_id": "abc123def456"
}
```

| 字段 | 来源 | 说明 |
|---|---|---|
| `time` | handler 自动 | RFC3339 格式，毫秒精度 |
| `level` | handler 自动 | DEBUG / INFO / WARN / ERROR |
| `msg` | 代码中指定 | 人类可读的日志消息，不要动态拼接 |
| `caller` | handler 自动（`AddSource: true`） | 调用位置：`文件:行号` |
| `trace_id` | context 传递 | 请求链路追踪 ID |
| `span_id` | context 传递 | 当前 span ID（可选） |

```go
// slog 配置：自动添加 time / level / caller
logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
    AddSource: true, // 自动添加 caller（文件:行号）
    Level:     slog.LevelInfo,
}))
```

### 2.2 字段命名规范

🔴 必加约束

| 规则 | 正例 | 反例 |
|---|---|---|
| **snake_case** | `user_id`、`request_id` | `userId`、`requestId` |
| **全小写** | `ip_address` | `IPAddress` |
| **不缩写** | `error_message` | `err_msg` |
| **时间用 `time.Time`** | `slog.Time("created_at", t)` | `slog.Int64("created_at", t.Unix())` |
| **耗时用 `time.Duration`** | `slog.Duration("latency", d)` | `slog.Float64("latency", d.Seconds())` |
| **错误用 `slog.Any("error", err)`** | 自动调用 `err.Error()` | 手动 `.Error()` 然后当字符串传 |

### 2.3 字段分组

🟡 推荐：相关字段用 `slog.Group` 分组

```go
// 正例：字段分组，便于查询和聚合
slog.Info("请求处理完成",
    slog.Group("http",
        slog.String("method", r.Method),
        slog.String("path", r.URL.Path),
        slog.Int("status", statusCode),
    ),
    slog.Group("db",
        slog.Duration("latency", dbLatency),
        slog.Int("queries", queryCount),
    ),
)

// 输出：
// {
//   "msg": "请求处理完成",
//   "http": {"method": "GET", "path": "/users", "status": 200},
//   "db": {"latency": "12ms", "queries": 3}
// }
```

### 2.4 不要做的事情

```go
// 反例：消息中动态拼接
slog.Info(fmt.Sprintf("用户 %s 从 %s 登录", userID, ip))
// 问题：消息不固定，无法按消息聚合

// 反例：字段名不一致
slog.Info("用户登录", slog.String("user_id", id))     // user_id
slog.Info("用户退出", slog.String("userId", id))     // userId ← 不一致！
// 问题：查询时无法跨日志按同一字段过滤

// 正例：消息固定 + 字段一致
slog.Info("用户登录成功",
    slog.String("user_id", userID),
    slog.String("ip", remoteIP),
)
slog.Info("用户退出成功",
    slog.String("user_id", userID),
)
```

## 3. Trace ID 传递

### 3.1 为什么需要 trace_id

🔴 必加约束：**每个请求必须有 trace_id**——从请求进入到响应返回，贯穿所有日志

```
请求进入 → trace_id 注入 context
  ├── handler 日志（含 trace_id）
  ├── service 日志（含 trace_id）
  ├── repository 日志（含 trace_id）
  └── 返回响应
```

**有了 trace_id**：一条查询就能串联起一个请求的所有日志。

### 3.2 最小化实现

🔴 必加约束

```go
// middleware/trace.go
func TraceMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 优先从请求头获取（上游传入），没有则生成
        traceID := r.Header.Get("X-Trace-Id")
        if traceID == "" {
            traceID = generateTraceID()
        }
        // 注入 context
        ctx := context.WithValue(r.Context(), traceIDKey, traceID)
        // 注入 logger（自动带 trace_id）
        logger := slog.Default().With(slog.String("trace_id", traceID))
        ctx = context.WithValue(ctx, loggerKey, logger)
        // 响应头返回
        w.Header().Set("X-Trace-Id", traceID)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

func generateTraceID() string {
    b := make([]byte, 16)
    _, _ = rand.Read(b)
    return hex.EncodeToString(b)
}
```

### 3.3 使用方式

```go
// 从 context 获取 logger（自动带 trace_id）
func getUser(w http.ResponseWriter, r *http.Request) {
    logger := LoggerFromContext(r.Context())

    logger.Info("get user request", slog.String("user_id", id))

    user, err := svc.GetUser(r.Context(), id)
    if err != nil {
        logger.Error("get user failed",
            slog.Any("error", err),
            slog.String("user_id", id),
        )
        // ...
    }
    logger.Info("get user success", slog.String("user_id", id))
}

// 辅助函数
type contextKey string

var (
    traceIDKey contextKey = "trace_id"
    loggerKey  contextKey = "logger"
)

func LoggerFromContext(ctx context.Context) *slog.Logger {
    if logger, ok := ctx.Value(loggerKey).(*slog.Logger); ok {
        return logger
    }
    return slog.Default()
}
```

### 3.4 OpenTelemetry 集成

🟡 推荐：正式项目接入 OpenTelemetry

```go
import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/trace"
)

func LoggerFromContext(ctx context.Context) *slog.Logger {
    span := trace.SpanFromContext(ctx)
    if !span.SpanContext().IsValid() {
        return slog.Default()
    }
    return slog.Default().With(
        slog.String("trace_id", span.SpanContext().TraceID().String()),
        slog.String("span_id", span.SpanContext().SpanID().String()),
    )
}
```

## 4. 错误日志规范

### 4.1 错误包装后再记日志

🔴 必加约束（与  互引）

```go
// 反例：裸记底层错误，丢失上下文
func GetUser(ctx context.Context, id string) (*User, error) {
    user, err := repo.FindByID(ctx, id)
    if err != nil {
        slog.Error("failed", slog.Any("error", err)) // 只有 "sql: connection refused"
        return nil, err
    }
    return user, nil
}

// 正例：包装后再传，日志记在最上层
func (r *userRepo) FindByID(ctx context.Context, id string) (*User, error) {
    user, err := r.db.GetContext(ctx, &user, "SELECT ...", id)
    if err != nil {
        return nil, fmt.Errorf("find user %s: %w", id, err) // 包装，不记日志
    }
    return user, nil
}

func GetUser(ctx context.Context, id string) (*User, error) {
    user, err := repo.FindByID(ctx, id)
    if err != nil {
        // 错误只在最上层记一次
        slog.ErrorContext(ctx, "get user failed",
            slog.String("user_id", id),
            slog.Any("error", err),
        )
        return nil, err
    }
    return user, nil
}
```

**原则**：每一层包装错误（加上下文），但**只记一次日志**——在最上层（handler 或顶层 service）。

### 4.2 错误日志必须包含的字段

🔴 必加约束

```go
slog.ErrorContext(ctx, "create order failed",
    // 必含
    slog.Any("error", err),           // 完整错误链
    slog.String("trace_id", traceID), // 链路追踪

    // 业务上下文
    slog.String("user_id", userID),
    slog.String("order_id", orderID),
    slog.Int("amount", amount),
)
```

### 4.3 带堆栈的错误日志

🟡 推荐：严重错误（`slog.Error`）建议附带调用栈

```go
// 方案 1：用 pkg/errors 获取堆栈
import "github.com/pkg/errors"

err := errors.Wrap(originalErr, "create user failed")
slog.Error("create user failed",
    slog.Any("error", err),
    slog.String("stack", fmt.Sprintf("%+v", err)), // 包含堆栈
)

// 方案 2：Go 1.21+ slog 的 source 已包含调用位置
// AddSource: true → caller 字段已显示 文件:行号
```

## 5. 敏感信息脱敏

### 5.1 绝对不能记入日志的信息

🔴 必加约束

| 类别 | 示例 |
|---|---|
| **密码 / 密钥** | `password`、`secret`、`api_key`、`token`（全值） |
| **个人身份信息** | 身份证号、护照号、驾照号 |
| **金融信息** | 完整银行卡号、CVV、PIN |
| **认证凭证** | JWT token、session id（全值） |
| **手机号 / 邮箱** | 仅在必要时脱敏后记录 |

```go
// 反例：日志中暴露完整 token
slog.Info("request", slog.String("authorization", r.Header.Get("Authorization")))

// 反例：日志中暴露密码
slog.Info("login", slog.String("password", req.Password))

// 正例：脱敏
slog.Info("request",
    slog.String("authorization", maskToken(r.Header.Get("Authorization"))), // "Bearer abc***xyz"
)

// 正例：只记录 token 是否存在
slog.Info("request", slog.Bool("has_auth", r.Header.Get("Authorization") != ""))
```

### 5.2 脱敏函数模板

```go
// 手机号脱敏：138****1234
func maskPhone(phone string) string {
    if len(phone) < 7 {
        return "***"
    }
    return phone[:3] + "****" + phone[len(phone)-4:]
}

// 邮箱脱敏：t***@example.com
func maskEmail(email string) string {
    parts := strings.SplitN(email, "@", 2)
    if len(parts) != 2 {
        return "***"
    }
    name := parts[0]
    if len(name) <= 1 {
        return "*@" + parts[1]
    }
    return name[:1] + "***@" + parts[1]
}

// Token 脱敏：只保留前 7 后 4 位
func maskToken(token string) string {
    if len(token) <= 11 {
        return "***"
    }
    return token[:7] + "***" + token[len(token)-4:]
}
```

### 5.3 自定义 slog Handler 实现全局脱敏

🟡 推荐：敏感项目可以实现带脱敏的 Handler

```go
type SanitizeHandler struct {
    handler slog.Handler
}

func (h *SanitizeHandler) Handle(ctx context.Context, r slog.Record) error {
    // 遍历所有字段，脱敏敏感 key
    r.Attrs(func(a slog.Attr) bool {
        if a.Key == "password" || a.Key == "secret" {
            // 替换值
        }
        return true
    })
    return h.handler.Handle(ctx, r)
}
```

## 6. 日志级别使用边界

### 6.1 四级日志定义

🔴 必加约束

| 级别 | 含义 | 示例 | 生产环境 |
|---|---|---|---|
| **DEBUG** | 开发期调试信息 | 变量值、函数进入/退出、SQL 参数 | ❌ 默认关闭 |
| **INFO** | 关键业务事件 | 请求开始/结束、用户登录、订单创建、关键状态变更 | ✅ 默认开启 |
| **WARN** | 可恢复的异常 | 重试成功、降级处理、接近阈值（配额 80%） | ✅ 默认开启 |
| **ERROR** | 影响当前请求的错误 | 请求处理失败、DB 查询失败、第三方调用失败 | ✅ 默认开启 |

```go
// DEBUG：仅开发期
slog.Debug("query parameters", slog.Any("params", params))

// INFO：业务事件
slog.Info("order created",
    slog.String("order_id", orderID),
    slog.Int("amount", amount),
)

// WARN：可恢复
slog.Warn("retry succeeded after 3 attempts",
    slog.String("endpoint", endpoint),
    slog.Int("attempts", 3),
)

// ERROR：请求失败
slog.Error("failed to create order",
    slog.Any("error", err),
    slog.String("user_id", userID),
)
```

### 6.2 不要在循环中记 INFO

🟡 推荐

```go
// 反例：循环中记 INFO——日志爆炸
for _, item := range items {
    slog.Info("processing item", slog.String("id", item.ID))
}

// 正例：聚合后记一次
slog.Info("batch processing",
    slog.Int("total", len(items)),
    slog.Int("success", successCount),
    slog.Int("failed", failCount),
)

// 正例：需要逐条信息时用 DEBUG
for _, item := range items {
    slog.Debug("processing item", slog.String("id", item.ID))
}
```

### 6.3 先判断级别再构造参数

🔴 必加约束：**昂贵的参数构造必须先用 `Enabled` 判断**

```go
// 反例：DEBUG 关闭时仍然构造了昂贵的参数
slog.Debug("user state",
    slog.Any("full_state", expensiveStateCalculation(user)), // 白算
)

// 正例：先判断
if slog.Default().Enabled(context.Background(), slog.LevelDebug) {
    slog.Debug("user state",
        slog.Any("full_state", expensiveStateCalculation(user)),
    )
}

// 或使用 LogAttrs（延迟计算）
slog.LogAttrs(ctx, slog.LevelDebug, "user state",
    slog.Any("full_state", lazyState(user)), // 仅在 DEBUG 开启时计算
)
```

## 7. runtime/debug 调试工具

### 7.1 pprof 端点

🔴 必加约束：**所有服务必须暴露 pprof 端点**（开发/测试环境），但**生产环境通过配置控制**

```go
import _ "net/http/pprof"

func main() {
    if cfg.EnablePprof {
        go func() {
            slog.Info("pprof listening", slog.String("addr", cfg.PprofAddr))
            http.ListenAndServe(cfg.PprofAddr, nil) // 通常 :6060
        }()
    }
    // ...
}
```

pprof 端点列表：

| 端点 | 用途 |
|---|---|
| `/debug/pprof/` | 索引页 |
| `/debug/pprof/profile?seconds=30` | CPU profile（30 秒） |
| `/debug/pprof/heap` | 堆内存快照 |
| `/debug/pprof/goroutine?debug=1` | 所有 goroutine 堆栈（查泄漏） |
| `/debug/pprof/goroutine?debug=2` | 完整 goroutine 堆栈（查死锁） |
| `/debug/pprof/block` | 阻塞 profile |
| `/debug/pprof/mutex` | 锁竞争 profile |

> 详细 pprof 使用见 [03 - 性能优化](./03-性能优化.md)。

### 7.2 Goroutine 堆栈排查

```bash
# 查看所有 goroutine 堆栈（不通过 pprof）
curl http://localhost:6060/debug/pprof/goroutine?debug=1

# 查死锁——找 sync.Mutex.Lock 阻塞的 goroutine
curl http://localhost:6060/debug/pprof/goroutine?debug=2 | grep -A 5 "sync.Mutex.Lock"

# 查泄漏——找数量异常的 goroutine 函数
curl http://localhost:6060/debug/pprof/goroutine?debug=1 | grep -c "someLeakingFunc"
```

### 7.3 内存与 GC

```bash
# 查看内存统计
curl http://localhost:6060/debug/pprof/heap?debug=1

# 查看 GC 统计
GODEBUG=gctrace=1 ./my-server
```

> **注意**：`net/http/pprof` **没有** `/debug/freeOSMemory` 这个HTTP端点。
> 手动触发GC需要通过代码调用 `runtime.GC()` 或 `runtime/debug.FreeOSMemory()`，
> 如果需要HTTP触发，需自己注册端点：
>
> ```go
> // 自己注册 GC 触发端点（谨慎使用，仅内网可访问）
> http.HandleFunc("/debug/freeosmemory", func(w http.ResponseWriter, r *http.Request) {
>     if r.Method != http.MethodPost {
>         http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
>         return
>     }
>     runtime.GC()                     // 强制执行 GC
>     debug.FreeOSMemory()             // 将空闲内存归还给 OS
>     w.Write([]byte("GC triggered, memory returned to OS\n"))
> })
> ```

### 7.4 GODEBUG 环境变量

🟡 推荐：排查特定问题时启用

| 变量 | 用途 |
|---|---|
| `GODEBUG=gctrace=1` | 打印每次 GC 的详细信息 |
| `GODEBUG=schedtrace=1000` | 每秒打印调度器状态 |
| `GODEBUG=scheddetail=1` | 调度器详细信息（含每个 goroutine 状态） |
| `GODEBUG=inittrace=1` | 打印每个 `init()` 的执行时间 |
| `GOTRACEBACK=crash` | 崩溃时打印所有 goroutine 堆栈 |

### 7.5 使用 `expvar` 暴露运行时指标

🟢 可选

```go
import _ "expvar"

// 访问 http://localhost:6060/debug/vars
// 返回 JSON：内存统计、GC 次数、goroutine 数量等
```
