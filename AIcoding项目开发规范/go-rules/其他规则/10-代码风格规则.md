# 10 - Go 代码风格规则

> 🟢 本文件适用于 Go 代码的外观风格与团队约定（gofmt / goimports / golangci-lint / 命名约定 / EditorConfig / CI 集成）。<br>
> 🔴 不适用：业务逻辑实现、API 设计、数据库设计

---

## 1. 强制格式化：gofmt

🔴 **必加约束**：所有纳入改动的 Go 源码必须符合 `gofmt` 输出；优先使用仓库已有的格式化脚本或编辑器集成，不另起一套格式化约定。

### 1.1 基本用法

```bash
# 递归格式化当前模块（排除 vendor）
find . -path ./vendor -prune -o -name '*.go' -exec gofmt -w {} +

# 仅检查（CI 用）
find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +
```

### 1.2 关键规则（gofmt 自动处理）

| 规则 | 说明 |
|---|---|
| 缩进 | Tab（**不是空格**） |
| 行宽 | 无硬限制（但建议 ≤ 99 字符，参考 01 § 命名/注释） |
| import 分组 | 标准库 / 第三方 / 本项目**用空行分隔** |
| 结构体字段对齐 | 自动对齐 |
| 函数签名 | 多参数自动对齐 |

**🔴 不要手动调整 gofmt 已经处理过的格式**——下一个人跑 `gofmt` 会改回去。

### 1.3 提交前必跑

```bash
# Git pre-commit hook（示例）
# .git/hooks/pre-commit
#!/bin/sh
unformatted=$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +)
[ -z "$unformatted" ] || { printf '%s\n' "$unformatted"; exit 1; }
```

## 2. 导入管理：goimports

🟡 **推荐**：在 `gofmt` 基础上使用 `goimports` 自动管理 import 顺序。

### 2.1 安装

```bash
go install golang.org/x/tools/cmd/goimports@latest
```

### 2.2 用法

```bash
# 格式化（含 gofmt + import 分组）
find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +

# 仅检查
find . -path ./vendor -prune -o -name '*.go' -exec goimports -l {} +
```

### 2.3 规则

- **标准库**在前
- **第三方**在中
- **本项目**在后
- **分组之间用空行分隔**
- **未使用的 import 自动删除**

## 3. 静态检查：golangci-lint

🔴 **必加约束**：CI 必须执行与仓库相容的静态检查，并至少覆盖 `go vet` 与项目已有的错误/未使用代码检查。若项目已采用 [golangci-lint](https://golangci-lint.run/)，保持其版本与配置；新引入它需要先获授权。

### 3.1 安装

```bash
# 仅在项目决定采用 golangci-lint 时：固定工具版本，避免 CI 与本地漂移
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest
```

### 3.2 最小配置文件

```yaml
# .golangci.yml
run:
  timeout: 5m
  go: '1.21'

linters:
  disable-all: true
  enable:
    - errcheck      # 未检查 error
    - govet         # 官方检查
    - ineffassign   # 无效赋值
    - staticcheck   # 静态分析
    - unused        # 未使用变量

linters-settings:
  govet:
    enable-all: true
```

### 3.3 推荐 Linters

| Linter | 用途 |
|---|---|
| `errcheck` | 检查 `error` 是否被忽略 |
| `govet` | Go 官方检查（包括 printf、shadow 等） |
| `staticcheck` | 高级静态分析（SA1000-SA5000 系列） |
| `gosimple` | 简化建议 |
| `unused` | 未使用的变量/函数/导入 |
| `gocritic` | 100+ 检查项（包括性能、风格） |
| `gocyclo` | 圈复杂度（推荐阈值 15） |
| `gofumpt` | 比 gofmt 更严格的格式化 |
| `prettier` | 用 Prettier 格式化 Go（可选） |
| `nlreturn` | `return` 前必须有空行 |

## 4. 命名约定总览

🔴 **必加约束**：Go 命名遵循**简洁 + 一目了然**原则。以下规则与 01-代码编写规则 § 1 互补（01 讲硬约束，本章讲风格细节）。

### 4.1 包命名

- **全部小写**，不混用大写 / 下划线 / 中划线
- **简短精炼**——包名在每个调用点都完整写出
- **不要复数**——`net/url` 不是 `net/urls`
- **不要泛义名**——禁止 `common` / `util` / `shared` / `lib` / `helpers` / `misc`

**正例**：`http`、`json`、`bytes`、`time`
**反例**：`url_utils`、`common`、`misc`

### 4.2 函数与变量命名

- **MixedCaps**：驼峰式（`camelCase` 或 `PascalCase`），**不用下划线**
- **导出用大写开头**：`GetUser`、`ParseConfig`
- **不导出用小写开头**：`getUser`、`parseConfig`
- **测试函数允许下划线分组**：`TestParse_EmptyInput`

**反例**：`get_user`、`parse_config`（Python 风格，不适用于 Go）

### 4.3 常量命名

| 类型 | 风格 | 示例 |
|---|---|---|
| 普通 const | MixedCaps | `const MaxRetryCount = 3` |
| 枚举 const | PascalCase + 类型前缀 | `const StatusOK Status = 1` |
| 包级错误变量 | `ErrXxx` | `var ErrNotFound = errors.New(...)` |
| 包级布尔 | `Is/Has/Can/Allow` 前缀 | `var IsEnabled = true` |

### 4.4 Receiver 命名

🔴 **必加约束**：Method receiver 用**类型首字母缩写**——保持一致。

```go
// Good
type Client struct{ ... }
func (c *Client) Get() {}      // receiver = c（Client 的 C）
func (cl *Client) Set() {}     // 也可以，但同一类型要一致

// Bad
func (this *Client) Get() {}   // 太长
func (self *Client) Get() {}   // 非 Go 惯用法
```

**短**（1-2 字母）、**同类型一致**（不要一个方法用 `c`、另一个用 `cl`）。

### 4.5 接口命名

- **单方法接口**：用 `方法名 + er` 后缀
  ```go
  type Reader interface { Read(p []byte) (n int, err error) }
  type Writer interface { Write(p []byte) (n int, err error) }
  type Closer interface { Close() error }
  ```
- **多方法接口**：用描述行为的名称
  ```go
  type ReadWriter interface {
      Reader
      Writer
  }
  type FileSystem interface {
      ReadFile(path string) ([]byte, error)
      WriteFile(path string, data []byte) error
  }
  ```

## 5. 命名风格细节

### 5.1 缩写大写规则

🔴 **必加约束**：常见缩写（`URL`、`HTTP`、`ID` 等）**全部大写**或**首字母大写其余小写**——保持一致。

```go
// Good
type UserID int
func GetURL() string { ... }
type HTTPClient struct{ ... }
func ParseJSON() { ... }

// Bad
type UserId int       // 应该 UserID
func GetUrl() string  // 应该 GetURL
type HttpClient struct{}  // 应该 HTTPClient
func ParseJson() { ... }  // 应该 ParseJSON
```

### 5.2 避免 Stuttering

🔴 **必加约束**：包名**不重复**出现在类型名中。

```go
// Good
package http
type Client struct{}    // 用法：http.Client

// Bad
package http
type HTTPClient struct{}  // 用法：http.HTTPClient（重复）
```

### 5.3 接口使用方命名（非实现方）

🟡 **推荐**：接口名以**使用方**视角命名，而非实现方。

```go
// 包 "store"
package store

// 由调用方定义接口
type Reader interface { Read(...) }

// 实现方（别的包）
type FileStore struct{}
func (f *FileStore) Read(...) { ... }  // FileStore 隐式实现 store.Reader
```

## 6. 行宽与排版

🟡 **推荐**：软上限 **99 字符**（不是硬限制）。

### 6.1 折行规则

```go
// Good：参数过多时按"主题"分组
func ProcessOrder(
    ctx context.Context,
    orderID string,
    user *User,
    options *Options,
) (*Result, error) {
    // ...
}

// Good：长字符串折行
log.Info("operation completed successfully",
    "user_id", userID,
    "duration_ms", elapsed.Milliseconds(),
)
```

### 6.2 函数调用风格

- **多参数且不超 99 字符**：放一行
  ```go
  result := Process(ctx, orderID, user, options)
  ```
- **超过 99 字符**：每个参数一行
  ```go
  result := Process(
      ctx,
      orderID,
      user,
      options,
  )
  ```

## 7. 注释风格

### 7.1 包注释

🔴 **必加约束**：每个包**必须有**包注释——写在 `package` 语句之前。

```go
// Package store provides persistent storage for orders.
package store
```

### 7.2 导出符号注释

🔴 **必加约束**：所有**导出**的（首字母大写）符号**必须**有注释——以符号名开头。

```go
// GetUser retrieves the user with the given ID.
// Returns ErrNotFound if no such user exists.
func GetUser(id string) (*User, error) {
    // ...
}

// User represents a registered user in the system.
type User struct {
    // Name is the user's full legal name.
    Name string
    // Age is the user's age in years.
    Age int
}
```

### 7.3 注释内容

- **说明 "why" 而非 "what"**（代码本身说明 what）
- **避免废话注释**（如 `// increment i`）
- **TODO/FIXME 注释**：必须包含负责人和日期

```go
// Good：说明 why
// Set timeout to 30s because the upstream service
// occasionally takes up to 25s during deployment.
const requestTimeout = 30 * time.Second

// Bad：说明 what（代码已经说明了）
// Increment i by 1
i++
```

## 8. .editorconfig 团队配置

🟡 **推荐**：项目根目录加 `.editorconfig` 锁定基础编辑约定。

```ini
# .editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = tab          # Go 用 Tab
indent_size = 4             # Go 默认 Tab = 4 空格宽
trim_trailing_whitespace = true
insert_final_newline = true

[*.{yml,yaml,json,toml}]
indent_style = space
indent_size = 2

[*.md]
trim_trailing_whitespace = false
```

**VS Code / GoLand 自动读取**——无需插件。

## 9. CI 中的风格检查集成

🔴 **必加约束**：CI 必须保留项目已经采用的格式化与静态检查。下例仅适用于使用 GitHub Actions、Go 1.21 和 golangci-lint 的项目；不要用它覆盖现有工具链或版本锁定。

### 9.1 GitHub Actions 示例

```yaml
# .github/workflows/lint.yml
name: Lint
on: [push, pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v4
        with:
          go-version: '1.21'
      - name: gofmt
        run: |
          unformatted=$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +)
          if [ -n "$unformatted" ]; then
            echo "gofmt failed:"
            printf '%s\n' "$unformatted"
            exit 1
          fi
      - name: go vet
        run: go vet ./...
      - name: golangci-lint
        uses: golangci/golangci-lint-action@v3
        with:
          version: latest
```

### 9.2 Makefile 集成

```makefile
# Makefile
.PHONY: lint
lint:
	@unformatted=$$(find . -path ./vendor -prune -o -name '*.go' -exec gofmt -l {} +); test -z "$$unformatted" || { printf '%s\n' "$$unformatted"; exit 1; }
	go vet ./...
	# 若本项目已采用 golangci-lint，再执行：golangci-lint run ./...

.PHONY: fix
fix:
	go fmt ./...
	# 若本项目已采用 goimports：find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +
```

### 9.3 Pre-commit Hook

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/golangci/golangci-lint-action
    rev: v3.7.0
    hooks:
      - id: golangci-lint
```

## 10. AI 写代码时的风格要点

AI 写完 Go 代码后，必须**主动验证**：

### 10.1 风格一致性

- [ ] **gofmt 无 diff**——`gofmt -d .` 应输出空
- [ ] **goimports 已分组**——标准库 / 第三方 / 本项目
- [ ] **golangci-lint 通过**——`golangci-lint run` 零错误
- [ ] **无未使用 import / 变量**——`go vet ./...` 零警告

### 10.2 命名风格

- [ ] 包名小写，无下划线、无复数（不是 `common` / `util`）
- [ ] 函数 / 变量用 MixedCaps，**无下划线**（除测试函数）
- [ ] 缩写大写：`UserID`、`GetURL`、`HTTPClient`
- [ ] 常量用 `ErrXxx`（错误）/ `Is/Has/Can`（布尔）
- [ ] Receiver 用类型首字母（1-2 字母），**同类型内一致**

### 10.3 注释与文档

- [ ] **每个包**都有包注释（`// Package xxx ...`）
- [ ] **每个导出符号**都有注释（`// FuncName ...`）
- [ ] 注释以符号名开头
- [ ] 注释说明 "why" 而非 "what"

### 10.4 工具必跑命令

```bash
# 写完代码后按项目实际工具链运行
go fmt ./...            # 格式化
go vet ./...            # 静态检查
# 若仓库已有 goimports：find . -path ./vendor -prune -o -name '*.go' -exec goimports -w {} +
# 若仓库已有 golangci-lint：golangci-lint run ./...
```

## 11. 与 01-代码编写规则 的关系

| 章节 | 01（硬约束） | 10（风格细节） |
|---|---|---|
| 命名 | 不允许 `common` / `util` / 单字母（导出） | 包名 / 缩写 / Receiver 命名细节 |
| 错误 | `errcheck` / `errors.Is` / 包装 | — |
| Goroutine | `go ...` 不在 `init()` / 必可停止 | — |
| 零值 | `var mu sync.Mutex` 优于 `new()` | — |
| 控制流 | 卫语句 / 无 else | — |
| API | 输入校验 / 输出包装 | — |
| 资源 | `defer` 清理 | — |
| 入口退出 | `panic` / `os.Exit` 限制 | — |
| **格式** | — | **gofmt / goimports / golangci-lint** |
| **命名细节** | 硬规则 | **缩写 / Stuttering / Receiver** |
| **注释** | — | **包注释 / 导出注释 / why-not-what** |
| **CI** | — | **gofmt/vet/lint 集成** |

**一句话总结**：01 是**必须遵守的硬约束**（违反即编译失败 / 风格错误），10 是**统一团队风格的工具与约定**（用工具保证不偏离）。
