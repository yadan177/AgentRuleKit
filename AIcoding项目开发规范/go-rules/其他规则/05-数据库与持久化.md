# 05 - Go 数据库与持久化

---

> 🟢 本文件适用于 **Go 项目中所有与关系型数据库交互的代码**（MySQL / PostgreSQL / SQLite 等）
> 🔴 **不适用**：NoSQL（MongoDB / Redis / Elasticsearch）、消息队列、对象存储
> 🟡 本文件假设使用 `database/sql` 作为底层接口——所有讨论的库（sqlx / GORM / sqlc）都在其之上构建

## 1. 选型：用哪种库

### 1.1 决策表

🔴 必加约束：**新项目必须在以下四者中选一，不自己造轮子**

| 库 | 抽象层级 | 性能 | 学习成本 | 适用场景 |
|---|---|---|---|---|
| **`database/sql` + 手写 SQL** | 最低 | 最高 | 中 | 需要完全控制 SQL、团队 SQL 能力强 |
| **`jmoiron/sqlx`** | 低 | 高 | 低 | 最推荐——薄封装，结构体映射，保留 SQL 控制力 |
| **`sqlc`** | 低 | 最高 | 中 | 编译期生成类型安全代码，适合 SQL 优先团队 |
| **`gorm.io/gorm`** | 高 | 低 | 低 | 快速原型、简单 CRUD 为主的项目 |

```go
// database/sql：最底层，完全手动
rows, err := db.QueryContext(ctx, "SELECT id, name FROM users WHERE status = ?", status)

// sqlx：薄封装，结构体自动映射
var users []User
err := db.SelectContext(ctx, &users, "SELECT id, name FROM users WHERE status = ?", status)

// sqlc：从 SQL 生成类型安全代码（编译期检查）
users, err := queries.ListUsersByStatus(ctx, status)

// GORM：全 ORM，链式调用
var users []User
db.Where("status = ?", status).Find(&users)
```

### 1.2 决策树

```
你的项目特征是什么？
├── SQL 复杂（多表 JOIN、窗口函数、CTE）
│   └── 团队能写 SQL → sqlx 或 sqlc
│   └── 团队不想写 SQL → 不适合用关系型数据库
├── 简单 CRUD 为主
│   └── 快速原型 / 小项目 → GORM
│   └── 有长期维护计划 → sqlx（SQL 显式可见，不黑盒）
├── 需要编译期安全（重构时 100% 发现 SQL 错误）
│   └── sqlc（从 SQL 生成代码，编译期检查）
└── 极高吞吐，需要精确控制每条 SQL
    └── database/sql（零抽象开销）
```

### 1.3 推荐：`sqlx`

🟡 推荐：大多数项目用 `sqlx`——在"完全手动"和"全自动 ORM"之间的最佳平衡点。

```go
import (
    "github.com/jmoiron/sqlx"
    _ "github.com/lib/pq" // PostgreSQL 驱动
)

// 连接
db, err := sqlx.ConnectContext(ctx, "postgres", dsn)

// 查询单条
var user User
err := db.GetContext(ctx, &user, "SELECT * FROM users WHERE id = $1", id)

// 查询多条
var users []User
err := db.SelectContext(ctx, &users, "SELECT * FROM users WHERE status = $1", status)

// 执行修改
result, err := db.ExecContext(ctx, "UPDATE users SET name = $1 WHERE id = $2", name, id)

// 命名参数
query := `SELECT * FROM users WHERE name = :name AND status = :status`
rows, err := db.NamedQueryContext(ctx, query, map[string]any{
    "name":   name,
    "status": status,
})
```

### 1.4 GORM 使用约束

🔴 必加约束：如果项目选择了 GORM，必须遵守以下约束

```go
// 反例：GORM 隐式行为——软删除全局生效，新人不知道
db.Where("id = ?", id).Find(&user) // 自动加了 deleted_at IS NULL

// 反例：链式调用中忽略错误
db.Where("name = ?", name).Find(&users) // 没有处理返回的 *gorm.DB

// 反例：N+1 预加载不显式声明
db.Preload("Orders").Preload("Orders.Items").Find(&users) // 嵌套预加载不直观

// 正例：显式处理每一步错误
result := db.WithContext(ctx).Where("name = ?", name).Find(&users)
if result.Error != nil {
    return fmt.Errorf("find users: %w", result.Error)
}

// 正例：复杂查询用 Raw SQL，不用链式拼接
db.Raw("SELECT u.*, COUNT(o.id) as order_count "+
    "FROM users u LEFT JOIN orders o ON u.id = o.user_id "+
    "WHERE u.status = ? GROUP BY u.id", status).Scan(&results)
```

**GORM 核心约束**：

| 约束 | 说明 |
|---|---|
| **始终 WithContext** | `db.WithContext(ctx).Find(...)`，不传 ctx 会导致无法超时取消 |
| **检查 Error** | 每个链式调用末尾都要 `.Error` 检查 |
| **复杂查询用 Raw SQL** | 三表以上 JOIN 或子查询，不要硬用链式 API |
| **显式禁用软删除** | 需要查已删记录时 `db.Unscoped().Find(...)` |
| **不依赖 AutoMigrate** | 生产环境必须用独立的 migration 工具（见 § 4） |

## 2. 连接池配置

### 2.1 必配参数

🔴 必加约束：**生产环境必须显式配置连接池参数**——不依赖默认值

```go
db, err := sql.Open("postgres", dsn)
if err != nil {
    return nil, err
}

// 生产环境必配
db.SetMaxOpenConns(25)                 // 最大连接数
db.SetMaxIdleConns(10)                 // 最大空闲连接数
db.SetConnMaxLifetime(5 * time.Minute) // 连接最大存活时间
db.SetConnMaxIdleTime(1 * time.Minute) // 空闲连接最大空闲时间
```

| 参数 | 推荐值 | 依据 |
|---|---|---|
| `MaxOpenConns` | CPU 核数 × 2 ~ 4，不超过 DB 端 `max_connections` 的 50% | 防止耗尽 DB 连接 |
| `MaxIdleConns` | `MaxOpenConns` 的 40%~50% | 平衡内存占用与连接复用 |
| `ConnMaxLifetime` | 5 分钟 | 小于 DB 端 `wait_timeout` / `idle_in_transaction_session_timeout` |
| `ConnMaxIdleTime` | 1 分钟 | 及时释放长时间空闲的连接 |

### 2.2 连接池配置反模式

```go
// 反例：默认值——无限制
db, _ := sql.Open("postgres", dsn)
// MaxOpenConns = 0 → 无限制！高并发时会创建成千上万连接，打爆 DB

// 反例：连接数太低
db.SetMaxOpenConns(2) // 一个慢查询阻塞两个连接，服务就不可用了

// 反例：连接存活时间太长
db.SetConnMaxLifetime(1 * time.Hour) // DB 端已回收但连接池不知道，请求报 connection reset

// 正例：配置来自环境变量或配置文件
db.SetMaxOpenConns(cfg.DBMaxOpenConns)
db.SetMaxIdleConns(cfg.DBMaxIdleConns)
db.SetConnMaxLifetime(cfg.DBConnMaxLifetime)
db.SetConnMaxIdleTime(cfg.DBConnMaxIdleTime)
```

### 2.3 连接健康检查

🟡 推荐：启动时 ping 一次验证连接可用

```go
func NewDB(dsn string) (*sql.DB, error) {
    db, err := sql.Open("postgres", dsn)
    if err != nil {
        return nil, fmt.Errorf("open db: %w", err)
    }
    // 配置连接池
    db.SetMaxOpenConns(25)
    db.SetMaxIdleConns(10)
    db.SetConnMaxLifetime(5 * time.Minute)
    db.SetConnMaxIdleTime(1 * time.Minute)

    // 验证连接可用
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    if err := db.PingContext(ctx); err != nil {
        return nil, fmt.Errorf("ping db: %w", err)
    }
    return db, nil
}
```

### 2.4 `database/sql` 连接池原理

🟢 可选理解

```
sql.Open() 不会建立连接——只验证 dsn 格式
第一次查询时才建立连接
连接用完后放回池子（不是关闭）
idle 连接数 > MaxIdleConns 时关闭多余连接
连接存活超过 ConnMaxLifetime 时关闭
```

> `sql.DB` 是并发安全的，**整个应用共享一个实例**——不要在多个地方 `sql.Open` 同一个 dsn。

## 3. 事务边界

### 3.1 一个 service 方法 = 一个事务

🔴 必加约束

```go
// 反例：在 handler 层管理事务
func createOrder(w http.ResponseWriter, r *http.Request) {
    tx, _ := db.Begin() // handler 不应该知道事务存在
    // ... 业务逻辑
    tx.Commit()
}

// 正例：service 层管理事务，handler 只管 HTTP
func (s *OrderService) CreateOrder(ctx context.Context, req CreateOrderReq) (*Order, error) {
    tx, err := s.db.BeginTxx(ctx, nil)
    if err != nil {
        return nil, fmt.Errorf("begin tx: %w", err)
    }
    defer tx.Rollback() // 如果未 Commit，Rollback 是安全的（已 Commit 后 Rollback 无操作）

    // 1. 扣减库存
    if err := s.inventoryRepo.Deduct(ctx, tx, req.ProductID, req.Quantity); err != nil {
        return nil, fmt.Errorf("deduct inventory: %w", err)
    }
    // 2. 创建订单
    order, err := s.orderRepo.Create(ctx, tx, req)
    if err != nil {
        return nil, fmt.Errorf("create order: %w", err)
    }
    // 3. 创建支付单
    if err := s.paymentRepo.Create(ctx, tx, order.ID, req.Amount); err != nil {
        return nil, fmt.Errorf("create payment: %w", err)
    }

    return order, tx.Commit()
}
```

**事务传递模式**：

```go
// repository 接口：接受 tx 参数
type InventoryRepo interface {
    Deduct(ctx context.Context, tx *sqlx.Tx, productID string, qty int) error
}

// 实现：有 tx 用 tx，没有用 db
func (r *inventoryRepo) Deduct(ctx context.Context, tx *sqlx.Tx, productID string, qty int) error {
    exec := r.getExecer(tx) // tx != nil → tx；tx == nil → db
    _, err := exec.ExecContext(ctx, "UPDATE inventory SET qty = qty - $1 WHERE product_id = $2", qty, productID)
    return err
}

func (r *inventoryRepo) getExecer(tx *sqlx.Tx) sqlx.ExecerContext {
    if tx != nil {
        return tx
    }
    return r.db
}
```

### 3.2 defer Rollback 模式

🔴 必加约束

```go
tx, err := db.BeginTxx(ctx, nil)
if err != nil {
    return fmt.Errorf("begin tx: %w", err)
}
defer tx.Rollback() // 保证异常时回滚

// ... 业务操作

return tx.Commit() // Commit 成功后，defer 中的 Rollback 是空操作
```

> `database/sql` 保证：`Commit()` 之后再调用 `Rollback()` 不会报错。所以 `defer tx.Rollback()` 是安全的惯用模式。

### 3.3 事务超时

🔴 必加约束：事务必须有超时

```go
// 反例：无超时的事务——慢查询可能无限占用连接
tx, err := db.Begin()

// 正例：context 超时控制整个事务
ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
defer cancel()
tx, err := db.BeginTxx(ctx, nil)
```

### 3.4 事务中不要做的事

🔴 必加约束

| 禁止 | 原因 | 替代方案 |
|---|---|---|
| **在事务中发 HTTP 请求** | 外部调用时长不可控，长时间持有锁 | 先发 HTTP，再开事务 |
| **在事务中发消息队列** | 事务回滚后消息已发出，数据不一致 | 事务提交后再发消息（outbox 模式） |
| **在事务中读大量数据** | 占用连接时间过长 | 事务外读取，事务内只写 |
| **嵌套事务** | `database/sql` 不支持真正嵌套 | savepoint（见 § 3.6） |
| **在事务中 sleep** | 无意义占用连接 | 绝不 |

```go
// 反例：事务中发 HTTP
tx, _ := db.Begin()
// ... 写数据库
resp, _ := http.Post(url, ...) // 如果这里超时 30 秒，事务一直持有锁
tx.Commit()

// 正例：先发 HTTP，再开事务
resp, err := http.Post(url, ...)
if err != nil { return err }
tx, _ := db.Begin()
// ... 用 resp 数据写数据库
tx.Commit()
```

### 3.5 只读事务

🟡 推荐：纯查询操作使用只读事务（PostgreSQL 支持，MySQL 8.0+ 支持）

```go
// 对只读查询减少锁开销
tx, err := db.BeginTxx(ctx, &sql.TxOptions{ReadOnly: true})
if err != nil {
    return err
}
defer tx.Rollback()

// 多个查询在同一快照下执行（可重复读）
var stats Stats
tx.GetContext(ctx, &stats, "SELECT COUNT(*) FROM users")
tx.GetContext(ctx, &stats, "SELECT COUNT(*) FROM orders")
```

### 3.6 Savepoint（部分回滚）

🟢 可选：复杂事务中需要部分回滚时使用

```go
tx, _ := db.Begin()
defer tx.Rollback()

// 第一步
tx.Exec("INSERT INTO users ...")

// 第二步——可能失败但不影响第一步
sp, _ := tx.Exec("SAVEPOINT sp1")
if err := doSomethingRisky(tx); err != nil {
    tx.Exec("ROLLBACK TO SAVEPOINT sp1") // 回退到 savepoint
}
tx.Exec("RELEASE SAVEPOINT sp1") // 释放 savepoint

tx.Commit()
```

## 4. Migration

### 4.1 方案对比

🔴 必加约束：**生产环境必须使用独立的 migration 工具**——不依赖 ORM 的 AutoMigrate

| 工具 | 方式 | 适用场景 |
|---|---|---|
| [**golang-migrate**](https://github.com/golang-migrate/migrate) | SQL 文件 + Go 库 | 最流行，支持多种 DB，可在代码中嵌入 |
| [**goose**](https://github.com/pressly/goose) | SQL 文件或 Go 函数 | 需要 Go 代码迁移逻辑时（数据修复脚本） |
| [**atlas**](https://atlasgo.io/) | 声明式 DSL 或 HCL | 想要声明式 schema 管理、自动生成 migration |
| **手写 SQL** | SQL 文件 + 手工执行 | 小项目、非自动化部署 |

```bash
# golang-migrate 用法示例
# 创建 migration
migrate create -ext sql -dir db/migrations -seq create_users_table

# 执行
migrate -path db/migrations -database "postgres://..." up

# 回滚
migrate -path db/migrations -database "postgres://..." down 1
```

```go
// golang-migrate 嵌入应用启动
import "github.com/golang-migrate/migrate/v4"

func runMigrations(db *sql.DB) error {
    m, err := migrate.NewWithDatabaseInstance(
        "file://db/migrations",
        "postgres",
        db,
    )
    if err != nil {
        return fmt.Errorf("init migrate: %w", err)
    }
    if err := m.Up(); err != nil && err != migrate.ErrNoChange {
        return fmt.Errorf("migrate up: %w", err)
    }
    return nil
}
```

### 4.2 Migration 文件命名

🔴 必加约束

```text
db/migrations/
├── 000001_create_users_table.up.sql
├── 000001_create_users_table.down.sql
├── 000002_add_email_to_users.up.sql
└── 000002_add_email_to_users.down.sql
```

| 规则 | 说明 |
|---|---|
| **序号递增** | `000001`、`000002`...，保证执行顺序 |
| **描述性名称** | 看到文件名就知道做了什么 |
| **每个 migration 有 down** | 保证可回滚 |
| **migration 文件不可修改** | 已经合并到主分支的 migration **绝不修改**——新增 migration 修正 |

### 4.3 Migration 编写规范

🔴 必加约束

```sql
-- 000001_create_users_table.up.sql
CREATE TABLE IF NOT EXISTS users (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    email       VARCHAR(255) NOT NULL UNIQUE,
    status      VARCHAR(20)  NOT NULL DEFAULT 'active',
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_users_email  ON users(email);
```

```sql
-- 000001_create_users_table.down.sql
DROP TABLE IF EXISTS users;
```

| 规则 | 说明 |
|---|---|
| **所有 DDL 用 `IF EXISTS` / `IF NOT EXISTS`** | 幂等性，防止重复执行报错 |
| **不要在 migration 中做数据迁移** | 数据迁移另开 migration，与 DDL 分离 |
| **不要 `SELECT *`** | 明确列名 |
| **索引在 migration 中创建** | 不要等到线上慢了再加 |

### 4.4 禁止事项

🔴 必加约束

```sql
-- 反例：migration 中修改已有数据（大表会锁表）
UPDATE users SET email = LOWER(email); -- 如果表有 1000 万行，锁表数小时

-- 反例：没有 down 的 migration
-- 只有 000003_change_status.up.sql，没有 down.sql

-- 反例：修改已合并的 migration 文件
-- 000001 已经合并到 main，又去修改它的内容
```

**正确做法**：

- 数据迁移用**批量 + 分批**（每次 1000 行，循环到处理完）
- 修改已有 schema 用**新增 migration**，不修改旧文件
- 重型 DDL（加索引、改列类型）评估锁表时间，必要时用 `CONCURRENTLY`（PostgreSQL）或在线 DDL 工具

## 5. 慢查询与监控

### 5.1 慢查询阈值

🟡 推荐

| 查询类型 | 阈值（p99） | 说明 |
|---|---|---|
| 主键查询（`WHERE id = ?`） | < 5ms | 最快 |
| 索引查询（`WHERE status = ?`） | < 20ms | 索引扫描 |
| 分页查询（`LIMIT 20`） | < 50ms | 可能涉及排序 |
| 聚合查询（`COUNT` / `SUM` / `GROUP BY`） | < 100ms | 可能全表扫描 |
| 报表查询 | < 500ms | 允许更长，但要隔离到只读副本 |

### 5.2 接入方式

```go
// database/sql 驱动层拦截——用 sqlcommenter 或手动包装
// 推荐：通过 OpenTelemetry 自动采集

import (
    "github.com/XSAM/otelsql"
    semconv "go.opentelemetry.io/otel/semconv/v1.17.0"
)

db, err := otelsql.Open("postgres", dsn,
    otelsql.WithAttributes(semconv.DBSystemPostgreSQL),
    otelsql.WithSQLCommenter(true), // 自动在 SQL 后加 trace comment
)
```

```go
// 手动包装：记录每条查询耗时
func queryWithMetrics(ctx context.Context, db *sqlx.DB, query string, args ...any) (*sqlx.Rows, error) {
    start := time.Now()
    defer func() {
        elapsed := time.Since(start)
        dbQueryDuration.Observe(elapsed.Seconds())
        if elapsed > 100*time.Millisecond {
            slog.WarnContext(ctx, "slow query",
                "query", query,
                "duration", elapsed,
            )
        }
    }()
    return db.QueryxContext(ctx, query, args...)
}
```

### 5.3 EXPLAIN 审查

🔴 必加约束：新增查询上线前**必须在生产量级数据上跑 EXPLAIN**

```sql
-- PostgreSQL
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'test@example.com';

-- MySQL
EXPLAIN SELECT * FROM users WHERE email = 'test@example.com';
```

关注指标：

| 指标 | 期望 |
|---|---|
| **type** (MySQL) / **Seq Scan** (PostgreSQL) | `const` / `ref` / `range`（走索引），不是 `ALL`（全表扫描） |
| **rows** | 扫描行数远小于表总行数 |
| **Extra** (MySQL) | 没有 `Using filesort`、`Using temporary` |

## 6. 查询规范

### 6.1 避免 `SELECT *`

🔴 必加约束

```go
// 反例：SELECT * 在表加列后可能返回不需要的数据，浪费带宽和内存
rows, _ := db.QueryContext(ctx, "SELECT * FROM users WHERE id = $1", id)

// 正例：明确列出需要的列
rows, _ := db.QueryContext(ctx, "SELECT id, name, email FROM users WHERE id = $1", id)
```

| `SELECT *` 的问题 | 说明 |
|---|---|
| **表加列后行为改变** | 返回的数据量不可预期 |
| **浪费带宽** | 不需要的列也被传输 |
| **无法利用覆盖索引** | 只查需要的列才能用索引覆盖 |
| **结构体映射易出错** | GORM / sqlx 的 Scan 对列顺序敏感 |

### 6.2 避免 N+1 查询

🔴 必加约束

```go
// 反例：N+1 查询——先查用户列表，再逐个查订单
users, _ := userRepo.List(ctx)
for _, u := range users {
    orders, _ := orderRepo.ListByUser(ctx, u.ID) // 每个用户一次查询
}

// 正例：一次查询带出所有关联数据
// 方案 1：JOIN
query := `
    SELECT u.*, o.id as order_id, o.amount
    FROM users u
    LEFT JOIN orders o ON u.id = o.user_id
    WHERE u.status = $1`
// 在代码中组装 user → []order

// 方案 2：批量 IN（推荐——逻辑清晰）
userIDs := extractIDs(users)
orders, err := orderRepo.ListByUserIDs(ctx, userIDs) // SELECT * FROM orders WHERE user_id IN (?, ?, ?)
orderMap := groupByUserID(orders)
for _, u := range users {
    u.Orders = orderMap[u.ID]
}
```

### 6.3 `IN` 子句上限

🔴 必加约束：`IN` 子句中参数数量 **≤ 1000**（MySQL 硬限制）或 **≤ 100**（推荐上限）

```go
// 反例：传入 5000 个 ID
ids := make([]int64, 5000)
db.SelectContext(ctx, &users, "SELECT * FROM users WHERE id IN (?)", ids)

// 正例：分批查询
func batchInQuery(ctx context.Context, db *sqlx.DB, ids []int64) ([]User, error) {
    const batchSize = 100
    var allUsers []User
    for i := 0; i < len(ids); i += batchSize {
        end := i + batchSize
        if end > len(ids) {
            end = len(ids)
        }
        var batch []User
        query, args, _ := sqlx.In("SELECT * FROM users WHERE id IN (?)", ids[i:end])
        query = db.Rebind(query)
        if err := db.SelectContext(ctx, &batch, query, args...); err != nil {
            return nil, err
        }
        allUsers = append(allUsers, batch...)
    }
    return allUsers, nil
}
```

### 6.4 参数化查询

🔴 必加约束：**绝不拼字符串构造 SQL**——必须使用参数化查询（占位符 `?` / `$1`）

```go
// 反例：SQL 注入风险
query := fmt.Sprintf("SELECT * FROM users WHERE name = '%s'", name)
db.QueryContext(ctx, query)

// 反例：动态排序用字符串拼接
query := fmt.Sprintf("SELECT * FROM users ORDER BY %s %s", sortField, sortOrder)

// 正例：参数化查询
db.QueryContext(ctx, "SELECT * FROM users WHERE name = $1", name)

// 正例：动态排序用白名单校验
var allowedSortFields = map[string]bool{"id": true, "name": true, "created_at": true}
var allowedSortOrders = map[string]bool{"ASC": true, "DESC": true}

func listUsers(ctx context.Context, db *sqlx.DB, sortField, sortOrder string) ([]User, error) {
    if !allowedSortFields[sortField] {
        return nil, fmt.Errorf("invalid sort field: %s", sortField)
    }
    if !allowedSortOrders[sortOrder] {
        return nil, fmt.Errorf("invalid sort order: %s", sortOrder)
    }
    // 白名单校验通过后再拼接
    query := fmt.Sprintf("SELECT * FROM users ORDER BY %s %s", sortField, sortOrder)
    var users []User
    return users, db.SelectContext(ctx, &users, query)
}
```

### 6.5 分页查询

🔴 必加约束（与  互引）

```go
// 偏移分页
func ListUsers(ctx context.Context, db *sqlx.DB, page, pageSize int) ([]User, int, error) {
    var total int
    db.GetContext(ctx, &total, "SELECT COUNT(*) FROM users")

    var users []User
    offset := (page - 1) * pageSize
    err := db.SelectContext(ctx, &users,
        "SELECT * FROM users ORDER BY created_at DESC LIMIT $1 OFFSET $2",
        pageSize, offset)
    return users, total, err
}

// 游标分页（大数据量推荐）
func ListUsersCursor(ctx context.Context, db *sqlx.DB, cursor string, limit int) ([]User, string, error) {
    var users []User
    err := db.SelectContext(ctx, &users,
        `SELECT * FROM users
         WHERE created_at < $1 OR (created_at = $1 AND id > $2)
         ORDER BY created_at DESC, id DESC
         LIMIT $3`,
        cursorTime, cursorID, limit+1) // 多查一条判断是否有下一页

    var nextCursor string
    if len(users) > limit {
        last := users[limit-1]
        nextCursor = fmt.Sprintf("%s_%d", last.CreatedAt.Format(time.RFC3339Nano), last.ID)
        users = users[:limit]
    }
    return users, nextCursor, err
}
```

### 6.6 `sqlx.In` 使用

🟡 若项目使用 `sqlx` 且查询参数需要展开为 `IN (...)`，推荐使用 `sqlx.In`。使用 `database/sql`、ORM 或查询构建器时，采用其已验证的参数化列表绑定方式；无论选型如何，不得拼接未经验证的用户输入。

```go
// 反例：手动拼接 IN
ids := []int64{1, 2, 3}
// 自己拼 "SELECT ... WHERE id IN (?,?,?)" —— 容易出错

// 正例：sqlx.In 自动展开
query, args, err := sqlx.In("SELECT * FROM users WHERE id IN (?)", ids)
if err != nil {
    return err
}
query = db.Rebind(query) // 将 ? 转换为 PostgreSQL 的 $1, $2, ...
db.SelectContext(ctx, &users, query, args...)
```

## 7. Context 传递

### 7.1 必须把 ctx 传到底层

🔴 必加约束

```go
// 反例：不传 ctx——查询无法超时、无法取消
rows, err := db.Query("SELECT * FROM users")

// 反例：创建了 ctx 但不传给 DB
ctx := context.Background()
db.Query("SELECT * FROM users") // 没有用 ctx！

// 正例：ctx 从头传到尾
func (r *userRepo) GetByID(ctx context.Context, id int64) (*User, error) {
    var user User
    err := r.db.GetContext(ctx, &user, "SELECT * FROM users WHERE id = $1", id)
    return &user, err
}
```

**传递链**：

```
HTTP request context
  → handler 获取 ctx
    → service 传递 ctx
      → repository 传递 ctx
        → db.QueryContext(ctx, ...)
```

### 7.2 不要在 struct 中存 context

🔴 必加约束

```go
// 反例：把 context 存在 struct 里
type UserRepo struct {
    db  *sqlx.DB
    ctx context.Context // 不要！
}

// 正例：context 作为方法参数
type UserRepo struct {
    db *sqlx.DB
}

func (r *UserRepo) GetByID(ctx context.Context, id int64) (*User, error) {
    // ctx 作为第一个参数
}
```

> 这是 Go 的惯例——context 是请求范围的，不是对象生命周期的。参见 [Go Context 官方文档](https://pkg.go.dev/context)。

### 7.3 超时与取消

🟡 推荐

```go
// service 层设置整体超时
func (s *UserService) GetUser(ctx context.Context, id int64) (*User, error) {
    ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
    defer cancel()
    return s.repo.GetByID(ctx, id)
}

// repository 层尊重 ctx 超时
func (r *userRepo) GetByID(ctx context.Context, id int64) (*User, error) {
    if ctx.Err() != nil {
        return nil, ctx.Err() // 如果已经超时，直接返回
    }
    var user User
    err := r.db.GetContext(ctx, &user, "SELECT * FROM users WHERE id = $1", id)
    return &user, err
}
```
