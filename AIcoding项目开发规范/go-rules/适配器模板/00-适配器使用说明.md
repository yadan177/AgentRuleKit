# 00 - Go AI 规则适配器使用说明

---

## 1. 目标与原则

本目录提供将 Go 规则库接入 Codex、Qoder 与 TRAE 的**常驻入口**。完整执行规则维护在 `go-rules/` 中；适配器负责强制触发关键门禁并定位到 [13 - Go AI 通用入口规则](../13-AI通用入口规则.md)。

- 🔴 **必须**保留 `go-rules/` 的现有目录和专题文档；适配器不得复制整套正文。
- 🔴 **必须**在目标项目中让入口能定位到规则库和所需专题文档。
- 🔴 **必须**把简短的文档影响门禁直接保留在 Codex、Qoder 等自动加载入口中；完整判断和执行细节仍由通用入口与技术文档任务入口维护。
- 🟡 推荐将规则库与实际使用的入口配置一并纳入版本控制。

## 2. 安装模式

| 模式 | 导入内容 | 能力边界 |
|---|---|---|
| 仅编码模式 | Go 开发规则及其编辑器入口 | 可以开发；发现文档影响时只能报告技术文档规则缺失，不得声称完成同步 |
| 开发—文档闭环模式（推荐） | Go 开发规则、Go 技术文档规则及两个编辑器入口 | 功能任务自动判断文档影响，并在有影响时进入文档同步流程 |

需要维护项目技术文档时必须使用闭环模式；不能只复制规则正文而遗漏入口。

## 3. 文件映射

| 源内容 | 目标位置 | 说明 |
|---|---|---|
| `AIcoding项目开发规范/go-rules/00-文档总览.md`、`13-AI通用入口规则.md`、`其他规则/` | `.ai-rules/go/` | Go 开发规则正文 |
| `AIcoding项目文档编写规范/Go项目文档编写规范/其他规则/` | `.ai-rules/go-project-docs/其他规则/` | Go 技术文档规则正文 |
| 开发规则 `适配器模板/codex/AGENTS.md` 与文档规则 `适配器模板/codex/AGENTS.md` | 项目根 `AGENTS.md` | 仅 Codex；合并内容，不覆盖已有入口 |
| 开发规则 `适配器模板/qoder/.qoder/rules/go-core.md` | `.qoder/rules/go-core.md` | 仅 Qoder；设为始终生效 |
| 文档规则 `适配器模板/qoder/.qoder/rules/go-project-docs.md` | `.qoder/rules/go-project-docs.md` | 仅 Qoder；闭环模式下设为始终生效 |
| 开发规则和文档规则各自的 `适配器模板/trae/` 使用说明 | 不创建未经验证的固定入口文件 | 仅 TRAE；按任务手动附加 |

目标项目采用闭环模式时结构如下：

```text
<go-project>/
├── .ai-rules/go/                 # 00、13 与其他规则/
├── .ai-rules/go-project-docs/    # Go 技术文档规则的其他规则/
└── <当前编辑器入口>
    ├── AGENTS.md                 # 仅 Codex：位于项目根，不实际嵌套在本目录
    ├── .qoder/rules/             # 仅 Qoder：go-core 与 go-project-docs
    └── TRAE 手动附加             # 当前不创建未验证的固定入口文件
```

上图三种入口是互斥示意，不要求同时安装；规则正文可以共用。

## 4. 安装顺序

1. 按文件映射复制规则正文。
2. 选择当前 AI 编辑器对应的一种入口；不要同时安装无关编辑器的入口。
3. 闭环模式下同时安装开发入口和技术文档入口，且不得相互覆盖。
4. 完成安装验证后再开始项目任务。

### 4.1 Codex

将 Go 开发适配器和 Go 技术文档适配器中的 `codex/AGENTS.md` 内容合并到项目根 `AGENTS.md`。已有项目入口必须保留；同义内容去重，开发门禁和文档任务路由都必须存在。

### 4.2 Qoder

复制 `go-core.md`；闭环模式下再复制 `go-project-docs.md`。在 Qoder 中将已复制入口设为始终生效，不能只依赖规则文件存在。

### 4.3 TRAE

未核实当前 TRAE 版本的稳定项目规则存储格式前，按 [TRAE 手动使用 Go AI 规则说明](./trae/00-TRAE手动使用说明.md) 手动附加开发与技术文档入口，不猜测配置路径，也不宣称自动触发。

## 5. 三层安装验证

1. 文件检查：确认规则正文和当前编辑器入口位于映射路径，入口引用的文件都存在。
2. 编辑器检查：确认 Codex 入口处于当前工作目录作用域，或 Qoder 入口已设为始终生效；TRAE 确认本次任务已手动附加。
3. 行为检查：执行最小测试任务，要求 AI 列出已加载入口并给出“文档影响结论”和依据；缺少任一项均视为接入未验证。

只有规则正文存在、但常驻入口未引用、未进入作用域或未设为始终生效，视为未完成安装。

## 6. 更新与维护

- 🔴 修改 13 号通用入口后，必须检查三个适配器仍能定位到它。
- 🔴 移动或改名专题文档后，必须更新总览和适配器中的链接。
- 🔴 更新 `.ai-rules/` 中的规则正文时可以按映射替换；更新项目根 `AGENTS.md` 时只能合并，禁止覆盖项目已有内容。
- 🔴 更新 Qoder 入口后重新确认始终生效状态；更新 TRAE 规则后在下一次任务重新附加。
- 🔴 每次规则路径、入口文件名或调用链变化后，重新执行三层安装验证。
- ❌ 禁止在多个适配器中复制完整专题规则；直接保留的简短文档影响门禁只负责触发，不得扩展成第二份完整规则。
