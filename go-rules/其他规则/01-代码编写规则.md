# 01 - Go 代码编写规则

> 🟢 本文件适用于 Go 包、函数、错误、context、goroutine、资源和泛型代码的实现或审查。
>
> 🔴 不适用：未经授权升级 Go/toolchain、重组包结构、引入依赖或全仓风格迁移。

---

## 1. 开始前确认

> **适用条件与验证**：先检查 `go.mod`、`go.sum`、`go.work`、Go/toolchain、构建脚本、包边界、已有测试和同包实现。

- 🔴 **必须**：只使用当前 toolchain、标准库和已声明模块中有证据支持的能力；不得从示例、其他仓库或新版 Go 推断可用 API。
- 🔴 **必须**：导出符号、包路径、结构体标签、错误语义和接口变更前检查跨包调用、生成代码、序列化和兼容性。
- 🟡 **推荐**：沿用同包的命名、receiver、错误包装、context、日志和格式化约定；没有证据时优先清晰的惯用写法而非个人偏好。

## 2. 错误、context 与资源

> **适用条件与验证**：函数可失败、接收 `context.Context`、访问 I/O/数据库/网络或创建可关闭资源时适用。

- 🔴 **必须**：错误在足够的边界添加安全上下文，并保留调用方需要的可判断语义；不得忽略错误、用 `panic` 代替普通失败或把敏感数据写进错误。
- 🔴 **必须**：`context.Context` 的传递、取消、超时和值使用遵循项目 API；不得以全局 context、后台 context 或自定义字段绕开请求生命周期。
- 🔴 **必须**：文件、响应体、Rows、事务、ticker、cancel 函数和项目资源句柄明确由谁关闭/调用；成功、失败、超时与提前返回都应安全释放。
- 🟡 **推荐**：使用 `defer` 处理作用域清晰的清理；循环或长生命周期中的资源应依据实际释放时机选择更明确的写法。

## 3. goroutine 与共享状态

> **适用条件与验证**：代码启动 goroutine、使用 channel、锁、原子操作、定时器或共享可变数据时适用。

- 🔴 **必须**：每个 goroutine 有启动者、退出条件、错误传递、取消路径和等待/回收责任；不得启动无人管理的后台工作。
- 🔴 **必须**：channel 容量、关闭者、接收者、锁和原子操作依据当前并发模型定义；不能把某种模式当作所有包的默认实现。
- 🟡 **推荐**：先确认顺序实现、队列或批量操作是否足够，再增加并发；为关键阻塞、超时和拒绝路径补充可观察证据。

## 4. API、泛型与可维护性

> **适用条件与验证**：新增公开接口、结构体、泛型、配置或跨包依赖时适用。

- 🔴 **必须**：公共 API 保持最小、行为明确且向后兼容；不要仅为测试或未来猜测提前抽象接口、工厂或全局服务。
- 🔴 **必须**：泛型仅在当前 Go 版本和项目已有用例支持时采用，并确保类型约束、零值、错误语义和调用可读性可验证。
- 🟡 **推荐**：接口定义在消费边界、只表达实际需要的行为；具体类型足够时不强行抽象。

## 5. 验证与例外

- 🔴 **必须**：运行仓库已有且相称的格式、构建、静态检查和测试；无法执行时说明原因、未验证范围和风险。
- 🟡 **推荐**：交付时说明 context/资源/并发所有权以及受影响的公开调用方。

> **例外**：公共 API、模块边界或 Go/toolchain 演进需要单独授权、兼容验证和回退方案。
