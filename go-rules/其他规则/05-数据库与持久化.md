# 05 - Go 数据库与持久化规则

> 🟢 本文件适用于 Go 客户端或服务端中已使用的关系型数据库、事务、迁移和查询代码。
>
> 🔴 不适用：未经确认的 NoSQL、消息队列、对象存储和数据库选型；这些需求必须先确认项目边界。

---

## 1. 先识别现有数据访问方案

> **适用条件与验证**：先检查 `go.mod`、连接初始化、driver、查询层、ORM/代码生成、migration 目录、事务封装和集成测试。既有项目沿用当前方案；新项目的选型、数据库创建和 schema 变更必须获得明确授权。

🔴 **必须**：不得因单个需求引入、替换或混用 `database/sql`、`sqlx`、`sqlc`、GORM 或任何 driver。不得臆造数据库方言、表、字段、索引、连接名或 migration 工具。

🟡 **推荐**：按项目已验证的能力选择实现：显式 SQL、已有查询生成代码或现有 ORM 均可；以可维护性、查询复杂度、团队已有实践和性能证据决定，而不是默认某一个库“最佳”。

🟢 **可选**：若用户要求新建持久化层，先提供选择依据和最小变更方案；不要从规则样例直接复制依赖或连接代码。

## 2. 查询与资源生命周期

> **适用条件与验证**：本节适用于执行 SQL、扫描结果或使用已有查询/ORM API 时；以当前 driver 的占位符、错误类型和封装约定为准。

🔴 **必须**：外部输入必须通过当前库支持的参数绑定传递，不能拼接为 SQL 片段。动态排序、列名、表名等无法参数化的部分只允许从代码维护的白名单选择。

🔴 **必须**：把请求 `context.Context` 传给项目已使用的查询 API；检查错误；对自行取得的 `Rows`、`Stmt`、事务等资源按其 API 配对关闭或回滚，并处理 `rows.Err()`。

🟡 **推荐**：只查询业务真正需要的列；避免在循环中发起 N+1 查询；批量、分页和预加载策略以查询计划、数据量与现有实现验证。

```go
// 占位符形态须与当前 driver 一致；示例只说明参数绑定原则。
row := db.QueryRowContext(ctx, query, userID)
if err := row.Scan(&user.ID, &user.Name); err != nil {
    return fmt.Errorf("load user: %w", err)
}
```

## 3. 连接与连接池

> **适用条件与验证**：仅在应用拥有并初始化连接池时适用。检查数据库端限制、部署副本数、并发、超时、已有配置键及运行指标。

🔴 **必须**：同一数据源复用项目约定的连接池实例；不要在请求路径或循环中反复 `sql.Open`。启动探活、关闭顺序和连接池参数遵循现有部署约定。

🟡 **推荐**：若项目暴露连接池配置，依据数据库连接上限、实例数和实测负载设置并观察 `DBStats` 或平台指标；不要复制固定连接数、生命周期或空闲时间。

🟢 **可选**：只有在已有健康检查约定且不会泄露 DSN、账户或内部网络信息时，增加有超时边界的连通性检查。

## 4. 事务与一致性

> **适用条件与验证**：仅当一个业务操作需要原子读写、已有事务边界或数据库支持相应事务语义时适用。先确认隔离级别、重试策略和跨服务一致性方案。

🔴 **必须**：事务内的读写使用同一事务句柄；在提交前遇到错误必须回滚；事务范围只包含必要的数据库操作。不要在事务中进行不可撤销的外部 HTTP、消息发送、长时间计算或等待。

🟡 **推荐**：使用当前项目惯用的 `defer Rollback` / 显式提交模式，并以可取消的请求上下文限制事务持续时间。可重试事务必须证明操作幂等，或由唯一约束、去重键等机制保护。

🟢 **可选**：只有项目已采用 outbox、savepoint 或 saga 等模式时才扩展相应实现；不要为了“分布式事务”自行加一层框架。

## 5. Schema 与迁移

> **适用条件与验证**：表结构、迁移工具、发布顺序、回滚能力和数据保留策略以仓库已有 migration 与部署流程为准。

🔴 **必须**：结构或数据变更必须作为可审查的迁移进入项目既有流程，并评估兼容部署、锁表、数据量、回滚和备份影响。不要在应用启动或普通业务请求中隐式执行生产 schema 变更。

🟡 **推荐**：采用扩展—迁移—切换—清理的兼容演进方式；对可能影响大表的索引、回填和删除任务，先在接近生产的数据量和环境中验证执行时间与锁影响。

🟢 **可选**：为关键迁移补充可重复的集成验证或演练，前提是项目已具备安全的测试数据库或迁移测试流程。

## 6. 性能与可观测性

> **适用条件与验证**：仅在有慢查询、超时、连接耗尽或容量风险证据时适用；使用项目可访问的 `EXPLAIN`、慢查询日志、指标、压测或集成测试验证。

🔴 **必须**：性能结论不能只凭代码外观得出；不能把生产数据、敏感 SQL 参数或完整结果写入日志、测试快照或规则输出。

🟡 **推荐**：对新增或显著改变的高频查询检查索引与查询计划；将超时、取消、错误和耗时接入项目已有监控字段，遵守脱敏规则。

## 7. AI 完成检查

> **验证**：仅执行仓库已提供、当前环境可运行且与本次变更相关的命令或测试；无法执行时明确记录原因。

- [ ] 已确认现有 driver、访问层、migration 与事务约定。
- [ ] 没有新增未经授权的数据库包、schema、连接配置或迁移工具。
- [ ] 所有外部值均通过参数绑定或白名单处理，且资源生命周期完整。
- [ ] 涉及事务、迁移或高频查询时，已说明一致性、兼容性或性能验证结果与风险。

> **例外**：紧急数据修复、生产 migration、连接池和隔离级别调整需要用户或项目既有变更流程的明确授权；本规则不替代 DBA 或安全评审。
