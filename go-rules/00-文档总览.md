# 00 - Go AI 项目开发规则总览

> 🟢 本文件适用于任何 AI 执行 Go 项目的开发、修改、审查、排障或规则维护任务。
>
> 🔴 不适用：替代项目事实、自动批准 Go/依赖升级、未经授权的架构迁移，或伪造构建与测试结果。

---

## 1. 使用方式与范围

开始任何 Go 任务前，先阅读 [13 - Go AI 通用入口规则](./13-AI通用入口规则.md)，再按本文件的任务查表加载必要专题规则。

- 🟡 只加载完成当前任务需要的专题规则，避免把整套规则作为不加区分的指令。
- 🔴 项目事实、用户任务、仓库内更具体的规则和工具安全限制优先于本规则库的通用建议。
- 🟢 规则库与实际 Go 项目分离时，按 `适配器模板/00-适配器使用说明.md` 复制一份完整规则源与一个当前工具入口。

## 2. 规则优先级与冲突处理

按以下优先级处理冲突：

1. 用户当前任务、法律/安全要求和工具安全限制。
2. 目标仓库的 `AGENTS.md`、贡献指南、CI、目录级规则、代码与配置事实。
3. 本规则库的 13 号通用入口规则。
4. 与任务直接相关的专题规则。
5. 本文档的导航与一般建议。

🔴 规则与代码、依赖、接口契约或运行环境不一致时，不得猜测；先检查证据，无法安全判断时说明问题并询问用户。

## 3. 开发前能力探测

### 3.1 必查项目事实

| 领域 | 优先检查的证据 |
|---|---|
| 模块与 Go 版本 | `go.mod`、`go.work`、`go.sum`、`toolchain`、CI 使用的 Go 版本 |
| 构建与工具 | `Makefile`、`Taskfile`、脚本、`go:generate`、`go:build` 标签、现有构建命令 |
| 架构与包 | 模块边界、`internal/`、`cmd/`、同包接口与既有实现 |
| 依赖与框架 | 已安装 HTTP/RPC、日志、ORM、配置、测试、观测和安全依赖 |
| 数据与发布 | migration、配置模板、容器镜像、编排、CI/CD 与运行平台约束 |

### 3.2 探测后的行动

- 已有同类实现：复用其包、错误、`context.Context`、日志、测试和资源生命周期约定。
- 多种方案共存：明确当前改动使用的方案、所有权和边界。
- 缺少证据：不新增框架、命令或基础设施；采用最小兼容改动，或询问用户。

## 5. 跨语言与系统边界

- Go 服务端规则负责服务内实现、并发、数据访问、部署与可观测性。
- Unity、前端或其他客户端规则负责各自的 UI、资源与客户端生命周期；接口、错误码、认证和幂等以已确认契约为准。
- Java、Go 等服务端技术栈各自维护自身的框架和运行时规则；跨服务协议与所有权由契约和团队决策维护，不在任一语言规则中重复臆造。

## 6. 文档维护要求

### 6.1 新增或修订规则

- 🔴 遵守 [规则文档编写格式规范](../00-规则文档编写规范/规则文档编写格式规范.md)。
- 🔴 涉及版本、依赖、框架、命令、部署或技术选型时，写明适用条件、验证和例外。
- 🔴 不将规则示例中的模块名、版本号、密钥、镜像、地址或命令伪装为项目事实。
- 🟡 修改专题规则后，更新本任务表与相关入口引用，并执行结构和链接检查。
