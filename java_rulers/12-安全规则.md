# 12 - Java 安全规则

> 🟢 本文件适用于 Java 项目安全红线（OWASP Top 10/BCrypt/JWT/Spring Security）。

> 🔴 不适用：业务逻辑实现、UI 样式设计

---

## 1. OWASP Top 10 概览

### 1.1 2021 版 OWASP Top 10

⚠️ **安全**：

- **AI 写任何 Web / 后端代码前，必须熟悉 OWASP Top 10**
- 这是**行业标准**的 10 大 Web 安全风险

| # | 风险 | 简述 |
|---|---|---|
| A01 | **Broken Access Control**（失效的访问控制）| 用户能访问 / 修改他人数据 |
| A02 | **Cryptographic Failures**（加密失败）| 弱密码 / 明文存储 / 错误加密算法 |
| A03 | **Injection**（注入）| SQL / NoSQL / OS / LDAP 注入 |
| A04 | **Insecure Design**（不安全设计）| 设计层面就缺少安全控制（如无防刷机制）|
| A05 | **Security Misconfiguration**（安全配置错误）| 默认配置 / 调试模式 / 默认账号 |
| A06 | **Vulnerable Components**（易受攻击组件）| 第三方库已知漏洞 |
| A07 | **Auth Failures**（认证失败）| 弱密码 / Session 固定 / 缺少多因子 |
| A08 | **Software & Data Integrity Failures**（数据完整性失败）| 不安全的反序列化 / 自动更新无校验 |
| A09 | **Security Logging Failures**（日志监控失败）| 缺少审计 / 攻击无告警 |
| A10 | **SSRF**（服务端请求伪造）| 攻击者诱导服务端访问内网 |

### 1.2 P3C 安全规约的覆盖

🟡 **推荐**：P3C 黄山版安全规约 8 条**部分覆盖**了 OWASP Top 10：

| P3C 条目 | 对应 OWASP |
|---|---|
| 1. 权限控制校验（水平权限）| A01 访问控制 |
| 2. 敏感数据脱敏展示 | A02 加密 + A04 数据保护 |
| 3. SQL 参数绑定 | A03 注入 |
| 4. 用户输入有效性验证 | A03 + A04 输入验证 |
| 5. HTML 输出安全过滤 / 转义 | A03 XSS |
| 6. CSRF 安全过滤 | A01 跨站请求伪造 |
| 7. 防重放限制 | A04 防刷设计 |
| 8. 用户生成内容风控 | A04 反垃圾 |

**P3C 未覆盖的**（AI 必须补全）：
- 加密 / 哈希算法（MD5 / SHA1 已过时）
- 认证（Session / JWT / OAuth）
- 授权（RBAC / ABAC）
- 反序列化漏洞
- 依赖漏洞扫描
- 安全日志

### 1.3 安全开发基本原则

⚠️ **安全**（业界公认）：

1. **深度防御（Defense in Depth）**：多层安全控制，不是单点
2. **最小权限原则（Least Privilege）**：每个用户 / 服务只给最少的权限
3. **白名单优于黑名单**：明确"允许的"而不是"禁止的"
4. **默认安全（Secure by Default）**：默认配置就是安全的（如不开放调试接口）
5. **失败要安全（Fail Securely）**：出错时拒绝而不是放行
6. **不信任输入（Never Trust User Input）**：所有外部输入视为不可信
7. **不保存不必要的数据（Don't Store What You Don't Need）**

## 2. 认证与授权

### 2.1 认证 vs 授权

🟢 **参考**：

- **认证（Authentication）**：你是谁？（登录）
- **授权（Authorization）**：你能干什么？（权限控制）

### 2.2 密码安全（P3C 隐含）

⚠️ **安全**：

- **密码绝不以明文存储**（数据库被攻破 → 用户密码全部泄露）
- 哈希算法必须用 **强密码哈希**：BCrypt / SCrypt / Argon2
- **不要用**：MD5 / SHA1 / SHA256 + salt（已被证明可破解 / 不抗 GPU 暴力破解）

✅ **正例**：
```java
// ✅ Spring Security 内置 BCrypt
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("user-password");  // 加盐 + 慢哈希
boolean matches = encoder.matches("user-password", hash);

// ✅ 用户登录时比对
if (!encoder.matches(inputPassword, user.getPasswordHash())) {
    throw new BizException("50101", "密码错误");
}
```

❌ **反例**：
```java
// ❌ MD5（已被破解）
String hash = DigestUtils.md5Hex(password);

// ❌ SHA-1（已被破解）
String hash = DigestUtils.sha1Hex(password + salt);

// ❌ 自制哈希（绝不要）
String hash = password.toUpperCase() + "_salt_2024";
```

### 2.3 密码强度策略

⚠️ **安全**：

- **最小长度 8 位**（推荐 **12 位**）
- 至少包含：数字 / 大写 / 小写 / 特殊字符 **3 类**以上
- **常见密码字典过滤**（`123456` / `password` / `qwerty` 等）
- **不能与用户名 / 邮箱相同 / 倒写**

### 2.4 JWT 认证（AI 视角扩展）

🟡 **推荐**：

- **JWT（JSON Web Token）** 是无状态认证的事实标准
- **不要自己手写 JWT 实现**（用成熟库：`io.jsonwebtoken.jjwt` / `nimbus-jose-jwt`）

```java
// 生成 JWT
String jwt = Jwts.builder()
    .setSubject(userId)
    .claim("roles", roles)
    .setIssuedAt(new Date())
    .setExpiration(new Date(System.currentTimeMillis() + 3600_000))  // 1 小时
    .signWith(SecretKeyProvider.getKey(), SignatureAlgorithm.HS256)
    .compact();
```

⚠️ **安全**：

- **JWT 签名密钥至少 256 位**（不能太短）
- **Access Token 短期**（15-60 分钟）+ **Refresh Token 长期**（几天到几周）
- **不要把敏感数据放 JWT payload**（payload 只是 base64 编码，**不加密**）
- **JWT 必须用 HTTPS 传输**（防止中间人）
- **刷新 Access Token 时同时 rotation Refresh Token**

### 2.5 OAuth 2.0 / OpenID Connect

🟢 **参考**：

- **OAuth 2.0**：授权框架（"让用户授权第三方访问资源"）
- **OpenID Connect**：基于 OAuth 2.0 的**身份认证层**
- 不自己实现（用 Spring Authorization Server / Keycloak / Auth0）

### 2.6 Spring Security 集成

🟡 **推荐**：Spring Boot 项目默认用 Spring Security：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())  // API 项目用 JWT 时通常禁用
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS));
        return http.build();
    }
}
```

⚠️ **安全**：

- **不使用默认的 CSRF token（API 项目禁用 CSRF，用 JWT 携带 traceId）**
- **不要使用明文密码比较**
- **必须 BCrypt / Argon2 哈希**
- **登录失败要统一错误提示**（不区分"用户不存在" vs "密码错误" → 防账号枚举攻击）

### 2.7 多因子认证（MFA）

🟡 **推荐**：

- 高安全场景（支付 / 后台 / 改密）启用 MFA
- 因素：密码 / 手机短信 / 邮箱验证码 / TOTP（Google Authenticator）/ 硬件 UKey
- **不应只有单一密码**

### 2.8 水平越权 vs 垂直越权

⚠️ **安全**（P3C 安全规约第 1 条）：

- **隶属于用户个人的页面或者功能必须进行权限控制校验**
- 防止没有做水平权限校验就可随意访问、修改、删除别人的数据
- 比如查看他人的私信内容、修改他人的订单

```java
// ❌ 水平越权（任何人能查任何订单）
@GetMapping("/orders/{id}")
public OrderDTO getOrder(@PathVariable Long id) {
    return orderService.findById(id);  // 没检查 order.userId == currentUser
}

// ✅ 水平越权防护
@GetMapping("/orders/{id}")
public OrderDTO getOrder(@PathVariable Long id, @CurrentUser Long currentUserId) {
    Order order = orderService.findById(id);
    if (!order.getUserId().equals(currentUserId)) {
        throw new BizException("50101", "无权访问");  // 不要直接 return 404，避免泄露
    }
    return OrderMapper.toDTO(order);
}
```

## 3. 注入攻击防御

### 3.1 SQL 注入

⚠️ **安全**（P3C 安全规约第 3 条 / 见 07 §3.6 也有讲）：

- **所有用户输入的 SQL 参数严格使用参数绑定或 METADATA 字段值限定**
- **禁止字符串拼接 SQL**

✅ **正例**：
```java
// ✅ MyBatis 用 #{} （预编译）
@Select("SELECT * FROM user WHERE id = #{id}")
User findById(@Param("id") Long id);

// ✅ JPA 用 :param 占位符
@Query("SELECT u FROM User u WHERE u.name = :name")
List<User> findByName(@Param("name") String name);
```

❌ **反例**：
```java
// ❌ 字符串拼接（注入风险）
String sql = "SELECT * FROM user WHERE name = '" + name + "'";

// ❌ MyBatis 用 ${}（不预编译，可注入）
@Select("SELECT * FROM user WHERE name = '${name}'")
List<User> findByName(@Param("name") String name);
```

### 3.2 NoSQL 注入

⚠️ **安全**：

- MongoDB / Elasticsearch 查询同样需要**参数化**
- **不要把用户输入直接拼到查询对象**

```java
// ❌ 危险：用用户输入拼查询
Query query = new Query();
query.addCriteria(Criteria.where("name").is(userInput));  // ${userInput} 形式还是安全

// ⚠️ 但如果用户输入是 {"$gt":""} 这种 MongoDB operator，会绕过条件
// ✅ 正例：先转义或类型检查
if (!userInput.matches("^[a-zA-Z0-9_]+$")) {
    throw new BizException("20101", "非法用户名");
}
Criteria.where("name").is(userInput);
```

### 3.3 OS 命令注入

⚠️ **安全**：

- **避免使用 `Runtime.exec()` 执行命令**
- 如必须：使用 `ProcessBuilder` + 转义参数列表（不拼字符串）

```java
// ❌ 危险：拼字符串
Runtime.getRuntime().exec("cmd /c dir " + userPath);  // userPath 可含 " ; rm -rf /"

// ✅ 正例：参数列表形式
ProcessBuilder pb = new ProcessBuilder("ls", "-la", userPath);  // 参数独立处理
pb.start();
```

### 3.4 LDAP 注入 / XPath 注入

⚠️ **安全**：

- 用户输入进 LDAP / XPath 查询前**必须转义或参数化**
- 不直接拼字符串

### 3.5 XSS（跨站脚本）

⚠️ **安全**（P3C 安全规约第 5 条）：

- **禁止向 HTML 页面输出未经安全过滤或未正确转义的用户数据**

```java
// ❌ 危险：直接拼接
page = "<div>欢迎您, " + user.getName() + "</div>";  // 如果 name = "<script>alert(1)</script>"

// ✅ 正例：HTML 转义
page = "<div>欢迎您, " + HtmlUtils.htmlEscape(user.getName()) + "</div>";
```

🟡 **推荐**：

- 用 **Thymeleaf / Freemarker / Vue / React** 等现代模板（默认转义）
- **Content-Security-Policy** header（防 XSS 兜底）

### 3.6 CSRF（跨站请求伪造）

⚠️ **安全**（P3C 安全规约第 6 条）：

- **表单、AJAX 提交必须执行 CSRF 安全过滤**
- CSRF 是利用用户在已登录站点 A 的身份去请求站点 B 的接口

⚠️ **安全**：

- **JWT 认证项目**：CSRF 不适用（因为 Authorization header 不会跨域自动发送）
- **Cookie Session 项目**：必须启用 CSRF token（Spring Security 默认开启）

```java
http.csrf(csrf -> csrf
    .ignoringRequestMatchers("/api/public/**")  // API 公开接口可豁免
    .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())
);
```

### 3.7 ReDoS（正则拒绝服务）

⚠️ **安全**（P3C 安全规约第 4 条）：

- **Java 代码用正则来验证客户端的输入，有些正则写法验证普通用户输入没有问题**
- **如果攻击人员使用的是特殊构造的字符串来验证，有可能导致死循环的结果**

**反例**：
```java
// ❌ 灾难：指数回溯
String evilPattern = "^([a-z]+)+$";
evilPattern.matcher("aaaaaaaaaaaaaaaaaaaaaaaaaaaaaab").matches();  // 死循环，CPU 100%
```

**正例**：
- 测试用 [ReScue](https://github.com/GeniS/JRegexFuzzer) / ReDoS-Checker 工具
- 关键正则**加超时**：Java 13+ `Pattern.matcher().group(timeout)`（不普及）
- 重写为**非灾难性正则**：避免 `(a+)+` 这种嵌套量词

## 4. 访问控制（AI 视角扩展）

P3C 只讲了"水平权限校验"，AI 视角补全 4 类访问控制。

### 4.1 4 类访问控制模型

| 模型 | 适用 | Java 实现 |
|---|---|---|
| **DAC（Discretionary）** | 资源所有者决定谁能访问 | ACL（Access Control List）|
| **MAC（Mandatory）** | 操作系统级别 | 操作系统实现（SELinux / Windows ACL）|
| **RBAC（Role-Based）** | 大多数企业应用 | Spring Security `@PreAuthorize("hasRole('ADMIN')")` |
| **ABAC（Attribute-Based）| 复杂策略（资源 / 时间 / 位置） | 自定义策略引擎（OPA / Cerbos）|

🟡 **推荐**：90% Java 后端用 **RBAC**。资源级 / 复杂场景用 ABAC。

### 4.2 RBAC 实现

🟡 **推荐**：

- 角色：`ADMIN` / `USER` / `GUEST` 等
- 权限：`order:read` / `order:create` / `user:delete` 等（对象:动作）

```java
@PreAuthorize("hasRole('ADMIN') or hasAuthority('order:create')")
@PostMapping("/orders")
public ApiResponse<OrderDTO> create(@RequestBody CreateOrderRequest req) {
    // 只有 ADMIN 角色 或 有 order:create 权限的用户能调用
}
```

### 4.3 资源级权限

🟡 **推荐**：

- 用 Spring Security `@PostFilter` 或 `@PostAuthorize` 做资源级过滤
- 或自定义 PermissionEvaluator

```java
@PostAuthorize("returnObject.userId == authentication.principal.id")
public OrderDTO getOrder(Long id) {
    return orderRepository.findById(id).orElseThrow();
}
```

### 4.4 URL 路径权限

🟡 **推荐**：

```java
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/public/**").permitAll()      // 公开接口
    .requestMatchers("/api/admin/**").hasRole("ADMIN")  // 后台管理
    .requestMatchers(HttpMethod.DELETE, "/api/users/**").hasAuthority("user:delete")
    .anyRequest().authenticated()                       // 其他都要登录
);
```

### 4.5 服务间调用权限

⚠️ **安全**：

- 微服务之间用 **`oauth2-client-credentials`** 模式授权
- 不在 Cookie 里放业务权限
- 网关层做统一权限校验（Zuul / Spring Cloud Gateway）

### 4.6 默认安全原则

⚠️ **安全**（用户没明确要的就不开放）：

- 新接口**默认需要登录**（`authenticated()`）
- 新接口**默认需要登录用户必须是本人**（水平越权防护）
- **新增管理接口必须显式声明**（`hasRole("ADMIN")`）

## 5. 敏感数据保护（P3C 强制）

### 5.1 P3C 第 2 条规则

⚠️ **安全**（P3C 安全规约第 2 条）：

- **用户敏感数据禁止直接展示**
- **必须对展示数据进行脱敏**
- **个人手机号码显示为：158\*\*\*\*9119，隐藏中间 4 位，防止隐私泄露**

### 5.2 常见敏感字段

⚠️ **安全**（必须脱敏或加密）：

| 字段 | 静态存储 | 日志 | 前端展示 | API 返回 |
|---|---|---|---|---|
| **手机号** | 加密（AES）| `138****1234` | `138****1234` | `138****1234` |
| **身份证** | 加密（AES）| `110101****1234` | 不展示原文 | `110101****1234` |
| **银行卡** | 加密（AES）| 前 4 后 4 | 前 4 后 4 | 前 4 后 4 |
| **邮箱** | 明文（业务需要） | `z****@example.com` | `z****@example.com` | `z****@example.com` |
| **密码** | **强哈希**（BCrypt）| **不记日志** | **不返回** | **不返回** |
| **姓名** | 明文 | `张*` | 明文 | 明文 |
| **地址** | 明文 | 详细到街道级**需脱敏** | 明文 | 明文 |

### 5.3 加密 vs 哈希

🟢 **参考**：

- **加密（Encryption）**：可逆（有密钥就能解密）— 适合**需要原文还原**的数据
- **哈希（Hash）**：不可逆（单向）— 适合**不需要原文还原**的数据（如密码）

```java
// 加密（AES）
public String encrypt(String plain, SecretKey key) throws Exception {
    Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
    cipher.init(Cipher.ENCRYPT_MODE, key);
    byte[] ciphertext = cipher.doFinal(plain.getBytes(StandardCharsets.UTF_8));
    return Base64.getEncoder().encodeToString(ciphertext);
}

// 哈希（BCrypt 用于密码）
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode(plainPassword);  // 不可逆
```

### 5.4 加密算法选择

⚠️ **安全**：

- ✅ **对称加密**：AES-GCM（AES-GCM 256-bit 带认证）
- ✅ **非对称加密**：RSA-OAEP 2048+ / ECC P-256
- ✅ **密码哈希**：BCrypt（cost=10+）/ Argon2id
- ❌ **不要用**：DES / 3DES / RC4 / MD5 / SHA1 / SHA-256 直接做密码哈希

### 5.5 密钥管理

⚠️ **安全**：

- **密钥绝不写在代码中**（明文 hardcode）
- **不在 Git 中提交**（`.env` / `application.properties` 加入 `.gitignore`）
- 使用 **密钥管理服务**：HashiCorp Vault / AWS KMS / Aliyun KMS / Spring Cloud Config + 加密

```yaml
# application.yml（开发环境）
spring:
  datasource:
    password: ${DB_PASSWORD}  # 环境变量注入

# production：环境变量 / Vault / KMS
# 绝对不能在 application.yml 写真实密码
```

### 5.6 PII 数据访问审计

⚠️ **安全**：

- **访问用户敏感数据需要审计日志**（谁 / 何时 / 查了什么）
- 符合《个人信息保护法》

## 6. API 安全（AI 视角扩展）

### 6.1 HTTPS 必须

⚠️ **安全**：

- **生产环境所有 API 必须走 HTTPS**
- **不要**用 HTTP（明文传输，被中间人攻击）
- **不要**只对部分接口用 HTTPS

### 6.2 CORS 配置安全

⚠️ **安全**：

- **不要用 `allowedOrigins("*")` + `allowCredentials(true)`**（浏览器禁止）
- 明确允许的源：

```java
registry.addMapping("/api/**")
    .allowedOrigins(
        "https://app.example.com",
        "https://admin.example.com"
    )
    .allowCredentials(true)  // 允许带 cookie / Authorization
    .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
    .allowedHeaders("Authorization", "Content-Type", "X-Trace-Id")
    .maxAge(3600);
```

### 6.3 限流（防爆破）

⚠️ **安全**（见 06-Web/API 设计规则 § 7 也讲）：

- **登录接口必须限流**：5 次 / 分钟 / IP（防密码爆破）
- **短信接口必须限流**：1 次 / 分钟 / 手机号（防刷）
- **公开 API 限流**：100 QPS / IP（防 DDoS / 滥用）

### 6.4 防重放（Nonce / Timestamp）

⚠️ **安全**：

- **重要操作（支付 / 转账）必须防重放**
- 用 **Timestamp + Nonce**：
  - 请求带 `timestamp`（秒级）+ `nonce`（UUID）
  - 服务端检查：timestamp 在 ±5 分钟内 + nonce 在 Redis 没出现过
  - 重复 nonce 直接拒绝

```java
public boolean checkReplay(Long userId, String nonce, long timestamp) {
    if (Math.abs(System.currentTimeMillis() / 1000 - timestamp) > 300) {
        return false;  // 超过 5 分钟
    }
    Boolean firstTime = redisTemplate.opsForValue()
        .setIfAbsent("nonce:" + userId + ":" + nonce, "1", Duration.ofMinutes(10));
    return Boolean.TRUE.equals(firstTime);
}
```

### 6.5 API 版本管理

🟡 **推荐**：

- 旧版 API 不删除（标记 `@Deprecated` + 给迁移期）
- v1 修 bug 不删接口，加 `/v2/`
- **Breaking Change 要走 v2**：URL 变化 / 返回值类型变 / 必填参数新增

### 6.6 SSRF（服务端请求伪造）

⚠️ **安全**：

- 不要让用户输入 URL 服务端直接请求（攻击者让服务端访问 `http://内网` / `http://169.254.169.254/...`）
- **必须**白名单允许的域名 / 验证 IP 不能是内网 / 169.254 / 127.x

```java
public boolean isSafeUrl(String url) {
    try {
        URI uri = new URI(url);
        String host = uri.getHost();
        if (!ALLOWED_DOMAINS.contains(host)) return false;
        InetAddress addr = InetAddress.getByName(host);
        if (addr.isLoopbackAddress() || addr.isLinkLocalAddress()
            || addr.isSiteLocalAddress()) {
            return false;  // 拒绝内网 / 环回
        }
        return true;
    } catch (Exception e) {
        return false;
    }
}
```

## 7. 加密与密钥管理（AI 视角扩展）

P3C 没专门讲加密，但**密码学是安全的基础**。

### 7.1 对称加密

⚠️ **安全**：

- **AES-GCM（AES/GCM/NoPadding）** 256-bit 是当前推荐的对称加密算法
- 同时提供**机密性 + 完整性**（认证加密 AEAD）

```java
public class AesGcmCipher {
    private static final String ALGORITHM = "AES/GCM/NoPadding";
    private static final int IV_LENGTH = 12;  // GCM 推荐 12 字节 IV
    private static final int TAG_LENGTH = 128;  // 16 字节认证标签

    public byte[] encrypt(byte[] plaintext, SecretKey key) throws Exception {
        // IV 必须每条消息随机生成
        byte[] iv = new byte[IV_LENGTH];
        SecureRandom.getInstanceStrong().nextBytes(iv);

        Cipher cipher = Cipher.getInstance(ALGORITHM);
        GCMParameterSpec spec = new GCMParameterSpec(TAG_LENGTH, iv);
        cipher.init(Cipher.ENCRYPT_MODE, key, spec);
        return cipher.doFinal(plaintext);  // 输出包含 IV + ciphertext + tag
    }
}
```

### 7.2 非对称加密

⚠️ **安全**：

- **RSA-OAEP** 2048+ 或 **ECC P-256**
- 私钥绝不外泄（用 HSM / Vault 管理）

### 7.3 哈希与 MAC

⚠️ **安全**：

- 用于密码：BCrypt（cost=12+）/ Argon2id（推荐）/ SCrypt
- 用于消息认证：HMAC-SHA256
- 用于指纹：SHA-256 / SHA-3（**不要用于密码**）

### 7.4 TLS / HTTPS

⚠️ **安全**：

- **生产用 TLS 1.3**（TLS 1.0 / 1.1 已废弃多年）
- 证书用 Let's Encrypt / 阿里云 SSL 等权威 CA
- 强加密套件：`TLS_AES_256_GCM_SHA384` 等
- **关闭不安全算法**：`SSLv3` / `TLS_RSA_*` / 弱 DH

### 7.5 不应自己实现的密码学

⚠️ **安全**：

- **绝不自己实现加密算法**（自己设计密码学 = 必然被破解）
- 绝不写自定义哈希函数
- 密码学算法只用**广泛审计的库**：OpenJDK / BouncyCastle / Tink
- 密码学协议只用在**已有标准**：JWT / OAuth 2.0 / TLS / WebCrypto API

### 7.6 密钥管理

⚠️ **安全**：

| 场景 | 密钥存储 |
|---|---|
| **配置文件** | `.env`（入 .gitignore）/ Vault / KMS（**不在代码**）|
| **数据库** | 加密列 / AWS RDS 加密 / TDE 透明加密 |
| **运行时** | Java `KeyStore`（密码保护的密钥库）|
| **生产环境** | HashiCorp Vault / AWS KMS / Aliyun KMS |

## 8. 会话管理

### 8.1 Session vs JWT

🟢 **参考**：

| 模式 | 状态 | 撤销 | 性能 | 适用 |
|---|---|---|---|---|
| **Session**（服务端）| 服务端存 | 立即撤销 | 每请求查 DB | 中小应用 / 后台 |
| **JWT**（无状态）| 客户端持有 | 需黑名单或短期 | 不查 DB | 移动端 / 微服务 |
| **混合** | 短 JWT + Refresh | Refresh 撤销 | 中等 | 主流 |

### 8.2 Session 固定攻击防护

⚠️ **安全**（P3C 安全规约第 7 条相关的隐含）：

- 用户登录成功后**生成新 Session ID**（防 Session 固定攻击）
- 不接受登录前的 Session ID

```java
// Spring Security 默认：登录成功 → 迁移 Session ID（防 Session 固定）
http.sessionManagement(s -> s
    .sessionFixation().migrateSession()  // 或者 newSession
);
```

### 8.3 Cookie 安全标记

⚠️ **安全**：

- **生产 Cookie 必须设置 4 个安全标记**：

```java
Set-Cookie: sessionId=abc123; Path=/; Domain=example.com; Secure; HttpOnly; SameSite=Strict
```

| 属性 | 作用 |
|---|---|
| `Secure` | 只在 HTTPS 发送（不被 HTTP 嗅探）|
| `HttpOnly` | 不能被 JS 读取（防 XSS 偷 cookie）|
| `SameSite=Strict` | 防止跨站 CSRF |
| `Path` / `Domain` | 限定 cookie 作用范围 |

### 8.4 Session 过期

⚠️ **安全**：

- **Session 必须有绝对过期时间**（如 30 分钟无活动后过期）
- 关键操作（转账 / 改密）需要**重新认证**（即使 Session 没过期）

### 8.5 Cookie 安全配置 Spring 示例

```java
http.sessionManagement(s -> s
    .maximumSessions(1)  // 同一时间只能 1 个 Session
    .sessionFixation().migrateSession()
    .invalidSessionUrl("/login")
);
```

### 8.6 JWT 安全实践

⚠️ **安全**：

- **JWT 不能存敏感信息**（payload 只是 base64，**不是加密**）
- **JWT 必须用强签名算法**：HS256+（HMAC 256）/ RS256+（RSA 2048）
- **Access Token 短期**（15-60 分钟）+ **Refresh Token 长期**
- **Refresh Token rotation**（每次刷新生成新的 Refresh Token）

### 8.7 Token 撤销

⚠️ **安全**：

- 用户的 **Access Token 可短期**，但**撤销要即时生效**（如改密码 / 检测到盗号）
- 实现：
  - 黑名单 token（Redis）：登出 / 改密时加进去
  - Token 版本号：用户表存 `tokenVersion`，JWT 带这个字段，每次改密 +1
- 验证时检查 Redis 黑名单 或 比对 `tokenVersion`

## 9. 文件上传安全

### 9.1 攻击向量

🟢 **参考**：

- **上传 WebShell**（`.jsp` / `.war` / `.php`）
- **覆盖文件路径**（`../../etc/passwd`）
- **存储型 XSS**（文件名注入脚本）
- **上传大文件 DoS**

### 9.2 必须的多重防护

⚠️ **安全**：

- ✅ **白名单 MIME 类型**：`image/jpeg` / `image/png` / `application/pdf`
- ✅ **验证文件扩展名**（双验证：客户端 + 服务端）
- ✅ **验证文件内容 magic bytes**（文件头）
- ✅ **重命名上传文件**：UUID + 扩展名，**不用用户输入文件名**
- ✅ **限制文件大小**（如 图片 ≤ 5MB，视频 ≤ 500MB）
- ✅ **存储到专门目录**（不在 WebRoot 直接放，避免被解释为脚本）
- ✅ **CDN / 对象存储**（阿里云 OSS / S3），不与应用服务器同机

✅ **正例**：
```java
@PostMapping("/upload")
public ApiResponse<String> upload(MultipartFile file) {
    // 1. 大小限制
    if (file.getSize() > 5_000_000) throw new BizException("20101", "文件过大");

    // 2. MIME 白名单
    String mime = file.getContentType();
    if (!ALLOWED_MIMES.contains(mime)) throw new BizException("20101", "类型不允许");

    // 3. 扩展名校验
    String ext = FilenameUtils.getExtension(file.getOriginalFilename());
    if (!ALLOWED_EXTS.contains(ext)) throw new BizException("20101", "扩展名不允许");

    // 4. Magic bytes 验证
    if (!isValidMagicBytes(file)) throw new BizException("20101", "文件内容异常");

    // 5. 重命名
    String newName = UUID.randomUUID() + "." + ext;

    // 6. 存储到对象存储（不在本地）
    String url = ossService.upload(newName, file.getInputStream());

    return ApiResponse.ok(url);
}
```

⚠️ **安全**：

- **防路径穿越**：`file.getOriginalFilename()` 可能含 `../../../etc/`，**用 `FilenameUtils.getName()`** 截取最后一段
- **不直接用用户输入构造路径**

### 9.3 文件下载安全

⚠️ **安全**：

- **下载文件用 Content-Disposition: attachment**
- 文件名要 RFC 5987 编码（防注入）
- 防 SSRF：下载用户提供的 URL 时，验证 URL 是允许的（见 § 8.6）

## 10. 依赖漏洞扫描

### 10.1 OWASP Dependency-Check

⚠️ **安全**：

- **CI 流水线必须集成依赖漏洞扫描**
- OWASP Dependency-Check / Snyk / GitHub Dependabot 等

```xml
<!-- pom.xml 添加 OWASP Dependency-Check Maven 插件 -->
<plugin>
    <groupId>org.owasp</groupId>
    <artifactId>dependency-check-maven</artifactId>
    <version>9.0.4</version>
    <configuration>
        <failBuildOnCVSS>7.0</failBuildOnCVSS>  <!-- CVSS ≥ 7 失败构建 -->
    </configuration>
    <executions>
        <execution>
            <goals><goal>check</goal></goals>
        </execution>
    </executions>
</plugin>
```

### 10.2 漏洞响应流程

⚠️ **安全**：

- **Critical / High 漏洞** → 48 小时内修复
- **Medium 漏洞** → 一周内修复
- **Low 漏洞** → 排期修复

### 10.3 依赖更新原则

🟡 **推荐**：

- **及时升级**：Spring / Hibernate / Jackson / Log4j 等关键库保持 minor / patch 更新
- 升级前看 CHANGELOG 和 GitHub Security Advisory
- 用 [Renovate](https://github.com/renovatebot/renovate) / Dependabot 自动 PR
