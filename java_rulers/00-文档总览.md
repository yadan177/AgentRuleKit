# 00 - Java AI 项目开发规则总览

> 🟢 本规则库适用于任何 AI 编程工具参与 Java 项目的开发、维护、审查、排障与文档修改。
>
> 🔴 不适用：替代项目事实、自动批准依赖或 JDK 升级、未经授权的架构迁移，以及伪造构建或测试结果。

---

## 1. 使用方式与范围

本规则库可用于 Codex、Cursor、Qoder、TRAE 及支持附加 Markdown 上下文的其他 AI 工具。每次 Java 任务先阅读 [14 - Java AI 通用入口规则](./14-AI通用入口规则.md)，再按任务读取下表中的少量专题规则。

- 🔴 以项目的构建文件、CI、实际依赖、模块边界和同模块既有实现为准；本规则库不要求升级 JDK、构建工具、框架、依赖或部署平台。
- 🔴 不确定包、API、配置键、数据库对象、测试命令或运行环境时，先查证已有实现；仍无法确认时向用户说明并询问。
- 🟡 推荐把本目录复制到目标项目的 `.ai-rules/java/`，并安装对应 AI 工具的 [薄适配器模板](./适配器模板/00-适配器使用说明.md)。
- 🟢 可选在一次性对话中只手动附加 14 号规则和本次任务相关专题规则。

## 2. 规则优先级与冲突处理

出现冲突时，按以下顺序决策：

1. AI 工具的安全限制与用户在当前任务中给出的明确要求。
2. 目标仓库的本地规则、构建脚本、CI、代码所有权和部署约束。
3. 已验证的项目事实：JDK/toolchain、构建工具、依赖、模块、框架、数据与运行环境。
4. 本规则库的通用入口和专题规则。
5. 通用经验或 AI 自身知识。

- 🔴 必须说明与项目既有规则冲突的依据；不能为了套用本规则而重写现有架构。
- 🔴 能力、契约或所有权不明确时，不得猜测默认技术；复用已有实现或询问用户。
- 🟡 长期架构取舍、依赖替换和协议变更推荐记录 ADR 或项目已有的设计决策记录。

## 3. 开发前能力探测

### 3.1 必查项目事实

| 检查项 | 证据位置 | 决定内容 |
|---|---|---|
| JDK 与语言能力 | `pom.xml`、`build.gradle(.kts)`、toolchain、`.java-version`、CI | 可使用的 Java 语法、JDK API、编译与运行参数 |
| 构建与测试 | `mvnw`、`gradlew`、`settings.gradle`、`.mvn/`、CI | 可执行的构建、格式检查、测试与打包命令 |
| 依赖与框架 | Maven/Gradle 依赖、BOM、版本目录、启动类和配置 | Spring、日志、ORM、测试、安全、消息与缓存能力 |
| 模块边界 | 多模块声明、包结构、模块描述符、同目录实现 | 可引用模块、依赖方向和公共 API 边界 |
| 数据与外部服务 | migration、DAO/Repository、客户端封装、接口契约 | SQL/ORM 写法、事务、重试、幂等与连接管理 |
| 运行与部署 | Dockerfile、K8s/Helm、配置模板、监控、CI | 容器、配置、健康检查、日志与发布验证 |

### 3.2 探测后的行动

- 🔴 只使用已安装且有项目证据支持的依赖、插件、框架和 API。
- 🔴 沿用当前模块的异常、并发、事务、日志、序列化、鉴权和配置模式，除非用户明确授权改造。
- ❌ 不得因为某项技术“更现代”就引入虚拟线程、记录类、Spring、JUnit、ORM、容器或云原生配置。
- ❌ 不得虚构配置键、环境变量、表/字段、接口契约、测试命令、镜像标签或 CI 步骤。

## 5. 跨语言与系统边界

| 工作内容 | 主要规则库 |
|---|---|
| Java 服务、任务、CLI 与运行运维 | 本目录 |
| Go 服务内部实现 | `go-rules/` |
| Web 前端、Node 服务与脚本 | `js_ts_rulers/` |
| Unity 客户端及其服务集成边界 | `unity_rulers/` |

- 🔴 Java 规则只约束 Java 项目内的实现和对外契约边界；前端、移动端、数据库运维及其他服务内部实现必须遵循其各自规则。
- 🔴 写入、支付、权限和安全关键行为以明确的服务契约和系统权威来源为准，不以客户端或文档示例替代。

## 6. 规则维护要求

### 6.1 新增或修订规则

- 🔴 每条强制规则写明适用条件、验证方式和例外；没有项目或官方证据的技术结论只能作为条件化建议。
- 🔴 规则示例必须标明依赖的 JDK、框架、构建工具或运行环境，不得伪装成所有项目可直接运行的代码。
- 🟡 推荐在修改专题文档时，同步修复该文件的标题编号、空章节、重复内容和失效交叉引用。
