# 12 - Java 安全规则

> 🟢 本文件适用于 Java 服务的认证、授权、输入、数据、文件、密钥、依赖和 API 安全边界。
>
> 🔴 不适用：把本文件当作法律意见、替代安全评审或自动批准身份与基础设施迁移。

---

## 1. 信任边界与授权

> **适用条件与验证**：先确认调用方、身份来源、权限模型、数据分类、接口契约和项目安全流程。

- 🔴 **必须**：不可信输入在服务端按现有策略校验、规范化、限量和授权；客户端字段、前端隐藏和内部网络位置不能作为权限证明。
- 🔴 **必须**：认证、授权、租户隔离、对象级权限和高风险操作遵循项目已有组件与策略；不得为局部功能新增或替换身份框架。
- 🟡 **推荐**：采用最小权限、拒绝优先和可审计的失败行为，并为权限变更补充正反向测试。

## 2. 数据、密钥与输出

> **适用条件与验证**：处理密码、令牌、个人数据、支付信息、日志、文件、序列化或缓存时适用。

- 🔴 **必须**：密钥仅通过项目批准的注入与轮换机制获取，不写入代码、测试夹具、镜像、日志或错误响应。
- 🔴 **必须**：数据收集、保存、传输、脱敏、加密、保留和删除遵循安全/隐私要求；输出不得泄漏内部异常、SQL、堆栈或敏感字段。
- 🔴 **必须**：文件、URL、表达式、序列化和数据库输入按现有防护链处理；不要通过黑名单、正则或客户端校验替代可信边界验证。

## 3. 依赖与交付供应链

> **适用条件与验证**：修改依赖、插件、镜像、构建或发布配置时适用。

- 🔴 **必须**：依赖来源、版本锁定、漏洞扫描、SBOM、许可证、秘密扫描和例外处理以组织既有流程为准；高风险漏洞、未知来源或校验失败不能静默忽略。
- 🔴 **必须**：不得为一次小改动关闭校验、绕过私有仓库、放宽安全门禁或自动合并依赖升级。
- 🟡 **推荐**：对无法立即修复的风险记录受影响范围、缓解措施、负责人流程和复核时间，避免编造风险已接受状态。

## 4. 验证与例外

- 🔴 **必须**：运行项目可用的安全/测试检查，复核授权、输入、日志、密钥和依赖影响；无法执行时说明风险。
- 🟡 **推荐**：安全、支付、权限、隐私和生产数据变更交由相应负责人复核。

> **例外**：应急处置按安全事件流程执行，变更、证据和恢复步骤必须可审计。
