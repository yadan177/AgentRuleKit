# 03 - Java 异常处理规则

> 🟢 本文件适用于 Java 的错误分类、异常转换、资源清理、事务失败和对外错误响应。
>
> 🔴 不适用：为了统一异常而替换框架、修改跨服务错误契约或隐藏业务失败。

---

## 1. 错误语义与边界

> **适用条件与验证**：先检查同模块异常层次、错误码、日志、API 契约、重试策略和调用方处理方式。

- 🔴 **必须**：保留可诊断的原因、上下文和可恢复性；在模块边界按当前契约转换异常，不能向调用方泄漏不应公开的实现、密钥或个人数据。
- 🔴 **必须**：区分输入/业务拒绝、暂时性外部失败、程序错误和取消/超时；不得捕获后静默返回默认值或把所有错误包装成同一种运行时异常。
- 🟡 **推荐**：为调用方可处理的失败提供稳定、可测试的错误语义；只在项目已有模型支持时使用 Result/错误码/领域异常。

## 2. 资源、异步与事务

> **适用条件与验证**：涉及可关闭资源、Future、线程池、数据库事务或框架事务管理时适用。

- 🔴 **必须**：资源、请求、任务和事务在成功、失败、超时和取消时都有关闭、取消或回滚路径；所有权与线程边界清晰。
- 🔴 **必须**：事务行为取决于当前框架、异常类型、代理边界和配置；只有项目已使用相应事务方案时才沿用其规则，不能从 Spring/JPA 示例推断默认回滚语义。
- 🟡 **推荐**：重试仅用于已知暂时性且具有幂等/去重保障的操作；记录重试次数、终止条件和用户可见的失败状态。

## 3. 对外错误与日志

> **适用条件与验证**：处理 HTTP/RPC/消息/CLI 的错误输出时适用。

- 🔴 **必须**：外部响应遵循已确认的状态码、错误码、序列化和安全策略；内部堆栈、SQL、令牌和敏感字段不得直接返回。
- 🟡 **推荐**：日志记录关联标识、操作和安全的上下文，避免在多个边界重复打印同一异常。

## 4. 验证与例外

- 🔴 **必须**：测试或复核成功、可预期失败、异常传播、资源清理、超时/取消及事务结果中与本次改动相关的路径。
- 🟡 **推荐**：交付时说明未覆盖的外部依赖、事务和重试风险。

> **例外**：跨服务错误契约或全局异常机制调整需要接口所有者和发布流程的明确批准。
