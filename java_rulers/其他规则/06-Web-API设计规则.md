# 06 - Java Web API 设计规则

> 🟢 本文件适用于 Java 服务的 HTTP、RPC、消息消费入口及其公开契约。
>
> 🔴 不适用：擅自改变协议、鉴权、网关、限流、序列化或 API 版本策略。

---

## 1. 契约与兼容性

> **适用条件与验证**：先检查接口定义、调用方、OpenAPI/IDL、错误码、认证、网关和版本兼容约定。

- 🔴 **必须**：请求、响应、字段、状态码/错误码、分页、排序、时间、幂等键和弃用行为以已确认契约为准；不得臆造路由、字段或默认值。
- 🔴 **必须**：公开变更评估调用方兼容性、灰度/发布顺序和回退；不能以单服务代码修改代替跨端协商。
- 🟡 **推荐**：将资源/操作语义、空结果和失败行为写清，并复用项目已有文档与版本机制。

## 2. 输入、授权与输出

> **适用条件与验证**：处理外部输入、身份、权限、文件、序列化或错误响应时适用。

- 🔴 **必须**：在可信边界按项目既有方式校验、规范化和限制输入；认证与授权由服务端权威策略决定，客户端字段和隐藏 UI 不能作为权限依据。
- 🔴 **必须**：输出遵循脱敏、最小化和错误暴露策略；不得返回堆栈、SQL、密钥、内部地址或未授权数据。
- 🟡 **推荐**：使用项目已接入的校验、序列化和文档框架；未安装时采用现有兼容写法或说明需要的授权。

## 3. 可靠性与外部调用

> **适用条件与验证**：接口执行写操作、远程调用、重试、限流、熔断、缓存或异步处理时适用。

- 🔴 **必须**：写操作的重试仅在幂等、去重或补偿已有保证时使用；定义超时、取消、失败映射和调用方可见结果。
- 🔴 **必须**：限流、熔断、缓存和队列沿用网关/框架/平台既有策略；不得为单个端点新建全局基础设施。
- 🟡 **推荐**：为关键契约补充集成、契约或调用方兼容验证，前提是项目已有安全的测试环境。

## 4. 验证与例外

- 🔴 **必须**：验证授权边界、输入失败、成功、幂等/重试、序列化、错误响应和受影响调用方。
- 🟡 **推荐**：交付时说明契约影响、未覆盖调用方和发布/回退风险。

> **例外**：协议、认证或 API 版本迁移需要接口所有者、消费者和发布流程的明确批准。
