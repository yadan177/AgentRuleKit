# 09 - Java 日志调试规则

> 🟢 本文件适用于 Java 日志、错误诊断、关联标识、脱敏与项目既有可观测性集成。
>
> 🔴 不适用：为单个需求替换日志实现、引入追踪平台或改变生产保留/采样策略。

---

## 1. 日志事实与边界

> **适用条件与验证**：先检查现有日志门面/实现、配置、级别、MDC/上下文传递、采样、告警、隐私和保留策略。

- 🔴 **必须**：使用项目现有日志 API、级别、字段和配置；SLF4J、Logback、Log4j2、框架拦截器、ELK/Loki 或 APM 仅在项目已采用时沿用。
- 🔴 **必须**：日志记录足以定位问题的安全上下文，但不得写入凭证、会话、完整个人数据、敏感业务载荷或绕过脱敏规则。
- 🟡 **推荐**：按事件严重度、用户影响和告警策略选择级别；不要把固定等级或某份风格指南当作所有服务的强制标准。

## 2. 关联、异常与调试

> **适用条件与验证**：请求链路、异步任务、批处理、消息消费或故障排查需要关联上下文时适用。

- 🔴 **必须**：上下文创建、传播、清理和线程池行为遵循现有实现；不得假定 MDC 或 trace ID 可自动跨线程/进程传递。
- 🔴 **必须**：异常在合适边界记录一次并保留安全的根因；对外错误与内部诊断分离，避免重复堆栈或静默吞错。
- 🟡 **推荐**：临时诊断日志限定范围、采样和删除计划；生产调试以现有指标、追踪和受控开关为准。

## 3. 验证与例外

- 🔴 **必须**：验证日志格式、字段、脱敏、错误路径、异步上下文和采集链路中受影响部分；不能把本地控制台输出当作生产采集成功。
- 🟡 **推荐**：交付时说明实际验证、采样/成本/隐私风险和未覆盖的链路。

> **例外**：安全事件、审计与事故响应可遵循更严格的日志和留存策略，但应以项目安全流程为准。
