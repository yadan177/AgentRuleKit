# 08 - Java 测试规则

> 🟢 本文件适用于 Java 的单元、集成、契约、端到端、性能和回归测试任务。
>
> 🔴 不适用：为了补测试而升级测试框架、修改 CI 门槛、连接生产系统或伪造测试结果。

---

## 1. 测试事实与范围

> **适用条件与验证**：先检查构建脚本、已有测试框架、fixtures、容器/数据库、Mock 约定、CI 和受影响风险。

- 🔴 **必须**：只使用项目已安装且当前模块已验证的测试库、注解、扩展和命令；不能把 JUnit、Mockito、AssertJ 或测试容器示例当作通用前提。
- 🔴 **必须**：测试可观察行为、明确输入和预期；不得以 mock 细节、覆盖率数字或偶然实现顺序替代业务契约验证。
- 🟡 **推荐**：按风险选择单元、集成、契约或端到端层级，并让测试名称说明场景与期望。

## 2. 隔离、数据与并发

> **适用条件与验证**：测试访问时间、线程、网络、文件、数据库、消息或外部服务时适用。

- 🔴 **必须**：测试数据、环境变量、端口、时钟和外部依赖可控、可清理且不接触生产；资源、事务、容器和线程在失败时也能回收。
- 🔴 **必须**：异步和并发测试使用项目认可的等待、超时和确定性机制；不得以任意 `sleep` 掩盖竞争或不稳定。
- 🟡 **推荐**：对公开契约、迁移、安全、幂等、取消和关键异常路径补充相应覆盖，前提是项目具备安全验证环境。

## 3. 质量门禁与交付

> **适用条件与验证**：项目已有覆盖率、突变测试、静态分析或 CI 门禁时适用。

- 🔴 **必须**：沿用项目门禁、失败策略和测试分层；不得通过跳过、放宽阈值或标记忽略来隐藏回归，除非获得明确授权并记录原因。
- 🟡 **推荐**：报告实际执行的测试、未执行的环境测试和剩余风险；失败时提供可复现证据而非猜测结论。

> **例外**：测试框架迁移、覆盖率目标变更和共享测试基础设施调整需作为独立任务评审。
