# 13 - Java 部署运维规则

> 🟢 本文件适用于 Java 服务的构建制品、配置、容器、发布、健康检查、观测与运行维护。
>
> 🔴 不适用：未授权的基础镜像、容器平台、配置中心、CI/CD 或监控体系迁移。

---

## 1. 运行环境事实

> **适用条件与验证**：先检查构建脚本、运行 JDK、镜像、部署描述、配置注入、平台限制、健康检查和当前发布流程。

- 🔴 **必须**：构建命令、制品路径、端口、启动参数、镜像、资源限制和环境变量以仓库与目标环境为准；不得从示例臆造 Docker、Kubernetes、Spring Boot 或云平台配置。
- 🔴 **必须**：配置、凭证和运行时差异遵循项目的安全注入和审计机制，不能写入制品、日志或版本库。
- 🟡 **推荐**：保持构建和运行环境可追溯，优先复用 Wrapper、CI 模板和已验证基础镜像。

## 2. 可用性、发布与回退

> **适用条件与验证**：任务影响服务启动、健康检查、流量、数据库迁移、后台任务或发布流程时适用。

- 🔴 **必须**：启动、就绪、存活、优雅停止、超时、资源限制和失败恢复遵循当前平台语义；不能复制别的编排平台探针配置。
- 🔴 **必须**：发布顺序、迁移兼容性、灰度、审批和回退由项目流程决定；未经授权不得部署、变更流量、执行生产操作或伪造发布成功。
- 🟡 **推荐**：为变更说明受影响服务、配置、迁移、健康指标、观察窗口和回退条件。

## 3. 观测与运维

> **适用条件与验证**：项目已接入日志、指标、追踪、告警、SLO 或运维平台时适用。

- 🔴 **必须**：指标、标签、采样、告警、日志、追踪和数据保留沿用现有平台约定，并满足隐私与成本限制。
- 🟡 **推荐**：验证部署后关键健康、错误率、延迟、资源和业务信号；无法执行时列出需要运行团队复核的项目。

## 4. 验证与例外

- 🔴 **必须**：执行项目允许的构建、配置校验、部署前检查或测试；明确未执行的环境验证及风险。
- 🟡 **推荐**：交付时提供改动范围、验证证据、回退前提和需要权限方执行的步骤。

> **例外**：生产应急处置遵从既有变更和事故流程，并保留授权与操作记录。
