# 01 - Java 代码编写规则

> 🟢 本文件适用于 Java 业务类、公共 API、集合、I/O、数据模型和基础逻辑的实现或审查。
>
> 🔴 不适用：未经授权的 JDK/依赖升级、跨模块重构或框架迁移。

---

## 1. 开始前确认

> **适用条件与验证**：先检查 JDK/toolchain、构建文件、模块边界、静态检查配置、同包实现和公共调用方。

- 🔴 **必须**：只使用项目已支持的 Java 语法、JDK API、注解和依赖；不能把规则示例、较新 JDK 能力或其他模块的库当作当前事实。
- 🔴 **必须**：修改公开类、方法、序列化模型、配置键或异常语义前检查调用方、反射/生成代码和兼容性要求。
- 🟡 **推荐**：沿用同模块的命名、可空性、结果/异常、日志和参数校验约定。

## 2. 数据、集合与资源

> **适用条件与验证**：处理输入、集合、数值、字符串、文件、流、连接或可关闭资源时适用。

- 🔴 **必须**：在边界验证不可信输入；包装类型、集合、Map、数组、Optional 和 `null` 的语义以现有接口约定为准，不能仅凭风格替换。
- 🔴 **必须**：资源由取得者或已定义的所有者关闭；使用项目现有的 try-with-resources、客户端封装或生命周期机制，并处理关闭/读取错误。
- 🔴 **必须**：金额、时间、字符集、排序、分页和精度沿用领域模型与已有 API；不得用演示常量或隐式默认值改变业务含义。
- 🟡 **推荐**：集合、Stream、循环和并发容器按可读性、异常语义和测量结果选择；避免为“函数式”或“简洁”引入难以调试的链式逻辑。

## 3. 控制流、状态与错误

> **适用条件与验证**：新增分支、重试、缓存、状态更新或外部调用时适用。

- 🔴 **必须**：失败、空结果、超时、取消、重复调用和部分完成状态有明确处理；不得吞掉异常、以 `null` 掩盖失败或在 setter/回调中隐式执行外部副作用。
- 🔴 **必须**：可变共享状态必须符合当前模块的并发模型；不能以 `final`、不可变包装或复制作为未验证的线程安全证明。
- 🟡 **推荐**：用清晰的卫语句、局部变量和小方法表达业务分支；复杂流程优先补测试而不是堆叠注释。

## 4. 注释、风格与生成物

> **适用条件与验证**：项目已有 formatter、linter、代码生成器、注释规范或 API 文档工具时适用。

- 🔴 **必须**：格式、import、命名、注释和生成文件遵从仓库配置；不要为单文件需求执行全仓格式化、改写生成物来源或重命名公共符号。
- 🟡 **推荐**：注释解释非显然的约束、原因和外部契约，不复述代码；公开行为变更同步更新项目要求的文档。

## 5. 验证与例外

- 🔴 **必须**：运行仓库可用且与改动相关的编译、静态检查和测试；无法运行时说明原因、未验证范围和风险。
- 🟡 **推荐**：交付时注明兼容性假设、受影响调用方和未覆盖的异常/并发路径。

> **例外**：公共 API、数据模型或模块边界的演进须经明确授权，并使用项目的兼容发布与回退流程。
