# 07 - Java 数据访问规则

> 🟢 本文件适用于 Java 服务的 SQL、ORM、事务、连接、迁移、缓存与数据性能修改。
>
> 🔴 不适用：未经授权修改生产数据、替换数据库/ORM/迁移工具或绕过发布流程。

---

## 1. 数据事实与迁移

> **适用条件与验证**：先检查 schema、migration、数据访问层、事务配置、连接池、数据保留和发布流程。

- 🔴 **必须**：表、字段、索引、约束、迁移命名、权限和数据分类以仓库与目标环境证据为准；不得凭规则示例生成 SQL 或直接操作生产数据。
- 🔴 **必须**：结构或数据变更进入项目既有的可审查迁移流程，并评估兼容部署、锁表、数据量、备份、回滚和观测影响。
- 🟡 **推荐**：采用项目认可的兼容演进方式；对大表、回填、删除和索引操作先在安全环境评估执行时间与资源影响。

## 2. 查询、ORM 与事务

> **适用条件与验证**：项目已使用 SQL、JDBC、MyBatis、JPA/Hibernate、查询生成器或其他数据访问方案时适用。

- 🔴 **必须**：沿用当前参数绑定、映射、事务、分页、连接和关闭方式；不能因示例引入 ORM、查询框架或连接池。
- 🔴 **必须**：事务内只保留必要的数据工作；远程调用、消息发送、长等待和不可逆副作用必须按当前一致性/补偿设计处理。
- 🔴 **必须**：查询参数化并受权限、范围和资源限制约束；不得拼接不可信输入、忽略行数/分页上限或泄漏敏感字段。
- 🟡 **推荐**：以真实查询计划、慢查询、指标和数据规模决定索引、批量、缓存或分片策略。

## 3. 一致性、缓存与错误

> **适用条件与验证**：读写缓存、异步复制、重试、去重或跨服务数据同步时适用。

- 🔴 **必须**：明确权威数据源、失效、并发写入、重试幂等、部分失败和恢复方式；缓存不能成为权限或账务的唯一真相。
- 🟡 **推荐**：沿用项目已有缓存/消息/同步机制，并记录用户可见的一致性延迟和失败行为。

## 4. 验证与例外

- 🔴 **必须**：在允许环境验证迁移、事务、权限、错误、查询结果和性能影响；无法运行时说明范围和风险。
- 🟡 **推荐**：交付时列出 schema 影响、回退限制、数据修复和发布依赖。

> **例外**：数据库引擎、ORM、分库分表或迁移工具更换属于独立基础设施变更，需专项评审与演练。
