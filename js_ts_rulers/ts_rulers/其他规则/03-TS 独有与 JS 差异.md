# 03 - TypeScript 与 JavaScript 互操作规则

> 🟢 本文件适用于 JS 到 TS 的渐进维护、模块互操作、类型擦除、装饰器和构建/运行时一致性问题。
>
> 🔴 不适用：未经授权将 JS 项目迁移为 TS、切换 CommonJS/ESM、启用装饰器或改变 emit、模块解析和发布产物。

---

## 1. 类型擦除与运行时事实

> **适用条件与验证**：检查当前构建器、模块格式、tsconfig、运行时、测试、发布产物和 JavaScript 调用方。

🔴 **必须**：TypeScript 的 interface、type、泛型和大多数类型修饰不会在运行时存在；不得把类型声明当作输入校验、反射、权限控制或序列化规则。需要运行时行为时，使用项目已有的值、schema 或元数据方案。

## 2. JS/TS 渐进维护

> **适用条件与验证**：是否允许 `allowJs`、JSDoc、声明文件、逐文件迁移和混合模块以仓库配置与发布策略为准。

🔴 **必须**：不得为单个文件改变整个项目的模块格式、编译目标、严格度或路径解析。JS 调用方、生成代码和发布文件仍需与新增 TS 类型/实现兼容。

🟡 **推荐**：渐进迁移时先在清晰边界补类型与运行时测试；优先维护可调用性和行为一致性，不追求一次性消除所有 JS 写法。

## 3. 模块、装饰器与 emit

> **适用条件与验证**：导入形式、`import type`、装饰器、enum、namespace、路径别名和 declaration emit 只有在当前 TypeScript、构建器和运行时均支持时适用。

🔴 **必须**：不得假定类型路径别名、装饰器或声明合并会自动在测试/运行时生效；相关变更必须沿构建、测试和发布链路验证。

## 4. AI 完成检查

- [ ] 没有未经授权的模块、emit、装饰器或项目级迁移。
- [ ] JS 调用方、测试和发布产物与改动兼容。
- [ ] 已说明构建/运行时未验证边界。
