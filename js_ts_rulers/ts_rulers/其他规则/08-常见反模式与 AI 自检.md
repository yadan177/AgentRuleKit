# 08 - TypeScript 专项反模式自检

> 🟢 本文件适用于 TypeScript 类型边界和编译/运行时一致性的补充自检，应与 [JS/TS AI 交付前自检](../../02-AI交付前自检.md) 一起使用。
>
> 🔴 不适用：用类型断言、工具链迁移或关闭检查掩盖设计、输入或运行时问题。

---

## 1. TypeScript 类型补充

- [ ] 不可信输入未通过 `any`、双重断言或非空断言直接进入业务类型。
- [ ] 高级类型、泛型、enum、装饰器、声明合并和路径别名都有当前项目支持与真实调用方依据。
- [ ] `tsconfig`、模块解析、构建、测试和发布产物对本次变更保持一致。
- [ ] 类型通过不被当作 API、权限、序列化或运行时校验已通过的证明。

## 2. 使用边界

🔴 **必须**：发现类型错误时优先修复真实契约、收窄或运行时校验；不得无授权改变 TypeScript 版本、strict 选项、lint 规则或使用宽泛断言。

🟡 **推荐**：需要进一步判断时，分别查阅 TS 01（类型系统）、TS 02（收窄）、TS 03（互操作）和 TS 04（高级类型）专题。
