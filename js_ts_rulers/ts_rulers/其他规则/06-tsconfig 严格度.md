# 06 - TypeScript tsconfig 规则

> 🟢 本文件适用于项目已有 TypeScript 编译配置、项目引用、模块解析和严格度选项的维护。
>
> 🔴 不适用：未经授权升级 TypeScript、切换模块解析/构建器、全仓开启严格选项或修改发布目标。

---

## 1. 配置前能力探测

> **适用条件与验证**：检查所有 `tsconfig*.json`、extends 链、实际 TypeScript 版本、构建器、测试配置、生成代码、浏览器/Node 目标和 CI typecheck 命令。

🔴 **必须**：不得把某个 `target`、`module`、`moduleResolution`、`strict` 子选项、路径别名或 `noEmit` 设为所有项目的默认答案。修改配置前必须确认运行时、构建器和下游工具支持。

## 2. 严格度与渐进迁移

> **适用条件与验证**：严格度取决于存量错误、公开 API、迁移成本、构建时长和项目维护策略。

🔴 **必须**：不得为消除错误而全局关闭类型检查、滥用 `skipLibCheck`、加入宽泛 include/exclude 或批量插入断言。不得把 `strict` 或任一子选项的开启/关闭伪装为无风险改动。

🟡 **推荐**：新配置或明确授权的迁移可分阶段进行；每阶段限定范围，修复可见问题并在相关构建、测试和运行时验证。

## 3. 路径、项目引用与模块解析

🔴 **必须**：`paths`、别名、项目引用和声明输出不是纯类型配置，运行时/打包器/测试也必须使用一致解析策略。不得仅改 tsconfig 就声称别名可运行。

🟡 **推荐**：沿用仓库已有的多 tsconfig 分层与构建脚本；发现 IDE 与 CI 使用不同配置时，明确报告差异。

## 4. AI 完成检查

- [ ] 已识别 TypeScript 版本、extends 链、构建器、目标环境和 typecheck 脚本。
- [ ] 没有未经授权的版本、模块解析、严格度、别名或输出迁移。
- [ ] 已说明 typecheck、构建和运行时验证结果及未验证项。
- [ ] 已记录可能影响 IDE、测试、发布和下游调用方的风险。
