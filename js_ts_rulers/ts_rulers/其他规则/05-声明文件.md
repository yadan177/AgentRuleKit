# 05 - TypeScript 声明文件规则

> 🟢 本文件适用于项目已有或明确需要维护的 `.d.ts`、类型包、全局声明和第三方模块声明。
>
> 🔴 不适用：未经授权为任意依赖补类型、覆盖真实运行时行为，或发布未验证的公共类型声明。

---

## 1. 声明前确认来源

> **适用条件与验证**：先检查依赖本身是否带类型、项目已有声明目录、`types`/`typeRoots`、模块解析、生成代码、运行时 API 和调用点。

🔴 **必须**：不得凭名称猜测模块导出、全局变量、环境变量、函数参数或返回值；不得用宽泛 `any` 声明掩盖未知契约。类型必须与实际运行时、目标版本和调用方证据一致。

## 2. 模块与全局边界

> **适用条件与验证**：模块增强、全局声明、JS 库声明和发布入口以当前构建与模块格式为准。

🔴 **必须**：全局声明只在项目确实需要且有命名空间/冲突评估时使用；模块声明应最小化范围，不得覆盖第三方包已有类型或污染无关项目。

🟡 **推荐**：优先使用依赖官方类型或项目已批准的类型来源；若维护本地 shim，记录其运行时依据、缺口和移除条件。

## 3. 验证与发布

🔴 **必须**：声明变更须通过项目现有 typecheck、相关调用方和（可用时）运行时/集成验证；不能只因类型能编译就认定运行时兼容。

🟡 **推荐**：对公开类型保持向后兼容意识；类型包、补丁或生成流程变更应在发布流程中单独审查。

## 4. AI 完成检查

- [ ] 已确认类型来源、模块解析、运行时 API 与实际调用点。
- [ ] 未新增猜测的全局、模块或 `any` 逃生声明。
- [ ] 已执行相关 typecheck/调用方验证，或说明未验证项。
- [ ] 已记录声明与运行时不完全一致时的风险和后续动作。
