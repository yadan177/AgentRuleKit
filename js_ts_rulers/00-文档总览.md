# 00 - JavaScript 与 TypeScript AI 项目开发规则总览

> 🟢 本文件适用于任何 AI 在 JavaScript、TypeScript、浏览器、Node.js、前端框架或全栈项目中进行开发、审查、排障与规则维护。
>
> 🔴 不适用：替代项目事实、自动批准依赖或运行时升级、未经授权迁移框架、构建工具、状态管理、样式体系或测试体系。

---

## 1. 使用方式与优先级

开始任务先阅读 [01 - JS/TS AI 通用入口规则](./01-AI通用入口规则.md)，再按任务读取 `js_rulers/` 与（仅 TS 项目需要的）`ts_rulers/` 中的专题规则；交付前使用 [02 - JS/TS AI 交付前自检](./02-AI交付前自检.md)。

1. 用户当前任务、法律/安全要求和工具安全限制。
2. 目标仓库中的 `AGENTS.md`、贡献指南、`package.json`、锁文件、配置、代码与部署事实。
3. 本规则库的 01 号通用入口规则。
4. 当前任务直接相关的 JS/TS 专题规则。

🔴 项目代码、配置、接口或运行环境与规则示例不一致时，不得猜测；优先复用项目既有实现，无法安全判断时说明问题并询问用户。

## 2. 开发前能力探测

### 2.1 必查证据

| 领域 | 优先检查的证据 |
|---|---|
| 运行时与包管理 | `package.json`、锁文件、`packageManager`、`engines`、工作区配置与实际脚本 |
| 语言与构建 | `jsconfig.json`、`tsconfig*.json`、构建工具、模块格式、浏览器/Node 目标与环境变量 |
| 框架与架构 | 路由、组件、状态、样式、请求封装、同目录既有实现与生成代码 |
| 质量与交付 | ESLint/格式化、测试、CI、容器、部署、错误上报与可观测性配置 |
| 安全与数据 | API 契约、认证、密钥注入、存储、CSP、依赖审计与隐私要求 |

### 2.2 探测后的行动

- 仅 JS：以 `js_rulers/` 的基础与专项规则为准。
- 使用 TypeScript：在 JS 基线之上按需读取 `ts_rulers/` 的类型、声明、tsconfig 与工具链规则。
- 已有同类实现：复用其框架、错误、异步、样式、测试与资源生命周期约定。
- 缺少证据：不新增框架、依赖、配置或脚本；采用最小兼容改动，或询问用户。

## 4. 跨端与跨语言边界

- JS/TS 规则负责浏览器、Node.js、BFF 与前端工程内的实现；服务端业务规则分别由 Go、Java 等规则库维护。
- 客户端不替代服务端的认证、授权、限流、审计和数据校验；跨端契约、错误码、幂等和数据归属以已确认的接口为准。
- 框架、状态管理、样式、测试、打包和部署是项目选择，不是本规则库的全局前提。
- 日志、错误上报、产品分析与诊断数据都受隐私、同意、采样和保留策略约束；以项目已有平台与安全要求为准。
