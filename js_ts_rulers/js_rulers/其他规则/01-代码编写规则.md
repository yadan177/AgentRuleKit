# 01 - JavaScript 代码编写规则

> 🟢 本文件适用于项目中现有的 JavaScript/TypeScript 运行时代码、模块、错误处理与资源生命周期。
>
> 🔴 不适用：未经授权重命名公开 API、迁移模块格式、引入类型系统、批量格式化或重构包边界。

---

## 1. 项目事实与模块边界

> **适用条件与验证**：先检查运行时目标、模块格式、目录、路径别名、导出方式、框架约定、生成代码和同目录实现。

🔴 **必须**：沿用现有模块解析、导出与目录约定；不得从规则示例假定路径别名、默认/具名导出、私有字段、循环依赖检查工具或编译能力可用。公开导出、路由、序列化字段和生成物引用变更须考虑调用方兼容性。

🟡 **推荐**：模块按单一清晰职责组织；名称在同一目录保持领域一致、可搜索且不与运行时/框架约定冲突。出现循环依赖、过大模块或不清晰边界时，先用仓库已有工具或 import 图确认，再决定是否拆分。

## 2. 值、输入与错误

> **适用条件与验证**：空值、默认值、数据结构、错误对象、日志和对外返回格式以当前项目及调用方契约为准。

🔴 **必须**：外部输入、可选字段和异步结果不能依赖隐式转换或未声明的非空假设；不得吞掉异常、Promise rejection 或清理错误。错误应保留项目需要的上下文，且不得泄露密钥、内部地址或敏感数据。

🟡 **推荐**：使用清晰的比较与空值语义，局部不可变更新只在当前状态模型要求时采用；不要为了语言偏好把全部对象、类或函数式代码重写为另一种风格。

## 3. 异步与资源生命周期

> **适用条件与验证**：事件监听器、timer、订阅、请求、流、WebSocket、AbortController 与框架生命周期以项目已有模式和目标运行时为准。

🔴 **必须**：创建监听器、订阅、timer、请求或资源句柄时明确所有者、结束条件和清理路径；避免无边界并发、未处理 rejection、跨请求共享可变状态或卸载后更新 UI。

🟡 **推荐**：有取消需求且当前 API 支持时，沿用项目的取消/清理方式；不能为一次局部需求新增全局错误处理或取消库。

## 4. DOM、浏览器与 Node 边界

> **适用条件与验证**：只有当前代码实际运行在浏览器、Node.js、worker 或混合环境时才使用对应 API；检查 SSR、测试环境和目标兼容范围。

🔴 **必须**：不可信内容不能直接进入 HTML、URL、样式或脚本 sink；浏览器专有 API 不能在服务端/测试环境中无条件调用。Node 文件、进程和网络资源按项目既有关闭与错误处理方式管理。

## 5. 验证与交付

- [ ] 已确认模块、运行时、导出、数据与相邻代码约定。
- [ ] 没有未处理异步错误、无主资源或未经授权的架构变更。
- [ ] 修改的公开行为、DOM/运行时边界和错误路径有相称验证。
- [ ] 已说明执行的检查、未验证项和兼容性风险。

> **例外**：模块迁移、公开 API 重命名和运行时兼容目标调整必须作为独立授权任务执行。
