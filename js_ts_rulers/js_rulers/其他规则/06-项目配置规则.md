# 06 - JavaScript 项目配置规则

> 🟢 本文件适用于 JavaScript/TypeScript 项目的依赖、scripts、构建、环境变量、CI 与部署配置修改。
>
> 🔴 不适用：未经授权的运行时升级、包管理器切换、框架/构建器迁移、目录重构或部署架构变更。

---

## 1. 修改前能力探测

> **适用条件与验证**：先检查 `package.json`、锁文件、workspace、`packageManager`、`engines`、scripts、构建配置、环境变量示例、CI、容器与同类应用。以当前仓库和目标环境为准。

🔴 **必须**：不得从规则样例推导运行时、包管理器、构建器、框架、脚本、端口、环境变量、镜像或部署目标。不得为单个功能升级依赖、添加脚本或替换配置文件。

## 2. 依赖与脚本

> **适用条件与验证**：包管理器与锁文件由仓库决定；同一项目不得混用或重建锁文件，除非用户明确授权。

🔴 **必须**：新增、升级、删除依赖或修改 scripts 前，确认其用途、许可、安全、兼容性和现有调用点。不得使用浮动“最新”版本或批量更新作为默认操作。

🟡 **推荐**：优先调用仓库已有 scripts；若 scripts 缺失，报告可执行的最小验证方式，而不是复制某个工具的模板。

## 3. 构建、模块与环境变量

> **适用条件与验证**：模块格式、入口、别名、目标浏览器/Node、代码分割、资产、环境变量前缀和注入方式以现有构建器与部署平台为准。

🔴 **必须**：不得假定所有项目使用 Vite、Webpack、Next、Babel、ESM 或 CommonJS；不得修改模块解析、浏览器兼容目标、别名或环境变量暴露边界而不验证构建和运行时。

🔴 **必须**：密钥、token、私有地址和生产数据不能写进前端代码、构建参数、`.env` 样例、日志或测试。前端可见环境变量不是秘密。

## 4. lint、格式化与 CI

> **适用条件与验证**：检查已有 ESLint、Prettier、Biome、EditorConfig、hook、CI 和脚本；版本和配置以锁文件或仓库配置为准。

🔴 **必须**：不得为一次业务变更新增/替换 lint 或格式化工具、修改阈值、安装浮动版本，或批量格式化无关文件。不得声称未执行的 CI、lint、构建或测试已通过。

🟡 **推荐**：项目已有质量门禁时保持其可用；仅对本次相关范围执行验证。

## 5. 容器与发布

> **适用条件与验证**：仅在已有容器、静态托管或发布流水线，或用户明确要求时适用。基础镜像、运行用户、Node 版本、缓存与制品策略以当前交付环境为准。

🔴 **必须**：不得无授权替换基础镜像、推送制品、修改发布凭证或把构建期变量误暴露到客户端。

## 6. AI 完成检查

- [ ] 已识别实际包管理器、锁文件、scripts、构建器和部署边界。
- [ ] 没有未经授权的依赖、运行时、框架、构建或 CI 迁移。
- [ ] 敏感信息没有进入源码、前端环境变量、日志或制品。
- [ ] 已说明执行的验证、未验证项和兼容性/发布风险。

> **例外**：新项目脚手架、依赖升级、构建迁移与发布策略调整需用户明确授权，并拆为可验证变更。
