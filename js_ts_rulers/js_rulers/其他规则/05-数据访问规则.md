# 05 - JavaScript 数据访问与同步规则

> 🟢 本文件适用于项目已有的 HTTP/RPC 客户端、缓存、Cookie、浏览器存储、离线数据和跨标签页同步。
>
> 🔴 不适用：未经授权新增请求库、缓存库、浏览器数据库、Service Worker、跨标签页机制或自行改变服务端 API/认证契约。

---

## 1. 契约与不可信数据

> **适用条件与验证**：API 契约、错误格式、认证、序列化、缓存、schema、运行时校验和数据保留策略以当前项目和服务端约定为准。

🔴 **必须**：网络响应、存储恢复值、URL 参数和跨窗口消息均视为不可信输入；TypeScript 类型不能替代运行时校验。不得臆造端点、字段、错误码、权限、过期时间或重试策略。

## 2. 请求、错误与同步

> **适用条件与验证**：请求封装、cookie/credential、超时、取消、重试、缓存和刷新策略沿用项目已有客户端与服务端语义。

🔴 **必须**：读取与写入操作的错误、取消、超时和缓存失效行为必须与调用方契约一致。写操作重试须具有幂等键、去重或等价保护；不得用固定超时/重试次数覆盖项目策略。

🟡 **推荐**：统一在现有请求边界处理认证、错误映射和可观测性；缓存、预取和离线策略须说明新鲜度、失效、权限和用户可见状态。

## 3. 浏览器存储与认证

> **适用条件与验证**：cookie、session、token、localStorage、sessionStorage、IndexedDB 和 Cache API 的选择由当前认证、隐私、浏览器配额、离线需求和数据敏感性决定。

🔴 **必须**：客户端不替代服务端授权；不得把密钥、长期高权限凭证或敏感数据存入不合适的浏览器存储。`HttpOnly` 只能防止脚本读取 Cookie，不能消除 XSS 或 CSRF 风险；cookie 属性、CORS 与 CSRF 防护遵循服务端既有方案。

🟡 **推荐**：存储容量和可用性因浏览器、用户设置和设备而异，应在目标环境验证；大量/离线数据仅在已有浏览器数据库或缓存方案中按其配额、迁移和清理策略处理。

## 4. AI 完成检查

- [ ] 已确认 API 契约、请求封装、认证、缓存与存储边界。
- [ ] 外部数据有运行时校验或项目已有等价保障。
- [ ] 写操作的重试/离线/同步语义不破坏幂等与数据一致性。
- [ ] 未新增未经授权的数据层、存储机制或敏感数据暴露。
