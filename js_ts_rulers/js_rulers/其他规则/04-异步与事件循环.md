# 04 - JavaScript 异步与事件循环规则

> 🟢 本文件适用于 Promise、`async`/`await`、事件、请求、timer、流和当前框架的异步生命周期。
>
> 🔴 不适用：未经授权引入 Promise 库、取消库、队列库、polyfill 或替换全局错误处理。

---

## 1. Promise 与错误传播

> **适用条件与验证**：异步 API、错误模型、事件循环、浏览器/Node 兼容范围和测试方式以项目现有实现为准。

🔴 **必须**：Promise 必须有明确的成功、失败和结束语义；不得遗留未处理 rejection、吞掉错误或混合回调/Promise 造成重复完成。并发任务的失败策略、结果顺序和部分成功语义必须符合调用方契约。

## 2. 取消、超时与重试

> **适用条件与验证**：仅当当前 API、运行时和项目请求层支持取消、超时或重试时适用；不同操作的时限与重试策略由业务、网络和服务端契约决定。

🔴 **必须**：不得将固定超时或重试次数写成通用默认；写操作重试前必须确认幂等、去重或服务端保护。取消后不得把预期取消误报为业务/系统故障。

🟡 **推荐**：用户可中断、路由切换会废弃或资源昂贵的任务，可沿用当前项目的 AbortSignal 或等价机制；无法取消时仍需避免陈旧结果覆盖最新状态。

## 3. 生命周期与并发控制

> **适用条件与验证**：组件卸载、路由切换、进程关闭、订阅、timer、队列与并发限制以框架和运行时已有模式为准。

🔴 **必须**：监听器、timer、订阅、流和请求拥有清理路径；不得在循环、渲染或重试中无限创建任务。并发限制只在有服务端限制、资源压力或测量证据时采用。

- [ ] 所有资源有对应清理/关闭路径。
- [ ] 已用现有测试或可复现步骤验证主要成功、失败和取消路径。
