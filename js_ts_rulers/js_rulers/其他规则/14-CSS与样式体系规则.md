# 14 - CSS 与样式体系规则

> 🟢 本文件适用于项目已使用的 CSS、CSS Modules、CSS-in-JS、Utility CSS、设计令牌或组件样式系统。
>
> 🔴 不适用：未经授权在样式体系间迁移、全量重命名 class、引入新的 CSS 框架或改变全局主题结构。

---

## 1. 样式体系与作用域

> **适用条件与验证**：先检查现有样式入口、命名、主题、token、reset、组件库、响应式与暗色模式方案。

🔴 **必须**：沿用当前样式体系和作用域边界；不得因局部需求把 CSS Modules、Tailwind、CSS-in-JS、全局 CSS 或组件库互相混用或替换。

🟡 **推荐**：复用项目已有 token、间距、颜色、字体、断点和组件变体；局部样式优先局部作用域，新增全局样式要评估级联影响。

## 2. 可维护性与可访问性

🔴 **必须**：不得依赖 `!important`、过高特异性或不稳定 DOM 层级来覆盖样式，除非项目已有受控例外且说明原因。颜色、焦点、对比度、缩放、动效和响应式行为须满足项目的可访问性要求。

🟡 **推荐**：使用语义 class/组件状态，不把布局、主题和业务状态耦合到不可读的临时选择器；动画遵循用户减少动态效果偏好（若项目已支持）。

## 3. 验证

> **适用条件与验证**：目标浏览器、设备、视觉回归和设计评审流程以项目现有支持范围为准。

🔴 **必须**：不得只在单一尺寸或本机主题下声称 UI 已验证；修改布局、颜色、交互或主题时应使用项目已有的浏览器/视觉验证，或明确未覆盖范围。

## 4. AI 完成检查

- [ ] 已识别现有样式体系、token、主题和作用域边界。
- [ ] 未引入未经授权的样式框架、全局覆盖或体系迁移。
- [ ] 新样式考虑了响应式、焦点、对比度和项目既有 UI 状态。
- [ ] 已说明视觉验证、未验证设备/主题和剩余风险。
