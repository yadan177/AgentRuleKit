# 02 - JavaScript 模式设计规则

> 🟢 本文件适用于 JavaScript 项目的模块组织与设计模式选型。

> 🔴 不适用：业务逻辑实现、具体 API 端点设计、UI 样式细节

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 模块组织（职责单一 / 公开 API 收敛）

**单一职责**：一个文件只做一件事。

```js
// ❌ 一个文件干所有事
// user.js 里塞：API 调用、状态管理、表单校验、UI 渲染

// ✅ 拆开
// user.api.js    - 网络请求
// user.store.js  - 状态
// user.schema.js - 校验
// UserCard.jsx   - UI
```

**barrel exports（`index.js` 重导出）禁用**——见 [01 §7](./01-代码编写规则.md)。

**顶层副作用禁止**：

```js
// ❌ 模块加载就执行
// analytics.js
window.dataLayer = [];

fetch('/api/init').then(...);  // 模块加载就发请求

// ✅ 导出函数，让调用方决定何时执行
export function initAnalytics() { /* ... */ }
```

### 1.2 错误传播（throw vs return / 全局兜底）

**统一 `throw`，不要 `return null` / `return false`**。

```js
// ❌ 返回值暗示失败，调用方难处理
function getUser(id) {
  if (!exists) return null;
  return user;
}
const user = getUser(1);
if (!user) { /* 这里忘了判断就 NPE */ }

// ✅ 抛错
function getUser(id) {
  if (!exists) throw new Error(`User ${id} not found`);
  return user;
}
try {
  const user = getUser(1);
} catch (e) {
  /* 强制处理 */
}
```

**全局 `unhandledrejection` 兜底**（必加）：

```js
window.addEventListener('unhandledrejection', (e) => {
  logger.error('Unhandled rejection', e.reason);
  e.preventDefault();            // 阻止默认控制台报错
});
```

**自定义错误类**携带业务信息：

```js
class BusinessError extends Error {
  constructor(code, message, data) {
    super(message);
    this.name = 'BusinessError';
    this.code = code;
    this.data = data;
  }
}
throw new BusinessError('USER_NOT_FOUND', '用户不存在', { userId: 1 });
```

### 1.3 Promise / async 模式

**全部 `await` + `try/catch`**，不要混用 `.then().catch()`。

```js
// ✅
try {
  const user = await fetchUser(1);
  return user;
} catch (e) {
  logger.error(e);
  throw e;
}

// ❌ 混用
fetchUser(1)
  .then(user => process(user))
  .catch(e => console.log(e));    // 不重抛 + console.log 丢失栈
```

**不要 `return await`**（保留栈 + 减少冗余）：

```js
// ✅
async function getUser(id) {
  try {
    return await fetchUser(id);  // await 让外层 catch 能捕获
  } catch (e) { /* ... */ }
}

// ❌ 多余 await
async function getUser(id) {
  return await fetchUser(id).catch(e => null);  // 行为已不同
}
```

**不要 `async` 修饰无 `await` 的函数**：

```js
// ❌ 假 async
async function getStaticConfig() {
  return { theme: 'dark' };       // 没 await，但返回 Promise
}

// ✅ 直接返回对象
function getStaticConfig() {
  return { theme: 'dark' };
}
```

**并发选型**：

| 场景 | API |
|------|------|
| 全部成功才继续 | `Promise.all` |
| 部分失败也能继续 | `Promise.allSettled` |
| 取最先完成的 | `Promise.race` |
| 取最先 fulfill 的（忽略 reject） | `Promise.any` |
| 顺序执行 | `for await` / `for` 循环 + await |

**并发限流**（防雪崩）：

```js
import pLimit from 'p-limit';
const limit = pLimit(5);                      // 最多 5 并发
const results = await Promise.all(
  urls.map(url => limit(() => fetch(url)))
);
```

### 1.4 状态管理（store / reducer / 副作用）

**状态放哪**（按范围）：

| 范围 | 方案 |
|------|------|
| 组件内临时态 | `useState` / `useRef` |
| 跨组件共享 | Context（少数场景） |
| 全局复杂态 | Redux Toolkit / Zustand / Pinia |
| 服务端态（缓存） | React Query / SWR / TanStack Query |

**不可变更新**：

```js
// ✅
const newState = { ...state, name: 'bob' };

// ❌ 直接 mutate
state.name = 'bob';                // React/Vue 检测不到变化，不重渲染
```

**副作用集中放**（不要散在组件里）：

```js
// ✅ Redux Toolkit slice
const userSlice = createSlice({
  name: 'user',
  initialState: null,
  reducers: { /* ... */ },
  extraReducers: (builder) => {
    builder.addCase(fetchUser.fulfilled, (state, action) => {
      state.data = action.payload;
    });
  },
});
```

### 1.5 设计模式选型（单例 / 工厂 / 观察者 / 装饰器）

**单例模式**：JS **模块天然单例**——不要再造。

```js
// ✅ ES Module 就是单例
// logger.js
export const logger = { /* ... */ };

// ❌ 假单例
class Logger {
  static instance = null;
  static getInstance() {
    if (!Logger.instance) Logger.instance = new Logger();
    return Logger.instance;
  }
}
```

**工厂函数 vs class**：

- 简单对象 → 工厂函数
- 需要继承 / instanceof / 私有字段 → class

**观察者 vs 发布订阅**：

| 模式 | 适用 |
|------|------|
| 观察者（Observer） | 一个 Subject 直接通知多个 Observer，耦合较紧 |
| 发布订阅（Pub/Sub） | 通过 Event Bus / Message Broker 解耦，跨组件 / 跨模块通信 |

**装饰器**（TC39 Stage 3）：**TS 5.0+ 实验支持**，生产项目慎用，可读性下降。

## 2. 🟡 推荐 · 团队约定

### 2.1 面向对象 vs 函数式

- **默认函数式**：纯函数 + 不可变数据 + 组合
- **OOP 仅在领域模型 / 框架要求时用**（Nest / Spring / Angular 的 DI 容器）

### 2.2 依赖注入 / 控制反转

- 构造函数注入 / 模块导入即注入
- 框架容器（Nest / Angular / InversifyJS）——业务框架已用时跟随

**不要**把 `new ClassName()` 散落业务代码里。

### 2.3 抽象层 / 接口

- TS 项目：用 `interface` 抽象依赖
- JS 项目：用 JSDoc `@typedef` + 鸭子类型

### 2.4 业务逻辑分层

**前端 store 三层**（与后端分层对齐）：

```
src/
├── api/         # 网络请求
├── store/       # 状态管理（Redux slice / Zustand store）
├── service/     # 业务逻辑（编排 API + store）
├── component/   # 视图组件
└── util/        # 纯函数工具
```

**后端三层**（Controller / Service / Repository）：

```
src/
├── controller/  # 路由 + 参数校验
├── service/     # 业务逻辑
├── repository/  # 数据访问
└── model/       # 数据模型
```

## 3. 🟢 可选 · 视情况

### 3.1 状态机（XState / 自实现）

复杂 UI 流程（订单 / 表单 / 工作流）才用。

```js
// 简单状态机
const stateMachine = {
  idle: { SUBMIT: 'loading' },
  loading: { SUCCESS: 'success', ERROR: 'error' },
  success: { RESET: 'idle' },
  error: { RETRY: 'loading', RESET: 'idle' },
};
```

极少用。列出适用边界：超高并发写入 / 需要完整审计日志 / 复杂业务规则。
