# 10 - JavaScript 代码风格规则

> 🟢 本文件适用于 JS/TS 源码的格式、命名、注释、导入与仓库既有静态检查。
>
> 🔴 不适用：以风格为理由的 API 重命名、组件/包迁移、全仓重构、工具链替换或批量无关格式化。

---

## 1. 格式化与 lint

> **适用条件与验证**：先检查 ESLint、Prettier、Biome、Standard、EditorConfig、hook、CI 和同目录代码。工具和版本以当前配置、锁文件和 scripts 为准。

🔴 **必须**：改动文件遵循项目已有格式与 lint 约定；不得为一次需求安装新工具、使用浮动版本、修改规则阈值或重写无关文件。

🟡 **推荐**：使用仓库已有的格式/检查脚本或仅作用于变更文件的命令；存量告警与本次引入的问题分开报告。

## 2. 命名、模块与注释

> **适用条件与验证**：以同目录、公开 API、框架约定、生成代码、序列化格式和调用方为准。

🔴 **必须**：不得为套用风格规则重命名公开符号、路由、序列化字段、CSS 选择器或生成物引用。注释不能与实现、契约或安全边界矛盾。

🟡 **推荐**：选择可读、领域明确且同模块一致的名称；注释重点解释边界、原因、异步/资源生命周期和调用方需知行为，而非重复代码。

## 3. AI 完成检查

- [ ] 改动文件符合项目实际格式约定，未产生无关 diff。
- [ ] 未安装/升级工具或改写 lint 配置来“通过检查”。
- [ ] 命名、注释和模块边界与调用方、框架及生成代码兼容。
- [ ] 已说明执行的检查、未执行项和存量问题边界。
