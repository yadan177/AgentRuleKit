# 07 - JavaScript 日志与调试规则

> 🟢 本文件适用于项目已有的浏览器、Node.js、错误上报、source map 和性能诊断能力。
>
> 🔴 不适用：未经授权新增/替换日志库、错误上报平台、source map 发布策略或生产调试端点。

---

## 1. 日志实现与等级

> **适用条件与验证**：先检查当前日志封装、控制台策略、错误上报、采样、source map、trace/request ID、隐私与保留期配置。

🔴 **必须**：沿用项目当前日志与错误上报方式；不得因单个需求引入 Sentry、console 替换库、trace SDK 或修改全局错误处理。

🟡 **推荐**：使用稳定事件消息与项目既有结构化字段；区分调试信息、可恢复异常与需要告警的错误，避免高频成功路径产生噪声。

## 2. 隐私与错误处理

> **适用条件与验证**：数据分类、脱敏、采样和上传策略由项目安全与隐私要求决定。

🔴 **必须**：不得记录或上报密码、token、cookie、认证头、完整请求体、完整 URL 查询参数、密钥、支付信息或未脱敏个人数据。展示给用户的错误不能泄露内部栈、地址或服务细节。

🔴 **必须**：不要在每一层重复捕获、上报同一错误；保留错误上下文和 cause，由项目约定的边界统一呈现或上报。

## 3. 调试、source map 与性能诊断

> **适用条件与验证**：仅在现有调试工具、受控环境或用户明确授权时适用；检查 source map 是否公开、访问控制、制品匹配和数据泄露风险。

🔴 **必须**：不得为了排障将 `debugger`、性能 profile、开发工具、source map 或内部错误详情暴露给生产用户；不得修改压缩/移除日志策略而不验证发布产物。

🟡 **推荐**：优先复现问题、最小化采集范围并记录证据；诊断完成后清理临时日志与开关。

## 4. 产品分析与隐私

> **适用条件与验证**：仅在项目已有产品分析、行为埋点、性能上报或用户同意机制时适用；事件 schema、同意状态、采样、保留期和数据出境要求以项目政策为准。

🔴 **必须**：不得为局部需求新增分析 SDK、向第三方发送未获同意的数据，或把用户标识、完整输入、敏感属性和凭证作为事件字段。事件名称、属性和版本遵循现有 schema，变更须评估下游报表与隐私影响。

🟡 **推荐**：只记录完成产品/故障目标所需的最小数据；对高频事件沿用现有采样和去重策略。

## 5. AI 完成检查

- [ ] 已识别当前日志、错误上报、source map 与采样方式。
- [ ] 新日志不包含凭证、敏感数据或高基数隐私字段。
- [ ] 未新增未授权的监控/上报依赖或生产调试能力。
- [ ] 已记录实际验证、未验证的采集链路和隐私风险。
