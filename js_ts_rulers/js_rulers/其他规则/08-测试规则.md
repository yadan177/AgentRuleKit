# 08 - JavaScript 测试规则

> 🟢 本文件适用于 JavaScript/TypeScript 项目的单元、集成、端到端、可访问性与浏览器测试。
>
> 🔴 不适用：未经授权新增测试框架、浏览器自动化平台、覆盖率服务、测试容器或改变 CI 门槛。

---

## 1. 从现有测试与风险出发

> **适用条件与验证**：先检查同目录测试、测试脚本、fixture、mock、CI、运行环境、浏览器矩阵和覆盖率规则。测试类型由变更风险、依赖边界和项目能力决定，不使用固定比例。

🔴 **必须**：行为变更应有与风险相称的验证；不得删除断言、降低门槛或跳过安全关键分支来让测试通过；未执行的验证不得声称通过。

🟡 **推荐**：优先扩展邻近测试。纯逻辑通常适合单元测试；跨网络、存储、路由、组件或部署边界时按项目已有方式选择集成、组件或端到端测试。

## 2. 异步、DOM 与替身

> **适用条件与验证**：假时钟、mock、MSW、Jest/Vitest、Playwright/Cypress、Testing Library 等仅在仓库已配置时使用。

🔴 **必须**：异步测试必须等待真实的可观察完成条件；测试后恢复 mock、timer、DOM、事件监听器、存储与全局状态，避免测试顺序依赖。

🟡 **推荐**：测试用户可观察行为和公开契约，避免对内部实现细节、非稳定 class 名或框架私有状态做脆弱断言。

## 3. 性能、可访问性与视觉验证

> **适用条件与验证**：仅当项目已有性能预算、可访问性检查、视觉回归或目标设备/浏览器环境时适用。

🔴 **必须**：性能结论需要可重复的前后测量条件；可访问性与视觉基线不能在未审查的情况下整体更新。

## 4. AI 完成检查

- [ ] 已识别相邻测试、fixture、mock 和可用 scripts。
- [ ] 行为、异步、组件或数据变更有匹配验证或明确未验证说明。
- [ ] 未新增未授权测试框架、浏览器平台或覆盖率服务。
- [ ] 测试数据不含真实凭证、生产数据或敏感个人信息。
