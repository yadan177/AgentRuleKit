# 15 - 前端交互与可访问性规则

> 🟢 本文件适用于项目中的浏览器 UI、表单、导航、弹层、响应式布局和当前组件框架的交互改动。
>
> 🔴 不适用：未经授权引入组件库、全局设计体系、路由方案、自动化测试平台或改写既有视觉规范。

---

## 1. 先识别 UI 契约

> **适用条件与验证**：检查现有组件、语义结构、焦点管理、表单校验、国际化、设计 token、断点、主题和可访问性测试约定。

🔴 **必须**：交互改动不得破坏已有键盘操作、焦点顺序、可读名称、错误反馈、加载/空状态、路由返回行为或移动端布局。不能只靠颜色、占位文本或鼠标悬停传达关键信息。

## 2. 语义、表单与焦点

> **适用条件与验证**：原生元素、ARIA、dialog、toast 和表单组件的使用以当前框架、组件库和浏览器支持为准。

🔴 **必须**：优先使用匹配语义的原生元素；自定义交互控件需要具备等价键盘、焦点、禁用和状态语义。错误信息应与输入或操作结果可关联，异步状态不得让用户失去上下文。

🟡 **推荐**：模态、菜单、抽屉和路由切换沿用项目已有的焦点捕获/恢复方案；仅在现有组件库或无障碍方案不足且获授权时新增实现。

## 3. 视觉与动效

> **适用条件与验证**：对比度、缩放、主题、响应式、减少动态效果和视觉回归以设计系统、目标设备和浏览器支持为准。

🔴 **必须**：UI 不能依赖固定视口、单一主题或单一输入方式才能工作；动效、自动刷新和滚动行为需尊重项目已有的用户偏好与可中断方式。

## 4. 验证与交付

- [ ] 已按项目支持范围检查键盘、焦点、错误/加载/空状态和响应式行为。
- [ ] 已使用现有无障碍、组件或手工验证方式，或说明未覆盖的设备/辅助技术。
- [ ] 未引入未经授权的组件库、全局设计体系或交互框架。
- [ ] 已说明视觉、交互和可访问性剩余风险。
