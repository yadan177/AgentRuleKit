# 11 - JavaScript 安全规则

> 🟢 本文件适用于 JS/TS 中涉及身份、授权、输入、存储、网络、依赖与敏感数据的改动。
>
> 🔴 不适用：将客户端校验当作服务端授权、绕过安全评审，或在代码、文档和测试中保存真实凭证。

---

## 1. 安全边界与数据分类

> **适用条件与验证**：先确认数据分类、信任边界、认证/授权契约、存储、CSP、网络出口、密钥注入和已有安全组件。

🔴 **必须**：不得在源码、测试、日志、构建变量、提交或规则样例中写入真实密码、token、私钥、连接串或生产用户数据。安全需求不明确时必须报告，不能猜测。

## 2. 前端与服务端职责

🔴 **必须**：客户端可做输入体验、显示控制与最小化数据暴露，但所有权限、对象归属、金额、配额、限流和关键校验必须由可信服务端执行。

🔴 **必须**：不可信内容进入 DOM 前必须按当前框架的安全渲染方式处理；不得为渲染 HTML、URL、样式或脚本而绕过框架转义、CSP 或既有 sanitizer。

## 3. 认证、存储与网络

> **适用条件与验证**：cookie、token、session、CSRF、CORS、缓存、浏览器存储和 API 客户端以现有身份与部署方案为准。

🔴 **必须**：不得自行设计认证协议、关闭 TLS/CSP/CSRF 保护、把长期凭证放入不适当存储，或把用户提供的 URL/参数直接用于网络请求、跳转或 DOM sink。

🟡 **推荐**：复用现有 API 客户端与鉴权刷新流程；错误信息与日志遵循脱敏要求。

## 4. 依赖与验证

> **适用条件与验证**：漏洞扫描、秘密扫描、许可证和 SAST 以仓库现有 CI 与安全流程为准。

🔴 **必须**：不得为了构建通过关闭校验或忽略高风险漏洞；不明来源依赖、校验失败或疑似泄密须停止并报告。

## 5. AI 完成检查

- [ ] 已确认输入、身份、存储、网络和服务端授权边界。
- [ ] 没有硬编码凭证、客户端信任授权或绕过安全控制。
- [ ] 新增 DOM/URL/存储/请求逻辑经过相应风险检查。
- [ ] 已说明执行的安全验证、未验证项和需要人工确认的风险。
