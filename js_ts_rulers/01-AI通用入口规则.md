# 01 - JS/TS AI 通用入口规则

> 🟢 本文件适用于任何 AI 工具在 JavaScript 与 TypeScript 项目中执行开发、修改、审查、排障或文档任务。
>
> 🔴 不适用：替代项目事实、未经授权的技术迁移，或伪造构建、测试与发布结果。

---

## 1. 开始前检查

在修改 JS/TS 内容前，检查能够获得的以下证据：

1. `package.json`、锁文件、workspace、`packageManager`、`engines`、scripts 与 CI。
2. `tsconfig*.json`/`jsconfig.json`、模块格式、浏览器或 Node 目标、构建与环境变量配置。
3. 路由、组件、状态、样式、请求、存储、错误处理及同目录既有实现。
4. 已安装的框架、测试、lint/formatter、数据访问、日志、监控与安全依赖。
5. API 契约、密钥管理、部署文件、生成代码和运行环境限制。

## 2. 决策与变更边界

🔴 **必须**：只使用项目已安装、版本兼容且有证据支持的包、API、脚本和配置。不得臆造依赖、路由、环境变量、接口、DOM 结构、测试命令、构建产物或云资源。

🔴 **必须**：未获明确授权时，不升级运行时、包管理器、依赖、框架、构建工具、tsconfig、lint/formatter、状态管理、样式体系或基础镜像；不执行全仓重构、依赖批量更新或无关格式化。

🔴 **必须**：沿用当前项目的错误处理、取消/清理、异步边界、状态更新、日志、测试、可访问性和安全约定。事件监听器、timer、订阅、请求、AbortController 与资源句柄必须有明确的所有权和清理路径。

🟡 **推荐**：先完成最小可验证改动；性能优化先使用项目已有 profile、指标、trace、benchmark 或用户可复现步骤定位问题。

## 3. JS 与 TS 的关系

🔴 **必须**：TypeScript 只提升编译期保障，不能替代运行时输入校验、权限验证、错误处理或安全控制。

🟡 **推荐**：TS 项目先使用 JS 基线规则，再按需读取类型、收窄、声明、tsconfig 与 TS lint 专题；纯 JS 项目不应被强行迁移为 TypeScript。

## 4. 验证与交付

🔴 **必须**：优先使用仓库已有且与改动相称的 scripts、测试和静态检查。无法执行时说明原因、未验证范围和风险；未执行的验证不得声称通过。

每次任务结束时，AI 应说明：

1. 修改了什么以及为什么。
2. 执行了哪些验证及其结果。
3. 哪些验证未执行、原因和剩余风险。
4. 需要用户确认的项目事实、迁移、密钥或外部协作事项。

交付前按 [02 - JS/TS AI 交付前自检](./02-AI交付前自检.md) 核对与本次任务相关的项目。

## 5. 规则编写模板

```markdown
### N.M 规则名称

**适用条件**：项目满足的运行时、包、框架、构建或环境前提。

🔴 **必须**：可执行的强制要求。

🟡 **推荐**：有条件的推荐做法。

🟢 **可选**：可按项目选择的方案。

**验证**：可检查的构建、测试、配置、日志、指标或审查操作。

**例外**：允许偏离规则的明确条件和处理方式。
```
