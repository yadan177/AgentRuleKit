# 02 - JS/TS AI 交付前自检

> 🟢 本文件适用于任何 JavaScript 或 TypeScript 任务完成后的范围、质量、安全与交付核查。
>
> 🔴 不适用：替代项目已有测试、审查、发布、安全审批或把未执行的检查标记为通过。

---

## 1. 改动范围

- [ ] 改动与用户任务、仓库规则和项目事实一致，没有无授权的依赖、运行时、框架、构建、状态或样式迁移。
- [ ] 没有臆造 API、环境变量、路由、DOM、配置、测试命令或云资源。
- [ ] 公开契约、生成代码、迁移、部署和跨端边界的影响已被识别并说明。

## 2. 运行时与资源

- [ ] 不可信输入在运行时有现有校验或等价保护；TypeScript 类型未被当作运行时安全证明。
- [ ] Promise 错误、事件、订阅、timer、请求、流与资源句柄都有明确所有者和清理/取消路径。
- [ ] 新的缓存、重试、并发、性能或离线行为有失效、幂等、资源与用户体验依据。

## 3. UI、安全与数据

- [ ] UI 改动遵循现有组件/样式体系，并覆盖需要的加载、错误、空状态、键盘、焦点和响应式行为。
- [ ] 没有硬编码凭证、敏感日志、客户端授权信任、DOM sink 注入或不安全存储。
- [ ] API、认证、Cookie、缓存、存储与服务端契约没有被擅自改变。

## 4. 验证与交付

- [ ] 已运行仓库可用且与改动相关的格式、typecheck、测试、构建或受控手工验证。
- [ ] 无法运行的验证、原因、未覆盖范围和剩余风险已如实说明。
- [ ] 交付内容包含：改动说明、验证结果、未验证项、风险及需要用户确认的外部事项。

> **例外**：高风险发布、生产数据、安全、支付、权限和合规改动须遵循项目专门审批；本清单不能替代人工决策。
