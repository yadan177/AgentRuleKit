# 09 - TypeScript AI 通用入口规则

> - 🟢 本文件补充 JavaScript 通用入口，适用于任何 AI 工具在 TypeScript 项目中开发、审查、排障与维护规则。
> - 🔴 不适用：跳过 JavaScript 基线、替代仓库事实、自动批准依赖/版本迁移，或伪造验证结果。

---

## 1. 使用方式

TypeScript 项目应先阅读 [JavaScript AI 通用入口规则](../js_rulers/15-AI通用入口规则.md)，再阅读本文件，最后按两个总览选择任务相关专题规则。本文件只补充类型、编译配置与 TS 工具链边界，不复制 JS 01 至 15 的内容。

- 🔴 **必须**以 `package.json`、锁文件、`tsconfig*.json`、实际运行时和现有脚本为事实来源。
- 🔴 **必须**区分类型层的结论和运行时的结论；类型通过不代表输入、权限、网络或序列化已经安全。
- 🔴 **必须**遵循三层优先级：用户任务与安全限制；目标项目入口、代码、依赖和配置事实；本规则库通用建议。类型专题不得覆盖项目既有运行时、框架或构建约定。
- ❌ **禁止**为了使用示例升级 TypeScript、切换模块解析、开启严格选项、替换 ESLint 配置或引入运行时校验库。

## 2. TypeScript 专项检查

开始修改前，按任务检查：

1. TypeScript 版本、`tsconfig` 继承链、`module`/`moduleResolution`、`target`、路径别名与声明输出。
2. 现有 lint、format、类型检查、测试、构建和生成声明的脚本及 CI 命令。
3. 公开类型、运行时校验、序列化边界、第三方类型来源和框架生成代码。
4. 已有的 `any`/`unknown`、断言、装饰器、ESM/CJS 互操作和迁移兼容约定。

## 3. 专题规则选择

| 任务 | 先阅读 |
|---|---|
| 任何运行时逻辑、异步、性能、数据或安全 | JS 15 和对应 JS 专题 |
| 类型、泛型、工具类型、接口设计 | TS 01、04 |
| `unknown`、外部数据、断言或错误边界 | TS 02、05，并回看 JS 11 |
| JS 迁移、模块、装饰器、导入导出 | TS 03 |
| `tsconfig`、编译目标、路径、项目引用 | TS 06 |
| ESLint、Prettier、类型化 lint 或提交钩子 | TS 07，并以现有工具链为准 |
| 代码完成后的类型反模式检查 | TS 08 |

## 4. 实现任务的文档影响门禁

- 🔴 **必须**在新增、修改或删除功能前判断技术文档影响；该判断适用于实现任务，不以用户是否明确提出“写文档”为前提。
- 🔴 类型、公开声明、模块边界、API、数据结构、构建输出、配置、契约、部署、术语或验证结论发生变化时，必须读取 `.ai-rules/js-ts-project-docs/其他规则/04-JS+TSAI技术文档任务入口.md` 和 `.ai-rules/js-ts-project-docs/其他规则/01-技术文档组织与维护规范.md`，并同步受影响文档。
- 🔴 跨工程契约发生变化时，必须检查所有相关工程的技术文档；受影响文档未同步时，不得将功能报告为完整完成。
- 🔴 确认不影响技术文档时，交付中必须写明“文档影响：无”及判断依据；不得静默跳过。
- 🟡 纯内部类型收窄、变量重命名或格式调整未改变公开契约、运行时行为和构建产物时，通常可以判定为无文档影响。
- 🔴 项目尚未导入技术文档规则或无法定位对应入口时，必须报告缺失，不得声称已经执行文档规则。

## 5. 验证与交付

- 🔴 **必须**运行项目实际采用的类型检查、测试、lint 或构建验证；不能以不存在的 `tsc --noEmit` 或工具版本假设代替项目脚本。
- 🔴 **必须**说明类型检查覆盖与运行时验证覆盖的差异，尤其是外部输入、生成类型和声明文件改动。
- 🔴 **必须**在类型、公开声明、运行时边界或跨端契约变化时同步维护原因、约束和失败语义注释，并在交付前检查错误、过时和缺失注释。
- 🟡 类型、模块解析、构建输出或公开声明发生变更时，应复核下游兼容性与发布产物。

交付时说明修改、实际读取的开发与文档规则、文档影响结论、同步的文档、验证结果、未验证范围和需要用户确认的 TypeScript/运行时事实。
