# 04 - JavaScript 异步与事件循环规则

> - 🟢 本文件适用于浏览器、Node.js 和 Worker 中的 Promise、任务调度、并发、取消与异步资源管理。
> - 🔴 不适用：用单一 async 风格覆盖项目契约，或把浏览器事件循环结论直接套到所有 Node.js 阶段

---

## 1. 运行时与错误所有权

- 🔴 先确认目标运行时、版本、模块系统和项目已有异步封装；`fetch`、Web API、Node.js API 和框架生命周期并非处处可用。
- 🔴 每个异步链必须有明确的最终错误所有者。中间函数可以让 Promise 拒绝向上传播，不要求每层重复 `try/catch`。
- 🔴 捕获错误后要处理、转换或带上下文重抛；只记录后吞掉、返回看似成功的空值或产生未观察拒绝都不可接受。
- 🟡 全局 `unhandledrejection`/`unhandledRejection` 只在项目已有进程或页面级观测边界时沿用；它不能替代调用方处理，也不能无条件阻止默认行为。

```js
async function loadUser(id) {
  return fetchUser(id); // 由调用边界处理拒绝，不需要重复 catch
}

async function renderUser(id) {
  try {
    const user = await loadUser(id);
    render(user);
  } catch (error) {
    showLoadFailure(error);
  }
}
```

## 2. Promise 与回调

- 🟡 `async/await`、Promise 链和回调按 API 契约、可读性与项目风格选择；不得用“全部改成 async/await”机械重写事件或流式接口。
- 🔴 不把回调 API 当成 Promise 使用；需要适配时优先使用运行时官方 Promise API或项目已有 wrapper。
- 🟡 `return await` 在 `try/catch/finally`、调试栈或明确需要等待时有意义；简单转发可直接返回 Promise。
- 🔴 `async` 函数始终返回 Promise。把同步 API 改成 `async` 会改变调用契约，必须检查所有调用方。

## 3. 任务与事件循环

- Promise reaction 和 `queueMicrotask` 进入微任务队列；timer、I/O、消息和渲染的调度细节取决于浏览器或 Node.js 运行时。
- 🔴 不能用循环、同步 I/O 或其他忙等方式等待 Promise；这会阻塞负责推进异步工作的线程。
- 🔴 微任务递归也可能长期阻塞其他任务和渲染；`queueMicrotask` 不是“立即执行”或通用性能优化。
- 🟡 长任务是否需要分片、Worker 或服务端任务队列，依据 profile、交互目标和运行环境决定，不使用通用固定毫秒阈值。
- 🔴 `setTimeout(..., 0)` 只安排后续 timer 任务，不保证立即执行，也不会让 CPU 工作并行。

## 4. 并发与背压

| 需求 | 可评估方式 | 注意事项 |
|---|---|---|
| 全部成功 | `Promise.all` | 首个拒绝会结束聚合等待，其他底层工作不会自动取消 |
| 收集全部结果 | `Promise.allSettled` | 必须检查每个结果状态 |
| 最先 settle | `Promise.race` | 其余任务需要单独取消/释放 |
| 最先成功 | `Promise.any` | 处理全部拒绝，并确认运行时兼容 |
| 顺序执行 | `for...of` + `await` | 适用于顺序依赖或主动限流 |

- 🔴 并发上限由下游容量、浏览器连接、API 配额、内存和项目既有调度器决定；不能用固定数字覆盖所有任务。
- 🔴 批量任务需要定义背压、部分失败、重试、取消和结果顺序。
- 🟡 优先复用项目已有队列或并发工具；没有现成能力时再实现最小调度器或申请引入依赖。

## 5. 取消、超时与竞态

- 🔴 创建请求、timer、订阅、Worker 或异步迭代的职责必须定义取消和释放路径。
- 🔴 AbortSignal 需要传到实际支持它的底层 API；仅修改上层状态不能停止底层工作。
- 🟡 超时可通过项目已有 client、AbortSignal 或平台机制实现；超时时长按接口 SLO 和业务容忍度确定。
- 🔴 重试前确认操作幂等、错误可重试并使用项目退避策略；取消和校验错误通常不应盲目重试。
- 🔴 多次请求可能乱序返回时，用取消、请求序号或数据层机制保证旧结果不会覆盖新状态。

```js
let requestSequence = 0;

async function refresh() {
  const sequence = ++requestSequence;
  const result = await loadLatest();
  if (sequence !== requestSequence) return;
  applyResult(result);
}
```

## 6. Timer、订阅与异步迭代

- 🔴 保存 timer/订阅句柄，并在所有权结束时清理；已经完成的一次性 timer 不需要机械调用 clear。
- 🔴 `setInterval` 的回调可能重叠或漂移；任务耗时不可控时，可评估完成后再调度下一次并定义停止条件。
- 🔴 异步迭代必须处理提前退出、错误和底层资源关闭；流和队列还要处理背压。
- 🟡 页面可见性、休眠、后台节流和 Node.js 进程退出会影响 timer，不把 wall-clock 精度建立在普通 timer 上。

## 7. 框架与交付检查

- React effect、组件卸载和状态更新读取 13；Vue 生命周期、watch 清理和异步竞态读取 16。
- 交付前检查错误所有者、取消、超时、重试、并发上限、乱序响应和资源释放。
- 在目标浏览器/Node.js/Worker 与真实构建模式验证，不以单次本地成功替代目标环境。
- 异步契约、生命周期或失败语义变化时同步注释和技术文档。
