# 05 - JavaScript 数据访问规则

> - 🟢 本文件适用于浏览器和 JavaScript 运行时中的 HTTP 请求、外部数据校验、客户端存储、缓存与跨页面同步。
> - 🔴 不适用：替代服务端鉴权、数据库设计，或默认引入请求、校验、缓存和存储库

---

## 1. 项目契约优先

- 🔴 先读取项目已有 HTTP/RPC 客户端、认证、错误模型、重试、缓存、schema 和测试方式；组件不得复制一套新的数据访问策略。
- 🔴 API 字段、状态码、分页、时间、空值和错误语义以跨端契约为准，不能从示例推断。
- 🔴 只使用项目已有且版本兼容的请求、校验、缓存和存储依赖；新增依赖必须获得授权。
- 🔴 外部数据在信任边界按风险校验；TypeScript 类型不能验证网络、URL、存储或消息中的运行时数据。

## 2. 认证与敏感数据

- 🔴 密码、服务凭据、长期私密密钥不得写入浏览器持久化存储、客户端代码或构建产物。
- 🔴 token/session 的存储和传递必须沿用项目威胁模型与服务端契约；`localStorage`、`sessionStorage` 中的数据可被同源脚本读取，HttpOnly Cookie 则需要同时处理 CSRF、SameSite、CORS 和会话生命周期。
- 🔴 客户端只能控制界面和发起请求，服务端必须执行最终认证与授权。
- 🔴 日志、错误、URL、埋点和缓存不得泄露 token、Cookie、个人信息或敏感响应内容。

## 3. HTTP 请求生命周期

### 3.1 凭据和跨域

- Fetch 的默认 `credentials` 是 `same-origin`，不是 `omit`。
- 跨源请求需要 Cookie 时，客户端通常显式使用 `credentials: 'include'`，服务端还必须返回匹配的 CORS 凭据与 origin 配置，并满足 Cookie 的 SameSite/Secure 约束。
- 🔴 不得为修复跨域问题使用任意 origin + credentials、关闭证书验证或在客户端绕过服务端策略。

```js
const response = await fetch(url, {
  credentials: 'include', // 仅在项目认证契约要求跨源 Cookie 时
  signal,
});
```

### 3.2 取消、超时与竞态

- 🔴 请求创建方必须明确取消所有权，以及组件卸载、路由切换、重复搜索和调用方退出时如何处理。
- 🟡 超时长度、重试次数、退避和可重试错误由项目 SLO、接口幂等性及现有客户端决定，不使用通用固定值。
- 🔴 Abort 只停止支持该 signal 的工作；取消、超时和真实失败必须按项目错误模型区分。
- 🔴 旧响应可能晚于新响应返回时，使用取消、请求序号或数据层机制防止过期结果覆盖新状态。

### 3.3 响应处理

- 🔴 在读取 body 前检查项目约定的成功状态，并正确处理无 body、流式响应、非 JSON 错误和解析失败。
- 🔴 错误转换保留 HTTP 状态、业务码、可恢复性和追踪信息，同时对用户隐藏敏感内部细节。
- 🟡 请求封装应复用项目已有 client；没有 client 时，先定义最小契约，再决定是否需要统一封装。

## 4. 缓存与服务端状态

- 🔴 缓存所有权、key、失效、并发合并、错误保留和刷新策略必须由项目数据层定义。
- 🟡 优先评估服务端 `Cache-Control`、`ETag`、条件请求等 HTTP 能力；浏览器通常会按协议自动处理缓存，不要求业务代码手工维护 `If-None-Match`。
- 🔴 认证或个性化响应必须核对 `private`、`no-store`、`Vary` 和共享缓存边界，避免跨用户泄露。
- 🟡 React/Vue 的服务端状态方案分别由对应框架专题和项目已有依赖决定；本文件不默认 React Query、SWR、Pinia 或其他库。

## 5. 浏览器存储

| 能力 | 主要特征 | 使用条件 |
|---|---|---|
| `localStorage` | 同步、同源、持久化 | 少量非敏感数据；容量和可用性需在目标浏览器验证 |
| `sessionStorage` | 同步、按标签页会话 | 少量非敏感会话数据，仍受 XSS 影响 |
| IndexedDB | 异步、结构化、配额较大 | 数据量或查询需求确实需要，并定义迁移和失败恢复 |
| Cache API | Request/Response 缓存 | 项目已采用 Service Worker/PWA 或明确缓存生命周期 |
| Cookie | 随请求发送、容量有限 | 服务端会话或协议明确需要，并配置安全属性 |

- 🔴 浏览器配额会随实现、设备和隐私模式变化，不能把固定 MB 数写成可靠契约；处理 quota、禁用存储和清理失败。
- 🔴 `localStorage`/`sessionStorage` 是同步 API，不用于大对象或高频写入。
- 🔴 IndexedDB schema、版本迁移、事务、并发标签页和清理策略必须明确；只有项目已采用 Dexie/idb 等封装时才使用对应 API。

## 6. DOM、消息与外部输入

- 🔴 普通文本使用 `textContent` 等不会解析 HTML 的接口；富文本只有在业务确需且经过项目已有、持续维护的净化策略时才进入 HTML sink。
- 🔴 不得因示例自动引入 DOMPurify 或其他净化库；项目没有可靠富文本边界时，拒绝或降级为纯文本。
- 🔴 `postMessage` 校验 origin、source 和消息 schema；BroadcastChannel、storage 事件和 Worker 消息同样不能信任 payload。
- 🔴 URL 参数、持久化数据和 API 响应均视为外部输入，并在实际使用边界校验。

## 7. 跨页面与离线同步

- 🟡 BroadcastChannel、SharedWorker、storage 事件、Service Worker 或服务端同步方案按浏览器支持、生命周期和项目现状选择。
- 🔴 监听器和 Channel 必须关闭；登出、账号切换、版本升级和多标签页冲突需要明确行为。
- 🔴 乐观更新必须有失败回滚、并发冲突和最终一致性策略；CRDT、last-write-wins 等不是无条件候选。
- 🟡 离线能力只在产品需求明确时引入，并验证缓存版本、失效、升级、重放和敏感数据清理。

## 8. 交付检查

- API、认证、错误、分页和字段契约是否与服务端及技术文档一致。
- 取消、超时、重试、竞态、缓存和离线失败路径是否覆盖。
- 外部输入、DOM sink、跨窗口消息和客户端存储是否保持安全边界。
- 是否未经授权引入请求、校验、缓存、PWA 或存储依赖。
- 是否在目标浏览器、真实 API 和项目测试体系中完成相称验证。
