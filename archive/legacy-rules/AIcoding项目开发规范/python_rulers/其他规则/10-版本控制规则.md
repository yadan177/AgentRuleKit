# 10 - Python 版本控制规则

> 🟢 本文件适用于 Python 项目的 Git、依赖锁定、提交和协作。<br>
> 🔴 不适用：替代仓库既有分支、评审、发布或包管理策略。

---

## 1. 受版本控制的内容

- 🔴 提交源码、测试、迁移、构建配置、格式化配置和项目选择的锁文件。
- 🔴 忽略虚拟环境、缓存、覆盖率产物、构建产物、本地日志、密钥和本机 IDE 文件。
- 🔴 不提交 `.env`、私钥、访问令牌、生产数据或生成的凭据。
- 🟡 锁文件是否提交以项目包管理器与仓库约定为准；不要因个人偏好删除或重建。

## 2. 提交与协作

- 🔴 一个提交聚焦一个可审查目的；避免把格式化、依赖升级和功能改动混在一起。
- 🔴 提交前运行与改动相称的格式化、静态检查和测试，并说明未运行项。
- 🟡 提交信息和分支命名遵循仓库现有约定；无约定时使用清晰的动词和影响范围。

## 3. 依赖变更

- 🔴 新增、删除或升级依赖必须说明原因、许可证/安全影响和验证结果。
- 🔴 不手工编辑锁文件来伪造依赖解析结果；使用项目既有工具完成并审查差异。
