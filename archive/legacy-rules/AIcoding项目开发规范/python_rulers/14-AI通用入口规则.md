# 14 - Python AI 通用入口规则

> 🟢 本文件适用于 AI 在 Python 项目中进行开发、审查、排障和规则维护。<br>
> 🔴 不适用：替代项目事实、伪造验证，或自动批准升级、迁移和生产发布。

---

## 1. 使用方式

本文件是 Python 规则库的执行入口。AI 先遵守本文件，再按 [00 - Python AI 编码规则总览](./00-文档总览.md) 读取当前任务需要的专题规则。

- 🔴 用户任务、目标项目约定和工具安全限制优先于通用建议。
- 🟡 只读取与当前任务直接相关的专题规则，避免把整套资料误作硬性前提。

## 2. 项目事实检查

开始前按任务检查：

1. Python 版本、`pyproject.toml`、锁文件、`requirements*.txt`、虚拟环境和包管理方式。
2. 包结构、入口脚本、类型检查、格式化、静态检查和测试配置。
3. 已采用的 Web、任务队列、ORM、迁移、日志、缓存、消息和部署方案。
4. 配置加载、环境变量、密钥管理、数据存储、构建与 CI 事实。
5. 同模块现有的异常、并发、资源释放、测试和日志模式。

- 🔴 只使用项目已安装、版本兼容且有证据支持的 API 与依赖。
- 🔴 证据不足时说明不确定点；无法安全判断时询问用户，不得默认选择框架或工具。
- ❌ 禁止仅依据目录名或“Python 项目通常如此”推断项目架构。

## 3. 变更边界

- 🔴 未获授权不得升级 Python、依赖、框架、包管理器、数据库驱动或部署配置。
- 🔴 未获授权不得引入依赖、批量重构、迁移目录、修改密钥或生产环境配置。
- 🔴 异步任务、线程、进程、文件、连接、事务和上下文管理器必须有明确的所有权、取消或关闭路径。
- 🟡 优先完成最小可验证改动，再讨论抽象、性能优化或架构重构。

## 5. 实现任务的文档影响门禁

- 🔴 **必须**在新增、修改或删除功能前判断技术文档影响；该判断适用于实现任务，不以用户是否明确提出“写文档”为前提。
- 🔴 业务模块、页面、路由、API、数据模型、数据库迁移、鉴权、配置、状态机、生命周期、部署、术语或验证结论发生变化时，必须读取 `.ai-rules/python-project-docs/其他规则/04-PythonAI技术文档任务入口.md` 和 `.ai-rules/python-project-docs/其他规则/01-技术文档组织与维护规范.md`，并同步受影响文档。
- 🔴 跨工程契约发生变化时，必须检查所有相关工程的技术文档；受影响文档未同步时，不得将功能报告为完整完成。
- 🔴 确认不影响技术文档时，交付中必须写明“文档影响：无”及判断依据；不得静默跳过。
- 🟡 纯内部重构、变量重命名或格式调整未改变外部契约、业务行为和运维方式时，通常可以判定为无文档影响。
- 🔴 项目尚未导入技术文档规则或无法定位对应入口时，必须报告缺失，不得声称已经执行文档规则。

## 6. 验证与交付

- 🔴 执行项目中可用且与改动相称的验证；无法执行时说明原因、未验证范围和风险。
- 🔴 核对改动是否超出任务范围，新增依赖或配置是否获授权。
- 🟡 API、数据、异步、性能和部署改动应列出需要在集成或目标环境复核的项目。

交付时说明修改内容和依据、实际读取的开发与文档规则、文档影响结论、同步的文档、验证结果、未验证范围与风险、需要用户确认的项目事实或外部协作事项。
