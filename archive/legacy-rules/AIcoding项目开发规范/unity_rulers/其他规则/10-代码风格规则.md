# 10 - Unity C# 代码风格规范

> - 🟢 本文件适用于 Unity C# 代码的外观风格（缩进/大括号/行宽/命名/m_ 前缀）。
> - 🔴 不适用：业务逻辑实现、API 设计、数据库设计

---

## 1. 排版格式

🔴 **AI 修改代码前**必须先检查 `.editorconfig`、`.DotSettings`、IDE 格式化设置、静态分析器和同模块代码。以下格式是没有更高优先级项目约定时的建议基线；不得为了本规则批量格式化无关文件。

### 1.1 缩进（4 空格 / Tab 禁用）

- 🔴 **遵循项目的缩进配置**；未配置时可使用 4 空格。
- ❌ 不要在同一文件或同一项目中混用 Tab 与空格。
- 🔴 续行缩进 8 空格（或对齐到括号）

### 1.2 换行（续行 / 垂直对齐）

- 🔴 长行拆成多行，避免超出最大行宽
- 🟡 多行参数 / 链式调用换行时对齐到括号或点

```csharp
// ✅ 好的换行
var result = SomeMethod(
    firstArgument,
    secondArgument,
    thirdArgument);

// ❌ 不好的换行（行太长）
var result = SomeMethod(firstArgument, secondArgument, thirdArgument);
```

### 1.3 行宽（≤ 120 字符）

- 🟡 最大行宽可参考 **≤ 120 字符**；以项目 `.editorconfig`、自动格式化器和可读性约定为准。
- 🟡 字符串拼接 / 参数列表可放宽到 140
- ❌ 单行超出 140 字符

### 1.4 大括号风格（Allman）

- 🔴 使用项目已配置的大括号风格；未配置时可采用 **Allman 风格**（左大括号单独成行）。
- 🔴 即使单行 if 也要换行大括号（避免误读）

```csharp
// ✅ Allman 风格
public void ProcessItems(List<Item> items, int startIndex)
{
    for (int i = startIndex; i < items.Count; i++)
    {
        ProcessItem(items[i]);
    }
}

// ❌ K&R 风格（不推荐）
public void ProcessItems(List<Item> items, int startIndex) {
    for (int i = startIndex; i < items.Count; i++) {
        ProcessItem(items[i]);
    }
}
```

### 1.5 空行（方法间 / 段落间 / 类成员组间）

- 🔴 方法间空一行
- 🟡 逻辑段落间空一行（如变量声明 vs 主体逻辑）
- 🟡 类成员组间空一行（字段组 / 属性组 / 方法组）


## 2. 空格与标点

### 2.1 运算符两侧空格

- 🔴 二元运算符两侧各加一个空格（`a + b`、`x == y`）
- ❌ 不留空格会导致阅读困难（`a+b`）

```csharp
if (x == y) { /* ✅ */ }
if (x==y) { /* ❌ */ }
```

### 2.2 逗号 / 分号后空格

- 🔴 逗号后加一个空格（`CollectItem(myObject, 0, 1)`）
- 🔴 分号后空一格（如 `for` 循环：`for (int i = 0; i < n; i++)`）

### 2.3 函数名与左括号无空格

- ❌ 函数名与左括号不加空格（`DropPowerUp(...)`，不是 `DropPowerUp (...)`）
- ❌ 关键字与左括号也不加空格（`if (...)`、`for (...)`）

### 2.4 关键字后空格（if / while / for）

- 🔴 关键字后加一个空格（`if (x)`、`while (x == y)`、`for (int i = 0; ...)`）

### 2.5 方括号内侧无空格

- ❌ 方括号内侧不加空格（`dataArray[index]` 不是 `dataArray [ index]`）

### 2.6 类型转换括号无空格

- 🔴 类型转换括号紧贴类型和值（`(int)value`，不是 `(int) value` 或 `( int )value`）

```csharp
int x = (int)value;       // ✅
int y = (int) value;      // ❌
int z = ( int )value;     // ❌
```


## 3. using 排序

### 3.1 排序规则（System → Unity → 第三方 → 项目）

- 🔴 using 放在文件顶部
- 🔴 排序规则：
  1. **系统命名空间**（`System.*`、`System.Collections.*`）
  2. **Unity 命名空间**（`UnityEngine`、`UnityEditor`）
  3. **已安装的第三方包**（仅引用 `Packages/manifest.json` 或程序集定义中确认存在的命名空间）
  4. **项目命名空间**（以当前 asmdef 与根命名空间为准）
- 🟡 同组内按字母顺序排序

```csharp
// ✅ 正确排序
using System;
using System.Collections.Generic;

using UnityEngine;
using UnityEngine.UI;

// using Cysharp.Threading.Tasks;  // 示例：仅项目已安装对应包时保留
// using R3;                        // 示例：仅项目已安装对应包时保留

// using ProjectNamespace.Utilities; // 示例：替换为当前项目真实命名空间
```

### 3.2 未使用的 using 必删

- 🔴 删除未使用的 using，保持文件整洁、避免不必要的依赖
- 🟡 启用 IDE 的"自动删除未使用 using"功能

### 3.3 using 别名规范

- 🟡 长命名空间用 `using` 别名缩短

```csharp
// ✅ 别名简化
using Mathf = UnityEngine.Mathf;
using UObject = UnityEngine.Object;
```


## 4. region 使用规范

### 4.1 谨慎使用 #region

- 🟡 `#region` 会隐藏代码、降低可读性
- 🟡 团队评审后再决定是否启用

### 4.2 允许场景（Animation Event / Input Event）

- ✅ 用 `#region` 分组由动画系统调用的 Animation Event Handlers
- ✅ 用 `#region` 分组由 Input System 调用的 Input Event Handlers

```csharp
        #region Animation Event Methods
        // 该方法由动画事件触发
        public void OnLand() { /* 调用当前项目的落地处理 */ }

        // 该方法由动画事件触发
        public void OnFootstep() { /* 调用当前项目的脚步处理 */ }
        #endregion
```

### 4.3 禁止场景（隐藏实现细节）

- ❌ **禁止**用 region 隐藏"实现细节"——应拆分类
- ❌ **禁止**给每个方法都加 region

```csharp
// ❌ 反例：region 滥用
#region Private Methods
private void Method1() { }
private void Method2() { }
private void Method3() { }
#endregion
```


## 5. 文件级格式

### 5.1 UTF-8 无 BOM

- 🔴 文件编码 **UTF-8 无 BOM**
- 🟡 IDE 设置中明确指定 UTF-8 编码

### 5.2 换行符 LF

- 🔴 换行符使用 **LF**（`\n`），不用 CRLF（`\r\n`）
- 🟡 Windows 用户在 `.gitattributes` 中设置 `*.cs text eol=lf`

### 5.3 文件末尾保留一个空行

- 🔴 每个文件末尾保留**一个**空行
- ❌ 禁止末尾多个空行

### 5.4 文件名 = 类名

- 🟡 原则上保持主要类型与文件同名；允许 partial 类型、紧密关联的小型枚举/DTO、Source Generator 输出、Unity/第三方生成代码和项目既有明确组织方式，不得为满足形式机械拆文件。
- 🟡 私有嵌套类放在宿主类同文件

```csharp
// 文件: PlayerController.cs
public class PlayerController : MonoBehaviour { }
```

### 5.5 缩进字符（4 空格）

- 🔴 缩进用 4 空格，不用 Tab
- 🟡 IDE 启用"显示空白字符"便于检查


## 6. 集合与字符串格式

### 6.1 集合初始化器对齐

- 🔴 集合初始化器每行一个元素
- 🟡 多元素时右括号单独一行

```csharp
// ✅ 对齐
var items = new List<string>
{
    "Item1",
    "Item2",
    "Item3",
};

// ✅ 简单集合单行
var flags = new[] { true, false, true };
```

### 6.2 字符串字面量用 "

- 🔴 普通字符串用双引号 `"..."`
- 🟡 字符字面量用单引号 `'a'`

### 6.3 字符串插值 $"..."

- 🟡 需要拼接时用 `$"..."` 插值
- ❌ 热路径（Update / 频繁执行）禁止插值（会产生分配）
- 详见 `01-代码编写规则.md` 9.1 字符串处理

```csharp
// ✅ 一次性场景
string greeting = $"Hello, {playerName}!";

// ❌ 热路径（会产生分配）
void Update() { m_text.text = $"Score: {score}"; }
```

### 6.4 verbatim 字符串 @"...\n..."

- 🟡 多行字符串 / 路径 / 正则用 `@"..."` verbatim 字符串
- 🟡 双引号转义用 `""`

```csharp
string path = @"C:\Users\Name\Documents";
string regex = @"\d+\s\w+";
string json = @"{
    ""name"": ""Player"",
    ""score"": 100
}";
```


## 7. 自动校验工具

> 风格规范应尽可能工具化，避免只靠人工 review。本章给出可按项目采用的工具配置；不要把示例配置覆盖到已有仓库。

### 7.1 .editorconfig 模板

```ini

root = true

[*]
indent_style = space
indent_size = 4
end_of_line = lf
charset = utf-8
trim_trailing_whitespace = true
insert_final_newline = true

[*.{cs}]
### C# 风格
csharp_new_line_before_open_brace = all
csharp_new_line_before_else = true
csharp_new_line_before_catch = true
csharp_new_line_before_finally = true
csharp_indent_case_contents = true
csharp_indent_switch_labels = true
csharp_prefer_braces = true:warning

### 命名
dotnet_naming_rule.m_prefixed_fields_should_be_camel_case.severity = warning
dotnet_naming_rule.m_prefixed_fields_should_be_camel_case.symbols = private_fields

dotnet_naming_symbols.private_fields.applicable_kinds = field

dotnet_naming_style.m_underscore_camel_case.word_separator = _

```

### 7.2 dotnet format 配置

```bash
### 检查风格
dotnet format --verify-no-changes --severity warn

### 自动修复
dotnet format --severity warn
```

项目采用 .NET SDK、`dotnet format` 且 CI 已配置时，可在 CI 中运行 `dotnet format --verify-no-changes`；否则使用仓库已有的格式化和静态检查命令。

### 7.3 IDE 插件（ReSharper / Rider / VS）

- **ReSharper / Rider**：`Settings → Code Editing → C# → Formatting Style` 导入 `.editorconfig`
- **VS Code**：`C# Dev Kit` 插件自动读 `.editorconfig`
- **Visual Studio**：`Tools → Options → Text Editor → C# → Code Style` 同步设置


## 8. 注释格式

> **本章只规定"注释的格式"**（用 `//` 还是 `///`、单行还是多行），**不规定"该注释什么 / 不该注释什么"**（注释意图见 `01-代码编写规则.md` 第 2 章）。

### 8.1 `///` XML 文档注释

- 🟡 对外程序集 API、Unity Package 公共 API、SDK 接口、跨模块公共契约，以及行为、异常或生命周期不直观的 public 成员，使用 `///` XML 文档注释并至少包含 `<summary>`。
- 🟢 简单数据容器、Unity 序列化字段、明确的事件参数、仅为 Inspector 暴露的内部字段、自动生成代码和名称已完整表达语义的简单成员，可按项目约定豁免。
- 🟡 有参数、返回值、异常契约或调用限制时，按实际需要使用 `<param>`、`<returns>`、`<exception>`、`<remarks>` 等标签；不得为了凑格式写无意义标签。

```csharp
/// <summary>
/// 对目标造成伤害并通知订阅者。
/// </summary>
/// <param name="amount">伤害值，正数。</param>
public void ApplyDamage(int amount) { }
```

### 8.2 // 单行注释

- 🔴 普通注释用 `//`
- 🔴 注释前后空一格（`// 注释内容`，不是 `//注释内容`）

```csharp
// 这是单行注释（✅ 前后空一格）
//这是注释（❌ 没空一格）
```

### 8.3 `/* */` 块注释（默认不用）

- ❌ **禁止**把 `/* */` 作为普通业务说明或多行说明的默认写法。
- 🟢 仅在不可改动的第三方/生成代码、授权声明或项目既有工具指令明确要求时保留；不得因方便排版而新增。
- 🔴 需要连续说明多个业务步骤或约束时，使用连续的 `//` 中文注释。

### 8.4 多行注释（按执行顺序逐行对应）

1. **使用 `//` 逐行写，不用 `/* */`**
2. **按表达需要决定单行或连续多行**；不以固定行数机械拆分或合并
3. **注释与被注释代码按执行顺序逐行对应**，不集中堆在方法开头
4. **每行注释独立、可独立删除**
5. **方法内存在明确先后依赖的处理步骤时，用连续序号标注**：统一写为 `// 1、说明`、`// 2、说明`、`// 3、说明`；序号对应一个完整的业务步骤，不为逐行代码机械编号

```csharp
// ✅ 好：注释与代码按执行顺序逐行对应
private void HandleDamage(int amount)
{
    // 1、边界检查：负数或零视为无效
    if (amount <= 0) return;

    // 2、状态检查：已死亡不再受伤害
    if (!m_isAlive) return;

    // 3、应用伤害并通知订阅者
    m_health -= amount;
    OnHealthChanged?.Invoke(m_health);
}

// ❌ 错：注释集中堆在方法开头（与代码脱节）
private void HandleDamageBad(int amount)
{
    // 边界检查 / 状态检查 / 应用伤害并通知订阅者
    if (amount <= 0) return;
    if (!m_isAlive) return;
    m_health -= amount;
    OnHealthChanged?.Invoke(m_health);
}

// ❌ 错：用 /* */ 块注释（与字符串中的 */ 冲突）
/*
 * 这是一个块注释
 * 里面如果出现字符串 "*/" 就会结束
 */
```

### 8.5 TODO / FIXME / HACK 格式

- 🟡 统一格式：`// TAG: 描述`
- 常见标签：
  - `// TODO:` 待办事项
  - `// FIXME:` 已知问题
  - `// HACK:` 临时方案 / 取巧写法
  - `// NOTE:` 重要说明
  - `// XXX:` 危险，需关注

```csharp
// TODO: 优化碰撞检测性能
// FIXME: 边界值未处理，可能越界
// HACK: 临时用反射访问私有字段
```


## 9. 速查表

| 项目 | 规则 |
|------|------|
| **缩进** | 4 空格，禁用 Tab |
| **行宽** | ≤ 120 字符 |
| **大括号** | Allman 风格（左大括号单独成行） |
| **运算符空格** | 两侧各一空格（`a + b`） |
| **逗号空格** | 逗号后一空格（`f(a, b)`） |
| **方括号空格** | 内侧无空格（`arr[i]`） |
| **关键字后空格** | if / while / for 后空一格（`if (x)`） |
| **空行** | 方法间空一行，逻辑段落间空一行 |
| **using 顺序** | System → Unity → 第三方 → 项目 |
| **region 使用** | 谨慎使用，仅 Animation/Input Event 允许 |
| **集合初始化器** | 每行一个元素，复杂时右括号单独一行 |
| **字符串字面量** | 用双引号 `"..."` |
| **字符串插值** | 用 `$"..."` |
| **verbatim 字符串** | 多行 / 路径 / 正则用 `@"..."` |
| **注释格式** | `// 单行` / `/// XML`（公开 API）/ 不用 `/* */` |
| **TODO 格式** | `// TODO: 描述` |
| **文件编码** | UTF-8 无 BOM |
| **换行符** | LF |
| **文件末尾** | 一个空行 |
| **文件名** | = 类名 |
