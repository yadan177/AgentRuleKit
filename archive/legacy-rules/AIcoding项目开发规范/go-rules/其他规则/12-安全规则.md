# 12 - Go 安全规则

> - 🟢 本文件适用于 Go 项目中涉及安全相关的代码（认证/鉴权/加密/OWASP）。
> - 🔴 不适用：业务逻辑实现、UI 样式设计

---

## 1. OWASP Top 10 概览

### 1.1 2025 版 OWASP Top 10

⚠️ **安全**：

- 涉及 Web 应用安全边界时，以 [OWASP Top 10 当前版本](https://owasp.org/Top10/) 作为风险意识和检查起点。
- OWASP Top 10 是安全意识文档，不替代项目威胁模型、组织安全基线、ASVS 或专项测试。

| # | 风险 | 简述 | Go 影响 |
|---|---|---|---|
| A01 | **Broken Access Control**（失效的访问控制） | 越权访问或修改资源 | 在 handler 与业务层校验主体、资源和动作 |
| A02 | **Security Misconfiguration**（安全配置错误） | 调试接口、默认权限或部署配置暴露 | 检查 pprof、CORS、TLS、错误信息和环境配置 |
| A03 | **Software Supply Chain Failures**（软件供应链失效） | 依赖、构建或发布链被污染 | 锁定来源与版本，审查依赖和 CI 权限 |
| A04 | **Cryptographic Failures**（加密失败） | 弱算法、密钥或敏感数据保护错误 | 使用项目批准的标准库/API 和密钥管理方案 |
| A05 | **Injection**（注入） | SQL、命令、模板等注入 | 参数化查询、输入边界和命令参数隔离 |
| A06 | **Insecure Design**（不安全设计） | 设计层缺少滥用与风险控制 | 建立威胁模型、速率限制和失败策略 |
| A07 | **Authentication Failures**（认证失败） | 会话、凭据或认证流程缺陷 | 复用项目认证体系并验证生命周期 |
| A08 | **Software or Data Integrity Failures**（软件或数据完整性失效） | 未验证的数据、更新或流水线产物 | 校验签名、来源、权限和发布完整性 |
| A09 | **Security Logging and Alerting Failures**（安全日志与告警失效） | 攻击不可追踪或无法响应 | 记录必要审计事件并接入现有告警流程 |
| A10 | **Mishandling of Exceptional Conditions**（异常条件处理不当） | 异常、资源耗尽或失败状态处理错误 | 明确超时、取消、回滚、限流和安全失败模式 |

### 1.2 Go 特有的安全问题（AI 视角扩展）

⚠️ **安全**：Go 语言本身的特性也会引入安全风险

| 问题 | 影响 | 防护 |
|---|---|---|
| **Nil pointer dereference** | 崩溃 panic | 在可为空的信任边界校验；内部可由构造器和类型不变量保证非空 |
| **Slice out of bounds** | 崩溃 panic | `if i < 0 || i >= len(s)` 边界检查 |
| **Goroutine 泄漏** | 内存耗尽 | goroutine 必须有退出条件 / context 可取消 |
| **Race condition** | 数据竞争导致数据损坏 | 对并发路径运行 race 测试并审查所有权；未执行路径仍需人工/静态分析 |
| **资源泄漏** | 文件句柄 / 连接耗尽 | 在所有权边界关闭；循环可抽取单次处理函数后使用 defer |
| **Go module 供应链风险** | 恶意代码注入 | 保持 `go.sum`、使用受控 GOPROXY/GOSUMDB 策略并执行依赖审查；`GOSUMDB` 不是 `on` 开关 |
| **`unsafe` 包误用** | 内存越界 / 指针篡改 | 🔴 **除非必要，否则禁止使用 `unsafe` 包** |

### 1.3 安全开发基本原则

⚠️ **安全**（业界公认）：

1. **深度防御（Defense in Depth）**：多层安全控制，不是单点
2. **最小权限原则（Least Privilege）**：每个 goroutine / 服务 / 用户只给最少权限
3. **白名单优于黑名单**：明确"允许的"而不是"禁止的"
4. **默认安全（Secure by Default）**：默认配置就是安全的（如不开放 pprof 到公网）
5. **失败要安全（Fail Securely）**：出错时拒绝而不是放行
6. **不信任输入（Never Trust User Input）**：所有外部输入视为不可信
7. **不保存不必要的数据（Don't Store What You Don't Need）**

## 2. 🟠 认证与授权

### 2.1 认证 vs 授权

🟢 **参考**：

- **认证（Authentication）**：你是谁？（登录）
- **授权（Authorization）**：你能干什么？（权限控制）

### 2.2 密码安全

⚠️ **安全**：

- **密码绝不以明文存储**（数据库被攻破 → 用户密码全部泄露）
- 哈希算法必须用 **强密码哈希**：BCrypt / Argon2id
- **不要用**：MD5 / SHA1 / SHA256 + salt（已被证明可破解 / 不抗 GPU 暴力破解）

✅ **正例**（Go 用 `golang.org/x/crypto/bcrypt`）：

```go
import "golang.org/x/crypto/bcrypt"

// cost 由部署硬件、登录延迟和拒绝服务预算基准测试确定，并保存在配置中。
func HashPassword(password string, cost int) (string, error) {
    bytes, err := bcrypt.GenerateFromPassword([]byte(password), cost)
    return string(bytes), err
}

// 比对密码（正确返回 nil，错误返回 error）
func CheckPasswordHash(password, hash string) bool {
    err := bcrypt.CompareHashAndPassword([]byte(hash), []byte(password))
    return err == nil
}
```

❌ **反例**：

```go
// ❌ MD5（已被破解，彩虹表秒破）
import "crypto/md5"
h := md5.Sum([]byte(password))  // 废弃！

// ❌ SHA-256 + salt（不抗 GPU 暴力破解，且没有内存硬度）
import "crypto/sha256"
h := sha256.Sum256([]byte(password + salt))  // 废弃！

// ❌ 自制哈希（绝不要）
hash := strings.ToUpper(password) + "_salt_2024"  // 绝对不要！
```

### 2.3 密码强度策略

⚠️ **安全**：

- 密码长度、最大长度和认证器要求遵循产品风险、法规与身份平台策略；面向普通用户时优先支持较长密码和密码管理器。
- 不把固定字符类别组合作为唯一强度标准；拒绝已泄漏、常见和与账号高度相关的密码。
- 登录、注册和重置流程必须配合限流、MFA/风险验证及安全的找回机制。

### 2.4 JWT 认证（AI 视角扩展）

🟡 **推荐**：

- JWT 是一种常见的签名声明格式，不是所有无状态认证场景的默认选型；Session、不透明 token 和平台代理身份同样可能更合适。
- **Go 用成熟库**：`github.com/golang-jwt/jwt/v5`（不要用 `dgrijalva/jwt-go`，已停止维护）
- **不要自己手写 JWT 实现**

```go
import (
    "fmt"
    "strconv"
    "time"

    "github.com/golang-jwt/jwt/v5"
)

type AccessClaims struct {
    UserID uint `json:"uid"`
    jwt.RegisteredClaims
}

// 生成 JWT（HS256 对称签名，不是加密）
func GenerateToken(userID uint, secret []byte) (string, error) {
    if len(secret) < 32 {
        return "", fmt.Errorf("HS256 key must be at least 32 bytes")
    }
    now := time.Now()
    claims := AccessClaims{
        UserID: userID,
        RegisteredClaims: jwt.RegisteredClaims{
            Subject:   strconv.FormatUint(uint64(userID), 10),
            Issuer:    "myapp",
            Audience:  jwt.ClaimStrings{"myapp-api"},
            IssuedAt:  jwt.NewNumericDate(now),
            ExpiresAt: jwt.NewNumericDate(now.Add(15 * time.Minute)),
        },
    }

    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString(secret)
}

// 验证 JWT
func ValidateToken(tokenString string, secret []byte) (*AccessClaims, error) {
    if len(secret) < 32 {
        return nil, fmt.Errorf("HS256 key must be at least 32 bytes")
    }
    claims := new(AccessClaims)
    token, err := jwt.ParseWithClaims(tokenString, claims, func(token *jwt.Token) (any, error) {
        return secret, nil
    }, jwt.WithValidMethods([]string{jwt.SigningMethodHS256.Alg()}), jwt.WithExpirationRequired(),
        jwt.WithIssuer("myapp"), jwt.WithAudience("myapp-api"))

    if err != nil {
        return nil, err
    }

    if token.Valid {
        return claims, nil
    }
    return nil, fmt.Errorf("invalid token")
}
```

⚠️ **安全**：

- 使用 HS256 时，密钥至少应有 256 位有效随机性并支持轮换；RSA/ECDSA/EdDSA 使用各自的密钥要求，不能套用 HMAC 长度。
- **Access Token 短期**（15-60 分钟）+ **Refresh Token 长期**（几天到几周）
- **不要把敏感数据放 JWT payload**（payload 只是 base64 编码，**不加密**！）
- **JWT 必须用 HTTPS 传输**（防止中间人）
- **刷新 Access Token 时同时 rotation Refresh Token**
- **必须验证 `alg` 算法头**（防 `none` 算法攻击）——上面代码已包含

### 2.6 Go HTTP 中间件认证

🟡 **推荐**：Go 用标准 `net/http` middleware 模式或 Gin 框架：

```go
// 标准 net/http 认证中间件
type userIDContextKey struct{}

func AuthMiddleware(secret []byte, next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        authHeader := r.Header.Get("Authorization")
        if authHeader == "" || !strings.HasPrefix(authHeader, "Bearer ") {
            w.WriteHeader(http.StatusUnauthorized)
            return
        }

        tokenString := strings.TrimPrefix(authHeader, "Bearer ")
        claims, err := ValidateToken(tokenString, secret)
        if err != nil {
            w.WriteHeader(http.StatusUnauthorized)
            return
        }

        // ✅ userID 注入 context（下游 handler 用）
        ctx := context.WithValue(r.Context(), userIDContextKey{}, claims.UserID)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

// 使用中间件
mux := http.NewServeMux()
mux.Handle("/api/orders", AuthMiddleware(jwtSecret, http.HandlerFunc(ordersHandler)))
```

⚠️ **安全**：

- Cookie 是否承载 JWT 取决于会话架构；Secure、HttpOnly、合适的 SameSite 和 CSRF 防护都需要按登录流程配置，不能只靠 SameSite=Strict 判定安全。
- **登录失败要统一错误提示**（不区分"用户不存在" vs "密码错误" → 防账号枚举攻击）

### 2.7 多因子认证（MFA）

🟡 **推荐**：

- 高安全场景（支付 / 后台 / 改密）启用 MFA
- Go 库：`github.com/pquerna/otp`（TOTP 标准实现，Google Authenticator 兼容）
- 因素：密码 / 手机短信 / 邮箱验证码 / TOTP / 硬件 U2F
- **不应只有单一密码**

### 2.8 水平越权 vs 垂直越权

⚠️ **安全**（Go 最高发安全漏洞之一）：

- **隶属于用户个人的页面或者功能必须进行权限控制校验**
- 防止没有做水平权限校验就可随意访问、修改、删除别人的数据
- 比如查看他人的私信内容、修改他人的订单

```go
// ❌ 水平越权（任何人能查任何订单）
func GetOrder(w http.ResponseWriter, r *http.Request) {
    orderID := r.URL.Query().Get("id")
    order, _ := db.GetOrder(orderID)  // 没检查 order.UserID == currentUser
    json.NewEncoder(w).Encode(order)
}

// ✅ 水平越权防护
func GetOrder(w http.ResponseWriter, r *http.Request) {
    // 从 context 拿当前登录用户 ID（中间件注入）
    currentUserID, ok := r.Context().Value("userID").(uint)
    if !ok {
        w.WriteHeader(http.StatusUnauthorized)
        return
    }

    orderID := r.URL.Query().Get("id")
    order, err := db.GetOrder(orderID)
    if err != nil {
        w.WriteHeader(http.StatusNotFound)
        return
    }

    // 🔴 必须校验：订单归属 == 当前用户
    if order.UserID != currentUserID {
        // 不要直接 return 403 Forbidden，避免泄露订单是否存在
        // 可以返回 404 或统一"无权访问"
        w.WriteHeader(http.StatusForbidden)
        return
    }

    json.NewEncoder(w).Encode(order)
}
```

## 3. 🟠 注入攻击防御

### 3.1 SQL 注入

⚠️ **安全**（Go 最高发安全漏洞）：

- **所有用户输入的 SQL 参数严格使用参数绑定（? 占位符）**
- **禁止字符串拼接 SQL**（`fmt.Sprintf("...%s...", input)`）
- **Go `database/sql` 包天然支持参数绑定**，务必使用

✅ **正例**：

```go
import "database/sql"

// ✅ 参数绑定（防注入）
func GetUserByID(db *sql.DB, userID string) (*User, error) {
    var user User
    // ? 是占位符，database/sql 自动处理转义
    err := db.QueryRow("SELECT id, name FROM users WHERE id = ?", userID).
        Scan(&user.ID, &user.Name)
    return &user, err
}

// ✅ 多个参数同样用 ?
func CreateUser(db *sql.DB, name, email string) error {
    _, err := db.Exec(
        "INSERT INTO users (name, email) VALUES (?, ?)",
        name, email,  // 按顺序填参数
    )
    return err
}
```

❌ **反例**：

```go
// ❌ 字符串拼接（注入风险！）
func GetUserByName(db *sql.DB, name string) (*User, error) {
    // 攻击者输入 name = "' OR 1=1 --"
    // SQL 变成: SELECT * FROM users WHERE name = '' OR 1=1 --'
    // 结果：返回所有用户！
    query := fmt.Sprintf("SELECT * FROM users WHERE name = '%s'", name)
    rows, err := db.Query(query)
    // ...
}

// ❌ 同样危险：字符串拼接（即使是用 strings.Builder）
query := strings.Builder{}
query.WriteString("SELECT * FROM users WHERE name = '")
query.WriteString(name)  // name 可以注入
query.WriteString("'")
```

🟡 **GORM / sqlx / sqlc 注意**：

- **GORM**：`.Where("name = ?", name)` 安全，但 `.Where(fmt.Sprintf("name = '%s'", name))` 危险
- **sqlx**：`sqlx.In` 用于 IN 子句安全
- **sqlc**：SQL 编译器，天然防注入（编译时生成参数化查询）

### 3.2 NoSQL 注入（MongoDB 等）

⚠️ **安全**：

- MongoDB / Elasticsearch 查询同样需要**参数化**
- **不要把用户输入直接拼到 BSON / JSON 查询对象**
- Go MongoDB 驱动：`go.mongodb.org/mongo-driver/mongo` 用 `bson.M` 是安全的

```go
import "go.mongodb.org/mongo-driver/bson"

// ✅ 安全：用 bson.M 结构化查询（驱动自动处理）
func FindUserByName(ctx context.Context, coll *mongo.Collection, name string) (*User, error) {
    filter := bson.M{"name": name}  // name 作为值传入，安全
    var user User
    err := coll.FindOne(ctx, filter).Decode(&user)
    return &user, err
}

// ❌ 危险：如果 name 是 bson.M（来自用户输入 JSON）
// 攻击者可以传 {"$gt": ""} 这样的查询操作符，绕过条件
func DangerousFind(ctx context.Context, coll *mongo.Collection, name interface{}) (*User, error) {
    filter := bson.M{"name": name}  // name 可能是 bson.M 操作符！
    // ...
}
```

### 3.3 OS 命令注入

⚠️ **安全**：

- **避免使用 `os/exec` 执行命令**
- 如必须：使用 `exec.Command(name, args...)` **参数列表形式**（不拼字符串）
- **`exec.Command` 第一个参数是命令名，第二个开始是独立参数** — Go 不会用 shell 解析，安全

```go
import "os/exec"

// ✅ 安全：参数独立（不通过 shell，不会注入）
func ListFiles(dir string) ([]byte, error) {
    // 第一个参数命令名，后面每个参数独立传。不拼字符串！
    cmd := exec.Command("ls", "-la", dir)  // dir 作为独立参数，不会被 shell 解析
    return cmd.Output()
}

// ❌ 危险：通过 shell 执行（bash -c）会被注入
func DangerousList(dir string) ([]byte, error) {
    // 攻击者输入 dir = "/ ; rm -rf /"
    // 执行: bash -c "ls -la / ; rm -rf /"
    cmd := exec.Command("bash", "-c", "ls -la "+dir)  // 字符串拼接，注入风险
    return cmd.Output()
}
```

🔴 **绝对禁止**：

- 不要用 `bash -c` / `sh -c` 去执行包含用户输入的命令字符串
- 不要拼任何用户输入到命令字符串

### 3.4 JSON 反序列化安全

⚠️ **安全**（Go 独有的特性）：

- Go `encoding/json` 是安全的（不会执行代码，只解析数据）
- 但**超大 JSON 可能导致内存耗尽**（DoS）
- 用 `io.LimitReader` 限制 JSON 大小

```go
import (
    "errors"
    "io"
)

// ✅ 安全：限制请求体大小（防 DoS）
maxBytes := int64(1024 * 1024) // 示例值，按接口契约配置
r.Body = http.MaxBytesReader(w, r.Body, maxBytes)
body, err := io.ReadAll(r.Body)
if err != nil {
    var maxErr *http.MaxBytesError
    if errors.As(err, &maxErr) {
        w.WriteHeader(http.StatusRequestEntityTooLarge)
    } else {
        w.WriteHeader(http.StatusBadRequest)
    }
    return
}

var req CreateOrderRequest
if err := json.Unmarshal(body, &req); err != nil {
    w.WriteHeader(http.StatusBadRequest)
    return
}
```

### 3.5 XSS（跨站脚本）

⚠️ **安全**：

- **禁止向 HTML 页面输出未经安全过滤或未正确转义的用户数据**
- Go 标准库 `html/template` 默认自动转义！（安全）
- 但 `text/template` **不会转义**，不要用于 HTML

✅ **正例**（用 `html/template`）：

```go
import "html/template"  // ✅ 自动 HTML 转义

// 模板渲染时，{{.Name}} 会自动被转义
t := template.Must(template.New("").Parse(`<div>Hello {{.Name}}</div>`))

// 如果 user.Name = "<script>alert(1)</script>"
// 渲染结果是: <div>Hello &lt;script&gt;alert(1)&lt;/script&gt;</div>
// 自动转义，安全！
```

❌ **反例**（用 `text/template` 渲染 HTML）：

```go
import "text/template"  // ❌ 不转义！XSS 风险

// 这里 {{.Name}} 原样输出，直接被注入脚本
t := template.Must(template.New("").Parse(`<div>Hello {{.Name}}</div>`))
```

🟡 **推荐**：

- React/Vue 的普通文本插值默认转义，但 `dangerouslySetInnerHTML`、`v-html`、URL、CSS 和第三方富文本仍需按对应上下文做校验与净化。
- **Content-Security-Policy header**（防 XSS 兜底）：

```go
w.Header().Set("Content-Security-Policy",
    "default-src 'self'; script-src 'self'")  // 只允许本域脚本
```

### 3.6 CSRF（跨站请求伪造）

⚠️ **安全**：

- 浏览器会自动携带 Cookie、客户端证书等环境凭据时，所有改变状态的表单和异步请求都必须纳入 CSRF 防护。
- CSRF 是攻击站点诱导浏览器携带用户在目标站点 B 的 Cookie，向目标站点 B 发起非预期请求。

⚠️ **安全**：

- **仅使用显式 Authorization header 且凭据不会由浏览器自动附带的接口**：通常不受传统 CSRF 影响，但仍需处理 XSS、CORS 和 token 泄漏。
- **Cookie Session 项目**：使用项目框架支持的 CSRF token、Origin/Referer 校验和合适的 SameSite 等组合防护；不能只凭请求来自 AJAX 或设置了 CORS 就判定安全。

- 🔴 沿用项目已有且维护中的 CSRF 中间件或框架能力，并核对 token 生成/校验、SameSite、CORS、代理 HTTPS 和密钥轮换。
- 🔴 不得从本节引入 Gorilla、Gin、Echo 或其他框架/中间件，也不得把示例密钥写入代码。

### 3.7 ReDoS（正则拒绝服务）

⚠️ **安全**：

- Go 标准库 `regexp` 使用 RE2 语法和线性时间匹配，避免了灾难性回溯，但超大输入、复杂表达式和高请求量仍可造成 CPU/内存拒绝服务。
- 🔴 在进入匹配前限制输入长度和请求成本，并对实际表达式做基准或压力验证。

- `regexp` 匹配 API 不接收 `context.Context`；仅创建 `context.WithTimeout` 不能中断正在执行的匹配。需要可取消边界时，在上层限制输入/并发并采用支持取消的任务设计。

## 4. 🟠 访问控制（AI 视角扩展）

P3C 只讲了"水平权限校验"，AI 视角补全 4 类访问控制。

### 4.1 4 类访问控制模型

| 模型 | 适用 | Go 实现 |
|---|---|---|
| **DAC（Discretionary）** | 资源所有者决定谁能访问 | ACL 列表（map / DB） |
| **MAC（Mandatory）** | 操作系统级别 | OS 实现（SELinux 等） |
| **RBAC（Role-Based）** | 角色边界稳定且权限可按角色聚合的系统 | 项目已有策略引擎或自研授权层 |
| **ABAC（Attribute-Based）** | 复杂策略（资源 / 时间 / 位置） | Open Policy Agent (OPA) / Casbin ABAC |

🟡 授权模型必须根据资源所有权、租户、角色稳定性、属性条件和审计要求选择；不得因本表自动引入 Casbin、OPA 或其他策略库。项目已有授权模型时沿用其契约。

### 4.2 RBAC 实现

🟡 **推荐**：

- 角色：`ADMIN` / `USER` / `GUEST` 等
- 权限：`order:read` / `order:create` / `user:delete` 等（对象:动作）

```go
// 简单 RBAC 中间件
func RequireRole(requiredRole string, next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 从 context 拿用户角色（登录时注入）
        userRole, ok := r.Context().Value("role").(string)
        if !ok {
            w.WriteHeader(http.StatusUnauthorized)
            return
        }

        // 检查角色
        if userRole != requiredRole && userRole != "ADMIN" {
            w.WriteHeader(http.StatusForbidden)
            return
        }

        next.ServeHTTP(w, r)
    })
}

// 使用：只有 ADMIN 能访问
mux.Handle("/api/admin/users", RequireRole("ADMIN", http.HandlerFunc(adminUsersHandler)))
```

### 4.3 默认安全原则

⚠️ **安全**（用户没明确要的就不开放）：

- 新接口**默认需要登录**（不是默认公开）
- 新接口**默认需要登录用户必须是本人**（水平越权防护）
- **新增管理接口必须显式声明**（`RequireRole("ADMIN")`）
- **不要写 `if isAdmin { ... } else { ... }` 这种模式** — 容易漏掉分支

## 5. 🟠 敏感数据保护

### 5.1 常见敏感字段

⚠️ **安全**（必须脱敏或加密）：

| 字段 | 静态存储 | 日志 | 前端展示 | API 返回 |
|---|---|---|---|---|
| **手机号** | 加密（AES-GCM）| `138****1234` | `138****1234` | `138****1234` |
| **身份证** | 加密（AES-GCM）| `110101****1234` | 不展示原文 | `110101****1234` |
| **银行卡** | 加密（AES-GCM）| 前 4 后 4 | 前 4 后 4 | 前 4 后 4 |
| **邮箱** | 明文（业务需要）| `z****@example.com` | `z****@example.com` | `z****@example.com` |
| **密码** | **强哈希**（BCrypt）| **不记日志** | **不返回** | **不返回** |
| **姓名** | 明文 | `张*` | 明文 | 明文 |
| **地址** | 明文 | 详细到街道级**需脱敏** | 明文 | 明文 |

### 5.2 Go 脱敏实现

🟡 **推荐**：

```go
// 手机号脱敏
func MaskPhone(phone string) string {
    if len(phone) < 7 {
        return "***"
    }
    return phone[:3] + "****" + phone[len(phone)-4:]
}

// 邮箱脱敏
func MaskEmail(email string) string {
    parts := strings.SplitN(email, "@", 2)
    if len(parts) != 2 {
        return "***"
    }
    name := parts[0]
    if len(name) <= 1 {
        return "*@" + parts[1]
    }
    return name[:1] + "***@" + parts[1]
}
```

### 5.3 加密 vs 哈希

🟢 **参考**：

- **加密（Encryption）**：可逆（有密钥就能解密）— 适合**需要原文还原**的数据
- **哈希（Hash）**：不可逆（单向）— 适合**不需要原文还原**的数据（如密码）

### 5.4 Go 加密算法选择

⚠️ **安全**：

- ✅ **对称加密**：AES-GCM（Go `crypto/aes` + `crypto/cipher`，AEAD 模式）
- ✅ **非对称加密**：RSA 2048+ / ECDSA P-256（`crypto/rsa` / `crypto/ecdsa`）
- ✅ **密码哈希**：BCrypt（cost=12+）/ Argon2id（`golang.org/x/crypto/argon2`，推荐）
- ❌ **不要用**：DES / 3DES / RC4 / MD5 / SHA1（已破解或不安全）

✅ **AES-GCM 正确示例**：

```go
import (
    "crypto/aes"
    "crypto/cipher"
    "crypto/rand"
    "io"
)

// AES-GCM 加密（带认证的 AEAD 模式，推荐）
func Encrypt(plaintext []byte, key []byte) ([]byte, error) {
    block, err := aes.NewCipher(key)
    if err != nil {
        return nil, err
    }

    // GCM 模式
    aesgcm, err := cipher.NewGCM(block)
    if err != nil {
        return nil, err
    }

    // Nonce 必须每条消息随机生成（GCM 推荐 12 字节）
    nonce := make([]byte, aesgcm.NonceSize())
    if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
        return nil, err
    }

    // 加密：输出 = nonce + ciphertext + tag（自动包含认证标签）
    ciphertext := aesgcm.Seal(nonce, nonce, plaintext, nil)
    return ciphertext, nil
}

// AES-GCM 解密
func Decrypt(ciphertext []byte, key []byte) ([]byte, error) {
    block, err := aes.NewCipher(key)
    if err != nil {
        return nil, err
    }

    aesgcm, err := cipher.NewGCM(block)
    if err != nil {
        return nil, err
    }

    // 拆分 nonce 和 ciphertext
    nonceSize := aesgcm.NonceSize()
    if len(ciphertext) < nonceSize {
        return nil, fmt.Errorf("ciphertext too short")
    }

    nonce, ciphertext := ciphertext[:nonceSize], ciphertext[nonceSize:]
    return aesgcm.Open(nil, nonce, ciphertext, nil)  // 认证失败返回 error
}
```

⚠️ **注意**：AES 密钥必须是 **16 / 24 / 32 字节**（对应 AES-128 / AES-192 / AES-256）。

## 6. 🟠 API 安全（AI 视角扩展）

### 6.1 HTTPS 必须

⚠️ **安全**：

- **生产环境所有 API 必须走 HTTPS**
- **不要**用 HTTP（明文传输，被中间人攻击）
- Go `net/http` 直接支持 TLS：

```go
// ✅ HTTPS 服务
// 应用直终止 TLS 时使用 ListenAndServeTLS；也可由可信反向代理/服务网格终止 TLS，
// 但必须保护代理到应用的链路并正确验证转发头。
http.ListenAndServeTLS(":443", "cert.pem", "key.pem", handler)

// ❌ 生产不要用 HTTP
http.ListenAndServe(":8080", handler)  // 仅开发环境！
```

### 6.2 CORS 配置安全

⚠️ **安全**：

- **不要用 `AllowedOrigins: "*"` + `AllowCredentials: true`**（浏览器禁止，安全风险）
- 明确允许的源白名单：

```go
import "github.com/rs/cors"  // 流行的 CORS 库

c := cors.New(cors.Options{
    AllowedOrigins:   []string{"https://app.example.com", "https://admin.example.com"},
    AllowedMethods:   []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
    AllowedHeaders:   []string{"Authorization", "Content-Type", "X-Trace-ID"},
    AllowCredentials: true,
    MaxAge:           3600,  // 预检缓存 1 小时
})

handler := c.Handler(mux)
http.ListenAndServe(":8080", handler)
```

### 6.3 限流（防爆破）

⚠️ **安全**：

- 登录、验证码和公开 API 必须按风险实施限流，但额度需基于账号、设备、可信代理后的客户端地址、业务成本和误伤预算确定，不使用通用固定数字。
- Go 库：`golang.org/x/time/rate`（标准限流器）或 `github.com/ulule/limiter/v3`

```go
import "golang.org/x/time/rate"

// limiterFor 必须按经过可信代理解析后的客户端键/账号键返回有界、可过期的 limiter。
func RateLimitMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        limiter := limiterFor(clientKey(r))
        if !limiter.Allow() {
            w.WriteHeader(http.StatusTooManyRequests)  // 429
            w.Write([]byte("Too many requests"))
            return
        }
        next.ServeHTTP(w, r)
    })
}
```

### 6.4 防重放（Nonce / Timestamp）

⚠️ **安全**：

- **重要操作（支付 / 转账）必须防重放**
- Timestamp + Nonce 只有与已认证请求内容绑定并由服务端原子占用时才有效：
  - 请求带 `timestamp`（秒级，±5 分钟内有效）+ `nonce`（UUID）
  - 服务端使用带过期的原子 `SET NX`（或等价事务）占用 nonce
  - 签名/认证覆盖方法、路径、规范化请求体、时间戳和 nonce；重复 nonce 直接拒绝

### 6.5 SSRF（服务端请求伪造）

⚠️ **安全**：

- 不要让用户输入 URL 服务端直接请求（攻击者让服务端访问 `http://169.254.169.254/latest/meta-data/` 拿云主机凭据）
- 优先使用固定目的地白名单。必须在实际连接时校验解析后的所有 IPv4/IPv6 地址，限制重定向，并考虑 DNS rebinding、代理环境、链路本地、保留地址和云元数据地址；只在请求前检查一次字符串 IP 不足以防护 SSRF。

```go
import "net"

func isSafeIP(ipStr string) bool {
    ip := net.ParseIP(ipStr)
    if ip == nil {
        return false
    }

    // 拒绝内网 / 环回 / 链路本地
    if ip.IsLoopback() || ip.IsLinkLocalUnicast() || ip.IsPrivate() {
        return false
    }
    return true
}
```

## 7. 🟠 会话管理

### 7.1 Session vs JWT

🟢 **参考**：

| 模式 | 状态 | 撤销 | 性能 | 适用 | Go 库 |
|---|---|---|---|---|---|
| **Session**（服务端）| 服务端存 | 可立即撤销 | 取决于存储方案 | 浏览器应用 / 后台 | 沿用项目已维护的 session 中间件 |
| **JWT**（无状态）| 客户端持有 | 需黑名单或短期 | 不查 DB | 移动端 / 微服务 | `golang-jwt/jwt/v5`（活跃维护） |
| **混合** | 短期 access token + 可撤销 refresh token | Refresh 撤销 | 中等 | 需跨端续期的系统 | 采用成熟身份服务或经过安全评审的实现 |

### 7.2 Cookie 安全标记

⚠️ **安全**：

- 生产 Cookie 通常应设置 Secure、HttpOnly 和适合流程的 SameSite；Domain、Path、过期和 SameSite 模式必须按子域、OAuth/SSO 和 host-only 边界决定。

```go
import "net/http"

http.SetCookie(w, &http.Cookie{
    Name:     "sessionId",
    Value:    "abc123",
    Path:     "/",
    // 默认不设置 Domain，使用 host-only Cookie；确需跨子域时再显式配置。
    Secure:   true,          // ✅ 只在 HTTPS 发送
    HttpOnly: true,          // ✅ 不能被 JS 读取（防 XSS 偷 cookie）
    SameSite: http.SameSiteLaxMode, // 示例；跨站登录流程可能需要其他模式和额外 CSRF 防护
    MaxAge:   cfg.SessionMaxAgeSeconds,
})
```

### 7.3 Session 过期

⚠️ **安全**：

- Session 应同时评估绝对过期与空闲超时；“30 分钟无活动”属于空闲超时，不是绝对过期。
- 关键操作（转账 / 改密）需要**重新认证**（即使 Session 没过期）

### 7.4 JWT 安全实践

⚠️ **安全**：

- **JWT 不能存敏感信息**（payload 只是 base64，**不是加密**！在线就能解码）
- JWT 签名算法、密钥类型和参数必须由威胁模型与身份系统确定；验证端锁定允许的算法，并使用与算法匹配、可轮换的密钥。不要用“HS256+ / RS256+”代替具体选型和密钥管理要求。
- **Access Token 短期**（15-60 分钟）+ **Refresh Token 长期**
- **Refresh Token rotation**（每次刷新生成新的 Refresh Token）
- Token 黑名单：Redis 存已撤销的 token（用户登出 / 改密时加入）

## 8. 🟠 文件上传安全

### 8.1 攻击向量

🟢 **参考**：

- **上传 WebShell**（`.go` 编译好的二进制文件被上传执行）
- **覆盖文件路径**（`../../etc/passwd`，路径穿越）
- **存储型 XSS**（文件名注入脚本，展示时被执行）
- **上传大文件 DoS**（耗尽磁盘 / 内存）

### 8.2 必须的多重防护

⚠️ **安全**：

- ✅ **白名单 MIME 类型**：`image/jpeg` / `image/png` / `application/pdf`
- ✅ **验证文件扩展名**（双验证：客户端 + 服务端）
- ✅ **验证文件内容 magic bytes**（文件头，如 PNG 是 `89 50 4E 47`）
- ✅ **重命名上传文件**：UUID + 扩展名，**不用用户输入文件名**
- ✅ **限制文件大小**（如 图片 ≤ 5MB，视频 ≤ 500MB）
- ✅ **存储到专门目录**（不在 WebRoot 直接放，避免被解释为脚本）
- ✅ **CDN / 对象存储**（阿里云 OSS / S3），不与应用服务器同机

✅ **正例**：

```go
func UploadHandler(w http.ResponseWriter, r *http.Request) {
    // 1. 限制请求体大小（防 DoS）
    r.Body = http.MaxBytesReader(w, r.Body, 5*1024*1024)  // 5MB 上限

    // 2. 解析 multipart form
    if err := r.ParseMultipartForm(5 * 1024 * 1024); err != nil {
        w.WriteHeader(http.StatusRequestEntityTooLarge)
        return
    }

    // 3. 取文件
    file, header, err := r.FormFile("file")
    if err != nil {
        w.WriteHeader(http.StatusBadRequest)
        return
    }
    defer file.Close()

    // 4. MIME 白名单
    // 4. 扩展名只用于辅助约束，不能信任客户端 Content-Type。
    ext := filepath.Ext(header.Filename)
    if !isAllowedExt(ext) {
        w.WriteHeader(http.StatusBadRequest)
        return
    }

    // 5. 基于实际读取字节检测内容类型
    buf := make([]byte, 512)
    n, err := io.ReadFull(file, buf)
    if err != nil && err != io.ErrUnexpectedEOF {
        w.WriteHeader(http.StatusBadRequest)
        return
    }
    detectedType := http.DetectContentType(buf[:n])
    if !isAllowedMIME(detectedType) {
        w.WriteHeader(http.StatusBadRequest)
        return
    }
    file.Seek(0, 0)  // 重置读指针

    // 7. 重命名（UUID + 扩展名，防路径穿越）
    newName := uuid.New().String() + ext
    safePath := filepath.Join("/upload/dir", filepath.Base(newName))  // Base 防穿越

    // 8. 存储到对象存储（不在本地）
    url, err := ossService.Upload(safePath, file)
    if err != nil {
        w.WriteHeader(http.StatusInternalServerError)
        return
    }

    json.NewEncoder(w).Encode(map[string]string{"url": url})
}
```

⚠️ **安全**：

- **防路径穿越**：`header.Filename` 可能含 `../../../etc/`，**用 `filepath.Base()` 截取最后一段**
- **不直接用用户输入构造路径**
- **文件权限 0644，可执行位必须去掉**（`chmod 644 file`）

## 9. 🟠 Go 特有安全实践

### 9.1 Race Condition（数据竞争）

🔴 **必加约束**：

- 对共享内存并发路径执行 race 测试；race detector 只覆盖实际运行路径，不能证明不存在竞争。
- CI 是否全量运行 `-race` 取决于平台、CGO、耗时和项目风险，可在专门任务中执行。
- 共享状态可通过锁、atomic、channel 所有权、不可变数据或串行执行保护，不限定为某一种原语。

```go
import "sync"

var (
    counter int
    mu      sync.Mutex
)

// ✅ 安全：互斥锁保护
func Inc() {
    mu.Lock()
    defer mu.Unlock()
    counter++
}

// ❌ 危险：并发读写无保护（race detector 会抓到）
func DangerousInc() {
    counter++
}
```

### 9.2 Goroutine 泄漏

🔴 **必加约束**：

- **每个 goroutine 必须有明确的退出条件**
- HTTP 请求内启动的同步工作应绑定请求 context；需要在响应后继续的后台任务必须转交有独立生命周期、持久化和关闭策略的任务系统。

```go
import "context"

func handler(w http.ResponseWriter, r *http.Request) {
    // 请求范围内并发：handler 等待结果后再返回
    ctx, cancel := context.WithTimeout(r.Context(), 5*time.Second)
    defer cancel()

    resultCh := make(chan Result, 1)
    go func() {
        select {
        case <-ctx.Done():
            return  // 请求取消或超时，退出
        case result := <-someWorkChan:
            resultCh <- result
        }
    }()
    select {
    case result := <-resultCh:
        writeResult(w, result)
    case <-ctx.Done():
        http.Error(w, "request canceled", http.StatusGatewayTimeout)
    }
}

// ❌ 危险：没有退出条件，goroutine 永远活着
func badHandler(w http.ResponseWriter, r *http.Request) {
    go func() {
        for {  // 无限循环！泄漏！
            time.Sleep(1 * time.Second)
        }
    }()
}
```

### 9.3 Defer 资源泄漏

🔴 **必加约束**：

- 获得资源所有权后必须在清晰的生命周期边界关闭；若所有权转移给长期对象，不能在创建函数中立即 defer Close。
- **循环内不要 defer Close()**（会累积到函数退出才执行）

```go
func processFiles(paths []string) error {
    for _, path := range paths {
        // ❌ 危险：循环内 defer — 文件句柄累积泄漏
        f, err := os.Open(path)
        if err != nil {
            return err
        }
        defer f.Close()  // 循环结束前不会执行！
    }
    return nil
}

// ✅ 正例 1：循环内用闭包包裹
func processFilesGood(paths []string) error {
    for _, path := range paths {
        if err := func() error {
            f, err := os.Open(path)
            if err != nil {
                return err
            }
            defer f.Close()  // 闭包退出就执行 ✅
            // 处理 f...
            return nil
        }(); err != nil {
            return err
        }
    }
    return nil
}

// ✅ 正例 2：显式 Close（不用 defer）
func processFilesExplicit(paths []string) error {
    for _, path := range paths {
        f, err := os.Open(path)
        if err != nil {
            return err
        }
        // 处理 f...
        f.Close()  // 显式关闭
    }
    return nil
}
```

### 9.4 禁止 `unsafe` 包

🔴 **必加约束**：

- **除非万不得已（调用 C / 底层优化），否则禁止使用 `unsafe` 包**
- `unsafe` 可以：
  - 绕过 Go 类型系统 → 内存越界 → 崩溃 / 代码注入
  - 修改只读内存 → 破坏常量
  - 指针运算 → UAF / 越界读写

项目已经配置 `govet`、Staticcheck、golangci-lint 或代码审查门禁时，沿用其 `unsafe` 策略；简单 grep 可能命中注释和生成代码，不能作为所有项目的统一拦截器。

### 9.5 nil 指针 / slice 越界 崩溃

🟡 **推荐**：

- 在 nil、索引或 key 可能来自不可信输入且调用契约没有保证时显式校验；不要为编译器或前置逻辑已经证明安全的访问机械添加检查。
- 未在发生 panic 的同一 goroutine 中 recover 的 panic 会终止整个 Go 进程；recover 只应放在项目确认的请求/任务隔离边界，并记录失败、清理资源和返回受控错误。

## 10. 🟠 依赖漏洞扫描

### 10.1 Go 官方漏洞扫描候选：govulncheck

⚠️ **安全**：

- 项目 CI、发布流程或安全规范已经采用 `govulncheck` 时，按锁定版本和既有参数执行。
- 尚未采用时，可在依赖升级、安全审查或发布门禁设计中评估；安装工具和新增 CI 门禁需要授权。
- `govulncheck` 使用 Go 漏洞数据库和调用图分析，但结果仍需结合构建标签、部署路径和其他供应链扫描判断。

```bash
# 仅在项目明确采用时安装已验证并锁定的版本
go install golang.org/x/vuln/cmd/govulncheck@<已验证版本>

# 扫描当前项目
govulncheck ./...
```

### 10.2 其他工具

- **Snyk**：项目已采用该平台时按既有策略执行
- **Dependabot**：GitHub 仓库已采用时按现有更新策略执行
- **Go module checksum**：`GOSUMDB=sum.golang.org`（默认开启，防依赖劫持）

### 10.3 漏洞响应流程

⚠️ **安全**：

- 按项目安全策略、漏洞可利用性、暴露面和补救难度确定响应时限；没有组织级 SLA 时不得由 AI 擅自承诺固定期限。

### 10.4 依赖更新原则

🟡 **推荐**：

- 根据漏洞影响和兼容性选择目标版本，不默认项目使用 gin、gorm、gRPC 等依赖。
- 升级前检查项目采用的公告来源、变更记录、迁移说明和测试范围。
- 优先逐个升级到明确版本并复核 `go.mod`、`go.sum`；避免用 `go get -u ./...` 批量改变无关依赖。

## 11. 🟠 安全配置与部署

### 11.1 pprof 安全

⚠️ **安全**：

- **生产环境 pprof 绝对不能暴露到公网**
- pprof 可以：堆分析 / goroutine 栈 / CPU profile → 泄露代码结构 / 内存数据
- 正确做法：
  - 只监听 `127.0.0.1:6060`（本地环回）
  - 或放在内网 VPN 后
  - 加认证中间件

```go
// ✅ 安全：只监听本地环回
go func() {
    log.Println(http.ListenAndServe("127.0.0.1:6060", nil))
}()

// ❌ 危险：监听所有网卡（0.0.0.0），公网可访问
go func() {
    log.Println(http.ListenAndServe(":6060", nil))  // 危险！
}()
```

### 11.2 Docker 容器安全

🟡 **推荐**：

- **用非 root 用户运行**：`USER appuser` 在 Dockerfile
- **不要用 `latest` tag**（不可重现）
- **多阶段构建**（最终镜像只含二进制，不含源码 / 构建工具）
- 基础镜像用官方镜像 + 固定 digest

```dockerfile
# ✅ 多阶段构建
# 将占位符、CGO 设置和运行依赖替换为项目在目标环境验证过的配置。
FROM <Go 构建镜像>@sha256:<digest> AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
# CGO 配置由项目构建环境按依赖和目标平台决定。
RUN go build -o /app/server ./cmd/server

# 最终运行阶段（用非 root 用户，不含构建工具）
FROM <运行时镜像>@sha256:<digest>
# 创建非 root 用户的命令取决于基础镜像；不要把 Alpine 的 adduser 参数套到其他发行版。
USER <运行镜像中已创建或自带的非 root 用户>
COPY --from=builder /app/server /server
EXPOSE 8080
ENTRYPOINT ["/server"]
```

### 11.3 安全 Header

🟡 **推荐**：HTTP 响应加安全 Header 中间件

```go
func SecurityHeadersMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 防 XSS / 点击劫持 / MIME 嗅探
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("X-Frame-Options", "DENY")
        // 现代浏览器主要依赖正确输出编码和 CSP；不再把已废弃的 X-XSS-Protection 当安全基线。
        w.Header().Set("Content-Security-Policy", "default-src 'self'")
        w.Header().Set("Referrer-Policy", "strict-origin-when-cross-origin")
        next.ServeHTTP(w, r)
    })
}
```
