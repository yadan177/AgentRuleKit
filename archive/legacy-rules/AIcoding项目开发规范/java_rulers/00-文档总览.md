# Java AI 编码规则 · 文档总览（AI 入口）

---

## 🎯 规则撰写的核心原则

1. AI 编程规则的本质，是将项目中的架构边界、业务约束与编码规范转化为机器可执行的决策规则，使 AI 输出的不只是能运行的代码，而是符合团队工程标准、可维护且可扩展的代码。
2. 不要有 AI 幻觉。
3. 不要过度设计。

---

## 1. 适用范围

- ✅ Java 项目开发（新项目 / 维护 / 重构）
- ✅ Codex / Qoder / TRAE 及其他可读取项目规则的 AI 工具
- ✅ Spring Boot / MyBatis / JPA 等已被项目采用的企业级 Java 生态

> Spring、ORM、构建工具、日志和测试框架均按仓库现有依赖与团队约定选择；本规则中的示例不授权引入、替换或升级技术栈。

❌ 不适用：Java 语法教学、特定业务领域规则

---

## 2. 硬性约束

| 等级 | 标识 | 含义 |
|------|------|------|
| 必须 | 🔴 | 当前适用场景必须遵守；无法执行时说明原因、范围和风险 |
| 推荐 | 🟡 | 默认采用；项目事实不适用时说明理由，无须为规则本身增加代码注释 |
| 可选 | 🟢 | 按项目实际灵活选择 |
| 安全 | ⚠️ | 涉及对应威胁时必须处理，具体措施以项目威胁模型为准（见 12） |

## 5. 跨语言继承

无。Java 是独立基线，无上游语言继承。

源材料：[阿里 P3C 黄山版](https://github.com/alibaba/p3c)（黄山版基于 JDK 8，未涵盖 JDK 9+ 新特性——本目录已补充 var / record / sealed / 虚拟线程等现代 Java 内容）。
