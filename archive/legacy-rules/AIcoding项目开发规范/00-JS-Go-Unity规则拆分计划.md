# 00 - JS、Go 与 Unity 规则拆分计划

> - 🟢 本计划只覆盖 JavaScript/TypeScript、Go、Unity/PICO 开发规则的大文件治理。
> - 🔴 不适用：本轮扩展到 Java/Python，或为缩短文件删除安全边界、所有权和失败语义。

---

## 1. 拆分原则

1. AI 通用入口只保留执行顺序、项目事实检查、强制边界、专题路由、文档影响和交付门禁。
2. 专题正文优先保留决策表、适用条件、反模式、安全边界、所有权和失败语义。
3. 大型完整示例、框架教程、速查 API 和背景知识移动到同专题 `references/`，正文保留精确链接。
4. 每次只拆一个专题，拆分前后执行相对链接、标题、关键词和入口路由检查；不得全仓机械格式化。
5. 拆分不改变规则强度。若发现规则本身错误，先单独修正并评审，再进行物理移动。

## 2. 执行顺序

| 优先级 | 文件 | 处理方式 | 验收条件 |
|---|---|---|---|
| P0 | `unity_rulers/其他规则/05-UI Toolkit设计规则.md` | 保留版本/生命周期/订阅/绑定决策；将完整 UXML、USS、MVP 和控件速查示例拆到 `references/ui-toolkit/` | 正文可独立决策；示例链接有效；Unity 版本边界未丢失 |
| P1 | `go-rules/其他规则/01-代码编写规则.md` | 按错误/并发/资源/泛型拆参考；正文保留 Go doc、所有权和失败语义 | Go 工具契约、交叉链接和反例完整 |
| P1 | `go-rules/其他规则/12-安全规则.md` | 将完整中间件、Docker 和扫描配置移入安全参考 | 威胁模型、强制边界和验证要求仍在正文 |
| P2 | `go-rules/其他规则/02-模式设计.md` | 将模式教程和长示例移入设计参考 | 选择条件、反模式和并发边界可直接检索 |
| P2 | `js_rulers/其他规则/06-项目配置规则.md` | 按包管理、lint/format、构建/部署拆参考 | 不再包含无条件技术栈默认值 |

## 3. 本轮处理边界

- 已先修正会直接给出错误默认答案的 JS 项目配置、Go 构建/workspace 和 PICO 选型规则。
- 已新增独立 Vue 3 专题，避免 Vue 任务误入 React 专题。
- UI Toolkit 的 2400 余行物理拆分留在 P0 独立变更中进行，避免与本轮语义修正混合后难以复查。
- P0 拆分时先建立引用文件，再逐章移动并逐次运行只读检查；不得一次删除大段内容后再补链接。

## 4. 验证方式

每次拆分至少执行：

1. `scripts/check-rule-docs.sh`。
2. `git diff --check`。
3. 对移动前后的强制词、适用条件、失败语义和安全边界做关键词对照。
4. 从对应 AI 通用入口按一个真实任务走完整路由，确认无需加载全部参考文件。
