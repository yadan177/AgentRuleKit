# Go 项目规则入口

先阅读 `.agent-rules/go/13-AI通用入口规则.md`，再按 `.agent-rules/go/00-文档总览.md` 选择当前任务相关专题规则。

- 以 `go.mod`、已有代码、脚本和 CI 为事实来源；不要把规则示例当成依赖升级或技术迁移指令。
- 未获授权不得新增依赖、修改模块路径、替换框架或重构无关目录。
- 完成后运行与改动相称的现有验证；不能运行时说明原因、范围和风险。

## Go 实现任务的文档影响门禁

- 任何新增、修改或删除 Go 功能的任务，在开始实现前必须判断技术文档影响；不得等待用户另行提出文档任务。
- 涉及业务模块、路由、API、数据结构、数据库迁移、鉴权、配置、状态机、生命周期、部署、术语或验证结论变化时，必须读取 `.agent-rules/project-docs/go/其他规则/04-GoAI技术文档任务入口.md` 和 `.agent-rules/project-docs/go/其他规则/01-技术文档组织与维护规范.md`。
- 受影响文档未同步时，不得将功能报告为完整完成。
- 确认不影响文档时，交付中必须写明“文档影响：无”及判断依据，不得静默跳过。
- 项目未导入 Go 技术文档规则或入口路径不存在时，必须报告缺失，不得假装已经执行。
