# Unity 版本相关指令

- ℹ️ 本项目使用 Unity 6.3。请确保使用适用于 Unity 6 或更高版本的最新资源与文档。
- ℹ️ 本项目使用较新的"Input System"，而非旧的"Input Manager"。
- ℹ️ 本项目使用较新的 UI Toolkit，而非旧的 UGUI 来构建 UI。
- ℹ️ 本项目使用 Universal Render Pipeline，而非旧的内置渲染管线。
- ℹ️ 在需要按序列执行时，优先使用 Unity 6 的 Awaitable 而不是协程：`await Awaitable.WaitForSecondsAsync(delay, token);`。续作记得用 `if (this == null || !isActiveAndEnabled) return;` 保护。
- ℹ️ 频繁实例化时，优先使用 `UnityEngine.Pool.ObjectPool<T>`，配合 `actionOnGet`/`actionOnRelease` 切换激活状态。

# 通用准则

## 格式

- ⚠️ 可读性至上。尽量保持单行短小，注意横向留白。
- ✅ 使用 Allman 风格（左大括号单独成行）。
- ✅ 定义一个标准最大行宽，小于 120–140 字符。
- ✅ 把长行拆成更小的语句，而不是让其超出。
- ✅ 在流程控制条件前加一个空格，如 `while (x == y)`。
- ❌ 避免在方括号内侧加空格，如 `x = dataArray[index]`。

```csharp
// 使用 Allman 风格与合适空格的好例子
public void ProcessItems(List<Item> items, int startIndex)
{
    for (int i = startIndex; i < items.Count; i++)
    {
        ProcessItem(items[i]);
    }

    // 这里的垂直空行用于视觉上的分隔
    Debug.Log("Processing complete");
}

// 避免这样
public void ProcessItems ( List<Item>items,int startIndex ) { for(int i=startIndex;i<items.Count;i++) { ProcessItem( items [ i ] ); } Debug.Log("Processing complete"); }
```

### 空格

- ✅ 在函数参数之间的逗号后加一个空格，如 `CollectItem(myObject, 0, 1);`。
- ❌ 不要在第一个或最后一个参数的圆括号内侧加空格，如避免 `CollectItem( myObject, 0, 1 );`。
- ❌ 函数名与左括号之间不要加空格，如避免 `DropPowerUp(myPrefab, 0, 1);`。
- ✅ 使用垂直空行（额外的空行）进行视觉分隔。
- ✅ 一般情况下每行声明一个变量，虽然稍显冗长，但更易读。
- ✅ 比较运算符前后各加一个空格，如 `if (x == y)`。

```csharp
// 良好的空格示例
public void ProcessItems(List<Item> items, int startIndex)
{
    for (int i = startIndex; i < items.Count; i++)
    {
        ProcessItem(items[i]);
    }

    // 这里的垂直空行用于视觉上的分隔
    Debug.Log("Processing complete");
}

// 不良的空格示例
public void ProcessItems ( List<Item>items,int startIndex ) { for(int i=startIndex;i<items.Count;i++) { ProcessItem( items [ i ] ); } Debug.Log("Processing complete"); }
```

### region 的使用
- ℹ️ 谨慎使用 `#region`，因为它会隐藏代码、降低可读性。
- ✅ 用 `#region` 把由动画系统等调用的 Animation Event Handlers 或 Input Event Handlers 分组，使其与其它代码分离。

```csharp
        #region Animation Event Methods
        // 该方法由动画事件触发，表示着地
        public void OnLand()
        {
            Debug.Log("OnLand called from animation event");
        }

        // 该方法由动画事件触发
        public void OnFootstep()
        {
            // 可用于播放脚步声
            Debug.Log("Footstep event triggered");
        }
        #endregion
```

- ✅ 给大多数行加上解释性注释以提供文档。
- ✅ 注释意图（"为什么"），而不是复述代码（"做了什么"）。
- ✅ 对于需要 Inspector 上下文的序列化字段，使用 `[Tooltip]`、`[Header]`、`[Space]` 等。

```csharp
// 好 - 解释为什么，而不仅仅是做了什么

    return;

```

## using 语句

- ✅ 把 `using` 语句放在文件顶部。
- ✅ 排序 `using` 语句能提升可读性并保证文件间一致，也能避免命名空间类名冲突。
- ✅ 先放系统命名空间（如 `System`、`System.Collections`）。
- ✅ 接着是 Unity 命名空间（如 `UnityEngine`）。
- ✅ 最后是项目特定命名空间（如 `MyGameProject.Utilities`）。
- ✅ 删除未使用的 `using`，保持文件整洁、避免不必要的依赖。

```csharp
// 系统命名空间
using System;
using System.Collections;
using System.Collections.Generic;

// Unity 命名空间
using UnityEngine;

// 项目特定命名空间
using MyGameProject.Utilities;
```

### 命名空间

- ✅ 使用命名空间，避免你的类、接口、枚举等与其他命名空间或全局命名空间冲突。
- ✅ 使用 PascalCase，不使用特殊符号或下划线。
- ✅ 使用点（`.`）运算符创建子命名空间，如 `MyApplication.GameFlow`、`MyApplication.AI`。

```csharp
namespace MyGame.Characters
{
    public class Player : MonoBehaviour
    {
        // 类实现
    }
}
```

## 字段
- ✅ 不要省略 private 访问修饰符——虽然在语法上可以省略，但它能显式表达意图。
- ✅ 私有变量使用 `m_` 前缀，常量使用 `k_` 前缀。
- ✅ 私有字段使用 `m_` 前缀，与局部变量区分。
- ✅ 常量使用 `k_` 前缀以表示不可变。
- ✅ 使用能清晰表达用途的描述性名称。
- ❌ 除非广为认知（如 `UI`、`ID`），否则避免缩写。
- ✅ 名称中包含单位（如 `m_speedInMetersPerSecond`）。
- ✅ 布尔字段使用 `is`、`has` 或 `can` 开头（如 `m_isActive`、`m_hasPermission`）。
- ❌ 避免在字段名中重复类名（如在 `Player` 类中用 `m_health` 而非 `m_playerHealth`）。
- ✅ 通过 `[SerializeField]` 让字段在 Inspector 中可编辑。
- ✅ 当其他类需要访问时，使用属性。

```csharp
// 私有变量使用 `m_` 前缀
private int m_health;

// 静态变量使用 s_ 前缀
private static int s_sharedCount;

// 常量使用 k_ 前缀
private const int k_maxCount = 100;

// 优先使用 [SerializeField] 而非公开字段；保持私有或通过属性暴露
[SerializeField] private int m_health;

// 名称中注明单位，避免猜测。可读性优先于简洁
private int m_elapsedTimeInHours;
private int m_elapsedTimeInDays;
private int m_elapsedTimeInSeconds;

// 布尔字段用 "is" 等动词开头，让含义一目了然
[SerializeField] private bool m_isPlayerDead;

```

### 属性
- ✅ 按类组织顺序，把属性放在字段之后、MonoBehaviour 方法之前。
- ✅ 属性使用 PascalCase，避免前缀/后缀。
- ✅ 布尔属性用类似动词的名称（Is/Has/Can），如 IsGrounded、HasHealtPack、CanJump。
- ❌ 不要序列化属性。如果需要在 Inspector 中暴露，请用 `[SerializeField] private T m_field` + 一个返回或校验它的公开属性。
- ✅ 用属性访问或修改对象状态。属性适合轻量、无副作用或仅有极小副作用的操作。
  示例：Health、Speed、IsGrounded。
- ℹ️ 用方法表示动作或操作（如输入处理、事件驱动行为）。应当命名为 `ApplyDamage(int amount)` 而非 `SetHealth(int amount)`。
  ❌ 不要用属性表示动作：属性不应执行大量计算、触发事件或产生副作用。

```csharp
// 私有后备字段
private int m_maxHealth;

// 只读属性
public int MaxHealthReadOnly => m_maxHealth;

// 完整实现的属性
public int MaxHealth
{
    get => m_maxHealth;
    set => m_maxHealth = value;
}

// 自动实现属性
public string DescriptionName { get; set; } = "Fireball";

// 避免：用属性实现 SetMovementInput 这类处理输入事件的动作
public Vector2 MovementInput
{
    set
    {
        m_forwardMovementInput = value;
        Debug.Log("Movement input set.");
    }
}
```

### 事件
- ✅ 大多数情况下用 `event Action` 或 `event Action<T>` 声明事件。
- ✅ 仅当需要在 Inspector 中暴露回调时才用 UnityEvent。代码内部事件我一般避免 UnityEvent，因为 Action 更轻量、灵活。
- ✅ 遵循 C# 事件命名约定：使用过去时动词（如 `DoorOpened`，而不是 `OnDoorOpen`）。
- ✅ 触发事件的方法使用 `On` 前缀（如 OnDoorOpened），事件名本身使用过去时动词（如 DoorOpened）。
- ✅ 使用观察者模式解耦系统、减少依赖（例如用事件通知 UI 更新，而不是直接引用 UI 组件）。
- ✅ 触发事件时使用空安全操作符（`?.`），避免空引用异常。
- ✅ 需要传递多个参数或复杂数据的事件，使用 `EventArgs` 或自定义事件参数类。这比传多个参数更易读、更易维护。
- ⚠️ 避免在紧密耦合的系统中过度使用事件——直接方法调用会更简单。
    - ✅ *使用事件*：当你需要解耦彼此不直接感知的系统（例如向多个系统广播游戏状态变化）。例如 GameManager 需要通知多个不相关的系统（UI、Audio、Analytics）游戏状态变化时。
    - ❌ *避免事件*：当系统紧密耦合时，直接方法调用或依赖注入更简单高效。例如 PlayerController 直接控制 Weapon。

```csharp
// 事件声明
public event Action DoorOpened;         // 事件名使用过去时动词
public event Action<int> PointsScored;
public event Action<CustomEventArgs> ThingHappened;

// 触发事件的方法
public void OnDoorOpened()
{
    // 使用空安全操作符避免空引用
    DoorOpened?.Invoke();
}

// 事件带参数时
public void OnPointsScored(int points)
{
    PointsScored?.Invoke(points);
}

// 复杂数据的自定义 EventArgs 类
public struct CustomEventArgs
{
    public int ObjectID { get; }
    public Color Color { get; }

    public CustomEventArgs(int objectId, Color color)
    {
        this.ObjectID = objectId;
        this.Color = color;
    }
}
```

#### 订阅与取消订阅事件
- ✅ 在 `OnEnable` 中订阅，并始终在 `OnDisable` 中取消订阅，避免内存泄漏。
- ✅ 避免使用 lambda 订阅事件——除非先把 lambda 存到变量里，否则无法取消订阅。
- ⚠️ 订阅时注意长生命周期对象（如单例）订阅短生命周期对象的事件可能引起内存泄漏。

```csharp
// 订阅事件
private void OnEnable()
{
    m_gameManager.DoorOpened += HandleDoorOpened;
}
private void OnDisable()
{
    m_gameManager.DoorOpened -= HandleDoorOpened;
}

```
## MonoBehaviour 方法

### Awake()
- ✅ 使用 Awake 初始化组件间的引用以及不同 GameObject 之间的引用。
- ✅ 缓存组件引用（GetComponent、Find、对象池创建）。
- ✅ 初始化不依赖其他 GameObject 的内部状态。
- ✅ 避免在 Awake 中做重型工作、依赖场景的调用，或订阅外部事件。

```csharp
private void Awake()
{
    // 在此处缓存组件引用
    m_rigidbody = GetComponent<Rigidbody>();
}
```

### OnEnable()
- ✅ 订阅事件、注册输入回调、重置每次启用时的状态。
- ✅ 让 OnEnable 中的工作轻量且可逆。在 OnDisable() 中取消订阅。

```csharp
private void Awake()
{
    // 在此处缓存组件引用
    m_rigidbody = GetComponent<Rigidbody>();
}
```

### Start()
- ✅ 用 Start 调用需要其他组件已存在并就绪的初始化方法。
- ✅ 执行依赖于其他组件或场景对象存在的初始化。
- ✅ 用于一次性设置（动画、UI 装配），必须在所有 Awake()/OnEnable() 之后运行。

```csharp
private void Start()
{
    // 使用缓存的引用，执行可能依赖其他组件已初始化的操作
    m_animator.SetTrigger("Initialize");
}
```

### OnDisable()
- ✅ 用 OnDisable 取消事件订阅，并在对象被禁用时清理状态。

```csharp
private void OnDisable()
{
    // 在此取消订阅，避免内存泄漏或异常行为
}
```

### FixedUpdate()
- ⚠️ FixedUpdate 在固定物理时间步长上运行，帧间可能执行零次、一次或多次，取决于帧时间。
- ✅ 用 FixedUpdate 处理物理相关更新（如施力、物理计算）。
- ✅ 把确定性物理工作放在这里：AddForce、刚体速度、模拟步进。
- ✅ 不要在 FixedUpdate 中读输入；在 Update() 中读输入，若需要则在 FixedUpdate() 中应用。
- ✅ 保持零分配、轻量化。

```csharp
// 用 FixedUpdate 处理物理
private void FixedUpdate()
{
    HandlePhysicsMovement();
}
```

### Update()
- ✅ 用 Update 处理常规帧更新（输入处理、非物理计算）。
- ✅ 在 Update 中读取输入、更新计时器、运行非物理的每帧逻辑与状态机。
- ✅ 避免分配，使用早返回（例如 `if (!m_isActive) return;`），并把工作分派到命名良好的辅助方法。
- ❌ 永远不要在 Update() 里 new 出新集合，而是复用现有集合。
- ✅ 使用早返回避免不必要的处理。
- ✅ 不要把逻辑直接写在 Update 循环里，而是移到命名良好的方法中，提高整洁度与自解释性。

```csharp
private void Update()
{
    // 把所有常规帧逻辑更新代码放在 Update() 中

    if (!m_isActive) return; // 早返回模式

    // 把逻辑移到命名良好的方法中
    HandleMovement();
    UpdateAnimations();
    CheckPlayerInput();
}

```

### LateUpdate()
- ✅ 用于收尾 transform 变更、相机跟随、动画驱动的调整，以及在所有 Update() 之后做清理。
- ✅ 用于必须在所有 Update() 之后运行的逻辑。

```csharp
// 用 LateUpdate 处理相机或后期处理更新
private void LateUpdate()
{

}
```

### 一般性说明
- ✅ 把相关方法组织在一起，提升可读性。
- ✅ 让 MonoBehaviours 保持单一职责。
- ✅ 存在依赖时使用 `[RequireComponent(typeof(OtherComponent))]`，确保所需组件一定存在，省去后续空引用检查。
- ✅ 把开销大的操作提到 Update 循环外缓存，避免重复分配。
- ❌ 避免魔数与魔字符串。把硬编码值（如 Speed 中的 `5f`）替换为常量或序列化字段，提升灵活性与可读性。



```csharp
// 避免 - 在 Update 中执行开销大的操作
private void Update()
{
   // 不良 - 每帧执行开销大的操作
   var nearbyEnemies = Physics.OverlapSphere(transform.position, m_detectionRadius);

   // 更好 - 缓存并降低更新频率
   if (Time.time > m_nextUpdateTime)
   {
       UpdateNearbyEnemies();
       m_nextUpdateTime = Time.time + m_updateInterval;
   }
}
```

### 方法
- ✅ 用方法表示行为与事件回调（动作、副作用、输入）。示例：Jump()、TakeDamage(int amount)、SetMovementInput(Vector2 input)。Unity 的 PlayerInput 和 Inspector 事件调用的是方法而非属性，因此输入处理器请优先使用方法。
- ✅ 用描述性动词命名方法，让动作清晰（如 ApplyDamage、PlaySound、RotateTurret、SetPosition、CalculateDamage）。
- ✅ 使用清晰的前缀：SetX 用于赋值/更新（如 `SetMovementInput(Vector2 input)`），ChangeX 用于修改/转换状态（如 `ChangeHealth(int amount)`）。
- ✅ 布尔方法应该以问句形式返回 bool，使用 Is、Has、Can（如 `IsPlayerAlive()`）。
- ❌ 避免名词式方法名（工厂方法、事件处理器除外）；避免动名词/进行时（如 Walking()、Rotating()）——这些表示状态，应当用 isWalking / isRotating 等变量或属性。
- ⚠️ 术语：在 C# 中请用"方法"（method）一词，指类中的函数。

```csharp
// 好：用方法表示动作或操作

// 动作：执行行为/副作用
public void Jump()
{
    m_rigidbody.AddForce(Vector3.up * m_jumpForce, ForceMode.Impulse);
}

// Setter：清晰赋值或更新值（适合作为输入回调）
public void SetMovementInput(Vector2 input)
{
    m_forwardMovementInput = input;
}

// Modifier：转换或改变状态
public void ChangeHealth(int amount)
{
    m_health += amount;
}

// 用动词命名方法以说明其作用
public void SetInitialPosition(float x, float y, float z)
{
    transform.position = new Vector3(x, y, z);
}

public void SaveGame()
{
    // 实现略：I/O 请使用 try/catch 并按需记录错误
}

// 好示例表明正在执行某个动作

public bool IsPlayerAlive();
```

# Unity 代码整洁的一般建议

## 接口
- ✅ 用接口定义清晰的"契约"，解耦系统。
- ✅ 接口遵循单一职责（接口隔离原则）。小而聚焦的接口优于大而全的接口。
- ✅ 用 `I` 前缀 + PascalCase（如 `IDamageable`、`IAudioService`）。
- ✅ 方法用动词命名，布尔成员用 Is/Has/Can。
- ✅ 纯契约场景用接口；多种实现共享行为或状态时使用抽象基类。

```csharp
public interface IDamageable<T>

}
```

## 命名文件与文件夹
- ✅ 文件和文件夹名统一使用 PascalCase，与类、脚本命名约定保持一致（如 `CharacterController.cs`、`AnimationController.cs`、`CoreSystems/`、`UI/`）。
- ✅ 按功能或特性把脚本归入对应文件夹（如 `CoreSystems/`、`UI/`）。
- ✅ 如果长路径能改善组织与清晰度，就别担心。这对未来的维护者和 Copilot 都有帮助。
- ❌ 文件和文件夹名中避免空格与特殊字符，以免给版本控制与跨平台带来问题。
- ℹ️ 如果文件夹名非常长且有变体，可以考虑用 `_` 代替空格分隔单词。例如 InputSystemActions_PlayerInputComponent_UnityEvents、InputSystemActions_PlayerInputComponent_CSharpEvents 等。
- ❌ 在桩方法或事件处理器中不要使用 `NotImplementedException`——它会增加噪音、降低可读性。应当让方法体保持为空，或加注释说明待实现。

### Async & Awaitable 使用
- ✅ 在 Unity 6 及更高版本中，对于定时延时、串行执行或不需要逐帧迭代的异步流程，使用 `Awaitable` API 配合 async/await。相比协程更清晰、更易读。
- ✅ async 方法以 `Async` 后缀命名（如 `OpenDoorAsync`），协程以 `Co` 后缀命名（如 `LoadAssetsCo`），以示区别。
- ✅ 两者都使用 PascalCase 与动词命名。
- ✅ 简单延时或顺序逻辑优先用 Awaitable 和 async/await，而不是 `StartCoroutine`。
- ❌ 不要在同一操作中混用 Awaitable 与协程——同一个工作流选择一种方式以保证清晰与可维护性。
- ✅ 使用 `CancellationToken`（针对 Awaitable）或检查 `this == null` 安全地处理取消、避免在对象销毁后继续执行回调。

```csharp
    Debug.Log("Door opened!");
}
```

## Unity 中的设计模式
- ✅ 务实选择模式。仅在模式能解决实际问题或改善可维护性时使用，不要为了用模式而用模式。
- ⚠️ **Command 模式**：适用于输入处理、撤销/重做与操作历史。
- ⚠️ **Observer 模式**（或 C# 事件）：适用于解耦系统（如 UI 更新或响应游戏事件）。
- ⚠️ **State 模式**：适用于复杂的角色控制器、AI 或 UI 流程，对象的行为随状态变化。
- ⚠️ **Factory 模式**：适用于灵活且集中的对象创建（如生成敌人、抛射物）。
- ⚠️ **Singleton 模式**：谨慎用于全局管理器（如 AudioManager），但不要滥用，否则会导致紧耦合。部分团队更倾向于依赖注入以获得更好的可测试性。
- ✅ 对频繁生成/销毁的对象使用 **Object Pooling** 模式，提升性能并减少 GC。
- ⚠️ **Strategy 模式**：适用于可互换的行为（如不同的移动或攻击方式）。
- ⚠️ **Service Locator / Dependency Injection**：适用于管理横切服务并提升可测试性。
- ✅ 对互斥状态使用枚举（动画、移动、UI 或游戏阶段）。


### 实现状态模式
- ✅ 对复杂的状态相关行为使用 State 模式，例如角色控制器或 AI。

```csharp
// 用 State 模式实现角色控制器
public class PlayerController : MonoBehaviour
{
    private PlayerState m_currentState;

    // 状态引用
    private IdleState m_idleState;
    private RunningState m_runningState;
    private JumpingState m_jumpingState;

    private void Awake()
    {
        // 初始化状态
        m_idleState = new IdleState(this);
        m_runningState = new RunningState(this);
        m_jumpingState = new JumpingState(this);

        // 设置默认状态
        m_currentState = m_idleState;
    }

    private void Update()
    {
        // 由当前状态处理 update
        m_currentState.Update();
    }

    public void ChangeState(PlayerState newState)
    {
        m_currentState.Exit();
        m_currentState = newState;
        m_currentState.Enter();
    }
}

// 状态基类
public abstract class PlayerState
{
    protected PlayerController m_controller;

    public PlayerState(PlayerController controller)
    {
        m_controller = controller;
    }

    public abstract void Enter();
    public abstract void Update();
    public abstract void Exit();
}
```

### 对象池
- ✅ 对频繁生成与销毁的对象（子弹、敌人、粒子效果）使用对象池，减少运行时分配、提升性能。
- ✅ 在 Unity 6 及更高版本中优先使用 Unity 自带的 `UnityEngine.Pool.ObjectPool<T>`，而不是自己实现对象池。
- ✅ 在场景加载时或按需初始化对象池，并预热一定数量以避免游戏中出现卡顿。
- ✅ 重用前始终重置池对象的状态（位置、旋转、激活状态等）。
- ✅ 将对象归还到池中而不是销毁；除清理外，不要在池化对象上调用 `Destroy()`。
- ✅ 使用清晰描述性的方法名（如 `GetFromPool()`、`ReturnToPool()`）。
- ✅ 封装好池管理逻辑——不要向使用者暴露内部实现。
- ✅ 按需使用 `[DisallowMultipleComponent]` 和 `[RequireComponent]` 强制约束池化对象的正确使用。
- ❌ 避免对状态复杂、难以重置的对象使用对象池。

```csharp
// 示例：使用 Unity 自带的 ObjectPool<T>
using UnityEngine.Pool;

public class BulletPool : MonoBehaviour
{
    [SerializeField] private Bullet m_bulletPrefab;
    private ObjectPool<Bullet> m_pool;

    private void Awake()
    {
        m_pool = new ObjectPool<Bullet>(
            createFunc: () => Instantiate(m_bulletPrefab),
            actionOnGet: bullet => bullet.gameObject.SetActive(true),
            actionOnRelease: bullet => bullet.gameObject.SetActive(false),
            actionOnDestroy: bullet => Destroy(bullet.gameObject),
            collectionCheck: false,
            defaultCapacity: 20,
            maxSize: 100
        );
    }

    public Bullet GetFromPool()
    {
        return m_pool.Get();
    }

    public void ReturnToPool(Bullet bullet)
    {
        m_pool.Release(bullet);
    }
}
```

## UXML
- ✅ 在 name 和 class 的值上使用 BEM（Block-Element-Modifier），可维护性、可读性、代码与样式一致性更好，这也是广泛认可的最佳实践。
- ✅ UXML 的 name 与 class 字符串优先使用 kebab-case（如 `navbar-menu`、`shop-button`）。
- ✅ `name` 用于唯一标识（如在 C# 中查询的元素），`class` 用于可复用样式或共享行为。
- ✅ 在同一 block 中保持 `name` 唯一，可提升 C# 中 `.Q()`、`.Query()` 的查询性能。
- ✅ 避免给单个元素堆叠过多不相关的 class；让 class 目的明确、聚焦。
- ✅ 把相关元素放到一个顶层 block 容器内，使查询与样式可预测。
- ✅ 对于嵌套 block，子 block 用父 block 名称作为前缀（如 `navbar-menu__dropdown`）。
- ✅ 在合适的 UXML 元素上添加无障碍属性（如 `aria-label`）。

**BEM 复习：**
- ℹ️ 模式：`block-name__element-name--modifier-name`
    - ℹ️ Block：独立有意义、可单独使用的组件（如 `navbar-menu`、`sidebar`、`login-form`）
    - ℹ️ Element：block 中无独立意义的部分，语义上依附于 block（如 `__item`、`__button`、`__input-field`）
    - ℹ️ Modifier：附加在 block 或 element 上的标志，用于改变外观或行为（如 `--active`、`--collapsed`、`--error`）
- ℹ️ 部分之间用 `__`（element）和 `--`（modifier）连接
- ℹ️ 示例：`menu__home-button`、`menu__shop-button`、`navbar-menu__shop-button--small`、`button--primary`

**示例**
- 这些示例遵循 BEM（Block-Element-Modifier）标准，保证清晰、结构化、可维护。

  ***Block 名称***：应清晰描述 block 在 UI 中的用途或角色，并适合用于对相关元素分组
    - ✅ `navbar-menu`（易于识别为导航菜单 block）
    - ✅ `sidebar`
    - ✅ `login-form`
    - ❌ `menu`（过于通用，缺乏上下文）
    - ❌ `navBarMenu`（使用了 camelCase 而非 kebab-case）
    - ❌ `navbar_menu`（使用了下划线而非短横线）

  ***Element 名称***：应描述其所属 block 的具体部分，保持与 block 的清晰关系
    - ✅ `navbar-menu__item`
    - ✅ `sidebar__toggle-button`
    - ✅ `login-form__input-field`
    - ❌ `navbar-item`（缺少 block 引用，应为 `navbar-menu__item`）
    - ❌ `sidebar-button`（缺少 block 引用，应为 `sidebar__button`）
    - ❌ `login-form-input`（缺少 element 的 `__`，应为 `login-form__input`）

  ***Modifier 名称***：应表明 block 或 element 的变体或状态
    - ✅ `navbar-menu__item--active`
    - ✅ `sidebar__toggle-button--collapsed`
    - ✅ `login-form__input-field--error`
    - ❌ `navbar-menu__item-active`（缺少 modifier 的 `--`，应为 `navbar-menu__item--active`）
    - ❌ `sidebar__toggleButton--collapsed`（使用了 camelCase 而非 kebab-case）
    - ❌ `login-form__input-field_error`（modifier 用了下划线而非 `--`）

**UXML 示例**
```xml
<ui:UXML xmlns:ui="UnityEngine.UIElements" xmlns:uie="UnityEditor.UIElements">
  <!-- Block 容器 -->
  <ui:VisualElement name="navbar-menu" class="navbar-menu">
    <!-- Element：block 内的特定按钮 -->
    <ui:Button name="navbar-menu__shop-button" class="navbar-menu__shop-button button button--primary" aria-label="Shop">
      <ui:Button.text>Shop</ui:Button.text>
    </ui:Button>
    <!-- 通过 modifier 体现的变体 -->
    <ui:Button name="navbar-menu__shop-button--small" class="navbar-menu__shop-button navbar-menu__shop-button--small button button--small" aria-label="Shop (Small)">
      <ui:Button.text>Shop</ui:Button.text>
    </ui:Button>
  </ui:VisualElement>
</ui:UXML>
```

**从 C# 查询**
```csharp
// 把选择器集中成常量，避免拼写错误
public static class UiSelectors
{
    public const string NavbarMenu = "navbar-menu"; // block
    public const string ShopButton = "navbar-menu__shop-button"; // element
    public const string ShopButtonSmall = "navbar-menu__shop-button--small"; // modifier
}

// 在 MonoBehaviour 或 UI 控制器中使用
var root = GetComponent<UIDocument>().rootVisualElement;
var navbar = root.Q<VisualElement>(UiSelectors.NavbarMenu);
var shopButton = root.Q<Button>(UiSelectors.ShopButton);
shopButton.clicked += OnShopClicked;
```

## USS
**指南**
- ✅ 不要把 CSS 和 USS 混为一谈。USS 是 CSS 的子集，存在 Unity 特定的属性与限制。请参阅 [Unity USS 文档](https://docs.unity3d.com/Manual/UIE-USS.html) 了解支持的功能。
- ✅ class 名使用 **kebab-case**，优先采用 **BEM** 编码结构与变体。
- ✅ 保持选择器**扁平且具体**：优先使用 `.block__element` 而不是深层后代链。
- ✅ **modifier** 作为叠加 class（如 `.button--small`），而不是重定义基础元素。
- ✅ 把**状态**样式单独抽到状态 class（如 `.is-selected`、`.is-disabled`），或使用内置的伪类。
- ✅ 在根部用 USS 变量定义**设计 token**（颜色、间距、尺寸）。
- ✅ class 名要简短、描述性强、符合 BEM。
- ✅ 集中化代码中使用的字符串常量，避免拼写错误。
- ❌ 不要依赖深层后代选择器（如 `.a .b .c`）——它们很脆弱。
- ❌ 不要在同一个 class 中混无关关注点；而是通过多个小 class 组合。

**USS 示例**
```css
/* Block 基础 */
.navbar-menu { padding: 8px; gap: 8px; }

/* Element 基础 */
.navbar-menu__shop-button { min-width: 120px; }

/* Modifier */
.navbar-menu__shop-button--small { min-width: 80px; }

/* 使用 BEM 风格 modifier 的通用按钮体系 */
.button { height: 32px; padding-left: 12px; padding-right: 12px; }
.button--primary { background-color: rgb(40, 120, 240); color: white; }
.button--small { height: 24px; font-size: 11px; }

/* 状态 class（在 C# 中添加/移除） */
.is-selected { outline-color: rgb(255, 200, 0); outline-width: 2px; outline-style: solid; }
.is-disabled { opacity: 0.5; }
```

**从 C# 切换 class**
```csharp
// 通过 classList 切换 modifier 和状态
var btn = root.Q<Button>(UiSelectors.ShopButton);
btn.classList.Add("button--primary");

// 设置状态
btn.classList.Toggle("is-selected", true);

// 切换到不同尺寸的变体
btn.classList.Remove("navbar-menu__shop-button--small");
btn.classList.Add("button--small");
```
