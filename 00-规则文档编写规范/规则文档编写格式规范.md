# 规则文档编写格式规范

> 🟢 本文件适用于所有规则库子项目的规则文档编写（go / java / js / ts / unity / pico 及未来新增）
> 🔴 不适用：业务代码注释、设计文档、接口文档、部署文档（那些用各自的规范）

---

## 1. 文档结构

每份规则文档必须严格遵循以下**三段式结构**：

```
# 一级标题（大标题）
                   ← 空行（强制，避免 Typora setext 误判）
---                ← 横线分隔（强制，仅 1 次）
                   ← 空行
## 1. 第一章
... 正文
## 2. 第二章
... 正文
```

带"适用范围副标题"的扩展结构：

```
# 一级标题（大标题）
                   ← 空行
> 🟢 适用范围副标题（如有，blockquote 形式）
> 🔴 不适用范围
                   ← 空行
---                ← 横线分隔
                   ← 空行
## 1. 第一章
... 正文
```

### 1.1 大标题（H1）

- 🔴 **文件首行必须直接是 `# 大标题`**，大标题之前**禁止任何内容**（YAML frontmatter / 空行 / 注释 / BOM 头一律不允许）
- 大标题格式：`# 编号 - 名称`，例如 `# 01 - Go 代码编写规则`、`# 00 - 文档总览`
- 编号使用阿拉伯数字两位补零（`00` / `01` / `02` ... `99`）

### 1.2 标题与正文分隔（强制）

- 🔴 **大标题（H1）与第一个 H2 之间必须有且仅有一道 `---` 横线分隔**，形成视觉断点
- 🔴 **H1 与 `---` 之间必须有 1 个空行**（`\n\n---\n`）—— 避免 Typora 等 Markdown 编辑器把 `# H1` + 紧跟的 `---` 误判为 setext 风格 H1 下划线（双重渲染成"两条线"）
- `---` 之后必须留 1 个空行接 H2（`\n---\n\n## ...`）
- 🔴 **H2 章节之间禁止用 `---` 分隔**——保持简洁，H2 标题 + 编号 + 留白已足够区分章节
- ✅ **H2 章节内部用 `---` 分隔子主题是允许的**——如 H2 末尾的小结分隔，或 H2 内部划分子区域

### 1.3 适用范围副标题（合法例外）

- ✅ **"适用范围"是 H1 下方唯一合法的副标题**——以 blockquote（`> ...`）形式呈现
- 适用范围副标题**必须放在 H1 与 `---` 之间**（即 `H1 → 空行 → > 适用范围 → 空行 → --- → 空行 → H2`）
- 副标题内容可以是单行或多行（如 `> 🟢 适用于 X` + `> 🔴 不适用于 Y` + `> 🟡 假设 Y`）
- ❌ 其他类型的副标题（导言、阅读指引、关键词列表等）仍**禁止**——直接进入 H2 正文

## 2. 章节编号规则

### 2.1 起始数字

- 🔴 **所有章节编号从 1 开始，禁止从 0 起始**
- ❌ 错误示例：`## 0. 适用范围`、`### 0.1 缩进`
- ✅ 正确示例：`## 1. 适用范围`、`### 1.1 缩进`

### 2.2 编号格式

| 层级 | 格式 | 示例 |
|---|---|---|
| H2 一级章节 | `## N. 标题` | `## 1. 命名规范` |
| H3 二级章节 | `### N.M 标题` | `### 1.1 包命名` |
| H4 三级章节 | `#### N.M.K 标题` | `#### 1.1.1 子包命名` |

- 编号用阿拉伯数字，**点号 + 空格**与标题文本分隔
- 编号**全局递增**（H2 跨整个文档），不重置

### 2.3 跨子项目一致性

- 同一子项目（如同 `go-rules/`）下所有文档的 H2 编号风格必须一致
- 跨子项目不强求统一（如 `unity_rulers/02-模式设计规则.md` 与 `go-rules/02-模式设计.md` 的 H2 章节不要求对齐）

## 3. 文档模板

### 3.1 不带适用范围副标题的模板

```markdown
# 编号 - 文档名称

---

## 1. 第一章标题

正文内容，**关键词**用粗体强调。

### 1.1 二级章节标题

- 要点 1
- 要点 2

### 1.2 二级章节标题

| 列 1 | 列 2 |
|---|---|
| 示例 | 示例 |

## 2. 第二章标题

🔴 **必加约束** / 🟡 **推荐** / 🟢 **可选**

### 2.1 二级章节标题

🔴 **必加约束**

- **约束说明 1**
- **约束说明 2**
```

### 3.2 带适用范围副标题的模板

```markdown
# 04 - Go API 设计规则

---

> 🟢 本文件适用于 **HTTP REST API** 和 **gRPC API** 的设计与修改

> 🔴 **不适用**：内部 Go 包之间的函数签名（见 01/02）

## 1. 路径与方法

🔴 必加约束

- 全部小写
- 单词用连字符 `-` 分隔

### 1.1 REST 风格

...
```

## 4. 反例 vs 正例

### 4.1 大标题顶部

| ❌ 反例 | ✅ 正例 |
|---|---|
| `---\ndescription: ...\n---\n\n# 01 - xxx` | `# 01 - xxx` |
| `\n# 01 - xxx`（首行是空行）| `# 01 - xxx` |
| `<!-- comment -->\n# 01 - xxx` | `# 01 - xxx` |

### 4.2 标题与正文分隔

| ❌ 反例 | ✅ 正例 |
|---|---|
| `# 01 - xxx\n\n## 1. 命名规范`（无 `---`）| `# 01 - xxx\n\n---\n\n## 1. 命名规范` |
| `# 01 - xxx\n---\n## 1. 命名规范`（横线前后无空行）| `# 01 - xxx\n\n---\n\n## 1. 命名规范` |
| `# 01 - xxx\n---`（H1 紧跟 `---`，Typora 渲染异常）| `# 01 - xxx\n\n---`（H1 与 `---` 之间留 1 空行） |
| `# 01 - xxx\n\n---\n\n## 1. ...\n\n---\n\n## 2. ...`（H2 之间重复 `---`）| `# 01 - xxx\n\n---\n\n## 1. ...\n\n## 2. ...` |

### 4.3 副标题

| ❌ 反例 | ✅ 正例 |
|---|---|
| `# 01 - xxx\n\n> 阅读本文档前请先看 00 总览\n\n---\n\n## 1. ...`（阅读指引不是适用范围）| `# 01 - xxx\n\n---\n\n## 1. ...`（指引直接进 H2 正文）|
| `# 01 - xxx\n\n> 本文件适用于 X\n\n---`（副标题位置不对）| `# 01 - xxx\n\n> 本文件适用于 X\n\n---\n\n## 1. ...`（副标题在 `---` 之前）|

### 4.4 章节编号

| ❌ 反例 | ✅ 正例 |
|---|---|
| `## 0. 命名规范` | `## 1. 命名规范` |
| `### 0.1 包命名` | `### 1.1 包命名` |
| `## 0.5 中间章节` | `## 1. 中间章节`（必须整数递增） |

## 5. AI 写规则文档的自检清单

写完一份规则文档后，AI 必须按本清单逐项勾选：

- [ ] **大标题顶部**：文件首行直接是 `# 编号 - 名称`，无 frontmatter / 空行 / 注释
- [ ] **H1 与 `---` 之间有 1 空行**：避免 Typora setext 误判
- [ ] **横线分隔**：H1 与第一个 H2 之间有且仅有一道 `---`，前后各 1 空行
- [ ] **H2 之间无 `---`**：H2 章节之间不使用 `---` 分隔
- [ ] **适用范围副标题**：如使用副标题，**只允许"适用范围"**，且放在 `---` 之前
- [ ] **编号起点**：第一个 H2 是 `## 1. xxx`，不是 `## 0. xxx`
- [ ] **编号格式**：H2 = `N.` / H3 = `N.M` / H4 = `N.M.K`
- [ ] **章节递增**：编号连续无跳号、无 0
- [ ] **格式约束**：🔴 必加 / 🟡 推荐 / 🟢 可选 标识完整
- [ ] **示例完整**：反例与正例成对出现，关键约束配反例

## 6. 与其他规范的关系

- 本规范**仅约束文档结构**（标题 / 副标题 / 编号 / 横线 / 模板）
- **不约束**内容质量、规则详尽度、措辞风格——那些由各子项目自己的 00-文档总览 决定
- 跨子项目引用本规范时，统一用 `[规则文档编写格式规范](./00-规则文档编写规范/规则文档编写格式规范.md)`（路径按实际目录调整）
