# 04 - UI 设计系统规则

> - 🟢 本文件适用于设计基础、变量、样式、组件、模板及其变更与复用。
> - 🔴 不适用：为组件数量或展示完整度预建无需求资产，或把探索稿直接当成全局标准。

---

## 1. 够用的基础与代表场景

- 🔴 先核对现有系统和视觉方向，补本次所需颜色语义、文字、间距、形状、素材约定与必要组件。
- 🔴 基础首版可在没有完整业务页面时建立；用真实代表页检查内容、状态、适配和实现条件，再修订基础并展开其他页面。
- 🔴 既有成熟系统优先复用，不因一次局部任务另建一套。
- 🟡 经授权可提前准备候选模板，标明适用范围与未验证内容；没有当前实例不自动等于废弃，也不自动进入正式业务。

## 2. 职责分层与展示

| 层级 | 维护内容 |
|---|---|
| 基础值 | 颜色、字体尺度、间距等原始值 |
| 语义变量与样式 | 主要文字、背景、危险操作等用途及主题映射 |
| 基础组件 | 按钮、输入、选择等稳定单元 |
| 业务组件与模式 | 特定领域组合、搜索或分步任务等协作行为 |
| 页面实例 | 在真实内容与场景中复用来源 |

- 🔴 资产职责不等于画板或目录数量。按读者任务与已有组织设置入口，不强制三块面板或每层一块大画板。
- 🔴 同类控件的来源、适用状态和示例可就近查找；候选、当前采用与兼容旧版清楚区分。
- 🔴 每项正式资产有唯一权威来源，展示与导出副本引用该来源，不独立维护第二套值。
- 🟡 简单项目可用短说明与少量样式，不为套用分层增加无用抽象。

## 3. 变量、样式与组件契约

- 🔴 名称描述语义和用途，避免“新灰色”“最终按钮”；沿用项目语言及工具/代码要求，不批量改名破坏引用。
- 🔴 同一语义有稳定映射；主题、模式、尺寸和平台变体只覆盖真实需要。
- 🔴 组件说明用途、必需与可选内容、可覆盖属性、尺寸/溢出、输入状态、可访问性与代码或资源映射。
- 🔴 内容变化用数据或实例属性表达；只有结构、视觉或行为确有差异时建立变体，不为每条文案和所有属性组合创建新变体。
- 🔴 设计组件、代码组件、资源和工程承载设施分别管理。画板或 Canvas 不是业务控件，组件数量不决定资源数量。

❌ 反例：每张课程卡都建立独立主组件，标题与图片修改就断开实例。

✅ 正例：复用卡片契约，通过内容属性替换；真实业务差异单独评估，保留来源关联。

## 4. 候选、采用与复用

| 阶段 | 可以说明 | 不能推断 |
|---|---|---|
| 候选 | 有可探索或备用的模板 | 业务已采用、已实现或设备通过 |
| 已采用 | 指定范围决定使用该方案 | 所有消费者已同步 |
| 已验证 | 指定版本与条件下有检查结果 | 其他输入、平台或版本也通过 |
| 已废弃 | 有替代方案或明确退出范围 | 所有引用已清理 |

- 🔴 新页面先查已有模板，复用来源与有效状态；能力不足时判断是业务特例、扩展还是新组件。
- 🔴 候选采用前核对真实内容、输入、适配与实现方式；按已有授权处理，不为已确认内容重复审批。
- 🔴 修改主组件先检查实例、嵌套、变量、原型、正式导出及代码消费者；完成后检查传播结果。
- 🔴 共享资源有唯一维护位置；项目要求复制交付时记录来源与同步关系，不擅自改工程目录。

## 5. 变更、发布与退出

- 🔴 发布范围、角色、版本与兼容要求按项目约定执行；不能把创建组件或工具保存成功写成库已发布。
- 🔴 破坏属性、状态或语义的变更说明影响与迁移路径，修复与需求变更分别记录。
- 🔴 删除前核对设计、原型、导出、资源与实现引用；正式导出节点与已授权备用模板不能仅因零实例而删除。
- 🔴 对确认可移除的旧稿、试验副本按项目约定清理，版本追溯优先使用已有版本控制；不默认生成长期备份目录。
- 🟡 文档中的契约和采用记录按 [UI 文档规则](../../project-docs/ui-design/其他规则/02-UI设计文档编写规范.md) 维护，避免重复登记所有工具可读取的值。

## 6. 完成检查

- [ ] 基础规模与本次任务相称，候选与已采用资产清晰。
- [ ] 变量、组件和实例来源唯一，语义与属性可理解。
- [ ] 代表场景、极限内容、状态与适配有实际检查记录。
- [ ] 消费者、导出与文档同步情况明确，未把设计采用等同实现完成。
- [ ] 清理没有破坏有效来源或形成无必要的归档副本。
