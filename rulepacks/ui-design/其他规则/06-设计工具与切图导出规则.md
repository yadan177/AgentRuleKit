# 06 - UI 设计工具与切图导出规则

> - 🟢 本文件适用于设计工具写入、画布维护、资源拆分、字体、切图与交付检查。
> - 🔴 不适用：把设计图层直接映射为资源文件，或把位图交付方式强制用于所有产品。

---

## 1. 先判断交付方式

先核对目标框架、输入、适配、性能、已有组件与设计基线，再确定各对象的实现角色。

| 方式 | 适用情况 | 交付重点 |
|---|---|---|
| 原生组件或代码绘制 | 目标工程已有相应控件、样式与行为能力 | 属性、布局、状态、语义和视觉对照 |
| 矢量或独立素材 | 图标、插画等确需资源且渲染链路支持 | 格式、颜色策略、尺寸、使用与来源 |
| 位图皮肤或完整状态图 | 工程明确采用位图表现或特殊视觉 | 独立控制边界、状态对齐、Alpha 与重建 |
| 混合实现 | 代码、文本与资源共同构成界面 | 每部分角色与组合方式 |

- 🔴 不预设所有按钮必须切 PNG，也不因理论上可以编码就取消项目已确定的资源交付。
- 🔴 视觉评审单位可以是完整控件，运行时实现可以由文字、皮肤和原生行为组合；两种边界分别说明。
- 🔴 整图或设计源作为对照基准；只有采用静态合成且实际需要时才制作底图，不生成无用途的空底图。

## 2. 元素与资源清单

AI 主动盘点本次完整范围，识别容器、独立成员、固定装饰、动态内容、组关系和复用范围。重复同构成员可共用规则，数量与例外可定位。

最少记录：对象与来源、变化/状态依据、独立控制、实现方式、资源或组件映射、适配与验证情况。进入导出时再补格式、尺寸、文件名和目录；模板见 [UI 文档模板](../../project-docs/ui-design/其他规则/03-UI设计文档模板.md)。

- 🔴 清单反查需求与源稿，检查成员漏项和误合并，不能只核对自己的导出计划。
- 🔴 已有约定和授权直接沿用；资源边界涉及新的业务、交付成本或未授权覆盖时，提供具体差异再处理。
- 🔴 不明确项标明原因与依赖；不阻塞的设计分析和临时验证继续执行。

## 3. 拆分与合成边界

### 3.1 独立控件与动态内容

- 🔴 需要独立输入、选择、显隐、替换、移动、动画、复用或适配的对象，在控制映射中单独定位。
- 🔴 容器包含独立成员时，不能用整组状态图替代成员控制；只有内部无需独立变化且整体语义明确时才采用完整业务组件图。
- 🔴 普通文字、数据、时间、本地化内容与连续属性保留运行时控制；固定艺术字或插画标签按用途处理，不能代替必要的文本语义。
- 🔴 连续进度不逐百分比切图；根据实现方案提供轨道、填充、滑块、遮罩或原生属性。
- 🟡 多个控件可共享皮肤，文件少于控件数不等于缺图；仍须说明每个实例的状态与内容映射。

### 3.2 静态合成

只有内容不变、不需独立控制或复用，且生命周期、适配、裁切与加载方式一致时才合成。合成还需符合纹理尺寸、清晰度和内存条件。

❌ 反例：把看似静止的加载文字和当前进度合入背景；或把每一条描边都导出独立文件。

✅ 正例：固定装饰按共同适配合成，文字与进度保留控制；明确采用位图皮肤时交付必要部件并重建检查。

## 4. 字体与格式

- 🔴 字体记录家族、字重、回退与文字覆盖，并明确使用系统字体、已有工程依赖还是需交付字体文件。
- 🔴 系统字体不要求额外复制；工程已存在的同版本字体通过引用复用。需交付文件时核对目标可用格式、来源与适用许可，提供所需文件或合法获取方式及必要说明，不默认下载或分发所有设计工具中的字体。
- 🔴 字体名称或截图不证明文件版本一致；存在差异时对照字形、排版和回退。可变字体需核对字重范围与目标支持。
- 🔴 不因交付字体自动创建 Unity 字体资产或逐字 PNG；运行时接入按任务范围处理。
- 🔴 PNG、SVG、JPEG 或其他格式由透明、缩放、渲染支持、压缩与性能条件决定；不固定所有资源的倍率和格式。
- 🟡 共享字体和素材使用项目既有目录，避免每页复制；项目要求自包含时记录复制与同步关系。

## 5. 位图导出专项

仅对实际采用的位图资源执行：

- 🔴 每个需要位图表现的已采用状态可定位；其他状态由组件、样式或属性表达，不机械一状态一图片。
- 🔴 同控件的状态图使用一致画布、锚点及透明留边，切换时不出现非预期位移；阴影与发光的扩展范围计入检查。
- 🔴 透明资源检查实际 Alpha、边缘、背景污染与裁切；缩略图看似透明不等于存在透明通道。
- 🔴 九宫格或等价拉伸方案明确边界、最小尺寸与目标参数，在适用实现中拉伸检查，不从工具参数猜测效果。
- 🔴 使用实际资源与动态内容重建，对照基准设计；同时按 [05](./05-验证交付与落地跟踪规则.md) 检查独立控制与有效状态组合。

## 6. 设计工具与画布维护

- 🔴 写入前明确文件、页面、父级、相邻内容和插入位置；沿用项目的阅读顺序与命名，不将新稿随意放到远处空白。
- 🔴 主组件、变量、实例与原型保持权威来源；导出节点引用源稿，修改来源后同步受影响节点。
- 🔴 批量操作先小范围验证；工具默认坐标、创建顺序和返回成功不代替结果检查。
- 🔴 写入后分别检查画布与图层列表顺序、同一界面内容连续性、边界/间距及来源引用。隐藏维护区不作为业务稿布局基准。
- 🔴 在总览和局部视图检查实际画面与标签拥挤；同级展示对象避免非预期相交，设计内部有意叠放不机械判错。
- 🔴 清理先检查实例、原型、正式资源与导出映射；有效导出节点不能仅因与主稿相似或零实例就删除。
- 🟡 工具支持时用变量、样式、组件、布局约束和关联实例；不把某工具的具体面板或 API 写成所有项目前提。

## 7. 目录、替换与清理

- 🔴 沿用项目已有资源目录与命名。需要新目录时说明归属与消费者，不按设计工具分组自动生成工程层级。
- 🔴 名称表达对象和用途；离散状态资源能区分状态，已有工程命名和引用优先，不为统一名称批量破坏绑定。
- 🔴 覆盖前完成适用的预览、文件差异与验证，按现有授权执行；已授权任务不因导出流程再次增加确认环节。
- 🔴 替换资源保留必要引用与元数据，例如工程实际使用的 GUID；设计导出不自动授权修改业务代码或场景。
- 🔴 使用现有版本控制或项目约定保证必要可恢复性；确需临时备份时明确范围与清理时机，不默认归档全部旧稿。
- 🔴 完成后清理本次临时导出、证明图与一次性脚本；正式文档进入约定文档位置，不混入资源目录。

## 8. 完成检查

- [ ] 实现角色、独立控件、动态内容与资源边界可追溯。
- [ ] 字体和素材取得方式符合项目，未无必要复制或栅格化文字。
- [ ] 实际导出的格式、尺寸、Alpha、状态对齐与映射经过适用检查。
- [ ] 视觉重建和控制关系分别核对，模拟与真实绑定分开报告。
- [ ] 画布、图层组织与引用完整，正式资源目录没有遗留过程性文件。
