# 02 - UI 交互设计规则

> - 🟢 本文件适用于信息架构、任务流程、控件、状态、原型、反馈和异常恢复。
> - 🔴 不适用：凭常见组件库默认值决定业务规则，或以状态数量代替状态语义。

---

## 1. 输入与范围

- 🔴 先核对用户任务、内容、平台输入、既有流程与实现边界；新行为按入口中的授权规则处理。
- 🔴 已有状态与明确授权可直接复用，记录来源；新增或改变业务行为、输入语义时说明变化，不逐控件重复确认。
- 🟡 探索线框可以暴露未知项，标明假设；不能把尚未确定的流程冒充正式契约。

## 2. 任务流程与 UI 覆盖

流程按用户目标组织，说明入口、前置条件、动作与反馈、结果、返回、取消和关键异常。名称使用用户理解的术语，不照搬数据库或组织结构。

### 2.1 多阶段任务

先画当前任务的短主线，再补对本次 UI 有影响的分支。已有菜单、异常或恢复机制直接引用，不默认绘制完整系统状态图。

| 阶段 | 呈现与行为 | 相关 UI | 当前情况 |
|---|---|---|---|
| <阶段与进入/退出条件> | <视觉、声音、场景或系统反馈> | <复用来源、位置和必要控制> | <已有、待改、待补或待确认> |

- 🔴 一个流程节点可以没有新页面或复用同一控件；一个 UI 也可以跨阶段存在，不按节点数创建页面。
- 🔴 每个节点有反馈去向，每项 UI 有使用条件与退出方式；检查并存面板、阻断层与中断后恢复。
- 🟡 简单线性任务可用步骤或短表；关系确实复杂时才补可编辑流程图。

❌ 反例：为了流程图完整，把每个阶段画成新全屏页，掩盖真正需要补的局部反馈。

✅ 正例：先写“选择 → 执行 → 结果”，标出共享面板与局部提示，只展开影响本次设计的失败分支。

## 3. 控件身份与状态

### 3.1 分别建模

| 维度 | 说明 |
|---|---|
| 控件与成员 | 区分容器、独立操作项与装饰；重复成员可以按同一规则分组，例外单列 |
| 输入反馈 | 焦点、悬停、按压等，由实际输入模型决定 |
| 选择值 | 单选、多选、当前项等持久值，不与焦点混用 |
| 可用性与业务状态 | 禁用原因、加载、失败、权限和恢复条件 |
| 连续属性 | 进度、时间、位置、滚动等初值、范围、更新与终止 |

- 🔴 可点击性与运行时变化分开。不可点击的步骤项仍可能由程序独立更新；Frame 或 Group 不能证明其内部只有一个控件。
- 🔴 不统一规定按钮三态、四态或五态；根据已有设计系统、输入与实际行为确定适用状态。
- 🔴 状态数量是模型的结果。分别记录维度、有效组合、优先级与互斥条件，不把所有组合机械生成变体或状态图片。
- 🔴 连续数值不按每个取值建离散状态；记录起点、中间、终点及异常边界的验证方式。

### 3.2 状态记录与采用

| 对象/维度 | 状态或取值 | 触发/来源 | 反馈与控制 | 退出/恢复 | 依据或未决项 |
|---|---|---|---|---|---|
| <控件或成员规则> | <离散状态或连续范围> | <输入/业务条件> | <可见、声音、触觉等> | <取消/下一状态> | <现有确认、授权或待决问题> |

1. 先盘点定义、调用或设计来源，检查现有状态是否适用于本次输入。
2. 既有规则明确时直接沿用；规则允许 AI 作出常规设计判断时形成可审查方案并说明依据。
3. 超出授权、改变关键任务或与既有契约冲突的选择集中确认，其他部分继续。
4. 在正式设计与交付说明中记录采用方案，不混用探索、采用与实测状态。

❌ 反例：三个独立选项只登记整栏三张图片，把焦点高亮当成当前选中值。

✅ 正例：记录三个成员、单选关系和各自状态；视觉资源可以共享，仍保留逐项输入与选择控制。

## 4. 反馈、焦点与容错

- 🔴 主要操作、当前状态和结果可识别；动作名称在上下文中说明后果。
- 🔴 耗时操作说明进度或等待、可否取消及失败恢复；避免无依据的精确百分比或承诺。
- 🔴 错误定位到相关输入或步骤，尽量保留有效内容；危险或丢失数据的操作提供项目需要的确认、撤销或恢复。
- 🔴 模态交互说明后层输入隔离、焦点进入与恢复、关闭方式；不把视觉遮罩当作这些行为已实现。
- 🔴 键盘、手柄等输入有可见焦点、合理顺序和退出方式；触摸、射线或手势检查误触、遮挡和可达性。
- 🔴 不只靠颜色表达关键状态；按场景提供文字、形状或其他适用线索。
- 🟡 在需要时设计字幕、减少动效或替代输入；依据实际平台和用户要求选择，不声称一套表现自动覆盖所有人群。

## 5. 原型与检查

原型采用真实或真实长度范围的内容，覆盖主路径、关键异常和有效状态组合。热点与动效只表现实际模拟的行为，不证明后端、权限或原生输入已接通。

- [ ] 主流程与 UI、非 UI 反馈双向对应。
- [ ] 控件、成员、输入反馈、选择值、业务状态和连续属性没有混淆。
- [ ] 返回、取消、中断、焦点恢复与异常处理可解释。
- [ ] 已有授权和状态被复用，关键未决项有明确范围。
- [ ] 原型检查与真实实现、设备验证分别记录。
