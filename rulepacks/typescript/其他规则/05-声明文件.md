# 05 - TypeScript 声明文件

> - 🟢 本文件适用于 TypeScript 声明文件（.d.ts）的写法。
> - 🔴 不适用：业务逻辑实现、UI 样式设计

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 .d.ts 里写运行时代码

```ts
// ❌ .d.ts 不应该有函数体
declare function greet(name: string): string {
  return `Hello, ${name}`;
}

// ✅ .d.ts 只放类型
declare function greet(name: string): string;
```

**类型声明错误立刻报错**（运行时错误才发现就晚了）。

### 1.2 全局类型污染

```ts
// ❌ 在文件顶层扩展全局(污染)
interface String {
  padZero(): string;                                  // 所有项目 String 都有 padZero
}

// ✅ 写在 declare global 里
declare global {
  interface String {
    padZero(): string;
  }
}
export {};                                            // 标记为模块
```

### 1.3 没有类型的库直接 import

```ts
// ❌ 跳过类型检查
import { foo } from 'no-types-lib';

// 包确有匹配的官方/DefinitelyTyped 声明且项目授权新增时，
// 使用现有包管理器安装与库版本兼容的声明包。
import { foo } from 'no-types-lib';

// ✅ 库没类型时自己写最小 .d.ts
// src/types/no-types-lib.d.ts
declare module 'no-types-lib' {
  export function foo(x: string): number;
  export const bar: string;
}
```

**不要**用 `// @ts-ignore` 掩盖类型缺失——后面改代码会爆。

## 2. 🟡 推荐 · 团队约定

### 2.1 .d.ts 文件位置

| 类型 | 位置 |
|------|------|
| **库**：与源码同目录 | `src/foo.ts` + `src/foo.d.ts` |
| **应用**：统一放 `types/` | `src/types/global.d.ts` / `src/types/css-modules.d.ts` |

### 2.2 模块声明

```ts
declare module 'my-lib' {
  export interface User {
    id: number;
    name: string;
  }
  export function getUser(id: number): Promise<User>;
}
```

### 2.3 全局声明

```ts
// src/types/global.d.ts
export {};                                            // 标记为模块

declare global {
  interface Window {
    myApp: { version: string };
    dataLayer: unknown[];
  }

  namespace NodeJS {
    interface ProcessEnv {
      DATABASE_URL: string;
      NODE_ENV: 'development' | 'production' | 'test';
      PORT?: string;
    }
  }
}
```

### 2.4 ambient 模块（无 import 的全局模块）

```ts
// jQuery 老项目 / 第三方插件
declare const $: JQueryStatic;
declare const _: _.LoDashStatic;
```

**现代项目**不要用——用 `import` 引入模块。

### 2.5 第三方库类型来源

| 来源 | 优先级 |
|------|--------|
| **库自带类型**（d.ts 在 npm 包内） | ✅ 首选 |
| **`@types/xxx`**（DefinitelyTyped） | ✅ 次选 |
| **自己写 minimal .d.ts** | 🟡 兜底 |
| **`declare module 'xxx': any`** | ❌ 禁止（污染） |

### 2.6 CSS Modules / 图片 / JSON 模块声明

```ts
// src/types/assets.d.ts
declare module '*.module.css' {
  const classes: { readonly [key: string]: string };
  export default classes;
}

declare module '*.svg' {
  const src: string;
  export default src;
}

declare module '*.png' {
  const src: string;
  export default src;
}
```

### 2.7 函数 / 类的声明合并

```ts
// 给已有 class 扩展静态方法
declare global {
  interface Array<T> {
    toSorted(this: T[], compareFn?: (a: T, b: T) => number): T[];
  }
}
export {};
```

### 2.8 发布带类型的库

```json
// package.json
{
  "main": "dist/index.js",
  "types": "dist/index.d.ts",                          // TS 入口
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.js"
    }
  },
  "files": ["dist"]
}
```

**自动生成 .d.ts**：

```json
// package.json
{
  "scripts": {
    "build": "tsc -p tsconfig.build.json"
  }
}
```

```json
// tsconfig.build.json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "declaration": true,                               // 生成 .d.ts
    "declarationMap": true,                            // sourcemap
    "emitDeclarationOnly": false,
    "outDir": "dist"
  },
  "include": ["src"]
}
```

## 3. 🟢 可选 · 视情况

### 3.1 triple-slash directives

```ts
/// <reference path="../node_modules/@types/jest/index.d.ts" />
/// <reference types="node" />
```

**现代项目不用**——`tsconfig.json` 的 `types` 字段更干净。

### 3.2 类型补丁

项目已经采用 patch-package、包管理器 patch 能力或内部 fork 时，可以按既有流程临时修补上游类型；不得为本节自动安装 patch 工具。补丁必须锁定上游版本、说明原因和移除条件，并在升级依赖时重新验证。

### 3.3 .d.ts 文件导入类型

```ts
// types/foo.d.ts
export interface Foo { id: number }

// 在代码中
import type { Foo } from '@/types/foo';               // ✅ 用 import type
```
