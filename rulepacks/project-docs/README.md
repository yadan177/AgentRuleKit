# 项目文档规则包

本目录分别维护技术文档和 UI 设计文档规则。技术文档基于目标仓库的实际源码、配置和测试，建立可导航的 Code Wiki，覆盖项目全貌、模块职责、关键代码、调用与数据关系，以及运行和验证方式。

项目技术文档规则按技术栈独立安装：

- [Python](./python/其他规则/00-Python技术文档编写规范总览.md)：`project-docs/python`
- [Go](./go/其他规则/00-Go技术文档编写规范总览.md)：`project-docs/go`
- [Java](./java/其他规则/00-Java技术文档编写规范总览.md)：`project-docs/java`
- [JavaScript / TypeScript](./js-ts/其他规则/00-JS+TS技术文档编写规范总览.md)：`project-docs/js-ts`
- [Unity](./unity/其他规则/00-Unity技术文档编写规范总览.md)：`project-docs/unity`

JavaScript 与 TypeScript 共用 `project-docs/js-ts`。CLI 根据检测到的开发技术栈自动选择对应文档规则包，并在配置中去重。

[UI 设计文档](./ui-design/其他规则/00-UI设计文档规则总览.md)使用 `project-docs/ui-design`，维护设计基础、流程、页面状态、组件/资源映射及分层验证记录。它可独立选装，也随 `ui-design` 规则包交付；不由语言检测自动加入，UI 设计说明与技术实现文档通过链接衔接。

每个技术栈使用相同的五层结构，并保留自身的源码、配置、运行和生命周期检查要求：

| 规则 | 作用 |
|---|---|
| `00` 总览 | 明确目标、范围、证据优先级和阅读路径 |
| `01` 组织与维护 | 复用已有目录，建立阅读导航、模块覆盖与维护机制 |
| `02` 编写规范 | 规定架构、核心链路、关键符号、依赖和运行说明的内容深度 |
| `03` 模板 | 提供技术总览、新人上手、架构、模块、契约、验证和 ADR 的写作结构 |
| `04` 任务入口 | 区分首次建立文档、局部完善、增量同步和审查，指导仓库分析与交付 |

首次建立文档时，从运行入口追踪初始化与主要功能，再把已核查的事实映射到已有文档。完整性按主要能力和关键链路覆盖衡量，不以文件数量或逐函数说明衡量；大型仓库需明确已分析与未覆盖范围。

后续维护从代码、配置和接口的实际变更出发，沿调用方、消费者及测试定位受影响内容。文档区分源码已核查、实际运行已验证和待确认状态，已有文档的 `有效` 状态不代表所有场景都已实测。

可用任务表述：

> 基于当前仓库建立或完善技术文档：先识别运行单元和入口，再追踪主要功能链路，说明架构、模块职责、关键类与函数、依赖及运行验证方式。复用现有目录，为关键结论提供源码依据，并明确未覆盖和未验证内容。

> 根据本次代码变更同步技术文档：识别受影响的入口、模块、调用方、消费者和测试，更新对应正文、来源与导航，并说明实际完成的核查范围。
