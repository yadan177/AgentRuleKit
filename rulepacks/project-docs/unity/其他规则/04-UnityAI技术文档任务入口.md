# 04 - Unity AI 技术文档任务入口

> 🟢 本文件适用于 AI 创建、修改、审查和同步 Unity 技术文档。<br>
> 🔴 不适用：臆造项目事实、伪造验证结果，或替用户批准工程迁移、发布和外部协作。

---

## 1. 任务路由

| 任务 | 必读规则 | 重点检查 |
|---|---|---|
| 目录、索引、命名或废弃 | 00、01 | 现有文档、链接、负责人、Git 历史 |
| 新建或修改技术正文 | 00、01、02、03 | 代码、配置、数据、测试和 Unity 项目事实 |
| 文档审查 | 00、01、02 | 来源、状态、边界、简洁性和验证 |
| 实现任务的文档影响判断与同步 | 00、01、02 | 模块、接口、配置、测试、运行流程、覆盖矩阵和 ADR |

- 🔴 先读取当前 AI 编辑器的项目级规则入口、贡献指南和已有技术文档；Codex 的入口通常是 `AGENTS.md`，其他编辑器使用各自已验证的入口形式。
- 🟡 只读取当前任务需要的专题规则。

## 2. 开始前检查

1. 确认任务属于技术文档，或由实现任务的文档影响判断触发；策划、美术、制作、运营和管理流程不在本规则范围，不得写入 `项目文档/技术文档/`。
2. 明确任务是新建、更新、审查、整理还是代码同步。
3. 阅读技术文档根目录 `README.md`、`00-新人上手.md`、`01-技术总览.md` 和已有主题目录，再搜索同主题技术文档、主题 `README.md` 和 ADR，避免重复。
4. 检查相关 Unity/Package 版本、程序集、代码、资源、配置、构建、测试和目标平台事实。
5. 确认权威来源、目标读者、状态和负责人；负责人缺失时先询问，仍无法确认只能在 `草稿` 中临时标记 `待确认`。

- 🔴 不得只凭目录名、单个资源或通用经验判断资源系统、渲染管线、网络库、XR SDK、设备或运行行为。
- 🔴 未获授权不得升级 Unity/Package、修改 `ProjectSettings`、移动资源或把文档任务扩大为代码重构。

## 3. 创建、更新与同步

### 3.1 创建或更新

1. 已有文档足够覆盖同一个主要问题时，更新原文；否则先归入既有 `02` 至 `07` 技术主题并按模板新建子文档。
2. 仅当现有 `00` 至 `07` 都无法合理容纳，且满足 `01-技术文档组织与维护规范.md` 的新增主题条件时，才新增 `08` 及后续一级技术主题。
3. 新建主题目录必须同时创建 `README.md` 和至少一篇真实正文；不得预建空目录或空模板。
4. 写清用途、范围、来源、边界、验证和待确认问题；删除不适用章节。
5. AI 不得臆造负责人；`待确认` 只允许用于 `状态: 草稿`，文档转为 `有效` 前必须明确人员、团队或项目认可的责任角色。
6. 更新技术文档根目录或最近一级主题目录的 `README.md`、关联链接和术语区。

### 3.2 代码变更后的同步

当代码、配置、数据、依赖、资源或流程变更使 `有效` 文档失真时，更新受影响段落、来源、验证和 `最后更新`；无法确认时标记待确认并在交付中说明。

- 🔴 新增、拆分、合并或删除独立业务模块时，检查并更新项目已有的模块覆盖矩阵；没有独立映射文件时至少检查技术文档 `README.md` 的模块入口。
- 🔴 当前事实必须以源码、公开类型、Scene、Prefab、资源、配置、数据迁移、契约和测试为依据；同步后扫描受影响文档中的旧术语和旧能力描述。

文档被替代时改为 `已废弃`，保留原因和替代路径，不直接删除。

## 4. 交付要求

完成后必须说明：

1. 本规则由明确的文档任务还是实现任务的文档影响判断触发。
2. 修改了哪些文档及其事实依据，负责人和状态是否明确。
3. 做了哪些校验，例如链接、索引、元数据、模块覆盖、旧术语和项目证据对照。
4. 未验证范围、剩余风险和待确认项。
5. 因本次代码或配置变更需要同步的其他文档及差异；确认无影响时说明判断依据。

交付前自检：

- [ ] 文档位置、`README.md` 和链接正确。
- [ ] 状态、负责人、来源和更新时间符合实际。
- [ ] 未将未知内容写成事实，且没有重复维护权威数据。
- [ ] 内容简洁：结论在前、无空章节、无重复解释。
