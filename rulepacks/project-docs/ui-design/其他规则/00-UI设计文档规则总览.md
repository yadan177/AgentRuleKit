# 00 - UI 设计文档规则总览

> - 🟢 本规则库适用于 UI 设计简报、流程、页面状态、设计系统、资源交接和验收记录。
> - 🔴 不适用：替代产品需求、设计工具源稿、技术实现文档，或把设计决定写成已实现能力。

---

## 1. 目标

UI 文档应让读者找到当前设计、理解采用理由、明确交互和适配契约、完成开发交接，并识别尚未实现或验证的内容。文档不是截图集合，也不是设计工具全部属性的复制品。

- 🔴 设计文档可以记录未实现的方案，但必须标明建议、采用、废弃及验证范围，不能伪装成当前产品行为。
- 🔴 同一事实只维护一个权威位置，其他文档用摘要和链接衔接。
- 🔴 复用项目已有目录、术语、编号和元数据，不为套模板迁移历史资料。
- 🟡 按任务规模选择内容，小项目可以少量文档覆盖，不要求每种模板都建文件。

## 2. 与其他产物的边界

| 产物 | 负责的事实 | UI 文档如何引用 |
|---|---|---|
| 产品需求与业务流程 | 用户目标、范围、业务决定与验收目标 | 引用需求和决定，不擅自新增功能 |
| 设计源稿与设计系统 | 视觉、组件来源、变量和原型 | 记录可定位来源、版本、用途与必要约束 |
| UI 设计文档 | 设计意图、状态与适配、采用范围、交付和验证 | 解释工具不能可靠表达的语义与交接关系 |
| 技术实现文档与代码 | 组件绑定、接口、资源加载和实际运行行为 | 链接实现入口，不用设计稿证明已接入 |
| 测试与设备记录 | 实际环境、操作、观察和结果 | 引用证据，不把计划当结果 |

UI 文档不强制安装某个语言的技术文档包；需要说明实现细节时沿用目标工程已有技术文档。

## 4. 质量要求

- [ ] 读者能找到当前源稿、设计契约和对应实现/验证入口。
- [ ] 流程、页面、状态、组件与资源按实际关系对应。
- [ ] 文档状态、设计采用、资源交付、实现和验证没有混为一个“完成”。
- [ ] 关键决定有依据，未知项不由 AI 编造成事实。
- [ ] 目录、索引、链接与变更影响已同步，没有重复权威来源。
