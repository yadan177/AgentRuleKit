# 01 - UI 设计文档组织与维护规范

> - 🟢 本文件适用于 UI 设计文档的目录、导航、命名、元数据、权威来源和维护。
> - 🔴 不适用：强制迁移已有目录、复制产品与技术文档，或把临时工作记录长期堆入正式文档。

---

## 1. 目录与内容归属

已有设计文档时沿用其目录与入口。没有约定时可采用 `项目文档/产品设计/界面设计/`；以下是内容职责示例，不是必须创建的文件清单：

```text
界面设计/
├── README.md             # 当前设计、阅读路线与覆盖入口
├── 设计基础.md           # 视觉语义、组件来源与使用边界
├── 页面与状态.md         # 页面/流程入口及采用范围
├── <主题>设计说明.md     # 复杂页面或组件按需要独立维护
├── <主题>交付清单.md     # 有资源交接需要时创建
└── <主题>验收记录.md     # 独立维护有价值时创建
```

- 🔴 产品目标和业务规则引用既有需求文档；实现细节链接技术文档，不复制成新的权威定义。
- 🔴 源设计文件、图片、字体与文档按各自约定存放。文档引用资源，不因整理文档复制一套素材。
- 🟡 参考研究沿用既有调研位置；简单简报、组件说明和验收内容可合并在相关正文中。

## 2. 索引与覆盖

根索引至少能导航设计基础、主要流程或页面、当前源稿、交付与验证；只链接真实存在的内容。

| 读者任务 | 应能找到 |
|---|---|
| 了解当前设计 | 范围、基础、主要任务及未覆盖内容 |
| 修改某个界面 | 当前源稿、状态/适配契约、组件来源与消费者 |
| 接入实现 | 组件/资源映射、动态内容、技术入口与缺口 |
| 判断能否交付 | 采用决定、设计与实现基线、已执行验证及剩余项 |

- 🔴 覆盖清单以主要任务、页面或组件职责为单位；一页多状态、多页复用组件时记录实际关系，不用画板或文件数量证明完整。
- 🔴 创建、移动、替换或删除文档时同步最近索引及引用。已有矩阵直接更新，不另建重复台账。
- 🟡 有复杂独立读者、契约或维护节奏时再拆文档，避免每个控件或每次小修单独建文件。

## 3. 命名与元数据

名称表达职责，默认简短中文；项目已有语言、编号与工具标识约定时沿用。已有稳定页面/组件标识不因排序变化重编号，文件名不使用“最终版”“新版”制造多份当前稿。

除索引外，可采用以下元数据或已有等价机制：

```yaml
---
标题: <标题>
负责人: <已有人员、团队或责任角色；未知时待确认>
状态: 草稿
最后更新: YYYY-MM-DD
来源: [<需求、设计文件/节点、版本或记录入口>]
关联文档: [<相对路径>]
---
```

- 🔴 文档状态使用草稿、有效、已废弃或项目等价体系；`有效` 表示本记录反映当前已核对情况，不表示设计、开发和设备全部完成。
- 🔴 设计采用、资源交付、实现进度和验证结果按 [编写规范](./02-UI设计文档编写规范.md) 单独记录，不把多阶段进度塞入元数据状态字段。
- 🔴 无法确认负责人时记录待确认，不臆造姓名；仍可完成独立核查与文档草稿。
- 🔴 实质变更更新日期与相关基线，创建日期如已有则保留，不因批量格式调整伪造业务更新时间。

## 4. 权威来源与变更

| 变化 | 同步范围 |
|---|---|
| 需求、流程、页面范围 | 流程与页面说明、覆盖清单、相邻节点 |
| 组件属性、状态、视觉语义 | 基础来源、组件契约、实例与采用说明 |
| 资源边界、文件或字体 | 交付映射、导入约定及受影响实现 |
| 实现接入、验收结果 | 对应基线、证据与未完成项 |

- 🔴 更新以实际变化为依据，不全量重写仍有效内容；陈旧的“当前”总结和进度表一并修正。
- 🔴 最新来源互相冲突时记录差异与范围，不能只按日期较新自动认定所有旧决定失效。
- 🔴 文档、源稿和实现各有自己的版本；映射说明核查的是哪些版本，未同步消费者明确列出。

## 5. 废弃与清理

- 🔴 正式决定与需追溯的契约保留必要原因、替代入口和范围，可依托已有 Git 或设计版本记录；不强制创建归档目录。
- 🔴 删除正式文档或资产前检查引用、替代与项目保留要求；任务已明确允许删除且无有效引用时按范围清理，不反复确认。
- 🔴 临时导出、测试截图和一次性脚本不因“过程记录”自动成为正式文档。必要验证结果提炼到已有记录，临时产物按约定清理。
- 🟡 使用项目已有链接和文档检查；自动校验不能替代设计与实现事实核对。
