# 02 - UI 设计文档编写规范

> - 🟢 本文件适用于 UI 设计简报、基础、页面、状态、组件、交付与验收正文。
> - 🔴 不适用：用截图或页面数量替代行为说明，或从设计稿推断已经实现。

---

## 1. 写作与来源

- 🔴 开头说明当前范围、读者问题、基线与结论；用短段落和必要表格，不复制整段需求或设计工具全部属性。
- 🔴 关键事实就近关联需求条目、设计文件/节点、组件、代码路径或验证记录；本地路径相对当前文档，外部来源使用可定位链接。
- 🔴 只有链接不够：记录该来源支持什么、采用哪个版本及适用范围。无法访问时明确是文档引用，不能声称已查看源稿。
- 🔴 截图标明来源、状态与用途，用于说明视觉；状态转换、适配、命中、权限与恢复仍需文字或结构化说明。
- 🔴 区分产品要求、已采用设计、当前实现与建议方案；设计理由无来源时标明判断或待确认，不替作者编造动机。

## 2. 页面与流程契约

按任务选择适用内容，不要求每个页面重复填写全套章节：

| 内容 | 应说明 |
|---|---|
| 用途与范围 | 用户任务、前置条件、权限与当前非目标 |
| 来源与身份 | 稳定页面/组件标识、当前源稿、相关需求与基线 |
| 进入与退出 | 触发、显示位置、返回、关闭、取消及恢复 |
| 内容与反馈 | 来源、长短范围、空值、错误、加载和动态内容 |
| 控件与状态 | 成员身份、输入反馈、选择值、可用性、有效组合与连续属性 |
| 适配与运动 | 尺寸/方向/缩放、布局变化、焦点、遮挡、动效与降级 |
| 交接与验证 | 组件/资源映射、实现入口、检查方法与缺口 |

- 🔴 多阶段任务先用局部主线和“阶段／呈现与行为／相关 UI／当前情况”简表，只有影响本次 UI 的分支才展开。
- 🔴 节点与页面不是一一对应，复用和非 UI 反馈也可记录；反查每项 UI 的使用、并存与退出条件。
- 🔴 状态记录进入、反馈、退出、优先级与依据；成员数量、单项状态数和组合数分别说明，不用一个总数代表完整性。
- 🔴 交互反馈、业务选中、权限/可用性与连续值分开；进度、滚动等记录范围，不为每个数值建状态文档。

## 3. 设计系统与资源说明

- 🔴 基础文档说明颜色、文字、间距、布局与材质的语义、使用条件和权威来源；工具或代码已有可读取定义时链接，避免复制数值后漂移。
- 🔴 组件说明用途、可变属性、状态、尺寸与溢出、输入、采用范围及消费者；候选不写成全产品已使用。
- 🔴 设计到实现按真实关系映射：可以是原生组件、代码样式、矢量、位图或混合，不强制每控件一 PNG。
- 🔴 需要导出时记录源节点、资源、状态、目录、尺寸/格式与使用方式；共享资源可一对多，运行时变化项不能误并入底图。
- 🔴 字体说明系统/已有依赖/需交付文件的取得方式、字重、回退与覆盖；只记录实际可证的文件或版本，不凭字体名称断言二进制相同。
- 🔴 平台参数记录原单位、适用设备、映射依据与验证条件；XR 设计像素、物理尺寸、视距和角尺寸不混用。

## 4. 状态与验证分别记录

不要用一个“已完成”覆盖整条交付链。使用项目已有等价字段或以下最小记录：

| 维度 | 记录内容 | 示例状态 |
|---|---|---|
| 设计决定 | 方案来源、采用范围、依据或确认记录 | 探索、待定、已采用、已废弃 |
| 资源交付 | 源稿与交付版本、实际文件/组件映射 | 未交付、部分交付、已交付、不适用 |
| 实现接入 | 实际组件/构建或技术文档与覆盖范围 | 未接入、部分接入、已接入、未核查 |
| 验证 | 对象版本、条件、方法、观察与结论 | 未执行、通过、未通过、不适用 |

- 🔴 记录“通过”必须有层级与条件：设计走查、原型、真实实现、设备或用户测试；未执行不能填通过。
- 🔴 设计被采用不证明资源已导出；文件存在不证明正确绑定；编辑器或构建通过不证明目标设备可用。
- 🔴 更新设计后，旧验证只适用于旧基线。保留证据，标明当前受影响项需复验，不把所有历史结果机械清零。
- 🔴 “不适用”给出原因，例如使用原生样式无需位图；不能把尚未执行写成不适用。
- 🟡 小任务可用短段落记录，不强制多张进度表；已有任务系统或测试报告直接链接。

❌ 反例：设计基础仍写“某模块切图暂缓”，新清单已记部分资源交付，根索引却统一标“完成”。

✅ 正例：总览注明已交付的实际范围并链接清单；设计、资源、实现与设备结果各自关联版本，剩余部分明确列出。

## 5. 差异与维护深度

- 🔴 设计与实现差异记录现象、影响、依据及决定，区分修复实现、修改设计、接受差异和待确认。
- 🔴 共享组件或流程变化追踪消费者，更新当前摘要、覆盖关系、契约及相关测试入口。
- 🔴 不把临时调试细节写入产品界面，不把每次操作日志追加到正式规范；仅保留当前约定、必要决定和可追溯验证。
- 🔴 敏感数据、个人信息与密钥不进入设计示例或截图；使用适合任务的脱敏内容。

## 6. 完成检查

- [ ] 当前设计、需求、实现与验证来源可定位且没有混用。
- [ ] 主要流程与页面/组件有对应关系，未覆盖项明确。
- [ ] 状态语义、动态内容、适配与关键异常足以支持交接。
- [ ] 资源和组件映射符合实际技术，未默认切图或复制字体。
- [ ] 当前摘要与详细记录一致，旧证据未冒充新版本通过。
- [ ] 链接、索引、负责人或待确认事项与实质更新时间同步。
