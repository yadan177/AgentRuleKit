# 04 - UI 设计文档任务入口

> - 🟢 本文件适用于首次整理、补充、审查或增量同步 UI 设计文档。
> - 🔴 不适用：因文档任务自动修改业务范围、设计源、正式资源或工程实现。

---

## 1. 判断任务与输入

先核对当前项目、有效规则、用户要求与已有文档。明确是分析建议还是写入 Markdown，以及本次页面、组件、流程或资源范围。

| 任务 | 规则与重点 |
|---|---|
| 首次建立或整体整理 | [00 总览](./00-UI设计文档规则总览.md)、[01 组织](./01-UI设计文档组织与维护规范.md)、[02 内容](./02-UI设计文档编写规范.md)、[03 模板](./03-UI设计文档模板.md) |
| 单页面/组件补充 | 现有正文、相关需求与源稿，02 及对应模板 |
| 设计或实现变更后同步 | 实际差异、权威定义、消费者与验证记录 |
| 审查与清理 | 来源一致性、覆盖、状态、重复内容和有效引用 |

- 🔴 只要求理解或评审时不自动批量建文件；需要写文档时复用实际目录。
- 🔴 文档包只规定记录方法；实际设计任务按已安装 UI 设计规则与项目授权执行，不因写文档新增设计审批。
- 🔴 外部设计文件无法读取时标明限制；链接存在不表示源稿已核对。

## 2. 首次整理

1. 识别现有需求、业务流程、设计基础、页面状态、源稿、资源、技术文档与验证入口，记录基线和不一致之处。
2. 以主要任务建立“流程/页面 → 状态与组件 → 源稿 → 实现或资源 → 验证”的对应关系；已有覆盖表直接补充。
3. 从主要流程梳理进入、呈现、动作、退出和必要异常，核对控件成员、状态语义、动态内容及适配。简单流程用短主线，不默认扩成复杂系统图。
4. 明确各类事实的权威位置，将设计意图、采用方案与实际实现分别记录。冲突先列范围和来源，不凭一份旧说明宣布完成。
5. 按 01/02/03 更新入口、基础、页面与交接正文；未覆盖内容和无法核实的事实明确标记，不创建空占位文档。
6. 从索引实际检查来源、引用、覆盖与状态；执行适用的已有检查，记录实际完成的方法和限制。

缺少完整设计或负责人时，可先完成已有证据的整理并保留草稿；不要伪造确认或要求用户逐个发现页面和状态。

## 3. 增量同步

先读取设计、配置、资源、代码或文档的真实差异。比较基线不明确时说明检查范围，不能声称全量同步。

| 变化 | 需要复核 |
|---|---|
| 需求或流程变化 | 页面范围、相关节点、关键异常与原型 |
| 组件或状态变化 | 契约、变量、实例、消费者与状态映射 |
| 文案或适配变化 | 内容来源、布局、极限情况、相关资源 |
| 资源或字体变化 | 源/文件/组件映射、版本、接入和引用 |
| 实现或验证变化 | 当前接入范围、实际环境、结果与剩余项 |

- 🔴 更新受影响正文、摘要、索引和实质更新时间，保留有效信息，不把局部变化扩大为全量重写。
- 🔴 设计变更后复核相关消费者与旧验证适用性；没有同步的部分标记待同步或待复验。
- 🔴 废弃或删除先核对引用和替代关系，临时产物按组织规则清理，不形成另一套归档文档树。
- 🟡 无文档影响时说明依据，例如纯工具内部整理未改变语义、来源链接、交付契约或当前状态。

## 4. 交付与自检

交付说明本次范围与基线、修改文档和入口、关键决定及依据、实际检查、未决项和未验证内容。

- [ ] 从索引能找到当前设计、采用范围、交付与实现/验证入口。
- [ ] 流程、状态、组件和资源按真实关系对应，未无依据新增业务。
- [ ] 文档状态与设计采用、交付、实现、验证分别记录。
- [ ] 当前摘要与详细条目一致，来源和链接可定位。
- [ ] 仅报告实际执行的核查，没有用文档更新冒充设计或设备验收。
