# 02 - Java 代码风格规则

> 🟢 本文件适用于 Java 代码的外观风格（缩进/大括号/行宽/Checkstyle 配置）。
> 🔴 不适用：业务逻辑实现、API 设计、数据库设计

---

## 1. 大括号

🟡 **推荐**：

- **大括号内为空**：简洁地写成 `{}`，不需要换行
- **非空代码块**：
  1. 左大括号**前**不换行
  2. 左大括号**后**换行
  3. 右大括号**前**换行
  4. 右大括号**后还有** `else` 等代码**不换行**；表示终止的右大括号**后必须换行**

**正例**：
```java
public static void main(String[] args) {
    String say = "hello";
    int flag = 0;
    if (flag == 0) {
        System.out.println(say);
    }
    if (flag == 1) {
        System.out.println("world");
    } else {
        System.out.println("ok");
    }
}
```

## 2. 空格与缩进

### 2.1 关键字与括号

🟡 **推荐**：

- `if` / `for` / `while` / `switch` / `do` 等保留字**与括号之间都必须加空格**
- **左小括号和字符之间不出现空格**；**右小括号和字符之间也不出现空格**
- **反例**：`if (空格a == b空格)`

### 2.2 运算符空格

🟡 **推荐**：

- **任何二目、三目运算符的左右两边都需要加一个空格**
- 运算符包括：赋值运算符 `=`、逻辑运算符 `&&`、加减乘除符号等

### 2.3 缩进

🟡 **推荐**：

- **采用 4 个空格缩进，禁止使用 tab 字符**
- IDEA 设置 tab 为 4 个空格时，请勿勾选 `Use tab character`
- Eclipse 必须勾选 `insert spaces for tabs`

### 2.4 注释空格

🟡 **推荐**：

- **注释的双斜线与注释内容之间有且仅有一个空格**
  - **正例**：`// 这是示例注释，请注意在双斜线之后有一个空格`
  - **反例**：`//这是注释`（无双斜线后空格）

### 2.5 对齐空格（不要做）

🟡 **推荐**：

- **不要增加若干空格来使某一行的字符与上一行对应位置的字符对齐**
  - **反例**：
    ```java
    int     a = 3;
    long    b = 4L;
    float   c = 5F;
    ```
  - 增加 `sb` 变量后要给 `a`、`b`、`c` 都增加空格，变量多时累赘
  - **正例**：
    ```java
    int a = 3;
    long b = 4L;
    float c = 5F;
    StringBuffer sb = new StringBuffer();
    ```

## 3. 行长度与换行

### 3.1 单行字符数限制

🟡 **推荐**：

- **单行字符数限制不超过 120 个**，超出需要换行
- 换行原则：
  1. 第二行相对第一行缩进 4 个空格，从第三行开始不再继续缩进
  2. **运算符与下文一起换行**
  3. **方法调用的点符号与下文一起换行**
  4. 方法调用多个参数需要换行时，**在逗号后进行**
  5. **在括号前不要换行**

**正例**：
```java
StringBuffer sb = new StringBuffer();
// 超过 120 个字符的情况下，换行缩进 4 个空格，点号和方法名称一起换行
sb.append("zi").append("xin")...
               .append("huang")...
               .append("huang")...
               .append("huang");
```

**反例**：
```java
sb.append("zi").append("xin")...append      // ❌ 在括号前换行
("huang");
method(args1, args2, args3, ...
       , argsX);                            // ❌ 在逗号前换行
```

### 3.2 方法参数的空格

🟡 **推荐**：

- **方法参数在定义和传入时，多个参数逗号后边必须加空格**
  - **正例**：`method("a", "b", "c");`
  - **反例**：`method("a","b","c");`（逗号后无空格）

## 4. import 顺序

### 4.1 import 分组（Google Java Style）

🟡 **推荐**：import 按以下顺序分组，**每组之间用空行分隔**：

1. **静态 import**（`import static`）
2. **本项目 / 本组织的 import**（如 `com.alibaba` / `com.company`）
3. **第三方库的 import**（如 `org.springframework.*` / `com.google.*`）
4. **Java 标准库的 import**（`java.*` / `javax.*`）

🟡 **推荐**：

- **import 中不允许使用通配符**（`*`）—— 影响可读性，且 git diff 无法追踪新增 import
  - **反例**：`import java.util.*;`
  - **正例**：`import java.util.List; import java.util.Map;`
- **静态 import 限制**：仅在确实频繁使用（如 JUnit 的 `assertEquals`、AssertJ 的 `assertThat`）时使用；不要为了一行省字而滥用

### 4.2 IDE 自动 import 配置

🟡 **推荐**：在 IDE 中配置：

- **IntelliJ IDEA**：
  - `Settings → Editor → Code Style → Java → Imports`
  - `Class count to use import with '*'`：设为 99（关闭通配符）
  - `Names count to use import with '*'`：设为 99（关闭静态通配符）
  - 勾选 `Use single class import`
  - `Import layout` 按 § 4.1 分组顺序配置
- **Eclipse**：
  - `Window → Preferences → Java → Code Style → Organize Imports`
  - `Number of imports needed for .*`：设为 99


## 5. 注释排版

### 5.1 Javadoc 格式

🔴 **必须**：

- 对外公开或由项目约定要求文档化的类、方法、字段使用 `/** ... */` Javadoc；Javadoc 应紧挨被说明的声明。
- 方法内部和局部逻辑说明使用 `//`；不得为了写多行说明而改用普通 `/* ... */`。
- Javadoc 标签顺序（推荐）：
  1. `@param`（按方法参数顺序）
  2. `@return`
  3. `@throws` / `@exception`
  4. `@deprecated`（如已废弃）
  5. `@see` / `@link`

**正例**：
```java
/**
 * 根据 ID 查询用户。
 *
 * @param userId 用户 ID
 * @return 用户对象；不存在返回 null
 * @throws IllegalArgumentException userId 为 null
 * @see UserService#findById(Long)
 * @deprecated 请使用 {@link #findById(Long, boolean)}
 */
@Deprecated
public User findById(Long userId) { ... }
```

### 5.2 `/* */` 块注释（默认不用）

- **临时禁用代码**用 `// TODO` 或行尾 `// FIXME` 标注（不用 `/* */` 块注释）
- ❌ **禁止**将普通 `/* ... */` 用作复杂算法或业务流程说明；连续说明使用贴近代码的多行 `//` 中文注释。
- 🟢 仅在不可改动的第三方/生成代码、授权声明或项目既有工具指令明确要求时保留普通 `/* ... */`；`/** ... */` Javadoc 不受此限制。

### 5.3 注释中的引用

🟢 **可选**：

- Javadoc 中引用其他类用 `{@link ClassName#methodName}`，**不要**写纯文本如 `see ClassName.methodName`
- 引用自动生成 javadoc.html 链接，IDE 能跳转

## 6. 空行

### 6.1 不同逻辑之间空一行

🟡 **推荐**：

- **不同逻辑、不同语义、不同业务的代码之间插入一个空行分隔**以提升可读性
- **没有必要插入多个空行**进行隔开（最多 1 个空行）

**正例**：
```java
public void process() {
    // 1. 参数校验
    validate();

    // 2. 业务处理
    doSomething();

    // 3. 返回结果
    return result;
}
```

### 6.2 文件末尾空行

🟡 **推荐**：

- **每个文件末尾必须有且仅有一个空行**（POSIX 标准，git / diff / IDE 都依赖此约定）
  - **反例**：文件末尾有 2 个或 0 个空行
- 许多 lint 工具会强制（如 Checkstyle 的 `NewlineAtEndOfFile`）

### 6.3 尾随空格

🟡 **推荐**：

- **每行末尾不留尾随空格**（trailing whitespace）
- 多数编辑器自动高亮：行末的 `····` 是空格，`·······` 是 tab
- 在 CI 中可用 `grep -nE " +$" file.java` 检测

## 7. 编码与换行符

### 7.1 文件编码

🟡 **推荐**：

- **IDE 的 text file encoding 设置为 UTF-8**（不要用 GBK / GB18030 / ISO-8859-1）
- IDEA：`Settings → Editor → File Encodings` 全设为 UTF-8
- Eclipse：`Window → Preferences → General → Workspace` 设为 UTF-8

### 7.2 换行符

🟡 **推荐**：

- **IDE 中文件的换行符使用 Unix 格式**（`\n`），**不要使用 Windows 格式**（`\r\n`）
- IDEA：`Settings → Editor → Code Style → Line separator` 选 `Unix and macOS (\n)`
- Eclipse：`Window → Preferences → General → Workspace → New text file line delimiter` 选 `Unix`

**为什么**：跨平台协作时 Windows / Unix 混用导致 git diff 噪音；Linux 服务器部署时 `\r` 会被识别为字符。

### 7.3 .editorconfig 共享配置（推荐）

🟡 **推荐**：项目根目录放 `.editorconfig` 文件，让所有 IDE 统一规则：

```ini
# .editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 4
insert_final_newline = true
trim_trailing_whitespace = true

[*.{yml,yaml,xml,json}]
indent_size = 2

[*.md]
trim_trailing_whitespace = false
```


## 8. 静态检查配置（AI 视角扩展）

P3C 原版不涉及 IDE / 构建工具配置。AI 在 CI / 项目初始化时立即要用的工具链。

### 8.1 Checkstyle 配置

🟡 **推荐**：Maven 项目引入 Checkstyle：

```xml
<!-- pom.xml -->
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-checkstyle-plugin</artifactId>
    <version>3.3.1</version>
    <configuration>
        <configLocation>checkstyle.xml</configLocation>
        <consoleOutput>true</consoleOutput>
        <failsOnError>true</failsOnError>
        <failOnViolation>true</failOnViolation>
    </configuration>
</plugin>
```

🟡 **推荐**：项目根目录放 `checkstyle.xml`（Google Java Style 基线）：

```xml
<?xml version="1.0"?>
<!DOCTYPE module PUBLIC
    "-//Checkstyle//DTD Checkstyle Configuration 1.3//EN"
    "https://checkstyle.org/dtds/configuration_1_3.dtd">
<module name="Checker">
    <property name="charset" value="UTF-8"/>
    <property name="severity" value="warning"/>
    <module name="FileTabCharacter">
        <property name="eachLine" value="true"/>
    </module>
    <module name="LineLength">
        <property name="max" value="120"/>
    </module>
    <module name="NewlineAtEndOfFile"/>
    <module name="RegexpSingleline">
        <property name="format" pattern="\s+$"/>
        <property name="message" value="行末不应有尾随空格"/>
    </module>
    <module name="TreeWalker">
        <module name="Indentation">
            <property name="basicOffset" value="4"/>
            <property name="caseIndent" value="4"/>
        </module>
        <module name="MethodParamPad"/>
        <module name="ParenPad"/>
        <module name="TypeName"/>
        <module name="ConstantName"/>
        <module name="LocalVariableName"/>
        <module name="MemberName"/>
        <module name="MethodName"/>
        <module name="PackageName"/>
        <module name="EmptyBlock">
            <property name="option" value="text"/>
        </module>
    </module>
</module>
```

### 8.2 SpotBugs 配置

🟡 **推荐**：SpotBugs 替代过时的 FindBugs，检测**潜在 bug**（不只是风格）：

```xml
<!-- pom.xml -->
<plugin>
    <groupId>com.github.spotbugs</groupId>
    <artifactId>spotbugs-maven-plugin</artifactId>
    <version>4.7.3.6</version>
    <configuration>
        <effort>Max</effort>
        <threshold>Medium</threshold>
        <failOnError>true</failOnError>
    </configuration>
</plugin>
```

**重点关注规则**（AI 写代码时立即避开）：

- `EQ_COMPARETO_USE_OBJECT_EQUALS`：`compareTo` 实现里调用 `equals`
- `EI_EXPOSE_REP`：内部可变对象直接暴露（`getXxx` 返回可变字段）
- `EI_EXPOSE_REP2`：构造方法 / setter 接收外部可变引用未做拷贝
- `DM_DEFAULT_ENCODING`：`new String(bytes)` 用默认编码（应显式 UTF-8）
- `UC_USELESS_OBJECT`：`String.valueOf(x)` 后立即 `toString()`
- `SIC_INNER_SHOULD_BE_STATIC`：内部类可声明为 `static`
- `DMI_RANDOM_USED_ONLY_ONCE`：`new Random()` 只用一次（应用 `ThreadLocalRandom`）

### 8.3 PMD 配置（P3C 官方 p3c-pmd）

🟡 **推荐**：阿里 P3C 自带 PMD 规则集：

```xml
<!-- pom.xml -->
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-pmd-plugin</artifactId>
    <version>3.21.0</version>
    <configuration>
        <rulesets>
            <ruleset>rulesets/java/ali-comment.xml</ruleset>
            <ruleset>rulesets/java/ali-concurrent.xml</ruleset>
            <ruleset>rulesets/java/ali-constant.xml</ruleset>
            <ruleset>rulesets/java/ali-exception.xml</ruleset>
            <ruleset>rulesets/java/ali-flowcontrol.xml</ruleset>
            <ruleset>rulesets/java/ali-naming.xml</ruleset>
            <ruleset>rulesets/java/ali-oop.xml</ruleset>
            <ruleset>rulesets/java/ali-orm.xml</ruleset>
            <ruleset>rulesets/java/ali-other.xml</ruleset>
            <ruleset>rulesets/java/ali-set.xml</ruleset>
        </rulesets>
    </configuration>
</plugin>
```

### 8.4 工具选型对比

🟢 **可选**：

| 工具 | 关注点 | 适用 |
|---|---|---|
| **Checkstyle** | 风格 / 排版 | 强制统一格式 |
| **SpotBugs** | 潜在 bug | 找真正可能出错的代码 |
| **PMD** | 代码异味 / 重复 | 静态分析 |
| **Error Prone** | 编译期 bug | 编译时拦截（更激进）|
| **SonarQube** | 综合（含安全）| 企业级代码质量平台 |

**推荐组合**：Checkstyle（格式）+ SpotBugs（bug）+ p3c-pmd（P3C 规约），三个工具各管一摊。

### 8.5 IDE 自动格式化触发

🟡 **推荐**：AI 写完代码后立即在 IDE 触发：

- **IntelliJ IDEA**：
  - 快捷键 `Ctrl + Alt + L`（Windows/Linux）/ `Cmd + Option + L`（Mac）格式化
  - `Ctrl + Alt + O`（Windows/Linux）/ `Cmd + Option + O`（Mac）优化 import
- **Eclipse**：
  - `Ctrl + Shift + F` 格式化
  - `Ctrl + Shift + O` 优化 import
- **保存时自动格式化**：
  - IDEA：安装 `Save Actions` 插件，启用 "format on save"
  - Eclipse：`Window → Preferences → Java → Editor → Save Actions` 勾选
