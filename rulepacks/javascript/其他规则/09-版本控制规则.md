# 09 - JavaScript 版本控制规则

> - 🟢 本文件适用于 Git 版本控制（Conventional Commits/.gitignore/PR/CI）。
> - 🔴 不适用：替项目擅自决定托管平台、分支策略、Code Owner 或发布流程

---

## 1. 🔴 硬约束 · 这些绝对不要写

### 1.1 绕过仓库既有主分支保护

```bash
# ❌ 仓库要求 PR 时不得绕过保护直接推送
git push origin main

# ✅ 走 feature 分支 + PR
git checkout -b feature/login
git commit -m "feat: add login page"
git push origin feature/login
# 在 GitHub / GitLab 提 PR
```

下列设置仅在团队已确认采用 PR 工作流时配置，不得由通用规则擅自修改仓库设置：

- ✅ 分支保护：禁止直接 push main
- 🟡 reviewer 数量和必需检查沿用仓库保护规则
- 🟡 Conventional Commits 仅在仓库已经采用时作为门禁

### 1.2 commit 信息含糊

```bash
# ❌
git commit -m "fix"
git commit -m "update code"
git commit -m "完成"

# ✅
git commit -m "fix(auth): handle expired token redirect"
git commit -m "feat(user): add profile page with avatar upload"
```

详见 [§ 2.1 Conventional Commits](#21-conventional-commits-规范)。

### 1.3 大文件 / 依赖入库

```gitignore
# .gitignore 必须有
node_modules/
dist/
build/
coverage/
.env
.env.local
.DS_Store
*.log

# 项目明确不入库的本地导出物按实际文件名或目录忽略
# 需要版本化的大型二进制应评估 LFS，不能同时被 .gitignore 排除
```

**`node_modules` 必须 gitignore**——队友 `npm install` 即可还原。

### 1.4 提交前未自检（lint / test）

项目已经采用 husky + lint-staged 时沿用现有配置；新增依赖和提交钩子必须获得授权，不能因本示例直接安装：

```bash
npm install -D husky lint-staged
npx husky init
```

```jsonc
// package.json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": [
      "eslint --fix",
      "prettier --write",
      "vitest related --run"
    ]
  }
}
```

```bash
# .husky/pre-commit
npx lint-staged
```

### 1.5 提交 .env / 密钥文件

```gitignore
# 必须
.env
.env.*
!.env.example           # 例外：示例文件
```

**泄漏密钥处理**：

1. 立即轮换密钥（不要只删文件，密钥已泄漏）
2. 评估泄漏范围；确需清理历史时，取得仓库管理员授权并制定备份、通知和强制推送方案
3. 优先使用团队已采用的历史清理工具；完成后让所有协作者按统一步骤更新本地

## 2. 🟡 推荐 · 团队约定

### 2.1 Conventional Commits 规范

```
<type>(<scope>): <description>

[body]

[footer]
```

| type | 用途 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(auth): add OAuth login` |
| `fix` | 修 bug | `fix(api): handle 500 from /users` |
| `refactor` | 重构（无功能变化） | `refactor(user): extract profile store` |
| `perf` | 性能优化 | `perf(list): virtualize scroll for 1000+ rows` |
| `test` | 测试 | `test(user): add login integration tests` |
| `docs` | 文档 | `docs(readme): update setup instructions` |
| `style` | 格式（不影响逻辑） | `style: fix unused imports` |
| `chore` | 杂项（依赖 / 配置） | `chore: bump axios to 1.7.0` |
| `build` | 构建系统 | `build: switch to pnpm` |
| `ci` | CI 配置 | `ci: add E2E workflow` |
| `revert` | 回滚 | `revert: feat(auth): add OAuth login` |

**BREAKING CHANGE**：在 footer 标注：

```
feat(api)!: rename /users to /v1/users

BREAKING CHANGE: /users endpoint is now /v1/users
```

### 2.2 分支策略

**Trunk-Based（推荐中小团队）**：

```
main                        # 生产分支（受保护）
├── feature/login           # 单 feature 用一个分支
├── feature/profile
├── fix/login-redirect
└── release/1.2.0           # 发布分支（可选）
```

**GitFlow**（大型项目 / 版本化发布）：

```
main                        # 生产分支
├── develop                 # 集成分支
│     ├── feature/login
│     └── feature/profile
└── hotfix/critical-fix     # 紧急修复
```

| 分支类型 | 命名 | 来源 | 合并到 |
|---------|------|------|--------|
| 主干 | `main` / `master` | — | — |
| 集成分支 | `develop` | main | — |
| 功能分支 | `feature/<name>` | develop | develop |
| 修复分支 | `fix/<name>` | develop | develop |
| 紧急修复 | `hotfix/<name>` | main | main + develop |
| 发布分支 | `release/<version>` | develop | main + develop |

### 2.3 PR 检查清单

- [ ] 标题符合 Conventional Commits
- [ ] 描述清楚改了什么、为什么改（链接 issue）
- [ ] `npm run lint` 通过
- [ ] `npm run test` 通过
- [ ] 覆盖率满足仓库当前 CI 门槛，且关键行为与失败路径已有有效断言
- [ ] 没有新的大文件 / 密钥泄漏
- [ ] .gitignore 完整（node_modules / .env / dist）
- [ ] CI 全绿
- [ ] 至少 1 个 reviewer approve
- [ ] 解决所有 review comments

### 2.5 Git LFS（大文件）

```bash
# 安装
git lfs install

# 追踪大文件
git lfs track "*.psd"
git lfs track "*.zip"
git lfs track "*.tar.gz"

# 项目确认采用 LFS 后提交对应 .gitattributes
git add .gitattributes
```

**.gitattributes 文件**：

```gitattributes
*.psd filter=lfs diff=lfs merge=lfs -text
*.zip filter=lfs diff=lfs merge=lfs -text
```

## 3. 🟢 可选 · 视情况

### 3.1 Conventional Commits 自动化

| 工具 | 用途 |
|------|------|
| **commitlint** | 校验 commit 信息格式 |
| **husky + commit-msg hook** | 提交时自动校验 |
| **release-please / semantic-release** | 自动生成 CHANGELOG / 版本号 / release |

```bash
npm install -D @commitlint/cli @commitlint/config-conventional
```

```js
// commitlint.config.js
export default {
  extends: ['@commitlint/config-conventional'],
};
```

```bash
# .husky/commit-msg
npx --no-install commitlint --edit "$1"
```

### 3.2 Monorepo / 单一仓库

工具：

- 项目已经采用的 workspace 方案（例如 npm/pnpm/yarn workspaces）；不得因本节切换包管理器
- **Turborepo**（增量构建 / 任务编排）
- **Nx**（更完整的企业级方案）

### 3.3 提交签名（GPG / SSH）

```bash
# 仅在用户明确要求后配置；优先使用仓库级设置，避免改变其他项目
git config commit.gpgsign true

# 或 SSH 签名（Git 2.34+）
git config gpg.format ssh
git config user.signingkey /absolute/path/to/approved_signing_key.pub
```

不得猜测签名密钥路径，也不得未经授权修改用户的全局 Git 配置。
