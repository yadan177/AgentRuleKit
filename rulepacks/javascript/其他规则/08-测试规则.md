# 08 - JavaScript 测试规则

> - 🟢 本文件适用于 JavaScript/TypeScript 的单元、集成、端到端和回归验证策略。
> - 🔴 不适用：替换项目测试框架、断言库、Mock 体系、覆盖率门禁或 CI 环境

---

## 1. 现有测试体系优先

- 🔴 先读取 `package.json`、lockfile、测试配置、现有测试、fixtures、CI 和目标运行时，再编写或执行测试。
- 🔴 沿用项目已经采用的 runner、断言、Mock、DOM/组件工具和 E2E 框架；不得因示例引入 Vitest、Jest、MSW、Supertest、Playwright、Cypress 或其他工具。
- 🔴 测试命令、文件位置、环境和全局 setup 以仓库事实为准，不能把 `npm test` 或某种文件后缀写成统一入口。
- 🟡 React/Vue 组件测试分别读取 13/16，并继续服从项目现有测试工具。

## 2. 测试层次与范围

| 层次 | 主要目标 | 常见边界 |
|---|---|---|
| 单元测试 | 快速验证纯逻辑和局部状态转换 | 函数、类、解析、校验、失败分支 |
| 集成测试 | 验证多个真实模块或外部边界协作 | 数据访问、存储、路由、进程内服务 |
| 端到端测试 | 验证用户可观察的关键流程 | 浏览器、真实构建、部署环境或跨服务路径 |

- 🔴 不使用 70/20/10 等固定比例；测试分布由风险、历史缺陷、运行成本和现有体系决定。
- 🟡 优先用低成本测试覆盖分支和失败语义，再为关键集成与用户流程增加更高层验证。
- 🔴 本次改动影响的行为、错误、取消、竞态、兼容和降级路径必须有与风险相称的验证。

## 3. 测试独立性与异步行为

- 🔴 每个测试建立自己的可变状态并在结束时清理；不得依赖测试顺序或上一个测试留下的数据、时间、网络和全局配置。
- 🔴 Promise、回调、定时器和事件测试必须等待真实完成条件；不能让测试在断言执行前结束。
- 🔴 订阅、监听器、临时文件、数据库事务、Worker、浏览器上下文和服务进程需要可靠 teardown，即使断言失败也要清理。
- 🟡 时间和随机性可通过项目已有 fake clock、可注入依赖或固定 seed 控制，并验证恢复真实全局状态。

```js
test('returns parsed data after the request completes', async () => {
  const result = await loadData();
  expect(result.status).toBe('ready');
});
```

> `test` 和 `expect` 仅表示项目现有测试 API；名称和匹配器以实际框架为准。

## 4. 断言与行为边界

- 🔴 测试必须包含能证明目标行为的断言；“没有抛错”只有在它本身就是契约时才足够。
- 🟡 优先断言公开输出、可观察状态、协议和用户行为，避免把私有方法调用次数或 DOM 内部结构固化为契约。
- 🔴 错误测试同时验证类型/业务码、关键上下文和恢复语义；不要只匹配易变的完整错误文案。
- 🟡 使用 Arrange-Act-Assert、Given-When-Then 或项目既有结构保持因果清晰，不为格式统一机械添加注释。

## 5. Test Double 边界

- 🟡 在网络、时间、随机数、文件、存储、平台 SDK 等非确定或高成本边界使用项目已有 mock、fake、stub 或测试实现。
- 🔴 Test double 必须符合真实接口的成功、失败、取消和时序语义；过度简化的 mock 不能替代集成验证。
- ❌ 不为验证内部调用次数而 mock 纯实现细节，也不把所有依赖都 mock 后声称完成集成测试。
- 🔴 第三方 SDK 无法在测试环境运行时，记录替代范围，并在可用的沙箱、设备或集成环境补充验证。

## 6. 覆盖率与质量门禁

- 🔴 覆盖率阈值沿用仓库和 CI 配置；AI 不得自行写入统一百分比或为通过门禁添加无行为价值的测试。
- 🟡 使用覆盖率发现未执行的关键分支，再结合 mutation、属性测试或人工审查判断断言质量；这些工具仅在项目已采用或获得授权时使用。
- 🔴 新增 ignore、降低阈值、跳过测试或更新 snapshot 前必须说明原因并符合项目审批规则。
- 🟡 Snapshot 只适合稳定且可审查的输出；大面积无审查更新不能证明行为正确。

## 7. 端到端与目标环境

- 🟡 E2E 聚焦项目确认的关键用户路径、跨系统契约和低层测试无法覆盖的风险，不按固定数量创建。
- 🔴 E2E 数据必须可隔离、可清理，并避免依赖生产账号、真实密钥或不可控第三方状态。
- 🔴 浏览器、Node.js、SSR、Worker、容器和设备行为存在差异时，在实际目标环境验证；本地测试通过不能替代目标平台。
- 🟡 视觉回归、可访问性、性能和兼容测试按产品风险与项目已有平台选择，不默认具体服务。

## 8. 交付检查

- 说明读取和使用的测试配置、命令及环境。
- 列出新增/修改测试覆盖的行为和未验证范围。
- 检查失败、取消、竞态、清理、权限和兼容路径。
- 确认没有未经授权安装工具、更新大面积 snapshot、降低门禁或跳过测试。
- 无法运行测试时说明具体原因、影响范围和需要补做的验证。
