# 00 - JavaScript AI 编码规则文档总览（AI 入口）

---

**🎯 规则撰写的核心原则**

1. AI 编程规则的本质，是将项目中的架构边界、业务约束与编码规范转化为机器可执行的决策规则，使 AI 输出的不只是能运行的代码，而是符合团队工程标准、可维护且可扩展的代码。
2. 不要有 AI 幻觉。
3. 不要过度设计。

## 1. 适用范围

- ✅ JavaScript 项目开发（Node.js / 浏览器 / React / Vue / 通用 JS，按项目实际运行时选择）
- ✅ Codex / Qoder / TRAE 及其他可读取项目规则的 AI 工具

> Node.js、浏览器、React、Vue、构建工具、测试工具和样式方案均以仓库已有运行时、依赖和脚本为准；本规则中的示例不构成默认技术栈。

❌ 不适用：TS 独有类型规则（见 `../typescript/`）/ 框架深度用法

## 2. 硬性约束

| 等级 | 标识 | 含义 |
|------|------|------|
| 必须 | 🔴 | 当前适用场景必须遵守；无法执行时说明原因、范围和风险 |
| 推荐 | 🟡 | 满足适用条件时优先评估；项目事实、风险和成本不支持时不采用 |
| 可选 | 🟢 | 按项目实际灵活选择 |
| 安全 | 🟠 | 涉及对应威胁时必须处理，具体措施以项目威胁模型为准（见 11） |

## 5. 跨语言继承

JS 是运行时基线层（TS 的上游）。TS 项目先加载 JS 通用入口，再按任务选择 JS 与 TS 专题，不要求一次读取全部文件。
