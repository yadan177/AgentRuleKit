# 02 - Python 代码风格规则

> 🟢 本文件适用于 Python 代码的格式、命名、导入、注释和静态检查。<br>
> 🔴 不适用：要求项目迁移到某个格式化器、检查器或类型工具。

---

## 1. 项目工具优先

- 🔴 优先遵守仓库中的 `pyproject.toml`、配置文件、CI 和现有代码风格。
- 🔴 修改代码后执行项目已有的格式化、静态检查或类型检查；无法执行时说明原因。
- ❌ 禁止仅为统一风格引入或升级 Black、Ruff、isort、mypy、pyright 等工具。

## 2. 命名与导入

| 对象 | 默认形式 |
|---|---|
| 模块、函数、变量 | `snake_case` |
| 类、异常、类型变量 | `PascalCase` |
| 常量 | `UPPER_SNAKE_CASE` |
| 私有实现 | 前缀 `_`，不作为公共契约 |

- 🔴 名称表达领域含义，禁止 `data`、`temp`、`handle` 等无上下文泛名长期存在。
- 🔴 导入放在文件顶部并按项目工具排序；避免 `import *` 和未使用导入。
- 🔴 新增或修改的说明性注释、文档字符串必须使用中文；代码标识符、文档字符串标记和项目既有术语保持规范原样。
- 🟢 可保留英文的情形仅限：工具可识别标记或指令（如 `TODO`、`FIXME`、`# type: ignore`、`# noqa`）、协议/标准/第三方专有名词、已明确对外发布的英文 API 契约，以及外部依赖或自动生成代码；除标记和专有名词外，仍应以中文说明含义或原因。
- ❌ 不得仅因模块名、类名、函数名或 API 为英文，就把说明性注释或文档字符串整体改写为英文。
- 🟡 注释解释原因、约束或风险，不复述代码表面动作。

## 3. 文档字符串与类型

- 🔴 公共模块、类和函数的文档字符串格式遵循项目既有约定。
- 🔴 方法内部和局部逻辑说明使用 `#`；需要多行说明时连续使用多行 `#`。
- 🔴 模块、类和函数的文档字符串使用 `"""..."""`，并放在定义体的第一条语句；它用于说明该定义的用途、契约或使用方式。
- ❌ **禁止**把三引号字符串当作普通块注释或临时禁用代码；它是可被运行时和文档工具读取的字符串，不是 `/* ... */` 的替代品。
- 🟢 `# type: ignore`、`# noqa`、shebang、编码声明、不可改动的第三方/生成代码或授权声明按工具和来源要求保留原格式。
- 🟡 公开边界和复杂数据建议标注类型；类型注释不能替代输入校验或业务说明。
- 🟢 小型私有函数若名称和类型已清楚，可不重复写冗长文档字符串。
