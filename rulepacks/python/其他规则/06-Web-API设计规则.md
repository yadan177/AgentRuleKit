# 06 - Python Web API 设计规则

> - 🟢 本文件适用于项目已存在的 HTTP、RPC 或消息接口的设计与修改。
> - 🔴 不适用：假定 Web 框架、认证方案、序列化库或网关能力。

---

## 1. 契约优先

- 🔴 先确认 OpenAPI、Proto、消息定义或既有路由约定，再修改接口实现。
- 🔴 请求校验、认证授权、业务处理和错误映射应分层；边界层不得把原始内部异常直接暴露给调用方。
- 🔴 响应字段、错误格式、分页、幂等和版本策略沿用项目契约；新增字段优先考虑兼容性。

## 2. 输入与错误

- 🔴 所有外部输入在边界校验类型、范围、长度、权限和业务前置条件。
- 🔴 错误响应不包含堆栈、密钥、SQL、内部路径或未脱敏数据。
- 🟡 可能重试的写操作应具有幂等键、去重或项目既有保护机制。

## 3. 变更验证

- 🔴 修改接口后同步契约、调用方、测试和文档。
- 🟡 对外接口变更记录兼容性影响、灰度或回滚条件。
