# 01 - Python 代码编写规则

> 🟢 本文件适用于 Python 模块、函数、类、脚本和库接口的创建与修改。<br>
> 🔴 不适用：替代项目已有框架、类型检查策略或公共 API 约定。

---

## 1. 模块与函数边界

- 🔴 一个函数完成一个可描述的动作；超过一个职责时拆为私有辅助函数或独立模块。
- 🔴 公共函数和类必须有稳定、可读的输入输出边界；修改公共签名前先搜索调用方。
- 🔴 避免导入时执行网络、数据库、文件写入或全局初始化等副作用；显式入口负责初始化。
- 🟡 业务逻辑优先依赖抽象的参数或 Protocol，而非在函数内部创建外部客户端。

## 2. 数据、类型与默认值

- 🔴 不使用可变对象作为默认参数；用 `None` 表示未提供，并在函数内创建新对象。
- 🔴 外部输入、反序列化结果和可空值必须在边界处校验；不能因类型标注存在就跳过运行时验证。
- 🔴 类型标注、`dataclass`、Pydantic、attrs 或其他建模方式必须沿用项目现有方案，不得擅自替换。
- 🟡 对公共 API、复杂返回值和跨模块数据建议提供类型标注；具体严格度以项目工具链为准。

## 3. 资源与副作用

- 🔴 文件、连接、锁、会话和临时资源必须使用上下文管理器或明确的 `close`/清理路径。
- 🔴 需要 I/O、时间、随机数或外部服务的逻辑应在边界注入，便于测试和替换。
- ❌ 禁止通过全局可变状态在模块间传递请求状态或业务数据。

## 4. 示例

```python
# ❌ 可变默认值会在调用间共享
def add_tag(tag: str, tags: list[str] = []):
    tags.append(tag)
    return tags

# ✅ 每次调用创建独立列表
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    result = [] if tags is None else list(tags)
    result.append(tag)
    return result
```
