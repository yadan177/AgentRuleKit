# 08 - Python 测试规则

> 🟢 本文件适用于 Python 的单元测试、集成测试、端到端测试和质量验证。
> 🔴 不适用：为了覆盖率数字编写无断言、无业务价值或依赖实现细节的测试。

---

## 1. 项目测试事实优先

- 🔴 沿用项目已采用的测试框架、目录、命名、fixture、mock 和 CI 命令。
- 🔴 测试名称描述可观察行为和条件，而不是内部函数实现。
- 🔴 新增或修改行为时，补充与风险相称的测试；无法补充时说明未覆盖范围和原因。
- ❌ 禁止默认引入 pytest、hypothesis、factory、容器测试或覆盖率工具。

## 2. 测试边界

- 🔴 单元测试隔离网络、时钟、随机数、文件和外部服务；通过项目既有注入点或替身控制。
- 🔴 集成测试使用隔离环境、可重复数据和清理路径；不得误连生产资源。
- 🔴 异步测试必须等待、取消和清理所有 task，避免测试结束后遗留后台任务。
- 🟡 对 bug 修复优先新增能复现问题的回归测试。

## 3. 断言与质量

- 🔴 每个测试断言业务结果、错误或外部副作用，不只验证代码未抛异常。
- 🟡 覆盖率是信号不是目标；重点覆盖权限、异常、边界、并发和数据迁移路径。
- 🟡 性能、负载和安全验证应使用项目已有基线或明确的验收标准。
