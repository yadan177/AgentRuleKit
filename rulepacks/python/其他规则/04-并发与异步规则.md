# 04 - Python 并发与异步规则

> - 🟢 本文件适用于 asyncio、线程、进程、后台任务和共享状态。
> - 🔴 不适用：未经项目证据在同步与异步架构之间迁移，或混用不兼容的并发模型。

---

## 1. 模型选择

- 🔴 沿用项目既有的同步、asyncio、线程、进程或任务队列模型；不要因“性能”猜测而替换。
- 🔴 在 async 路径中不得调用阻塞 I/O 或长 CPU 计算，除非项目已有明确的隔离方式。
- 🟡 I/O 并发、CPU 并行和离线任务分别评估；选择依据必须是项目约束和测量结果。

## 2. 生命周期与取消

- 🔴 创建 task、线程、进程或后台任务时，必须明确谁持有、等待、取消和记录失败。
- 🔴 取消时传播 `CancelledError`，仅在完成必要清理后继续抛出；禁止静默吞掉取消。
- 🔴 超时、限流、队列容量和并发上限必须沿用项目约定或显式配置。

## 3. 共享状态

- 🔴 不在多个 task/线程中无保护地修改共享可变状态。
- 🔴 线程锁、async 锁、队列和 `contextvars` 的使用范围必须与实际并发模型匹配。
- 🟡 并发问题先用日志、指标、追踪或测试复现，再改动同步策略。
