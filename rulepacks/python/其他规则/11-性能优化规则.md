# 11 - Python 性能优化规则

> 🟢 本文件适用于 Python 的 CPU、内存、I/O、并发、缓存和数据库性能问题。
> 🔴 不适用：未测量即引入缓存、并行、复杂数据结构或架构迁移。

---

## 1. 先测量后优化

- 🔴 优化前明确场景、输入规模、基线、瓶颈证据和验收指标。
- 🔴 优化后使用相同场景复测，确认正确性、资源消耗和回归风险。
- 🟡 使用项目已有 profiler、基准脚本、APM 或指标；工具选择不是默认依赖。

## 2. 常见边界

- 🟡 I/O 密集任务评估批处理、连接复用、超时和并发上限；CPU 密集任务评估算法和合适的隔离方式。
- 🟡 大集合优先减少不必要加载、复制、序列化和 N+1 查询；保留可读性和错误处理。
- 🔴 缓存必须定义 key、TTL、失效、容量、并发一致性和降级路径；不能把缓存当作数据正确性的唯一来源。

## 3. 禁止事项

- ❌ 禁止通过忽略错误、减少校验、取消鉴权或吞掉超时来“优化”。
- ❌ 禁止在 async 路径中以阻塞操作掩盖性能问题。
