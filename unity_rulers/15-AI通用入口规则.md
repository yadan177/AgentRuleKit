# 15 - Unity AI 通用入口规则

> 🟢 本文件适用于任何 AI 工具执行 Unity 项目开发、修改、审查或排障任务。
> 🔴 不适用：替代项目事实、自动批准架构迁移或伪造验证结果。

---

## 1. 使用方式

本文件是 Unity 规则库的最小入口。AI 必须先遵守本文件，再按 [00 - 文档总览](./00-文档总览.md) 读取与任务相关的专题规则。

- 🔴 **必须**将用户当前任务、工具安全限制和目标项目事实置于通用建议之前。
- 🟡 **推荐**只加载当前任务必要的专题文档，避免把整套参考手册当作无差别指令。
- 🟢 **可选**在一次性对话中手动附加本文件与相关专题文档。

## 2. 项目能力探测

### 2.1 开始前检查

在编写或修改 Unity 内容前，AI 必须检查能够获得的以下证据：

1. `ProjectSettings/ProjectVersion.txt` 与已有脚本语法。
2. `Packages/manifest.json` 和 `packages-lock.json`。
3. `.asmdef`、命名空间、当前模块的依赖和既有实现。
4. 渲染管线、UI 框架、输入系统和资源加载系统。
5. 构建脚本、CI、测试和项目规定的验证命令。

### 2.2 决策规则

- 🔴 **必须**只调用项目中已安装且已有证据支持的包与 API。
- 🔴 **必须**沿用同模块已验证的异步、资源释放、日志、事件和错误处理模式，除非用户明确授权改造。
- 🔴 **必须**在配置缺失或能力无法判断时说明不确定点；优先采用已有兼容实现，仍无法安全决策时询问用户。
- ❌ **禁止**把特定 Unity 编辑器版本、包或第三方框架设为本规则库的全局前提。

## 3. 变更边界

### 3.1 必须遵守的边界

- 🔴 未获明确授权时，不升级 Unity、包、C# 语言级别、渲染管线或资源系统。
- 🔴 未获明确授权时，不引入新第三方依赖、不重写无关模块、不批量移动资源或修改 Project Settings。
- 🔴 修改资源时必须维护 Asset 与 `.meta` 的对应关系，并验证受影响引用。
- 🔴 任何资源句柄、事件订阅、协程或异步操作都必须明确生命周期与所有权。

### 3.2 推荐做法

- 🟡 先完成最小可验证改动，再处理可选重构。
- 🟡 对性能优化先用 Profiler 或现有指标定位，再选择缓存、对象池或渲染方案。
- 🟡 对跨模块或跨语言改动，先写清客户端、服务端和资源服务各自负责什么。

## 4. 禁止臆造

- ❌ 禁止臆造包已安装、资源地址存在、场景或 Prefab 结构、程序集名称、构建命令、测试结果或服务端协议。
- ❌ 禁止把示例 API 当作项目已有 API。
- ❌ 禁止在未执行验证时声称编译、测试、构建或设备验证通过。

## 5. 验证与交付

### 5.1 验证要求

- 🔴 **必须**执行项目可用且与改动相称的验证；若无法执行，必须说明原因和未验证范围。
- 🔴 **必须**检查修改文件是否超出用户任务范围，资源与 `.meta` 是否成对，新增依赖是否获得授权。
- 🟡 推荐对 UI、资源、网络和性能改动给出需要在 Unity Editor 或目标设备上复核的清单。

### 5.2 交付说明

每次任务结束时，AI 应说明：

1. 修改了什么，以及为什么。
2. 执行了哪些验证及其结果。
3. 哪些验证未执行、原因和剩余风险。
4. 需要用户确认的项目事实、迁移或外部协作事项。

## 6. 规则编写模板

新增或改写专题规则时使用以下结构：

```markdown
### N.M 规则名称

**适用条件**：项目满足的配置、包或模块前提。

🔴 **必须**：可执行的强制要求。

🟡 **推荐**：有条件的推荐做法。

🟢 **可选**：可按项目选择的方案。

**验证**：可检查的命令、文件、测试或 Editor 操作。

**例外**：允许偏离规则的明确条件和处理方式。
```
