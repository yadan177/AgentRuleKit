# 00 - Unity AI 项目开发规则总览

---

## 1. 使用目标与适用范围

本规则库帮助任何 AI 编程工具在 Unity 项目中做出与**当前项目事实**一致的开发决策。它适用于 Codex、Cursor、Qoder、TRAE 及支持附加 Markdown 上下文的其他 AI 工具。

- 🔴 **必须**先以项目实际配置、已安装包和同模块既有实现为准；本规则库不要求升级 Unity、C# 语言版本、包版本或渲染管线。
- 🔴 **必须**在执行前读取 [15 - AI 通用入口规则](./15-AI通用入口规则.md)，再按任务读取下表中的专题文档。
- 🟡 **推荐**将本目录复制到目标 Unity 项目的 `.ai-rules/unity/`；按所用工具安装 [适配器模板](./适配器模板/00-适配器使用说明.md)。
- 🟢 **可选**仅将 15 号规则和当前任务相关专题文档附加到一次对话中。

不适用：Unity 引擎源码开发、美术制作工序、未经项目授权的平台 SDK 接入，以及独立服务端内部实现。

## 2. 规则优先级与冲突处理

出现冲突时，按下列顺序决策：

1. AI 工具自身的安全限制与用户在当前任务中给出的明确要求。
2. 目标 Unity 项目的本地约束、构建脚本、CI、已有 `AGENTS.md` 或同类规则。
3. 已验证的项目事实：Unity 编辑器能力、`Packages/manifest.json`、asmdef、渲染管线、资源系统和同模块实现。
4. 本规则库的通用入口和专题规则。
5. 通用社区经验或 AI 自身知识。

- 🔴 **必须**记录冲突的依据；不得为了套用本规则而改写项目既有架构。
- 🔴 **必须**在能力或所有权不明确时停止假设，采用已有实现或向用户询问。
- 🟡 **推荐**将长期架构取舍写入 ADR，而不是用临时代码或注释暗中改变边界。

## 3. 开发前能力探测

### 3.1 必查项目事实

| 检查项 | 位置或证据 | 决定内容 |
|---|---|---|
| 编辑器与语言能力 | `ProjectSettings/ProjectVersion.txt`、已有脚本语法 | 可使用的 Unity API 和 C# 写法 |
| 已安装包 | `Packages/manifest.json`、`packages-lock.json` | Addressables、Input System、网络与测试框架 |
| 模块边界 | `.asmdef`、命名空间、同目录代码 | 可引用程序集和依赖方向 |
| 渲染与 UI | `ProjectSettings/GraphicsSettings`、场景和 Prefab | 渲染管线、UGUI、UI Toolkit 或混用边界 |
| 资源系统 | Addressables/YooAssets/Resources/自定义服务的既有配置 | 加载 API、句柄所有权和释放方式 |
| 验证方式 | CI、构建脚本、现有测试和 README | 可执行的编译、测试与资源检查 |

### 3.2 探测后的行动

- 🔴 **必须**只使用项目中已验证可用的 API 与包。
- 🔴 **必须**先遵循同模块的资源、异步、日志和事件生命周期模式。
- ❌ **禁止**仅因某 API 在较新 Unity 中存在就引入它。
- ❌ **禁止**虚构资源地址、程序集名称、构建命令、测试结果或第三方包能力。

## 5. UI、跨语言与服务边界

### 5.1 UI 框架边界

- 🔴 **必须**为每个界面指定一个 UI 主负责框架。
- 🟡 UGUI 与 UI Toolkit 可以在同一项目共存；混用时要明确输入、数据绑定、生命周期和层级归属。
- ❌ **禁止**在同一界面无边界地让两个框架同时控制同一交互或状态。

### 5.2 跨语言边界

| 工作内容 | 主要规则库 |
|---|---|
| Unity 客户端、资源、Editor、UI | 本目录 |
| 服务端内部实现、数据库、部署 | `go-rules/` 或 `java_rulers/` |
| Web 前端或运营页面 | `js_ts_rulers/` |
| PICO 平台 SDK 选型与集成 | `pico_rulers/` |

- 🔴 Unity 规则只约束客户端与服务端的接口边界；不得据此生成未验证的服务端实现。

## 6. 文档维护与发布

### 6.1 规则新增与修订

- 🔴 每条强制规则必须写清适用条件、验证方式和例外。
- 🔴 涉及 Unity API、包行为或平台事实的规则必须以已验证项目能力或官方资料为依据。
- 🟡 推荐为规则保留正反例；示例必须标注依赖的项目能力，且不得伪装为通用可编译代码。
- 🟡 推荐每次修改专题文档时，同时消除该文件中的标题、编号和交叉引用问题。
