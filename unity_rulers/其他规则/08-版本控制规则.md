# 08 - Unity 版本控制规则

> 🟢 本文件适用于 Unity 资产、`.meta`、文本序列化、Git 忽略、审查和协作提交。
>
> 🔴 不适用：未经授权的提交、推送、合并、打 tag、历史改写、分支删除或 Git LFS 迁移。

---

## 1. 资产与引用完整性

> **适用条件与验证**：新增、移动、重命名或删除 Unity Asset、Prefab、场景、脚本或配置时适用。

- 🔴 **必须**：Asset 与其 `.meta` 始终作为同一引用单元处理；移动或删除时保持二者同步，并在 Editor/文本引用检查中验证受影响引用。
- 🔴 **必须**：不要手写或批量重建 GUID、复制 `.meta`、在文件系统中单独移动资产，或提交/忽略项目未确认的生成目录。
- 🟡 **推荐**：优先通过 Unity Editor 或项目既有资产工具移动资源；发生冲突时以引用完整性和团队流程为准处理。

## 2. 仓库约定与生成物

> **适用条件与验证**：先检查贡献指南、`.gitignore`、`.gitattributes`、LFS、YAML/文本序列化、CI、许可证和目标平台要求。

- 🔴 **必须**：遵循仓库实际跟踪、忽略、LFS、分支、提交和审查约定；不要套用固定 `.gitignore` 或文件大小阈值而删除有意跟踪的内容。
- 🔴 **必须**：不得提交凭证、签名、用户本地缓存、未获授权的构建产物或大文件；发现已跟踪敏感信息时遵循安全流程，不擅自改写历史。
- 🟡 **推荐**：将项目设置、资源、脚本和 `.meta` 的关联改动保持在可审查范围；测试场景、最小复现资产可在团队约定允许时提交。

## 3. 验证与例外

- 🔴 **必须**：提交/审查前检查 diff、缺失/孤立 `.meta`、资源引用、受影响场景/Prefab 和可用构建；未获授权不得执行远程 Git 操作。
- 🟡 **推荐**：交付时说明实际验证、尚未在 Editor 打开的资源及潜在合并风险。

> **例外**：资产重组、序列化策略和 LFS 历史迁移属于独立任务，必须先获得授权并演练引用和回退。
