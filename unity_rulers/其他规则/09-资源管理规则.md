# 09 - Unity 资源管理规则

> 🟢 本文件适用于 Unity 项目的资源加载、Prefab 管理、ScriptableObject 配置。

> 🔴 不适用：业务逻辑实现、API 设计、平台原生 API 细节

---


## 1. 资源加载与释放

先确认项目实际采用的加载方式，再写对应 API。**不要擅自换方案**；目录或单个资源存在只能作为线索，不能单独证明运行时加载系统。

### 1.1 项目加载方式识别（先看这里）

🔴 **AI 写代码前**必须同时检查 Package、初始化代码、构建配置、资源地址/包配置和同模块调用，而不只看目录：

| 项目标识文件 / 目录 | 加载方式 | AI 写代码时 |
|-----------------|---------|-----------|
| `Assets/Resources/` 与现有调用 | **Resources 的候选证据** | 仅在现有代码确认使用时沿用 `Resources.Load<T>("path")` |
| `Assets/StreamingAssets/` 与平台读取代码 | **StreamingAssets 的候选证据** | 沿用已有跨平台读取方式 |
| Addressables 包、设置与初始化代码 | **Addressables 的候选证据** | 沿用已有地址、句柄和释放模式 |
| YooAssets 包、设置与初始化代码 | **YooAssets 的候选证据** | 沿用项目现有的 Package、初始化与 API |
| 自定义打包脚本与运行时加载代码 | **AssetBundle 的候选证据** | 沿用现有依赖、校验和释放流程 |
| `[SerializeField]` 引用与同类 Prefab | **直接引用的候选证据** | 仅在对象生命周期和引用关系匹配时使用 |

**判断流程**：

```text
看项目根目录
  ├─ Assets/AddressableAssetsData/ → Addressables
  ├─ Assets/YooAssetSettings.asset → YooAssets
  ├─ Assets/Resources/ 有内容 → Resources
  ├─ Assets/StreamingAssets/ 有内容 → StreamingAssets（部分资源）
  └─ 证据不足 → 检查同类调用或询问用户，不默认选择加载方案
```

**🔴 AI 写代码时**：

- **不要擅自换方案**（项目用 Resources 你就别用 Addressables）
- **不知道用哪种** → 问用户，别瞎猜
- **混合方案**（Resources + Addressables）→ 常见，分别用对应 API

### 1.2 加载方式对比

| 方式 | 适用 | 优点 | 缺点 | 项目类型 |
|------|------|------|------|---------|
| **Resources** | 启动必须的引导资源 / 小型 demo / 工具脚本 | 简单 / 不需配置 | 全部进包 / 无依赖管理 / 难卸载 | 中小项目 / 工具脚本 |
| **StreamingAssets** | 视频 / 大型数据表 / 不走 AssetBundle 的原始资源 | 原样随构建产物提供 | 平台读取差异 / 难热更 | 项目明确需要原始文件时 |
| **Addressables** | 项目已采用的可寻址资源 | 依赖管理 / 异步 / 内存跟踪 | 需维护 Group 与地址 | 采用该系统的项目 |
| **YooAssets** | 项目已采用的资源与热更新系统 | 由项目配置决定 | 第三方依赖与运维成本 | 采用该系统的项目 |
| **AssetBundle** | 老项目 / 自定义打包 | 灵活 | 需手动管理依赖 / 易泄漏 | 老项目（YooAssets 基于此） |
| **直接引用** | Prefab / ScriptableObject（编辑器拖入） | 简单 / 无运行时路径查找 | 引用随构建发布 / 不适合独立远程更新 | 固定配置类 |

**选型决策树**：

```text
你的资源需要热更吗？
├─ 否 → 直接 [SerializeField] 引用
└─ 是
   ├─ 资源是视频/大型数据？→ StreamingAssets
   ├─ 项目用 Addressables？→ Addressables
   ├─ 项目用 YooAssets？→ YooAssets
   └─ 老项目自定义？→ AssetBundle

引导资源（首帧必须加载）？
└─ 是 → 沿用项目已有引导加载链路；它可能是 Resources、Addressables 本地组或自定义启动流程
```

### 1.3 Resources 加载 API

**适用场景**：启动必须的引导资源 / 小型 demo / 工具脚本。

```csharp
// 加载
GameObject prefab = Resources.Load<GameObject>("Enemies/Zombie");
T config = Resources.Load<T>("Configs/GameSettings");

// 实例化
GameObject instance = Instantiate(Resources.Load<GameObject>("Enemies/Zombie"));

// 释放：不存在“每次 Resources.Load 都必须手动释放”的通用配对。
// 仅在对象类型、引用所有权与项目生命周期都确认时，才评估 UnloadAsset。
Resources.UnloadUnusedAssets(); // 只在项目确认的加载/切场景流程中使用
```

**🔴 限制**：

- 路径**必须**在 `Assets/Resources/` 下
- **全部进包**（不能用包外资源）
- **无依赖跟踪**（AssetBundle 内有依赖图，Resources 没有）
- **不能用 `Resources.UnloadAsset` 释放 Prefab**（只对 ScriptableObject / Texture 有效）

**AI 写代码时**：

- 🟡 **已有项目**用 Resources **可继续用**（不强制迁移）
- 🟡 小型 demo / 工具脚本可用 Resources
- 🟡 启动必须的引导资源应沿用项目已有启动链路，不默认要求 Resources。
- ❌ 项目未采用 Resources 时，不要为新业务代码新增它。

### 1.4 StreamingAssets 加载 API

**适用场景**：视频 / 大型数据表 / 不打包成 AssetBundle 的原始资源。

**文件位置**：`Assets/StreamingAssets/`。其内容会按平台规则原样包含在构建产物中，但读取方式可能受平台限制；它不等同于“包外资源”。

```csharp
// 跨平台路径
string path = System.IO.Path.Combine(
    Application.streamingAssetsPath,  // Unity 自动给正确平台路径
    "Videos/Intro.mp4"
);

// 读取文件
byte[] data = System.IO.File.ReadAllBytes(path);

// 视频用 VideoPlayer（自动找路径）
var videoPlayer = GetComponent<VideoPlayer>();
videoPlayer.url = System.IO.Path.Combine(
    Application.streamingAssetsPath, "Videos/Intro.mp4"
);
```

**🔴 跨平台路径**（`Application.streamingAssetsPath` 自动处理）：

| 平台 | 路径 |
|------|------|
| Windows / macOS | `Application.streamingAssetsPath/Video.mp4` |
| Android | `jar:file:///data/app/.../base.apk!/assets/Video.mp4`（**Jar 内**）|
| iOS | `Application.streamingAssetsPath/Video.mp4`（**App Bundle 内**） |

**AI 写代码时**：

- 🔴 **Android 平台用 `UnityWebRequest` 读**（不能在 Jar 内用 `File.ReadAllBytes`）
- 🟡 iOS / Windows / macOS 用 `File.ReadAllBytes`
- 🟡 视频用 `VideoPlayer.url` 跨平台

### 1.5 Addressables 加载 API

**适用场景**：项目已经采用 Addressables、包与 Group 配置存在，且当前资源的加载/释放所有权已确认。不要仅因 Unity 版本或“新项目”就新增 Addressables。

```csharp
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

// 加载资源
AsyncOperationHandle<GameObject> handle =
    Addressables.LoadAssetAsync<GameObject>("Enemies/Zombie");
await handle.Task;
GameObject prefab = handle.Result;

// 实例化
AsyncOperationHandle<GameObject> instHandle =
    Addressables.InstantiateAsync("Enemies/Zombie", spawnPos, Quaternion.identity);
GameObject enemy = await instHandle.Task;

// 加载配置
AsyncOperationHandle<EnemyConfig> configHandle =
    Addressables.LoadAssetAsync<EnemyConfig>("Configs/Enemy/Zombie");
EnemyConfig config = await configHandle.Task;
```

**释放**（**必须成对**）：

```csharp
private AsyncOperationHandle<GameObject> m_handle;

private void OnDestroy()
{
    if (m_handle.IsValid())
    {
        if (m_handle.Result != null)
            Addressables.ReleaseInstance(m_handle.Result);  // InstantiateAsync
        else
            Addressables.Release(m_handle);               // LoadAssetAsync
    }
}
```

**AI 写代码时**：

- 🔴 **必须按项目既有所有权模型保存可释放的句柄或实例**，并在对象不再拥有资源时成对 Release；不应仅因字段形式而忽略共享所有权或场景生命周期。
- 🟡 需要配 `AddressableAssetSettings`（项目维护者配，AI 写代码不用管）

### 1.6 YooAssets 加载 API

**适用场景**：项目已采用 YooAssets 的资源或热更新流程。

```csharp
using YooAsset;

// 同步加载
T config = YooAssets.LoadAssetSync<T>("path").AssetObject as T;

// 异步加载
var op = YooAssets.LoadAssetAsync<T>("path");
await op.Task;
T asset = op.AssetObject as T;

// 实例化
var instOp = YooAssets.InstantiateAsync("path");
GameObject obj = await instOp.Task;

// 释放
YooAssets.ReleaseAsset(asset);
YooAssets.ReleaseInstance(obj);
```

**AI 写代码时**：

- 🔴 **判断项目用 YooAssets 后**才能用这套 API
- 🔴 看 `Assets/YooAssetSettings.asset` 或 `Packages/manifest.json` 是否有 `com.tuyooflex.yooasset`
- 🟡 性能与功能取舍应以目标项目的包版本、资源规模和实际测量为准，不将 YooAssets 与 Addressables 的优劣写成固定结论。
- 🟡 资源路径是 **Package 路径**（不是 Assets/ 路径）

### 1.7 AssetBundle 加载 API（老项目）

**适用场景**：老项目 / 自定义打包 / YooAssets 底层（**不直接用**）。

```csharp
// 加载 AssetBundle
AssetBundle bundle = AssetBundle.LoadFromFile(path);

// 加载资源
GameObject prefab = bundle.LoadAsset<GameObject>("Zombie");

// 释放
bundle.Unload(true);  // true = 卸载所有依赖
```

**AI 写代码时**：

- ❌ 项目未采用原生 AssetBundle 加载链路时，不要为新代码自行新增它；已有项目维护时沿用其依赖、校验与卸载策略。
- 🟡 **老项目**维护时用
- 🟡 **YooAssets 项目**不需要直接用（YooAssets 封装了）

### 1.8 释放规则（避免内存泄漏）

🔴 **资源释放必须遵循加载 API、引用计数和所有权模型**。并非每种直接引用或 Resources 访问都适合机械地“一次加载对应一次释放”；先确认项目现有模式：

| API | 释放方式 |
|------|---------|
| `Resources.Load<T>()` | 无通用的一对一释放；仅对适用对象且所有权明确时使用 `UnloadAsset`，不要对 Prefab/场景正在引用的对象机械调用 |
| `Addressables.LoadAssetAsync` | `Addressables.Release(handle)` |
| `Addressables.InstantiateAsync` | `Addressables.ReleaseInstance(go)` |
| `YooAssets.LoadAssetAsync` | `YooAssets.ReleaseAsset(asset)` |
| `YooAssets.InstantiateAsync` | `YooAssets.ReleaseInstance(obj)` |
| `AssetBundle.LoadFromFile` | `bundle.Unload(true)` |

**🔴 容易犯的错**：

- ❌ **只释放 `LoadAssetAsync`，忘记 `ReleaseInstance`**
- ❌ **没保存句柄**，GC 后无法释放
- ❌ **多次加载同一资源**忘了 `Release` 多次（引用计数平衡）

### 1.9 资源加载决策示例

```csharp
// 决策：项目用 Addressables，加载敌人 Prefab

// 1. 加载
AsyncOperationHandle<GameObject> m_handle = Addressables.LoadAssetAsync<GameObject>(
    "Enemies/Zombie"  // Addressable Group 中的地址
);

// 2. 实例化
GameObject enemy = await m_handle.Task;

// 3. 用
enemy.transform.position = spawnPos;

// 4. 释放
private void OnDestroy()
{
    if (m_handle.IsValid())
        Addressables.Release(m_handle);
}
```

**🔴 AI 写代码时**：

- 1️⃣ **先看 1.0 识别项目加载方式**
- 2️⃣ **用对应 API**（不要混用）
- 3️⃣ **保留句柄**为字段
- 4️⃣ **OnDestroy 中成对 Release**


## 2. Prefab 管理

### 2.1 Prefab 实例化 vs Instantiate

**Prefab** = 可复用的 GameObject 模板（带组件 / 配置）。

**直接 Instantiate**（Prefab 已加载到字段）：

```csharp
[SerializeField] private GameObject m_zombiePrefab;  // Inspector 拖入

private void SpawnZombie(Vector3 pos)
{
    GameObject zombie = Instantiate(m_zombiePrefab, pos, Quaternion.identity);
    // 不用了
    Destroy(zombie);
}
```

**Addressables.InstantiateAsync**（Prefab 通过 Addressable 加载）：

```csharp
private AsyncOperationHandle<GameObject> m_instanceHandle;

private async void SpawnAsync(Vector3 pos)
{
    m_instanceHandle = Addressables.InstantiateAsync("EnemyZombie", pos, Quaternion.identity);
    var zombie = await m_instanceHandle.Task;
}

private void OnDestroy()
{
    if (m_instanceHandle.IsValid())
        Addressables.ReleaseInstance(m_instanceHandle.Result);
}
```

**选型**：

| 场景 | 用法 |
|------|------|
| 项目已有直接引用的固定配置 | `Instantiate(prefab)` |
| 项目已确认的热更 / 远程资源体系 | 使用该体系的异步实例化 API（如既有 Addressables 或 YooAssets 封装） |
| 频繁创建 / 销毁（子弹 / 粒子）| **对象池**（见 `03-性能优化规则.md` 3 章） |

### 2.2 Prefab 引用方式

| 方式 | 优点 | 缺点 | AI 写代码时 |
|------|------|------|-----------|
| **直接引用**（`[SerializeField] GameObject`） | 简单 / 无运行时路径查找 | 随构建发布 | ✅ 项目已有固定引用策略时使用 |
| **Addressables** | 远程加载 / 热更 / 异步 | 需要 Group 与句柄管理 | ✅ 项目已采用且资源已配置时使用 |
| **Resources** | 简单 | 全部进包 / 路径与内存管理受限 | 🟡 维护项目已有 Resources 链路时沿用，不擅自扩张 |
| **AssetDatabase（仅 Editor）** | Editor 工具能用 | 运行时崩溃 | ❌ 严禁运行时用 |

**AI 写代码时**：

- 🔴 先读取资源目录、加载封装、Addressable Group/YooAssets 配置和现有调用点，确认项目资源体系。
- 🟡 固定 Prefab 沿用项目既有的直接引用或资源管理器边界；不要仅凭“固定”就改写现有加载链路。
- 🟡 需要远程或热更的资源，只能使用项目已配置并已验证的资源体系。
- 🟡 现有项目若仍使用 `Resources.Load`，可在其边界内维护；新路径是否迁移由资源架构决定，不能写成一律禁止或一律新增。

### 2.3 Prefab 变体（Variant）

**Prefab Variant** = 继承父 Prefab 的所有属性 / 组件，可**只覆盖差异部分**。

**适用场景**：

- 🔴 同一类型敌人有多个变种（普通僵尸 / 强化僵尸）
- 🔴 同一武器多种皮肤
- 🔴 同一 UI 多种配色

```text
EnemyZombie (Base Prefab)
├── EnemyZombie_Fast (Variant: 速度+50%, HP-30%)
├── EnemyZombie_Tank (Variant: 速度-50%, HP+200%)
└── EnemyZombie_Boss (Variant: 全属性+100%)
```

**AI 写代码时**：

- 🟡 **3 个以上相似 Prefab** → 用 Variant 继承
- 🟡 Variant 改**只覆盖差异**（不要复制整个 Prefab）


## 3. ScriptableObject 配置

### 3.1 ScriptableObject 用法

**ScriptableObject** = 独立于场景的**数据容器**（配置 / 状态 / 配方）。

**创建 ScriptableObject**：

```csharp
using UnityEngine;

[CreateAssetMenu(fileName = "EnemyConfig", menuName = "Game/Config/Enemy")]
public class EnemyConfig : ScriptableObject
{
    [Header("基础属性")]
    public string EnemyName = "Zombie";
    public int MaxHealth = 100;
    public float MoveSpeed = 2f;

    [Header("战斗属性")]
    public int AttackDamage = 10;
    public float AttackRange = 1.5f;
    [Range(0, 100)] public int CriticalChance = 5;
}
```

**使用方法**（直接引用）：

```csharp
public class Enemy : MonoBehaviour
{
    [SerializeField] private EnemyConfig m_config;  // Inspector 拖入

    private int m_currentHealth;

    private void Awake()
    {
        m_currentHealth = m_config.MaxHealth;
    }
}
```

### 3.2 配置数据 vs 运行时数据

🔴 **ScriptableObject 只放"配置数据"**，**不放"运行时数据"**：

```csharp
// ✅ 对：ScriptableObject 是配置（不可变）
[CreateAssetMenu]
public class WeaponConfig : ScriptableObject
{
    public int Damage = 10;
    public float FireRate = 1f;
}

// ✅ 对：运行时数据放在普通 C# 类（可变）
public class WeaponState
{
    public int CurrentAmmo;
    public float ReloadTimer;
}

// 用法
public class Weapon : MonoBehaviour
{
    [SerializeField] private WeaponConfig m_config;  // 配置（不变）
    private WeaponState m_state = new();             // 运行时（可变）

    public int Damage => m_config.Damage;
    public int CurrentAmmo => m_state.CurrentAmmo;
}
```

**❌ 反例**（运行时数据放 ScriptableObject，会被持久化）：

```csharp
// ❌ 错：CurrentAmmo 是运行时数据，放 ScriptableObject 会污染
[CreateAssetMenu]
public class WeaponConfig : ScriptableObject
{
    public int MaxAmmo = 30;
    public int CurrentAmmo;  // ❌ 错！运行时数据
}
```

### 3.3 ScriptableObject 引用

**AI 写代码时**：

| 场景 | 用法 |
|------|------|
| 🔴 **固定配置**（武器参数 / 敌人属性） | `[SerializeField] ScriptableObject` |
| 🟡 **可热更配置** | Addressables + ScriptableObject |
| 🟡 **运行时动态创建** | `ScriptableObject.CreateInstance<T>()`（**慎用**） |
| ❌ **不要**运行时 `CreateInstance` + 持久化 | 会污染 .asset 文件 |

**异步配置缓存示例**（仅项目已采用 Addressables，且该缓存是已确认的资源所有者时）：

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public sealed class AddressableConfigCache : IDisposable
{
    private readonly Dictionary<string, AsyncOperationHandle<EnemyConfig>> m_handles = new();

    public async Task<EnemyConfig> GetEnemyConfigAsync(string id)
    {
        if (m_handles.TryGetValue(id, out var cached))
            return cached.Result;

        var handle = Addressables.LoadAssetAsync<EnemyConfig>($"Config/Enemy/{id}");
        await handle.Task;
        if (handle.Status != AsyncOperationStatus.Succeeded)
        {
            Addressables.Release(handle);
            throw new InvalidOperationException($"无法加载配置: {id}");
        }

        m_handles.Add(id, handle);
        return handle.Result;
    }

    public void Dispose()
    {
        foreach (var handle in m_handles.Values)
            Addressables.Release(handle);
        m_handles.Clear();
    }
}
```

🔴 不要在运行时默认使用 `WaitForCompletion()`。同步等待会阻塞主线程，并且是否可接受取决于平台、资源位置和项目加载流程；如确有启动期同步加载需求，必须由项目架构明确并在目标平台验证。
