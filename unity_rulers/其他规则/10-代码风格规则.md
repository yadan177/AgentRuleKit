# 10 - Unity 代码风格规则

> 🟢 本文件适用于 Unity C# 的格式、命名、注释、序列化字段和静态检查调整。
>
> 🔴 不适用：以风格为由的资源重命名、公共 API 修改、全仓格式化、语言版本升级或无关重构。

---

## 1. 配置与既有代码优先

> **适用条件与验证**：先检查 `.editorconfig`、asmdef、analyzers、格式化设置、命名约定和同模块近期实现。

- 🔴 **必须**：以仓库实际配置和受影响模块的既有风格为准；没有配置时只做局部、一致且不改变行为的调整。
- 🔴 **必须**：不得把未安装 formatter/analyzer、固定行宽、region 规则或个人命名偏好写成项目强制标准。
- 🟡 **推荐**：将格式修改与行为修改分开，降低 Unity YAML/Prefab 冲突和代码审查噪音。

## 2. Unity 序列化与公共符号

> **适用条件与验证**：修改 `SerializeField`、公共字段/属性、事件、ScriptableObject、反射、动画或 Prefab/场景引用时适用。

- 🔴 **必须**：名称、可见性、序列化、默认值和字段类型变更前检查资产引用、反序列化、反射和调用方；不得仅为风格重命名。
- 🔴 **必须**：注释、Tooltip、Suppress 和文档真实反映行为、约束和原因，且不包含凭证、个人数据或虚构验证结论。
- 🟡 **推荐**：以可读性和边界清晰度组织字段、方法和 using；复杂或兼容性敏感的意图优先写原因而非重复代码。

## 3. 自动化与验证

> **适用条件与验证**：项目已有静态检查、格式化、pre-commit 或 CI 时适用。

- 🔴 **必须**：只运行仓库已有且与改动相关的检查；自动修复后复核 diff，避免修改生成文件、资源引用和无关脚本。
- 🟡 **推荐**：交付时说明实际执行的格式/静态检查和未执行原因。

> **例外**：统一风格、analyzer 升级或公开命名迁移需独立授权、完整编译/测试和可回滚范围。
