# 07 - Unity 日志与调试规范

> 🟢 本文件适用于 Unity 项目的日志、调试、异常排查、故障定位。

> 🔴 不适用：APM 商业工具、Profiler 高级用法

---

## 1. Debug 日志规范

### 1.1 5 级日志体系（Trace / Debug / Info / Warn / Error）

Unity 默认只有 3 级（Log / LogWarning / LogError）。项目已封装日志门面并需要按级别筛选、采样或上报时，可采用更细的 5 级体系；否则应沿用现有日志约定。

| 级别 | 用途 | Unity 对应 | Console 颜色 |
|------|------|----------|-------------|
| **Trace** | 最细粒度（每步细节、变量值） | `Debug.Log` | 灰 |
| **Debug** | 调试信息（函数进出、状态变化） | `Debug.Log` | 白 |
| **Info** | 业务信息（"玩家进入战斗"） | `Debug.Log` | 青 |
| **Warn** | 警告（不致命但需注意） | `Debug.LogWarning` | 黄 |
| **Error** | 错误（致命 / 异常） | `Debug.LogError` | 红 |

**何时用哪个**：

- 🔴 **Error**：异常 / 致命错误 / 必须修的 bug
- 🟡 **Warn**：潜在 bug / 不规范的输入 / 资源即将耗尽
- 🔵 **Info**：业务流程关键节点（"战斗开始" / "玩家升级"）
- ⚪ **Debug**：开发期调试信息（"HP: 100 → 80"）
- ⚫ **Trace**：最细粒度（"进入 OnTriggerEnter, target: {0}"）—— 发布构建是否保留、采样或剔除以项目日志与排障策略为准。

### 1.2 关键词筛选（Category 中文筛选）

🔴 先检查项目是否已有日志门面、日志分类和发布构建策略。以下 `Log` 示例只适用于**项目已经定义了同名门面**或团队明确决定新增该基础设施的情况；没有它时，不要让 AI 凭空调用 `Log.Category` 或 `Log.Info`。

**核心设计**：每个日志带一个 **Category 字符串**（业务关键词），AI 在 Editor 调试面板里**只显示匹配某关键词的日志**，方便排查单条逻辑线路。

```csharp
// 只看"玩家战斗"这条线路
Log.Category = "玩家战斗";
Log.MinLevel = Log.Level.Trace;

// 切换到"网络"线路
Log.Category = "网络";
Log.MinLevel = Log.Level.Debug;

// 关闭筛选（看全部）
Log.Category = null;
```

**Console 中输出格式**：`[Category][Level] Message`

```
[玩家战斗][Trace] 进入战斗场景
[玩家战斗][Debug] 玩家 HP: 100
[网络][Debug] 收到服务器消息: {0}
[玩家战斗][Warn] 玩家血量过低: 10
```

**筛选体验**：Unity Console 顶部搜索框输入"玩家战斗" → 立刻过滤出战斗线路。

**多关键词**（同时看两条线路）：

```csharp
Log.Category = "玩家战斗|网络";  // | 分隔，匹配任一即可
```

**类别继承**（子模块自动继承父类）：

```csharp
Log.Category = "玩家战斗";
// 实际匹配 "玩家战斗" / "玩家战斗.技能" / "玩家战斗.受击" 等所有子类别
```

### 1.3 Log 类 API 完整定义

**适用前提**：项目已确认需要统一日志门面，并已决定其目录、程序集、发布级别与上报边界。下面是可选参考实现，不是所有 Unity 项目都必须新建 `Assets/Scripts/Common/Log.cs`。

```csharp
using UnityEngine;
using System.Text.RegularExpressions;

/// <summary>
/// 5 级日志 + 关键词筛选。
/// 仅供已采用本日志门面的项目调用。
/// </summary>
public static class Log
{
    public enum Level { Off = 0, Error = 1, Warn = 2, Info = 3, Debug = 4, Trace = 5 }

    /// 全局最低显示级别。低于此级别的日志不输出（性能 + 防刷屏）。
    public static Level MinLevel = Level.Info;

    /// 关键词筛选：null = 显示所有；否则只显示 Category 匹配的日志。
    /// 支持 "战斗|网络" 多关键词；子类别自动继承（"战斗.技能" 匹配 "战斗"）。
    public static string Category = null;

    // === 5 级输出方法 ===
    public static void Trace(string category, string msg, params object[] args) => LogAt(Level.Trace, category, msg, args);
    public static void Debug(string category, string msg, params object[] args) => LogAt(Level.Debug, category, msg, args);
    public static void Info(string category, string msg, params object[] args)  => LogAt(Level.Info,  category, msg, args);
    public static void Warn(string category, string msg, params object[] args)  => LogAt(Level.Warn,  category, msg, args);
    public static void Error(string category, string msg, params object[] args) => LogAt(Level.Error, category, msg, args);

    // === 异常专用 ===
    public static void Exception(string category, System.Exception ex)
    {
        LogAt(Level.Error, category, "异常: {0}\n{1}", new object[] { ex.Message, ex.StackTrace });
    }

    private static void LogAt(Level level, string category, string msg, object[] args)
    {
        // 1. 级别过滤
        if (MinLevel == Level.Off || (int)level > (int)MinLevel) return;

        // 2. 关键词过滤
        if (!MatchCategory(category)) return;

        // 3. 格式化
        string formatted;
        try
        {
            formatted = (args == null || args.Length == 0) ? msg : string.Format(msg, args);
        }
        catch
        {
            formatted = msg + " [format error]";
        }

        // 4. 输出
        string prefix = $"[{category}][{level}]";
        switch (level)
        {
            case Level.Error: UnityEngine.Debug.LogError($"{prefix} {formatted}");   break;
            case Level.Warn:  UnityEngine.Debug.LogWarning($"{prefix} {formatted}"); break;
            default:          UnityEngine.Debug.Log($"{prefix} {formatted}");       break;
        }
    }

    /// 判断日志 category 是否匹配当前过滤词
    private static bool MatchCategory(string category)
    {
        if (string.IsNullOrEmpty(Category)) return true;
        category ??= string.Empty;

        // 多关键词："战斗|网络"
        var keywords = Category.Split('|');
        foreach (var kw in keywords)
        {
            var trimmed = kw.Trim();
            if (trimmed.Length == 0) continue;

            // 子类别自动继承："战斗.技能" 匹配 "战斗"
            if (category == trimmed) return true;
            if (category.StartsWith(trimmed + ".")) return true;
            if (category.Contains(trimmed)) return true;  // 模糊匹配（兜底）
        }
        return false;
    }
}
```

**未采用日志门面时**：沿用项目现有的 `UnityEngine.Debug` 包装、条件编译和错误上报策略；若项目确实没有包装层，可直接使用 `Debug.Log` / `Debug.LogWarning` / `Debug.LogError`，不要为了本节示例引入未定义类型。

### 1.4 使用示例

```csharp
public class BattleController : MonoBehaviour
{
    private const string CAT = "玩家战斗";  // 类别常量（避免拼写错误）

    public void TakeDamage(int amount)
    {
        // 1. Trace：进入关键函数
        Log.Trace(CAT, "TakeDamage 接收: amount={0}", amount);

        // 2. 边界检查
        if (amount <= 0)
        {
            Log.Warn(CAT, "伤害值异常: {0}", amount);
            return;
        }

        // 3. Info：业务关键节点
        Log.Info(CAT, "玩家受击: {0} → {1}", m_health, m_health - amount);

        // 4. 修改状态
        m_health -= amount;

        // 5. 异常处理
        try
        {
            ApplyDamageEffect(amount);
        }
        catch (System.Exception ex)
        {
            Log.Exception(CAT, ex);  // 输出异常 + 堆栈
        }
    }
}
```

**Editor 中排查时**：

1. 打开 `Tools → Log Filter Panel` 调试面板（见 1.5）
2. Category 设为 `"玩家战斗"`，MinLevel 设为 `Trace`
3. Console 立刻只显示"玩家战斗"线路的所有日志
4. 关闭关键词（`null`）就恢复全部

### 1.5 Editor 调试面板

**文件位置**：`Assets/Editor/LogFilterWindow.cs`

```csharp
using UnityEngine;
using UnityEditor;

public class LogFilterWindow : EditorWindow
{
    [MenuItem("Tools/Log Filter Panel")]
    public static void Open() => GetWindow<LogFilterWindow>("Log Filter");

    private void OnGUI()
    {
        EditorGUILayout.LabelField("实时筛选（AI 调试 / 问题排查用）", EditorStyles.boldLabel);

        // 最低级别
        Log.MinLevel = (Log.Level)EditorGUILayout.EnumPopup("最低级别", Log.MinLevel);

        // Category 关键词
        EditorGUILayout.LabelField("Category 关键词（留空 = 显示所有）");
        Log.Category = EditorGUILayout.TextField("Category", Log.Category ?? "");

        EditorGUILayout.Space();

        // 快捷按钮
        EditorGUILayout.BeginHorizontal();
        if (GUILayout.Button("全开 (Trace)")) Log.MinLevel = Log.Level.Trace;
        if (GUILayout.Button("只看 Error"))   Log.MinLevel = Log.Level.Error;
        if (GUILayout.Button("关闭"))          Log.MinLevel = Log.Level.Off;
        EditorGUILayout.EndHorizontal();

        EditorGUILayout.BeginHorizontal();
        if (GUILayout.Button("清除关键词"))   Log.Category = null;
        if (GUILayout.Button("重置（显示所有+Info）")) { Log.MinLevel = Log.Level.Info; Log.Category = null; }
        EditorGUILayout.EndHorizontal();

        // 常用类别快捷按钮
        EditorGUILayout.Space();
        EditorGUILayout.LabelField("常用类别快捷：");
        EditorGUILayout.BeginHorizontal();
        if (GUILayout.Button("玩家战斗")) Log.Category = "玩家战斗";
        if (GUILayout.Button("网络"))      Log.Category = "网络";
        if (GUILayout.Button("物理"))      Log.Category = "物理";
        if (GUILayout.Button("UI"))        Log.Category = "UI";
        EditorGUILayout.EndHorizontal();
    }
}
```

### 1.6 发布版剔除（#if UNITY_EDITOR）

🔴 **发布版不应有 Trace / Debug 输出**（影响性能 + 暴露信息）。用 `#if UNITY_EDITOR` 包裹：

```csharp
public static void Trace(string category, string msg, params object[] args)
{
#if UNITY_EDITOR
    LogAt(Level.Trace, category, msg, args);
#endif
}

public static void Debug(string category, string msg, params object[] args)
{
#if UNITY_EDITOR
    LogAt(Level.Debug, category, msg, args);
#endif
}
```

**或者**用 `ConditionalAttribute`（更优雅）：

```csharp
[System.Diagnostics.Conditional("UNITY_EDITOR")]
public static void Trace(string category, string msg, params object[] args) => LogAt(Level.Trace, category, msg, args);

[System.Diagnostics.Conditional("UNITY_EDITOR")]
public static void Debug(string category, string msg, params object[] args) => LogAt(Level.Debug, category, msg, args);
```

> `Info / Warn / Error` 保留（发布版也需要记录业务信息和错误）。

### 1.7 避免日志反模式

| 反模式 | 后果 | 修复 |
|--------|------|------|
| ❌ 每帧 `Debug.Log`（在 Update） | 性能崩溃 | 用 `Log.Trace` + `#if UNITY_EDITOR` 剔除 |
| ❌ 字符串拼接 `$"HP: {hp}"` | 每次都分配 | 用 `string.Format("HP: {0}", hp)` 占位符 |
| ❌ `Debug.Log(testObj.ToString())` | testObj 为 null 抛 NullRef | 先 null 检查 |
| ❌ `Debug.Log("test")` 提交到主分支 | 噪音 + 暴露信息 | Code Review 拦截 |
| ❌ 用 `Debug.Log` 代替异常 | 丢失堆栈 | 真正异常用 `throw` |
| ❌ `Debug.Log(password)` | 密码泄露 | 不要 log 敏感信息 |

## 2. Profiler 与性能标记

> **写规范**：AI 在写性能关键代码时**必须**打 ProfilerMarker，让 Profiler 能看清函数耗时。Profiler 本身的用法（5 大模块、GC.Alloc 排查、帧时间目标）详见 `03-性能优化规则.md` 7 章 Profiler 标记。

### 2.1 ProfilerMarker 使用

```csharp
using Unity.Profiling;

public class BattleController : MonoBehaviour
{
    // 静态字段（避免每次 new）
    private static readonly ProfilerMarker s_updateMarker =
        new ProfilerMarker("BattleController.Update");
    private static readonly ProfilerMarker s_processAttacksMarker =
        new ProfilerMarker("BattleController.ProcessAttacks");

    private void Update()
    {
        using (s_updateMarker.Auto())
        {
            ProcessInput();
            ProcessAttacks();
            ProcessUI();
        }
    }
}
```

**`using Auto()` 优势**：

- 异常安全（抛异常也正确结束）
- 不会忘记 `End()`
- Profiler 树形视图清晰

### 2.2 静态字段缓存

🔴 **ProfilerMarker 必须 `static readonly`**：

```csharp
// ❌ 错：每次 new（GC + 缓存失效）
public class A
{
    private ProfilerMarker m_marker = new ProfilerMarker("A.Update");  // 错
}

// ✅ 对：static readonly（一次 new，所有实例共享）
public class A
{
    private static readonly ProfilerMarker s_marker = new ProfilerMarker("A.Update");
}
```

### 2.3 嵌套标记

```csharp
private static readonly ProfilerMarker s_outerMarker = new ProfilerMarker("AI.Decide");
private static readonly ProfilerMarker s_innerMarker = new ProfilerMarker("AI.Decide.EvaluateOptions");

public void Decide()
{
    using (s_outerMarker.Auto())
    {
        foreach (var option in options)
        {
            using (s_innerMarker.Auto())
            {
                Evaluate(option);  // 嵌套标记
            }
        }
    }
}
```

### 2.4 发布版剔除

🔴 **发布版不应有 ProfilerMarker**（标记本身有性能开销）：

```csharp
private static readonly ProfilerMarker s_marker = new ProfilerMarker("HeavyWork");

public void HeavyWork()
{
#if UNITY_EDITOR || DEVELOPMENT_BUILD
    using (s_marker.Auto())  // 仅 Editor / Dev Build
#endif
    {
        DoStuff();
    }
}
```

或者用 `[Conditional]`：

```csharp
[System.Diagnostics.Conditional("DEVELOPMENT_BUILD")]
private static void MarkerScope(ProfilerMarker marker) => marker.Auto();

// 调用
MarkerScope(s_marker);  // Release 自动剔除
```

## 3. 调试技巧

### 3.1 断点 vs 日志 vs 断言

| 方式 | 适用场景 | 优势 | 劣势 |
|------|---------|------|------|
| **断点** | 复杂逻辑、单步跟踪 | 完整看上下文 | 打断执行流程 |
| **日志** | 频繁调用 / 生产环境 | 不打断 | 需格式化 |
| **断言** | 验证前置条件 | 自动失败 | Release 可禁用 |

**选型决策**：

- 🔴 **异常路径** → `Log.Error` / `Log.Exception`
- 🟡 **可疑输入** → `Debug.Assert(condition, "原因")` / `Log.Warn`
- 🔵 **状态变化** → `Log.Info`
- ⚪ **变量值** → `Log.Debug` / 断点
- ⚫ **每步细节** → `Log.Trace`（仅 Editor）

### 3.2 Conditional Compilation

🔴 **调试代码不进发布包**。三种方式选一种：

```csharp
// 方式 1：#if 包裹（最直接）
#if UNITY_EDITOR || DEVELOPMENT_BUILD
    Log.Trace(CAT, "TakeDamage: {0}", amount);
#endif

// 方式 2：[Conditional] 特性（Log 类用，最优雅）
[System.Diagnostics.Conditional("UNITY_EDITOR")]
public static void Trace(string category, string msg, params object[] args)
    => LogAt(Level.Trace, category, msg, args);

// 调用 Log.Trace() → 发布包自动剔除（不进入方法体）
```

**常用宏**：

| 宏 | 启用场景 |
|------|---------|
| `UNITY_EDITOR` | 仅 Editor |
| `DEVELOPMENT_BUILD` | Editor + Development Build（真机调试版也有） |
| `UNITY_ASSERTIONS` | Editor + Development Build 启用（`Debug.Assert` 用）|

### 3.3 Editor 工具辅助（Gizmos / Inspector）

**Gizmos 绘制**（Scene 视图可视化）：

```csharp
public class EnemyAI : MonoBehaviour
{
    public float m_viewRadius = 10f;

    private void OnDrawGizmos()
    {
        // 视野范围（黄色）
        Gizmos.color = Color.yellow;
        Gizmos.DrawWireSphere(transform.position, m_viewRadius);

        // 攻击范围（红色）
        Gizmos.color = Color.red;
        Gizmos.DrawWireSphere(transform.position, 2f);
    }

    private void OnDrawGizmosSelected()
    {
        // 选中时画更多细节
        Gizmos.color = Color.cyan;
        Gizmos.DrawLine(transform.position, m_target.position);
    }
}
```

### 3.4 单元测试 + Mock

🔴 **关键业务逻辑在项目已有可运行测试框架时必须补充相称的回归测试**；没有测试基础设施时，不得臆造 NUnit、Mock 工具或测试命令，应说明未验证范围并采用可行的编辑器或设备验证。

```csharp
using NUnit.Framework;
using UnityEngine;

public class BattleControllerTests
{
    [Test]
    public void TakeDamage_ReducesHealth()
    {
        var go = new GameObject();
        var bc = go.AddComponent<BattleController>();
        bc.Health = 100;

        bc.TakeDamage(30);

        Assert.AreEqual(70, bc.Health);
        Object.DestroyImmediate(go);
    }

    [Test]
    public void TakeDamage_Negative_DoesNothing()
    {
        var go = new GameObject();
        var bc = go.AddComponent<BattleController>();
        bc.Health = 100;

        bc.TakeDamage(-10);

        Assert.AreEqual(100, bc.Health);  // 不变
        Object.DestroyImmediate(go);
    }
}
```

**Mock 依赖**（避免测试时启动真实子系统）：

```csharp
public interface IInputProvider
{
    Vector2 GetMoveInput();
}

// 测试时用 Mock
public class MockInput : IInputProvider
{
    public Vector2 Input = Vector2.zero;
    public Vector2 GetMoveInput() => Input;
}
```
