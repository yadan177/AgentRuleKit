# 11 - Unity 扩展编辑器规则

> 🟢 本文件适用于 Unity CustomEditor、PropertyDrawer、EditorWindow、菜单、导入处理和编辑器工具。
>
> 🔴 不适用：把 Editor API 引入运行时代码、修改用户资产而不提供撤销/确认，或强制采用某种 Editor UI 框架。

---

## 1. Editor 与运行时边界

> **适用条件与验证**：先检查 `Editor` 目录、asmdef 平台约束、目标 Unity 能力、现有 Inspector/窗口和同类工具。

- 🔴 **必须**：Editor 代码通过目录、asmdef 或项目既有方式与运行时代码隔离；运行时程序集不得引用 `UnityEditor`。
- 🔴 **必须**：IMGUI、UI Toolkit、SerializedObject/SerializedProperty 和自定义窗口模式以项目和目标版本已验证能力为准；不得因示例升级 API 或重写既有工具。
- 🟡 **推荐**：复用当前项目的菜单路径、窗口状态、图标、资源加载和用户反馈约定。

## 2. 资产修改与用户操作

> **适用条件与验证**：Inspector、批处理工具、菜单、导入回调或窗口会修改对象、Prefab、场景或设置时适用。

- 🔴 **必须**：遵循项目已有的序列化、Undo、Dirty、Prefab 覆盖、保存和多对象编辑方式；修改前确认作用范围，避免静默批量破坏资产。
- 🔴 **必须**：菜单、快捷键、文件路径和资源查询从项目现有结构推导；不得硬编码另一项目的目录、类型或资产名。
- 🟡 **推荐**：为可能耗时或不可逆的操作提供进度、取消、预览、确认或干运行，前提是当前 Unity/项目已有可用机制。

## 3. 验证与例外

- 🔴 **必须**：验证 Editor 编译、目标 Inspector/窗口打开、Undo/Redo、Dirty/保存、Prefab/多对象行为和运行时构建不含 Editor 引用。
- 🟡 **推荐**：交付时说明操作范围、资产备份/回退前提和需要人工复核的结果。

> **例外**：全项目资产迁移或自动修复工具需要独立授权、备份、试运行和可审计的回退步骤。
