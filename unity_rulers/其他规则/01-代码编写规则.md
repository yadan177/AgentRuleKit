# 01 - Unity C# 编码规范

> 🟢 本文件适用于 Unity C# 脚本的基础编码规范（命名/生命周期/序列化字段等）。

> 🔴 不适用：项目级架构决策、美术资源制作流程、平台原生插件用法

---

## 1. 命名规范

### 1.1 命名总原则

- 🔴 **见名知意**：名称应清晰表达用途，避免无意义缩写
- 🔴 **先遵循项目既有命名配置**：优先检查 `.editorconfig`、Rider/IDE 设置和同模块代码；没有项目约定时，可采用私有字段 `m_`、静态字段 `s_`、常量 `k_`、布尔 `is/has/can` 的一致前缀方案。
- 🔴 **类型与公开成员使用 PascalCase、局部变量与参数使用 camelCase**，除非项目的已验证约定另有规定。
- 🟡 名称包含单位时标注单位（如 `m_speedInMetersPerSecond`）

### 1.2 类与接口

> **本章规定命名的"语义"（什么名字算好名字），不重复"格式"细节**（PascalCase / I 前缀 / Base 后缀等格式约束见 `10-代码风格规则.md` 对应章节）。

- 🔴 **类名见名知意**：名词或名词短语，从名字就能看出类的作用
- 🔴 **接口名表示"能力"**：形容词或动词性名词（`IDamageable` / `IState` / `ISerializable`）
- 🟡 **抽象类名用"Base"或"Abstract"后缀**（表明它是基类）
- 🟢 **静态工具类用 `Util` / `Helper` / `Extensions` 后缀**（表明它的用途）
- 🟢 **全局管理类可用 `Manager` 后缀**（需配合具体前缀，如 `GameManager` / `AudioManager`）
- ❌ **不要在类名中重复父类名**（`PlayerController : MonoBehaviour` 不要叫 `PlayerMonoBehaviour`）
- ❌ **不要单独用通用名作为类名**（单独叫 `Manager` / `Helper` / `Data` 没有具体语义，搜索困难）

```csharp
// ✅ 好：见名知意
public class PlayerController { }     // 玩家控制器
public class InventorySystem { }      // 背包系统
public class AttackDamageCalculator { }  // 攻击伤害计算器

// ❌ 错：通用名（搜不出来）
public class Manager { }              // 什么 Manager？
public class Helper { }               // 帮什么？
public class Data { }                 // 什么数据？
```

### 1.3 方法

- 🔴 方法名**动词或动词短语开头**，明确表达动作
- 🔴 **区分前缀语义**：
  - `SetXxx` —— 赋值/更新（`SetMovementInput(Vector2)`）
  - `ApplyXxx` —— 施加影响（`ApplyDamage(int)`）
  - `ChangeXxx` —— 转换状态（`ChangeHealth(int)`）
  - `GetXxx` —— 单纯取值
  - `CalculateXxx` / `ComputeXxx` —— 计算并返回
- 🔴 **布尔返回方法以问句形式命名**（`IsPlayerAlive()` / `HasKey()` / `CanJump()`）
- ❌ **禁止名词式命名**（除工厂方法 `CreateXxx` / `BuildXxx`）
- ❌ **禁止动名词**（`Walking()`、`Rotating()` —— 应改为状态字段 `isWalking`）
- ❌ **禁止无意义前缀**（`DoDamage()` / `HandleHealth()` 这种 `Do`/`Handle` 太泛）

```csharp
// ✅ 好：动词明确
public void Attack(Enemy target) { }
public void TakeDamage(int amount) { }
public bool IsAlive() { return m_health > 0; }

// ❌ 错：名词式
public void Damage() { }  // 应改为 DealDamage / TakeDamage（Damage是名词不是动词）

// ❌ 错：动名词
public void Walking() { }  // 应改为 isWalking 状态
```

### 1.4 字段与变量

> **本章规定命名的"语义"原则（什么名字算好名字），不重复"格式"细节**（`m_` / `s_` / `k_` / `camelCase` 等格式约束见 `10-代码风格规则.md` 对应章节）。

- 🔴 **字段名见名知意**：从名字就能看出字段存的是什么
- 🔴 **名称中包含单位**（避免猜测）：`m_speedInMetersPerSecond` / `m_timeInSeconds` / `m_sizeInBytes`
- 🔴 **布尔字段用 `is` / `has` / `can` 开头**（`m_isActive` / `m_hasPermission` / `m_canJump`）
- 🔴 **字段名不重复类名**（`Player` 类中用 `m_health` 而非 `m_playerHealth`）
- 🔴 **不用拼音、缩写、无意义名字**（`m_hp` ❌ / `m_n` ❌ / `m_tmp1` ❌）
- 🟡 **每行声明一个变量**（虽然稍显冗长，但更易读）
- 🟡 **Inspector 暴露用 `[SerializeField] private`**（见 4.2）
- ❌ **禁止魔数命名**（`m_health = 100` 应改为 `m_maxHealth = 100` + `m_health = m_maxHealth`）
- ❌ **禁止中文字段名**（编辑器可能显示乱码）

```csharp
// ✅ 好：见名知意 + 单位
[SerializeField] private float m_speedInMetersPerSecond = 5f;
[SerializeField] private int m_maxHealth = 100;
[SerializeField] private float m_timeInSeconds = 2f;
[SerializeField] private bool m_isPlayerDead = false;
[SerializeField] private bool m_hasWeapon = true;

// ❌ 错：缩写（HP 谁知道是啥）
public int m_hp = 100;
public int m_atk = 10;

// ❌ 错：无意义名字
private int m_n;
private string m_tmp1;

// ❌ 错：每行多个变量
private int m_a, m_b, m_c;  // 不推荐
```

### 1.5 属性

> **本章规定属性的"语义"原则（什么时候用属性、什么时候用方法），不重复"格式"细节**（PascalCase 格式约束见 `10-代码风格规则.md` 对应章节）。

- 🔴 **属性是状态的"读取窗口"，方法是动作**
- 🔴 **属性无副作用**（`get` 不修改状态、不打日志、不发事件）
- 🔴 **布尔属性用动词**（`IsGrounded` / `HasHealthPack` / `CanJump`）
- ❌ **禁止序列化属性**：如果需要在 Inspector 暴露，用 `[SerializeField] private T m_field` + 公共属性
- ❌ **禁止用属性执行动作**：属性不应触发事件、计算、抛异常
- ❌ **禁止 set 有副作用**（`set` 中只赋值，不调方法、不发通知）
- 🟡 **属性适合轻量操作**（`Health` / `Speed` / `IsGrounded`）
- 🟡 **重操作或异步操作用方法**（`RecalculateStats()` / `LoadAsync()`）

```csharp
// ✅ 好：属性无副作用
public int MaxHealth => m_maxHealth;
public bool IsGrounded => Physics.Raycast(transform.position, Vector3.down, m_groundDistance);
public int Health
{
    get => m_health;
    set => m_health = value;  // set 也只是赋值
}

// ❌ 错：属性有副作用
public Vector2 MovementInput
{
    set
    {
        m_forwardMovementInput = value;
        Debug.Log("Movement input set.");  // ❌ 副作用
        OnInputChanged?.Invoke();           // ❌ 触发事件
    }
}

// ❌ 错：序列化属性（应改用 [SerializeField]）
[SerializeField]
public int MaxHealth { get; set; }  // ❌ 应改为 private + [SerializeField] + 公共属性
```

### 1.6 事件与委托

- 🔴 大多数情况用 `event Action` 或 `event Action<T>`
- 🔴 事件名使用**过去时动词**（`DoorOpened`，不是 `OnDoorOpen`）
- 🔴 触发事件的方法使用 `On` 前缀（`OnDoorOpened()`）
- 🔴 在 `OnEnable` 订阅、`OnDisable` 取消订阅（避免内存泄漏）
- 🟡 需 Inspector 暴露回调时用 `UnityEvent`；代码内部事件优先 `Action`
- 🟡 多个参数用自定义 `EventArgs` 或事件参数类
- ❌ 禁止 lambda 订阅事件（无法取消订阅）

```csharp
// 事件声明（过去时动词）
public event Action DoorOpened;
public event Action<int> PointsScored;
public event Action<CustomEventArgs> ThingHappened;

// 触发事件（On 前缀）
public void OnDoorOpened()
{
    // 用 ?. 避免空引用
    DoorOpened?.Invoke();
}

public void OnPointsScored(int points)
{
    PointsScored?.Invoke(points);
}

// 复杂数据用自定义 EventArgs
public struct CustomEventArgs
{
    public int ObjectID { get; }
    public Color Color { get; }

    public CustomEventArgs(int objectId, Color color)
    {
        this.ObjectID = objectId;
        this.Color = color;
    }
}
```

### 1.7 枚举与常量

- 🔴 枚举使用 **PascalCase** 类型名 + PascalCase 成员
- 🔴 枚举成员前可加类型前缀避免命名冲突（`PlayerState.Idle` 而非 `Idle`）
- 🟡 状态管理优先用枚举替代字符串常量
- 🟡 魔数提取为 `const` 或 `[SerializeField]`

### 1.8 命名空间

- 🔴 使用命名空间，避免类冲突
- 🔴 PascalCase，不使用下划线或特殊符号
- 🔴 用点（`.`）创建子命名空间（`MyApplication.GameFlow`、`MyApplication.AI`）

```csharp
namespace MyGame.Characters
{
    public class Player : MonoBehaviour
    {
        // 类实现
    }
}
```

### 1.9 文件与文件夹

- 🔴 一个文件一个 public 类，**文件名 = 类名**
- 🟡 文件夹命名 PascalCase
- 🟡 私有嵌套类放在宿主类同文件
- ❌ 禁止中文、禁止空格、禁止特殊字符（美术资源除外）


## 2. 注释规范

> **本章只规定"该注释什么 / 不该注释什么"（意图层面）**。注释的**格式层面**（`///` 还是 `//`、单行还是多行）见 `10-代码风格规则.md` 第 8 章。

### 2.1 什么该注释 / 什么不该注释

- 🔴 **注释应通俗易懂、简洁明了**：使用团队成员可直接理解的中文或项目既有术语；一句说明一个意图，优先写清对象、原因或影响。
- ❌ 不堆砌抽象术语、无关背景或重复限定语；读者不需要先猜测注释的含义。
- ✅ **该注释**：
  - 复杂业务逻辑的"为什么"
  - 公开 API 的用途
  - 临时方案（`// TODO: ...`）
  - 已知问题（`// FIXME: ...`）
  - 已知的 hack（`// HACK: ...`）
- ❌ **不该注释**：
  - 复述代码本身（`i++; // i 加 1`）
  - 显而易见的命名
  - 大段废弃代码（用版本控制）

```csharp
// ✅ 玩家断线后保留输入缓存，重连时用于补发未确认指令
// ❌ 为了处理某种特殊的缓存同步相关逻辑而进行必要操作
```

### 2.2 Inspector 字段注释工具

- 🟡 用 `[Tooltip]` 给 Inspector 字段加提示（鼠标悬停可见）
- 🟡 用 `[Header]` 给字段分组加标题
- 🟡 用 `[Space]` 在字段间加垂直间距
- 🟡 用 `[Range]` 限制数值范围
- 🟡 用 `[SerializeReference]` 处理多态序列化

```csharp
[Header("玩家设置")]
[Tooltip("玩家单帧最大移动距离（米）")]
[SerializeField] private float m_maxDeltaMovement = 10f;

[Tooltip("血量上限")]
[Range(1, 1000)]
[SerializeField] private int m_maxHealth = 100;

[Space(20)]
[Header("战斗设置")]
[Tooltip("基础攻击力")]
[SerializeField] private int m_attackPower = 10;
```


## 3. 类结构与组织

### 3.1 类成员排序原则

按以下顺序组织类成员，**自上而下**：

1. 常量（`const`）
2. 静态字段（`static`）
3. 实例字段
4. 属性
5. 事件
6. 构造函数
7. Unity 生命周期方法（见 3.3）
8. 公共方法
9. 私有方法
10. nested 类 / 结构体

### 3.2 访问修饰符顺序

按可见性从高到低：

1. `public`（慎用）
2. `internal`（同 Assembly）
3. `protected`（仅继承用）
4. `private`（默认，绝大多数情况）

- 🔴 显式写 `private`（语法上可省略，但写上能显式表达意图）
- 🔴 不要为了"方便"用 `public` 字段（用 `[SerializeField] private` + 属性，见 4.2）

### 3.3 Unity 生命周期方法顺序

类内 Unity 生命周期方法按执行顺序排列（**自上而下**）：

```csharp
// 1. 初始化阶段
private void Awake() { /* 缓存引用、初始化内部状态 */ }
private void OnEnable() { /* 订阅事件、注册输入回调 */ }
private void Start() { /* 依赖其他组件的初始化 */ }

// 2. 帧更新阶段
private void FixedUpdate() { /* 物理相关 */ }
private void Update() { /* 输入、计时器、状态机 */ }
private void LateUpdate() { /* 相机跟随、动画收尾 */ }

// 3. 销毁阶段
private void OnDisable() { /* 取消订阅 */ }
private void OnDestroy() { /* 释放手动创建的资源 */ }
```

**统一顺序的好处**：
- 阅读代码时一眼能定位到生命周期
- 维护时改某一阶段不影响其他阶段
- code review 效率高

### 3.4 公共 / 私有 / 保护方法分组

- 🔴 公共方法集中在生命周期方法之后
- 🔴 私有方法放在公共方法之后
- 🔴 同一职责的方法靠近放置
- 🟡 嵌套辅助类放文件末尾


## 4. 封装与访问控制

### 4.1 访问修饰符使用原则

- 🔴 默认 `private`，**仅在必要时放宽**
- 🔴 `public` 仅用于对外 API
- 🟡 `protected` 仅用于预期被继承的类
- ❌ 禁止 `public` 字段（见 4.2）

### 4.2 字段封装（避免 public 字段）

- 🔴 **禁止 `public` 字段**，改用 `[SerializeField] private` + 属性
- 🔴 Inspector 暴露用 `[SerializeField] private`，**不要**直接 `public`
- 🟡 需要子类访问时用 `protected`

```csharp
// ❌ 错：public 字段
public float health = 100f;

// ✅ 对：[SerializeField] private + 公开属性
[SerializeField] private float m_health = 100f;
public float Health => m_health;
```

### 4.3 属性 vs 公共字段

| 场景 | 用属性 | 用字段 |
|------|--------|--------|
| 仅内部访问 | 🔴 `private` 字段 | ✅ |
| Inspector 暴露 | 🔴 `[SerializeField] private` + 公共属性 | ❌ 禁止 |
| 只读外部访问 | 🔴 `public T Prop { get; }` | ❌ 禁止 |
| 需要校验/通知 | 🔴 完整属性 | ❌ 禁止 |
| 频繁调用 + 无副作用 | ✅ 属性 | ❌ |

### 4.4 接口使用规范

- 🟡 接口隔离：小接口优于大接口（ISP）
- 🟡 依赖抽象（接口 / 抽象类），不依赖具体类（DIP）
- 🟡 跨系统通信优先用接口 + 事件，不用单例

```csharp
// ✅ 小接口
public interface IDamageable { void ApplyDamage(int amount); }
public interface IHealable { void Heal(int amount); }

public class Player : IDamageable, IHealable { /* ... */ }
```


## 5. 异常处理与防御性编程

### 5.1 空引用防护

- 🔴 Inspector 引用、GetComponent、Find 结果都要做空检查
- 🔴 `Camera.main` 每次访问都查表，**要缓存或空检查**
- 🟡 用 `[RequireComponent(typeof(OtherComponent))]` 减少空检查

```csharp
// ✅ 缓存 + 空检查
private Transform m_targetTransform;
private void Awake() { m_targetTransform = m_target?.transform; }
private void Update() { if (m_targetTransform == null) return; }
```

### 5.2 try-catch 使用原则

- 🟡 谨慎使用 `try-catch`（catch 阻止堆栈展开，影响性能）
- 🔴 禁止 `catch (Exception) {}` 静默吞掉异常
- 🔴 catch 中用 `Debug.LogException(e, this)` 传 context

```csharp
try
{
    LoadCriticalData();
}
catch (IOException e)
{
    Debug.LogException(e, this);
    // 明确处理：回退到默认数据
    UseDefaultData();
}
```

### 5.3 异常类型选择

- 🔴 用具体异常类型，不用 `catch (Exception)`（除非最外层兜底）
- 常见 Unity 异常：
  - `NullReferenceException` —— 引用为空
  - `MissingReferenceException` —— Destroy 后访问
  - `MissingComponentException` —— RequireComponent 缺失
  - `UnityException` —— 跨线程 API 误用

### 5.4 断言与边界检查

- 🟡 用 `Debug.Assert(condition, "msg")` 做开发期断言
- 🟡 Release 包用 `if (!condition) return;` 守护关键路径
- ❌ 禁止用异常做流程控制

```csharp
// ✅ 关键路径守护（边界检查 + 状态检查）
public void TakeDamage(int amount)
{
    if (amount <= 0) return;  // 边界检查
    if (!m_isAlive) return;   // 状态检查
    m_health -= amount;
    OnHealthChanged?.Invoke(m_health);
}

// ✅ Debug.Assert 做开发期断言
private void Awake()
{
    m_rigidbody = GetComponent<Rigidbody>();
    Debug.Assert(m_rigidbody != null, $"{name} 需要 Rigidbody 组件");
}

// ✅ try-catch 配合 Debug.LogException
try
{
    LoadCriticalData();
}
catch (IOException e)
{
    Debug.LogException(e, this);  // 传 context 便于定位
    // 明确处理：回退到默认数据
    UseDefaultData();
}
```


## 6. Unity 生命周期规范

### 6.1 Awake / OnEnable / Start 的职责划分

| 方法 | 职责 | 不应做 |
|------|------|--------|
| **Awake** | 缓存组件引用（GetComponent）、初始化内部状态 | 场景依赖调用、外部事件订阅、IO 操作 |
| **OnEnable** | 订阅事件、注册输入回调、注册消息、每次启用重置状态 | 重型计算 |
| **Start** | 依赖其他组件的初始化（其他 Awake 已跑完）、一次性装配 | 不依赖任何其他组件的工作（应放 Awake） |

```csharp
private void Awake()
{
    m_rigidbody = GetComponent<Rigidbody>();  // ✅ 缓存
    m_renderer = GetComponent<Renderer>();
}

private void OnEnable()
{
    GameManager.OnGameStart += HandleGameStart;  // ✅ 订阅
}

private void Start()
{
    m_animator.SetTrigger("Initialize");  // ✅ 依赖其他组件
}
```

### 6.2 Update / FixedUpdate / LateUpdate 的使用场景

| 方法 | 频率 | 适用 |
|------|------|------|
| **FixedUpdate** | 固定 0.02s（默认） | 物理相关（AddForce、刚体操作） |
| **Update** | 每帧 | 输入、计时器、状态机、AI |
| **LateUpdate** | 每帧，Update 之后 | 相机跟随、动画收尾、依赖其他 Update 之后的逻辑 |

- ❌ 禁止在 FixedUpdate 中读输入（应在 Update 中读输入，FixedUpdate 中应用）
- ❌ 禁止在 Update 中直接 new 引用类型（见 3-性能优化规则）
- 🟡 Update 中用早返回模式：`if (!m_isActive) return;`

### 6.3 OnDisable / OnDestroy 与资源释放

- 🔴 OnDisable 取消所有 OnEnable 订阅的事件
- 🔴 OnDestroy 释放手动创建的资源（Texture2D、RenderTexture 等）
- 🟡 监听 GameManager / 单例事件时尤其注意（长生命周期对象订阅短生命周期对象会引起泄漏）
- 🟡 用 `if (xxx == null) return;` 保护 OnDestroy 中的资源清理（防止重复销毁）

```csharp
private void OnEnable()
{
    GameManager.OnGameOver += HandleGameOver;  // 订阅
}

private void OnDisable()
{
    GameManager.OnGameOver -= HandleGameOver;  // ✅ 必配对取消
}

private void OnDestroy()
{
    // 释放手动创建的资源
    if (m_runtimeTexture != null)
    {
        Destroy(m_runtimeTexture);
        m_runtimeTexture = null;
    }

    if (m_renderTexture != null)
    {
        m_renderTexture.Release();
        Destroy(m_renderTexture);
        m_renderTexture = null;
    }
}
```

### 6.4 协程的生命周期管理

- 🔴 协程启动后，**GameObject 被禁用或销毁**时协程自动停止
- 🔴 协程续作前检查对象是否被销毁（`if (this == null) return;`）
- 🟡 长时间运行的协程考虑加取消开关
- 🟡 协程命名以 `Co` 后缀（`OpenDoorCo`）


## 7. 协程与异步编程

### 7.1 协程使用规范

- 🔴 协程方法返回 `IEnumerator`，命名以 `Co` 后缀
- 🟡 对固定时长、高频重复且经 Profiler 确认产生可见分配的等待，可评估复用 `WaitForSeconds`；不要把缓存或每次创建写成无条件禁令。
- 🟡 协程、`Awaitable` 或第三方异步库的选择以 Unity 版本、已安装包、取消模型和项目现有异步边界为准。

```csharp
// ✅ 可选：固定间隔、复用行为已验证时缓存 WaitForSeconds
private static readonly WaitForSeconds k_oneSecond = new WaitForSeconds(1f);

private IEnumerator SpawnEnemiesCo()
{
    while (m_isActive)
    {
        SpawnEnemy();
        yield return k_oneSecond;  // ✅ 复用，无 GC
    }
}
```

### 7.2 async/await 使用规范

- 🔴 async 方法以 `Async` 后缀（`LoadDataAsync`）
- 🔴 续作保护：协程用 `if (this == null) return;`；await 用 `CancellationToken` 或空检查
- ❌ 禁止在同一操作中混用 `await` 与协程

### 7.3 续作保护（对象销毁后）

```csharp
// ✅ 协程
private IEnumerator LoadDataCo()
{
    yield return new WaitForSeconds(2f);
    if (this == null) return;  // 续作保护
    m_data = LoadData();
}

// ✅ 已验证 Unity 6+ Awaitable 支持时使用 async/await
private async Awaitable LoadDataAsync()
{
    await Awaitable.WaitForSecondsAsync(2f);
    if (this == null) return;  // 续作保护
    m_data = LoadData();
}
```

### 7.4 取消令牌的使用

- 🟡 可取消、可能跨场景、用户可中断或长时间运行的 async 操作应接受并传递 `CancellationToken`；同步完成或不具备取消语义的短操作不必机械添加。
- 🟡 Unity 6+ 且项目已采用 `Awaitable` 时，沿用既有取消与异常处理约定。
- 🟡 长任务定期检查 `token.ThrowIfCancellationRequested()`

```csharp
public async Awaitable LoadDataAsync(CancellationToken token)
{
    await Awaitable.WaitForSecondsAsync(2f, token);
    if (token.IsCancellationRequested) return;
    m_data = await LoadFromDiskAsync(token);
}
```


## 8. 常用最佳实践

### 8.1 字符串处理

- 🔴 禁止在 Update / 频繁路径用 `+` 拼接字符串
- 🔴 禁止热路径用 `string.Format`
- 🟡 动态构建用 `StringBuilder` 复用
- 🟡 值不常变时缓存格式化字符串
- 🟢 零分配场景用 `string.Create` / `Span<char>`

### 8.2 集合类型选择

| 场景 | 选型 |
|------|------|
| 顺序访问、按索引 | `T[]` / `List<T>` |
| 频繁查找（O(1)） | `Dictionary<K,V>` / `HashSet<T>` |
| 队/栈 | `Queue<T>` / `Stack<T>` |
| 不可变 | `ImmutableArray<T>` / `ImmutableList<T>` |
| 临时小数组 | `Span<T>` + `stackalloc` |

- 🔴 预分配容量，避免扩容
- 🔴 复用 `List<T>.Clear()`，不要 new
- 🟡 临时集合用 `ListPool<T>` / `CollectionPool<T>`

### 8.3 枚举 vs 字符串常量

- 🔴 状态 / 类型 / 模式用 `enum`（类型安全、重命名友好）
- ❌ 禁止 `string` 比较状态（`if (state == "running")`）
- 🟢 显示文本才用 `string`（配合枚举的 `ToString()` 或本地化）

```csharp
// ✅ 用枚举
public enum PlayerState { Idle, Running, Jumping, Dead }
if (m_playerState == PlayerState.Running) { /* ... */ }
```

### 8.4 避免 if 嵌套

- 🔴 用**早返回（卫语句）**降低嵌套层级
- 🔴 超过 3 层 `if` 嵌套考虑重构

```csharp
// ❌ 嵌套
if (player != null)
{
    if (player.IsAlive)
    {
        if (player.HasWeapon)
        {
            Attack(player);
        }
    }
}

// ✅ 早返回
if (player == null) return;
if (!player.IsAlive) return;
if (!player.HasWeapon) return;
Attack(player);
```

### 8.5 动画参数 / Layer / Tag 命名

- 🔴 动画参数用 `static readonly int` 缓存（`Animator.StringToHash`）
- 🔴 Layer 用 `LayerMask` 缓存（**禁止每帧 `LayerMask.GetMask()`**）
- 🔴 Tag / Sorting Layer 提取为常量
- ❌ 禁止在代码中用魔术字符串

```csharp
// ✅ 动画参数用 hash 缓存（避免每帧字符串查找）
private static readonly int k_speedHash = Animator.StringToHash("Speed");
private static readonly int k_attackTrigger = Animator.StringToHash("Attack");
private static readonly int k_isGrounded = Animator.StringToHash("IsGrounded");

private void Update()
{
    // 用 hash 而非字符串
    m_animator.SetFloat(k_speedHash, m_currentSpeed);
    m_animator.SetBool(k_isGrounded, m_isGrounded);
    m_animator.SetTrigger(k_attackTrigger);
}

// ✅ LayerMask 缓存到字段
private LayerMask m_enemyLayer;

private void Awake()
{
    m_enemyLayer = LayerMask.GetMask("Enemy");  // ✅ 缓存，Awake 中调一次
}

private void FixedUpdate()
{
    int hitCount = Physics.OverlapSphereNonAlloc(
        transform.position, m_radius, m_hitBuffer, m_enemyLayer);
}

// ❌ 错：每帧调用 LayerMask.GetMask
private void Update()
{
    var mask = LayerMask.GetMask("Enemy");  // ❌ 慢
    var hits = Physics.OverlapSphere(transform.position, 10f, mask);
}

// ✅ Tag 提取为常量
private const string k_playerTag = "Player";
private const string k_enemyTag = "Enemy";

private void OnTriggerEnter(Collider other)
{
    if (other.CompareTag(k_playerTag)) { /* ... */ }
}
```


## 9. 禁用写法与常见坑

### 9.1 高风险写法

- ❌ **`FindObjectOfType` / `FindObjectsOfType` 在热路径**（O(n) 场景扫描）
- ❌ **`GameObject.Find` 按字符串查找**（极慢、易断）
- ❌ **在项目未采用 Resources 时新增 `Resources.Load` / `Resources.LoadAll`**；资源加载方案应先按 09 号规则和现有实现确认。
- ❌ **在 Update / FixedUpdate / LateUpdate 中 `new` 引用类型**
- ❌ **`.material` 访问**（会创建材质实例）
- ❌ **字符串访问 Shader 属性**（用 `Shader.PropertyToID` 缓存）
- ❌ **协程里 `new WaitForSeconds`**（缓存在字段）
- ❌ **事件不取消订阅**（OnEnable 订阅必须 OnDisable 取消）
- ❌ **`public` 字段**（用 `[SerializeField] private` + 属性）
- ❌ **单例 + 静态可变状态滥用**（优先 ScriptableObject 注入）
- ❌ **不空检查 `Camera.main` / `GetComponent` / `Find`**
- ❌ **`catch (Exception) {}` 静默吞异常**
- ❌ **静态字段未在 `RuntimeInitializeOnLoadMethod` 中重置**（Domain Reload 关闭时）

### 9.2 常见性能陷阱

- ❌ Update 中字符串拼接 / 插值（`$"value={x}"` 产生分配）
- ❌ Update 中 LINQ 查询（产生大量分配）
- ❌ Update 中 `ToArray()` / `ToList()`（产生新集合）
- ❌ 频繁 `SetActive` 切换 UI（用 CanvasGroup）
- ❌ 嵌套 Layout Group 多层（导致频繁重建）
- ❌ Image 不打包到 Sprite Atlas（破坏合批）
- ❌ 频繁 `Physics.OverlapSphere` 不用 NonAlloc

### 9.3 常见逻辑错误

- ❌ `OnEnable` 订阅了事件但 `OnDisable` 没取消（内存泄漏）
- ❌ 协程续作没保护（`if (this == null) return;`）
- ❌ Destroy 后访问组件（`MissingReferenceException`）
- ❌ 跨线程访问 Unity API（`UnityException`）
- ❌ 用 `==` 比较浮点数（应用 `Mathf.Approximately`）
- ❌ `Time.deltaTime` 用在 FixedUpdate 中（应用 `Time.fixedDeltaTime`）
- ❌ `Camera.main` 每帧访问（应缓存）
- ❌ 用 `Resources.FindObjectsOfTypeAll`（极慢）
