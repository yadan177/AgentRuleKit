# 01 - Unity 代码编写规则

> 🟢 本文件适用于 Unity C#、MonoBehaviour、ScriptableObject、事件和异步流程的实现或审查。
>
> 🔴 不适用：未经授权的包、C# 语言级别、架构或资源系统迁移。

---

## 1. 开始前确认

> **适用条件与验证**：先读取 `ProjectVersion.txt`、`Packages/manifest.json`、相关 asmdef、同模块脚本和测试/构建入口。C# 语法、Unity API、异步库及命名约定以项目实际能力为准。

- 🔴 **必须**：只引用当前程序集可见、已安装且有既有用例支持的 API 与包；不要从示例、博客或其他项目推断能力。
- 🔴 **必须**：先确认脚本属于运行时、Editor、测试或共享模块；Editor API 不得泄漏到运行时程序集。
- 🟡 **推荐**：以同目录最近维护的实现作为命名、日志、空值处理和错误传递的优先参考。

## 2. 生命周期、状态与所有权

> **适用条件与验证**：适用于持有组件、资源、订阅、协程、任务或原生对象的脚本。

- 🔴 **必须**：为每个事件订阅、资源句柄、协程、任务、定时器和原生对象明确创建者、停止/释放时机和重复启用行为。
- 🔴 **必须**：不要在 `Awake`、`OnEnable`、`Start`、`OnDisable`、`OnDestroy` 中假定固定调用顺序以外的项目状态；跨对象依赖应有空值、销毁和场景切换保护。
- 🟡 **推荐**：序列化字段用于已知场景/Prefab 引用；运行时查找只在项目既有模式允许且成本、失败路径可接受时使用，并缓存热路径结果。
- 🟢 **可选**：将可配置、可复用的数据放入项目已有的 ScriptableObject、配置服务或数据模型；不要仅为“解耦”新建一套数据框架。

## 3. 事件、协程与异步

> **适用条件与验证**：项目已使用协程、Unity 提供的 await 能力或其他已验证异步方案时适用。

- 🔴 **必须**：沿用同模块的异步方案；不要因规则提到 `async`、协程或第三方库就混用或引入其中任一方案。
- 🔴 **必须**：订阅使用可取消/可注销的处理器；捕获 lambda 时要保留可注销实例，或采用项目已有的集中生命周期管理方式。
- 🔴 **必须**：异步续作在对象已销毁、场景切换、请求取消或资源失效时安全退出；异常、超时和取消不得被静默吞掉。
- 🟡 **推荐**：把长流程拆成可验证的状态边界，而不是在属性 setter、事件回调或 `Update` 中隐式启动不可追踪的异步工作。

## 4. 可维护性与边界

> **适用条件与验证**：适用于新增或修改公共脚本接口、序列化字段、状态和模块依赖。

- 🔴 **必须**：公开方法、事件、序列化字段和资源键的改动先检查调用点、Prefab/场景引用与反序列化兼容性；不得因命名或格式偏好批量重命名。
- 🔴 **必须**：错误处理保留上下文，但日志不得记录令牌、个人数据或项目密钥；日志等级和封装沿用项目约定。
- 🟡 **推荐**：方法保持单一、可测试的责任；复杂状态转换显式表达输入、输出、失败和恢复路径。
- 🟢 **可选**：项目已有 analyzers、`.editorconfig` 或格式化工具时，按其配置格式化受影响文件，避免无关全仓格式化。

## 5. 验证与交付

- 🔴 **必须**：执行项目可用且与改动相称的编译、测试、Play Mode/Edit Mode、场景或设备验证；无法执行时说明原因、未验证范围和风险。
- 🔴 **必须**：检查新增引用、事件取消、资源释放、asmdef 边界和序列化影响；不得把未运行的验证写成已通过。
- 🟡 **推荐**：交付时说明生命周期假设、使用的项目能力、验证结果和需要在 Editor/设备上复核的事项。

> **例外**：升级 Unity、启用新语言特性、更换异步库或跨模块重构，须作为独立授权任务并补充兼容性与回退验证。
