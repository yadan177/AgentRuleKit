# 14 - Unity 安全模块规则

> 🟢 本文件适用于 Unity 客户端的数据保护、资源保护、风险信号、网络、隐私和支付接入边界。
>
> 🔴 不适用：替代服务端认证/授权/风控、提供法律意见，或擅自启用侵入式安全能力。

---

## 1. 客户端信任边界

> **适用条件与验证**：先确认服务端权威规则、平台能力、数据分类、目标地区、身份/支付 SDK 与项目安全流程。

- 🔴 **必须**：把客户端视为不可信环境；分数、库存、货币、权限、价格、支付结果、风控结论和最终存档由服务端或平台权威校验，不能只依赖客户端混淆、隐藏或本地校验。
- 🔴 **必须**：不得把密钥、长期凭证、管理员能力、生产端点或绕过校验的开关写入脚本、资源、Prefab、日志或规则示例。
- 🟡 **推荐**：仅在项目安全策略和平台限制明确时采用混淆、完整性信号、调试检测或资源保护，并说明误判、兼容、性能和用户支持影响。

## 2. 数据、网络与资源

> **适用条件与验证**：处理本地存储、令牌、网络、内容、日志、崩溃报告或第三方 SDK 时适用。

- 🔴 **必须**：本地数据、缓存、传输、证书、资源和诊断遵循已有加密、密钥注入、最小保存、脱敏和删除策略；不得关闭传输安全或绕过平台校验。
- 🔴 **必须**：资源保护、反篡改和反作弊只作为延缓/检测能力，不应伪装为服务端安全控制；发现风险后的处置由服务端和产品流程决定。
- 🟡 **推荐**：对高风险事件采用项目已有的安全上报与审计字段，避免上传原始敏感载荷或无必要设备指纹。

## 3. 隐私与支付

> **适用条件与验证**：收集个人数据、设备信号、分析事件、广告标识、年龄信息或接入支付时适用。

- 🔴 **必须**：以产品、地区、平台、法律/隐私负责人和 SDK 要求确认告知、同意、最小化、保留、删除和用户权利；本文件不能替代合规判断。
- 🔴 **必须**：支付由已批准的平台/SDK 与服务端验单流程处理；客户端不得保存支付敏感数据、伪造结果或把本地回调作为最终成功。
- 🟡 **推荐**：对拒绝同意、撤回同意、网络失败和平台不可用展示项目既有的用户路径。

## 4. 验证与例外

- 🔴 **必须**：验证权限、数据存储、日志脱敏、网络失败、第三方 SDK 初始化、支付/恢复和风险信号中的受影响路径；不能将未执行的安全测试标为通过。
- 🟡 **推荐**：安全、隐私、支付、反作弊或生产数据变更由相应负责人复核，并记录未覆盖设备/地区风险。

> **例外**：安全事件和监管要求按既有应急/合规流程执行，保留授权、证据和恢复记录。
