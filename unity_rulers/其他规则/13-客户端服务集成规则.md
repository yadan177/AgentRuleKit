# 13 - Unity 客户端服务集成规则

> 🟢 本文件适用于 Unity 客户端与账户、配置、存档、内容、分析、支付或业务服务的集成边界。
>
> 🔴 不适用：服务端内部架构、数据库、风控、结算或部署实现；这些内容应遵循 Go 或 Java 规则库。

---

## 1. 集成事实与职责

> **适用条件与验证**：先检查已确认的协议/IDL、SDK、错误码、版本策略、身份、数据归属、网络封装和服务端联系人/文档。

- 🔴 **必须**：客户端只实现已经确认的请求、展示、缓存和恢复行为；不得臆造服务、字段、错误码、版本、权限、密钥或服务端流程。
- 🔴 **必须**：明确客户端、服务端、资源服务和支付/身份平台各自的权威数据、校验、重试、审核和失败责任；客户端缓存不能替代服务端最终状态。
- 🟡 **推荐**：将协议演进、依赖 SDK、最低客户端版本和联调前提写入交付说明或项目已有契约记录。

## 2. 生命周期、兼容与数据

> **适用条件与验证**：集成登录、配置、云存档、内容下载、增量同步、推送或版本检查时适用。

- 🔴 **必须**：会话、令牌、请求、缓存、版本、数据迁移和退出处理遵循当前服务契约；场景切换、重复登录、取消、离线和恢复不能遗留旧身份或旧数据。
- 🔴 **必须**：写入、同步、重试和冲突解决需要服务端定义的幂等、版本或合并规则；客户端不得自行决定覆盖顺序或伪造成功。
- 🟡 **推荐**：向用户呈现项目约定的加载、离线、过期、冲突、升级和不可用状态，并最小化本地敏感数据保存。

## 3. 诊断与安全

> **适用条件与验证**：采集服务错误、版本、性能或产品事件时适用。

- 🔴 **必须**：日志、分析和诊断事件遵循字段 schema、同意、采样、脱敏、保留和上传策略；不得上传令牌、完整个人数据、支付信息或未获同意的设备数据。
- 🟡 **推荐**：将可安全公开的关联标识、客户端版本、错误分类和重试结果用于联调，但不把客户端日志当作服务端事实。

## 4. 验证与例外

- 🔴 **必须**：验证已授权环境中的成功、认证失败、权限拒绝、兼容错误、超时、取消、离线、重试和恢复路径；明确未联调的服务端风险。
- 🟡 **推荐**：交付时列出契约版本、依赖 SDK、实际验证、回退前提和需要服务端/产品确认的项。

> **例外**：服务端协议、数据模型、身份、支付或风控策略变更需由对应所有者单独批准和联调。
