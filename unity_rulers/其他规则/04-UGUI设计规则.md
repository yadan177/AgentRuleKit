# 04 - UGUI 设计规则

> 🟢 本文件适用于以 UGUI 为单个界面主负责框架的 Canvas、Prefab、交互和分辨率适配任务。
>
> 🔴 不适用：强制迁移至 UI Toolkit、替换输入系统，或在同一界面无边界混用两套 UI 框架。

---

## 1. 前置事实与界面边界

> **适用条件与验证**：先检查目标界面的 Canvas、Prefab、输入模块、事件系统、Canvas Scaler、资源来源和同类界面。

- 🔴 **必须**：每个界面指定唯一的 UI 主负责框架；与 UI Toolkit 或其他界面系统共存时，明确输入、状态、层级和生命周期边界。
- 🔴 **必须**：仅当场景包含需要 UGUI 指针、键盘或触控交互的界面时，确认可用的 EventSystem 及其输入模块；沿用项目当前输入方案，不得随意替换模块。
- 🟡 **推荐**：优先复用项目既有 Canvas 层级、弹窗管理、导航、字体和本地化约定。

## 2. 布局、适配与资源

> **适用条件与验证**：修改 RectTransform、布局组件、图片、文本、Safe Area 或多分辨率行为时适用。

- 🔴 **必须**：锚点、轴心、缩放、布局组件和 Canvas Scaler 的选择以设计稿、目标设备、现有 Prefab 与项目适配策略为准；改动后在相关分辨率、方向和安全区域验证。
- 🔴 **必须**：Sprite、字体、图集、材质和动态资源沿用现有导入与加载策略；不得臆造图集名称、地址或替换资源系统。
- 🟡 **推荐**：将重复布局和样式放在项目已有 Prefab/组件/主题机制中；避免仅为通用性堆叠多层 Layout Group 或 ContentSizeFitter。

## 3. 交互与生命周期

> **适用条件与验证**：适用于 Button、Toggle、滚动列表、拖拽、导航和自定义事件。

- 🔴 **必须**：事件订阅、输入拦截、按钮防重入、加载/错误/空状态和禁用状态遵循当前界面的交互约定；启用/销毁时取消订阅。
- 🔴 **必须**：列表复用、滚动、拖拽和动态增删不得遗留旧数据、监听器或资源引用；虚拟化只在项目已使用且适合数据规模时采用。
- 🟡 **推荐**：使用可访问的文本、焦点、键盘/手柄导航和反馈方式，前提是目标平台与项目已有无障碍方案支持。

## 4. 性能与渲染

> **适用条件与验证**：Profiler 或 Frame Debugger 表明 Canvas rebuild、布局、Raycast、材质、纹理或 overdraw 是实际问题时适用。

- 🔴 **必须**：根据测量结果调整 Canvas 边界、布局更新、Raycast Target、图集或滚动列表；不得机械要求合批、拆 Canvas、关闭对象或改用另一套 UI。
- 🟡 **推荐**：高频数据更新仅刷新受影响元素，并在目标设备验证布局、输入和视觉结果。

## 5. 验证与例外

- 🔴 **必须**：验证相关 Prefab/场景加载、交互、分辨率/安全区、输入路径、资源引用和目标平台构建。
- 🟡 **推荐**：交付时列出验证设备、未覆盖输入方式和需要设计/无障碍复核的风险。

> **例外**：项目正式授权的 UI 框架迁移须单独规划输入、数据、资源、测试和回退，不能作为单个界面需求的附带改动。
