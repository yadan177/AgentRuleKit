# 05 - Unity UI Toolkit 设计规则

> 🟢 本文件适用于以 UI Toolkit 为单个界面主负责框架的 UXML、USS、VisualElement、Editor UI 或运行时 UI 任务。
>
> 🔴 不适用：以本文件为由升级 Unity、启用未验证的数据绑定 API，或把既有 UGUI 界面强制迁移到 UI Toolkit。

---

## 1. 项目能力与界面边界

> **适用条件与验证**：先检查 `ProjectVersion.txt`、已安装包、运行时或 Editor 目标、UIDocument/UXML/USS、输入方式和同模块实现。

- 🔴 **必须**：只使用当前项目已验证的 UI Toolkit API、控件和数据绑定方式；版本相关 API 必须由项目能力或官方资料与本地用例共同确认。
- 🔴 **必须**：每个界面指定唯一 UI 主负责框架。与 UGUI 或 IMGUI 共存时，明确元素层级、输入、状态、数据流与生命周期，避免双向控制同一交互。
- 🟡 **推荐**：沿用项目的目录、命名、主题、UXML/USS 组织、控件封装和运行时/Editor 隔离方式。

## 2. 结构、样式与本地化

> **适用条件与验证**：新增或修改 UXML、USS、主题、资源引用、文本和布局时适用。

- 🔴 **必须**：UXML 表达结构，USS 表达样式；选择器、类名、变量、资源路径和主题机制遵循项目已有约定，不能把 CSS、网络地址或另一项目路径直接复制为 USS/资源事实。
- 🔴 **必须**：布局、颜色、字体、图片、文本、缩放、深浅主题、Safe Area 和本地化依据设计系统、目标平台和已有实现验证；颜色和 USS 属性只使用当前 UI Toolkit 支持的语法。
- 🟡 **推荐**：为可复用控件定义稳定且有限的公开样式/行为边界，避免依赖深层元素树或高特异性覆盖。

## 3. 查询、事件与生命周期

> **适用条件与验证**：从 C# 查询元素、注册回调、创建自定义控件、打开窗口或切换界面状态时适用。

- 🔴 **必须**：在正确的面板/文档创建时机查询元素，并处理查找失败、重复初始化、禁用和销毁；缓存是否合适由元素重建和生命周期决定。
- 🔴 **必须**：每个 `RegisterCallback`、`clicked`、定时器、绑定、资源或自定义对象都有相应注销、取消或释放路径；不要假定项目存在某个事件注册器、基类或全局 UI 服务。
- 🟡 **推荐**：通过具名方法、项目已有控制器或清晰的局部所有权管理事件；避免在不受控回调中混入业务状态、网络请求或资源加载。

## 4. 列表、绑定与可扩展控件

> **适用条件与验证**：项目已使用可复用列表、数据绑定、自定义 VisualElement 或序列化对象绑定时适用。

- 🔴 **必须**：ListView/TreeView 的项创建、绑定、回收与数据更新保持一致，复用项不能保留旧监听器、索引、样式或资源。
- 🔴 **必须**：运行时绑定、Editor `SerializedObject` 绑定和手动刷新是不同能力；仅采用项目已验证的一种，并在数据变更、撤销/重做（若适用）和对象销毁时验证。
- 🟡 **推荐**：只有多个实际使用点需要时才自定义控件；公开属性、UXML 工厂/特性和样式接口随项目版本能力选择，不强制采用某一注册写法。

## 5. 性能、可访问性与调试

> **适用条件与验证**：出现布局、绘制、列表、样式、输入或内存问题，或项目有无障碍目标时适用。

- 🔴 **必须**：先通过项目已有 Profiler、UI 调试器或复现步骤定位问题，再处理查询频率、列表虚拟化、样式、重绘和数据更新；不要机械缓存或迁移框架。
- 🟡 **推荐**：按项目约定覆盖加载、错误、空状态、焦点、键盘/手柄导航、文本缩放和对比度；目标平台不支持的能力应明确记录而不是伪造通过。

## 6. 验证与例外

- 🔴 **必须**：验证受影响的 UXML/USS 载入、元素查询、交互、样式、数据更新、事件清理和运行时或 Editor 目标；说明未覆盖的版本/设备风险。
- 🟡 **推荐**：交付时列出所依赖的 UI Toolkit 能力、验证环境以及与 UGUI/IMGUI 的边界。

> **例外**：UI 框架、绑定模型或共享主题的迁移必须获得明确授权，单独验证资源、输入、无障碍、性能和回退方案。
